# A default-off pilot has `plan-architect` challenge the `/code-review` orchestrator's own dispositions

*2026-10-29.*

By default, the `/code-review` orchestrator both writes and judges its own ADDRESS and DEFER dispositions, so a DEFER that should have been an ADDRESS, or an ADDRESS that over-fixes, stands on one judgment. A per-account config key, `architect_disposition_challenge_pilot`, default `false`, pilots a second opinion. With the key on, one Opus `plan-architect` dispatch in a new `MODE=challenge` argues each row the orchestrator decided itself, and answers `uphold` or `flip` per row. A flip changes a row only when the orchestrator concedes it after one re-evaluation, or the human decides it.

## Decision

- **The key.** `architect_disposition_challenge_pilot` is a `bool`, default `false`, resolved per account (`config-dir`), with no legacy predecessor and no prompt. The skill reads it through `config-get.sh`, and only exit 0 applies the rule.
- **The rule.** `claude-skills/skills/code-review/SKILL.md`'s `DISPOSITION_RULE:code-review-disposition-challenge` region is canonical for the rule. This record does not restate it and states only why the pilot has this shape.
- **The mode.** `claude/.claude/agents/plan-architect.md` § "MODE=challenge" is canonical for the verdict grammar and the flip standard. This record does not restate them.
- **Exact first line.** `claude/.claude/agents/plan-architect.md` § "Mode selection" now runs a mode only for an exact first line, as both classifiers (`log-reviewer-round.sh` and `review-trace`) already read one. Any other first line, an absent one included, is a consult.
- **Classifiers.** `log-reviewer-round.sh` writes no round-3 latch for `MODE=challenge`, and `review-trace` emits no `architect-consult` event for it, as for `MODE=plan-sections`. Every other first line still counts as a consult.

## How this differs from the not-adopted pilot

[The architect-authored fix-plan pilot is not adopted](architect-fix-plan-pilot-not-adopted.md) found no detectable benefit, a gross consult cost, and a guardrail that failed on a DEFER of an enforcement-invariant finding. It named a narrower challenger design as the starting point, and the engineer widened it to every row and every round. Five differences follow:

- **The orchestrator still writes every disposition.** The architect only argues, and a flip changes a row only through the orchestrator's concession or the human's decision.
- **A marked row is not a numbered row,** receives no verdict, and never ends DEFER without the human. The orchestrator sets the mark from the finding before any argument. This record does not claim that every DEFER of an invariant finding reaches the human: the architect can still read a marked finding in a findings file and the diff the prompt names, and the checks on a barred finding the orchestrator fails to mark are the ones the Known-gaps bullet on that case lists.
- **The metric pairs each row's original disposition with its outcome.** It draws no comparison set, so the not-adopted record's workload and consult-routing confounds do not enter it. The definitions are written before enabling. An ad-hoc key-on/key-off comparison of rounds and cost carries those confounds, so it is read by judgment and moves no part of the decision rule.
- **It runs as its own mode,** so the round-3 foundation consult still fires on a key-on branch and the two are measured apart. The sibling pilot's first dispatch on a branch released that gate.
- **It is not cheaper per round.** Each round with a payload, outside a `/review-pr` pass, costs one Opus dispatch at `plan-architect`'s pinned `effort: xhigh`. The strata below exist so the data can narrow it later.

## Which rows are challenged

The engineer settled the cadence: "I think we want to have the adversarial architect on every round and then refine based on data." The engineer also answered that a `/review-pr` pass is not a round for this rule: "Yes skip in review-pr passes since it has its own consult process". That pass's standing override forbids fixes and its synthesis drops the ADDRESS/DEFER axis, so a challenge there would change nothing that reaches the posted review. The region names that standing override, not any instruction to change nothing, because `review-orchestrator` also changes nothing itself yet sends every fix to `code-writer`, and the rule runs under it.

- **Challenged:** every ADDRESS or DEFER the orchestrator decided itself, less the rows it marks as barred. That includes an ADDRESS row the heavier-mechanism rule routes to a consult, because the orchestrator wrote it and its consult has not yet run, and every row after `fix-plan: fell-back`, which reaches this rule as the orchestrator's own.
- **Not challenged:**
  - Rows a valid fix-plan table or the human decided.
  - Rows on the contradiction route, which that route's own consult decides.
  - Carries.
  - Marked rows.
- **No KEEP is challenged,** because the orchestrator writes no KEEP of its own. KEEP rows come from a contradiction consult, the human, or a carry.
- **Carries are an unchallenged orchestrator-only judgment.** A carry is a later finding the orchestrator alone matched to a live decision, which the engineer did not see. A flip on a carry would re-open a live decision outside the contradiction route's rules, so a DEFER conceded here carries forward unchallenged, and the safety guardrail lists every carry.

## Why marked rows are not challenged

The mark has two limbs, and each applies the rule that bars the finding rather than restating it:

- **The enforcement-invariant rule's own test,** judged from the finding before dispatch: a finding that the diff opens a path around an enforcement invariant, anywhere in the PR. The engineer narrowed the mark to that test: "I think we should narrow to enforcment-invariatn rule alone."
- **A loaded project layer's own procedure.** The engineer kept the layer's bar beside that test by selecting "Keep project-layer bar (Recommended)". In this repository the layer judges a finding against a gate by the gate's tier line and by whether it is a regression, a genuinely-lax failure or a per-vector gap.

The orchestrator counts a finding as barred when unsure. A marked ADDRESS stays ADDRESS. A marked DEFER becomes ADDRESS or the stop-and-ask the rule that bars it prescribes. The region says a marked DEFER is re-dispositioned, not only which outcomes a marked row may take, because the orchestrator may already have tagged such a finding DEFER, the failure the not-adopted record describes.

The engineer chose to leave marked rows out of the challenge: "Well yeah if marked rows need to go to me anyway then having the architect look at them doesn't really help unless it provides me with Opus-level judgment so I could make the determination, but that's at the cost of extra machinery, so I agree with the ligher touch of not including them." The quote covers that exclusion only. It gives up the architect challenging an over-fix on a marked ADDRESS, which is fixed with no ask and no challenge.

**How a flip is resolved.** The orchestrator re-evaluates the row once under the rules above, with the architect's argument in front of it, and concedes only when that re-evaluation reaches the flip's result. A re-evaluation cannot reach a result the rules above bar, so a flip toward a barred result is a disagreement and stops for the human. The engineer's ask shape is that the orchestrator re-evaluates and, "if it doesn't agree then ask me". The closed DEFER list, the invalid DEFER rationales and a loaded project layer's bar from DEFER therefore bind every concession unchanged, and the safety guardrail checks every conceded DEFER against them. The engineer also rejected sending every DEFER-ward flip to the human: "if you just have all differs go to me, then it's gonna be like a bunch of different questions to me and including on things that are obvious so that's not the right solution".

**Alternatives rejected:**

- *Dispatching marked rows and never conceding a flip toward DEFER on one.* The architect can add no result the barring rules allow: an uphold changes nothing, and a flip toward DEFER must stop anyway. It cost a clause in both files, its pins, two outcome tags for stops the orchestrator agreed with, and deny fixtures with ablation runs, all for a result set of no change or a stop.
- *A guard keyed on what the flip argues.* A flip naming only a closed-list criterion passes it, and the invariant question is then first asked under persuasion, because an ADDRESS needs no rationale and the ledger checks a DEFER only for a criterion name and a source. The not-adopted pilot's third guardrail failed on that path. The mark is set before any argument for the same reason.
- *A per-flip invariant statement the orchestrator must answer before it may concede.* The call still rests with the orchestrator under persuasion.
- *A mark on every finding that concerns a gate, hook, permission check, required approval or marker guarantee.* It also marks findings on those surfaces that open no path around them, and the engineer narrowed the mark to the rule's test.
- *Never conceding any flip toward DEFER.* It removes the re-evaluation from every finding and sends the obvious ones to the human, which the engineer rejected.
- *Voiding a barred flip silently.* It hides the dispute from the human.

**How each human outcome at a flip's stop is logged.** The tag's suffix names whether the human chose the flip (`-architect`) or the row's original disposition (`-orchestrator`):

- Siding with an orchestrator ADDRESS: ADDRESS, with the `-orchestrator` suffix.
- Siding with the architect's DEFER on an orchestrator ADDRESS: a human keep, with the `-architect` suffix.
- Siding with an orchestrator DEFER: a human keep, with the `-orchestrator` suffix.
- Siding with the architect's ADDRESS on an orchestrator DEFER: ADDRESS, with the `-architect` suffix.
- Each keep is `SETTLED --decided-by engineer` with the engineer's quote. The ledger takes no `--decided-by` on ADDRESS and only `carry` on DEFER, so a keep is the one shape that makes the human's decision attributable in the PR body. The engineer chose "Log as SETTLED (Recommended)" for stop logging and "Keeps only (Recommended)" for its scope, so a human decision to fix a row is logged ADDRESS.
- Every stop here gives the contradiction route's notice once before the human answers, because the answer is quoted in the public PR body. A keep may take `--carry-forward` under that route's conditions, which withhold it wherever the enforcement-invariant rule applies.

## Why a distinct mode

The engineer named the like-for-like condition: "if we don't have the foundation consult when we're having the architect adverse adversely review the dispositions then I think we're not having apples to apples comparison". The engineer leaned toward a distinct mode ("I would almost recommend still making this a different mode.") and delegated the call ("you tell me."). The mode itself is the session's choice on that lean, not the engineer's. The engineer kept it as a mode, not a separate agent, by selecting "Keep MODE=challenge (Recommended)", a label that covers the challenger's form only, and kept its cost: "I'm inclined to keep it for now. We know what an extra architect costs from the other architect fix pilot and if it ends up saving code review rounds and reducing asks to me safely then that's worth it."

Alternatives rejected:

- *Reusing `MODE=consult` and accepting the latch gap.* The first key-on dispatch would release the branch's round-3 gate with no foundation question, and `review-trace` would show it as a consult, which `skill-fidelity-reviewer` reads as the consult a gate deny demanded.
- *A recorder exemption keyed on a marker inside a `MODE=consult` prompt.* Both classifiers would have to read past the first line, the one place the mode is fixed, and a consult's free-text prompt can carry the marker by accident. It is a mode signal nested inside a mode.
- *A `foundation:` line in every challenge.* It re-adds the not-adopted pilot's per-round foundation question without the round history the round-cap consult carries.
- *A separate read-only challenger agent, selected by `subagent_type`.* Neither classifier would see it, and it costs a second agent description in every session. The engineer's bar for any new agent is: "we don't want to apply an agent as a bandaid, we want to make this agent hold weight in the sdlc". A standing adversarial agent is a separate plan.
- *An allowlist that latches only `MODE=consult` or a line with no `MODE=` prefix.* A mistyped mode would then run as a consult yet write no latch, so the gate would deny a branch that had one.

**Why an unknown mode line fails toward consult.** That mirrors `plan-architect`'s own resolution, so the latch keeps meaning a consult ran. [§37](plan-architect-consult-mode.md) chose consult as the fail-safe for an unmarked line, and the round-3 gate allows on state failure. The change only removes latch writes, so it opens no path around the gate. The cost: a mistyped `MODE=challenge` runs as a consult and releases the branch's gate. The region requires exactly `MODE=challenge` on the first line, and a deviation the agent can see ends its return in a `Stance:` line, which the region tags `ran-as-consult`.

This departs from [the sibling pilot](architect-authored-fix-plan-pilot.md), which reused `MODE=consult` and kept its row grammar in its own pinned region. Here the grammar lives in the agent's definition, with a pin on both sides.

## Why a missing verdict stops

The sibling record's "Why every return that is not a valid table stops" section gives the reasoning: treating a missing verdict as upheld leaves unknown whether the challenge ran. A row without exactly one verdict line is one blocking stop-and-ask covering every such row, and so is every row of a failed dispatch. A `Stance:` line marks a return that ran as a consult, because only a consult return ends with one. `ran-as-consult` takes precedence over `no-verdict`, because an accidental consult returns prose with no row lines and would otherwise hide the first-line deviation. Nothing re-dispatches: a second dispatch would overwrite the round's failure tag and add an Opus dispatch, and the next round challenges again. The region defines which lines count as verdicts, because the architect may quote findings-file or diff text that a PR's author shaped. Under `review-orchestrator` the stop becomes a `HALT:` entry.

## Why the outcome rides in `--rationale`

- The ledger rejects `--decided-by` on ADDRESS and accepts only `carry` on DEFER, so the human's decision cannot ride in a field.
- A new ledger field touches the script, its lib, two test files and two docs, and bumps a schema version that reaches every consumer, all for a default-off pilot.
- `fix-plan:` is the precedent for a `--rationale` prefix that marks how a row was decided.
- The scope tag exists because the ledger has no pass-kind field: `<scope>` copies the `Spawn decisions:` line's `narrowed` or `unnarrowed`.
- A marked row carries `barred`. Without it, a marked ADDRESS would be an untagged candidate, and the untagged-round figure, which is where a skipped rule shows, would read every round whose rows are all marked as a skipped rule. The tag also gives the tally a count of the rows the mark kept from the challenge.
- A tag on the `Fix route:` line was rejected: it lives in transcripts that age out, and under routing it lands in a subagent transcript.

## Pre-registration, fixed before enabling

- **Unit.** A payload row on the enabling account in a ledger file the reader's path set selects, with an `event_time` inside the window. A `barred` row is no payload row. Rows in other repositories run the rule and are not counted.
- **Baseline.** Each payload row's own original disposition, with no key-off arm. A SETTLED row counts as the DEFER side, because a payload row is SETTLED only as a human keep. `upheld` and `escalated-orchestrator` rows keep their final side as the original. For `conceded` and `escalated-architect` rows, the original is the other side.
- **Correction.** A row tagged `conceded` or `escalated-architect`.
- **Primary metric.** Corrections per payload row, in four strata: original disposition (ADDRESS or DEFER) by scope (`narrowed` or `unnarrowed`). Rows tagged `no-verdict` or `ran-as-consult` count in no stratum, because no verdict decided them.
- **Agreement check.** `escalated-architect` rows per `escalated-*` row. Every stop at a flip is a disagreement, so every such row is a dispute. The check is not evaluated when the window holds no `escalated-*` row.
- **Interrupt guardrail.** Rows tagged `escalated-*`, plus rounds holding a `no-verdict` row, per round with a payload. The barring rules' own stops on marked rows are outside it, because a marked row is no payload row. The tally reports beside it the count of window rows with `enforcement_invariant: true`, which covers the `invariant` keeps from any route, and the `barred` count by logged disposition. A SETTLED `barred` row is a stop the mark produced, and a stop the human answered with a fix reads as ADDRESS. A `layer` keep made before this rule ran is not separable from a contradiction-route keep.
- **Tag-coverage guardrail.** Untagged rows per candidate row, over every round in the window. A candidate is an ADDRESS or DEFER with an empty `decided_by` whose rationale does not start with `fix-plan:`, in a round from no `/review-pr` pass, which the region skips. For each round holding an untagged row, the engineer reads its session's transcript at evaluation to tell whether that session ran `/review-pr`, because neither skill text settles whether such a pass appends ledger rows. An untagged row is a candidate whose rationale does not start with `challenge:`, so a marked ADDRESS, tagged `barred`, is not one. The tally also reports the untagged-round figure, where a skipped rule shows: rounds (same `session_id` and `round`) whose candidates are all untagged, per round with a candidate.
- **First-line count.** The tally reports how many rows are tagged `ran-as-consult`. A nonzero count means the region's prompt wording needs fixing. It is no guardrail and turns nothing off, and it misses a consult return that omits its `Stance:` line (Known gaps). The engineer agreed to drop key-off on a first-line deviation: "OK agreed about dropping".
- **Safety guardrail.** Three bars. No DEFER row in the window is on a finding the enforcement-invariant rule or this repository's project layer bars from DEFER. No `conceded` DEFER row breaks the closed DEFER list or rests on an invalid DEFER rationale, because a concession the rules above bar is the case the region's concession test exists to stop. No row tagged `barred` is logged DEFER, because the region re-dispositions every barred DEFER. The tally lists every DEFER row in the copy in the window, carries included, whatever its tag or origin, and counts the `barred` ones, expected zero. The engineer judges each listed row against the first bar, and each `conceded` row against the second as well, at evaluation, and reads a key-on PR's Deferred table before merging it.
- **Cost.** The gross cost of the challenge dispatches, each an Opus dispatch at `plan-architect`'s pinned `effort: xhigh`, read privately once at evaluation from the window's subagent transcripts and used only to choose among narrowing options. The same read records whether every challenge dispatch in the window ran Opus, and the outcome record states that verdict, because a challenger on the orchestrator's model is non-independent agreement, a source `code-review/SKILL.md`'s Reconciliation section names. It also records each challenge dispatch's wall-clock duration, which the engineer reads beside the cost, because every payload round waits on that dispatch. Neither is a decision-rule input.
- **Window and sample floor.** The window is the 7 days after the last recorded enable time, ended early by a recorded disable time, and evaluation runs when it closes. The engineer set the week: "are you saying that I need to wait 25 days in order to make a conclusion about the experiment because that's not gonna work for me I need like a week." The sample floor is a number of payload rows counted in a stratum, the primary metric's own unit. Its value is chosen, not sourced from any data. A window holding fewer such rows than the sample floor is inconclusive. An inconclusive window may be extended once by 7 days, at the engineer's choice ("Allow one extension (Recommended)"), recorded privately when the first window closes. Evaluation then runs when the extension closes, over both.
- **Withheld values.** The sample floor, the correction floor, the agreement share, the interrupt ceiling and the tag-coverage ceiling. They go in a dated file in a private directory outside the repository before enabling and are never published, because a value paired with its verdict bounds the figure.
- **Decision rule.**
  - A safety-guardrail failure turns the key off at once, and the pilot is not adopted.
  - An inconclusive first window is either extended once, as above, or the pilot is not adopted. An inconclusive extended window is not adopted.
  - At evaluation, the pilot is not adopted when either ceiling is exceeded, the agreement share is not met, or every stratum is below the correction floor.
  - Otherwise, when some strata fall below the correction floor, the key stays on, and narrowing to the strata at or above it goes through its own plan and record.
  - Otherwise the key stays on as is. A default change for stow consumers needs its own record, because this pilot measures one account in one repository.
  - No branch of this rule reads the ad-hoc comparison below.
- **Action for not adopted.** The key goes off at once, and a follow-up PR carries out the revert contract below. A dormant region would keep its eleven lines with their separator in a file near its line cap, which the engineer will not keep raising ("We can't just keep raising the cap"), and its `config-get.sh` call on every such round for every stow consumer. The outcome record and that PR land together.
- **Changes after enabling.** Any change to a definition or value is disclosed in the outcome record, saying what changed and when. The fixture set checks four spans:
  - the region;
  - the DEFER rules, from the `**DEFER criteria (closed list).**` lead through the `code-review-defer-invariant` region's end anchor, which bind every concession;
  - `plan-architect.md` § "MODE=challenge";
  - `.claude/skills/code-review-claude-config/SKILL.md` § "Finding disposition addition".

  A PR that changes any of them while the key is on is a recorded disable. The engineer, who alone merges, sets the key `false` before merging it and records the disable time, which ends the window or extension then open. That ended segment is not evaluated. Instead the engineer takes a copy at the disable, as at a window's close, and runs the safety guardrail's read over the segment at once, so every key-on interval gets that read, and a failure there means not adopted. A session then re-runs the set against the merged text, and the engineer reads its new table before the key goes back on. The re-enable opens a fresh first window, with its own extension right, so no verdict pools rows from two versions of the spans. A restructure of `code-review/SKILL.md` under its 500-line ceiling (issue #1351) is the foreseeable case, because it re-fits the region. Enabling only after it merges avoids that disable with no mechanism, at the engineer's choice. The engineer said that PR merges first: "Your PR will merged first. #1351 is not going to be worked on for another week or so." A merged edit elsewhere in `claude-skills/skills/code-review/SKILL.md`, `claude/.claude/agents/plan-architect.md` or the layer file neither ends nor restarts the window, which keeps the engineer's week. The window-close reminder runs `git log <fixture-set commit>.. -- <those three files>` in the enabling machine's checkout and compares the four spans at that commit with the live text. The outcome record discloses each commit the log lists, with its date, and any span change no recorded disable preceded, because rows after it ran on text the fixture set did not check.
- **Publication.** The outcome record states verdicts and which strata passed, never a count, rate or value. For the ad-hoc comparison below it carries at most one sentence, saying the comparison was read and which way it pointed, beside its confounds. No round count, cost or token figure from it is published, per PR, per account, per project or pooled. `docs/private-project-redaction.md` § "Publishing a tooling measurement" is the governing bar. The reader's input is a hand copy filtered by file name, so the reader is not the command that refuses a wider corpus which `docs/private-project-redaction.md` § "This repository, one account" requires before any figure is published. ## Reader contract

The reader is a private tool kept in a private directory outside this repository, never in it, that only selects ledger files by an explicit path set and copies them. It computes nothing, so it has no output contract and no output fixture. The engineer endorsed shrinking the measurement apparatus rather than adding layers: "I think your recommendation about handling the foundation signal makes sense".

- **Path set.** A ledger file's name starts with a per-path hash of the toplevel path its review ran from, so each worktree of one repository writes under its own prefix. The set is that hash of every path this repository's reviews ran from: the main checkout, each worktree `git worktree list` prints, and `<main checkout>/.claude/worktrees/<branch>` for each head branch of a PR whose head repository is this repository, open at any point in the window, which covers removed worktrees. A fork's head branch never had a worktree here, so it is left out. The branch names come from public GitHub data and are data only: the reader hashes each derived path string and never places a name in a shell word. A branch whose worktree was removed without a PR is missed. A file whose name starts with no hash in the set never enters the reader's directory, so no other repository's rows do.
- **Input.** One copy, taken by hand when the window or its one extension closes, of the enabling account's `review-narrative-ledger/` files the path set selects, and the private enable and disable times. The ledger's idle sweep deletes only files more than 30 days old, so no sweep can have deleted a file holding a window row by then. The copy goes into a directory created mode `0700`, with each file mode `0600`, because a default umask can leave a plain copy group-readable while ledger rows carry finding summaries and engineer quotes.
- **Tally.** At evaluation the engineer tallies from the copy, by hand or by ad hoc query: per-stratum counts of each tag value; the agreement, interrupt, tag-coverage and untagged-round figures; the `ran-as-consult` count; the `barred` count by logged disposition, whose DEFER cell the safety guardrail requires to be zero; the count of rows with `enforcement_invariant: true`; whether the window reached the sample floor; and the list of every DEFER row in the window. The tally is recorded privately beside the copy, with the query or written steps that produced each figure, so a second pass over the copy can reproduce it.
- **Live selection check.** Before enabling, the selection runs on file names only against the live `review-narrative-ledger/`. It must select the file of a merged PR of this repository whose worktree is removed, so a path set that misses removed worktrees shows before the window opens.

## Enabling, checking, disabling

Four things must exist first: the withheld-values file, a passing live selection check, a dated reminder for the day the window closes, and a recorded behavioral fixture set with its control arm. The engineer also records the PR-body notice correction (Known gaps) as met or consciously waived. A session runs the set, and the engineer reads its pass/fail table and decides whether to enable. The sibling pilot's engineer ran its own fixture pair. Here the engineer chose that a session runs it: "Session runs it, but I don't know how to weigh in on trimming because I feel like you just pulled 20 out of a hat I mean, what are we losing by trimming to 20". The engineer has not chosen the set's run counts, so trimming them stays the engineer's open choice.

- **How a case runs.** A session running from the enabling checkout on its default branch dispatches each run of a case as one `general-purpose` subagent with an explicit `model: sonnet`, the default `claude/.claude/CLAUDE.md` § "Model & Effort Routing" sets for that agent. In each case below, "the session" is that subagent, and the session that dispatches it is the running session. The prompt names, by path, the checkout's `claude-skills/skills/code-review/SKILL.md`, or a control-arm scratch copy of it, and the case's scratch input, and tells the session to apply the region to the stated rows, handed over unmarked. The case text and the table stay outside the repository. The missed-mark case alone starts after the marking step. Each project-layer case's scratch input says Step 0.5 loaded this repository's layer, `.claude/skills/code-review-claude-config/SKILL.md`, and every other case's says Step 0.5 loaded no layer. The scratch input says the region's `config-get.sh` read exited 0. The session thus reaches the key-on state without the key being set on the account, which would make every concurrent session on it run the rule before the recorded enable time. The session writes out, without sending or running them, the dispatch it would make and every `review-ledger.sh` command it would run, so no fixture row reaches a ledger. ## Known gaps

- A first line that is not exactly `MODE=challenge` runs as a consult and releases the branch's round-3 gate. A deviation the agent can see ends the return in a `Stance:` line, tagged `ran-as-consult`, and the key stays on. Until the wording is fixed, every branch it happens on loses its round-3 foundation consult. A whitespace-only first-line difference stays undetectable: the agent may miss it and run the mode while both classifiers count a consult, and `review-trace`'s consult event carries no prompt text by design.
- A consult return that omits its `Stance:` line, against its own section's rule, stops as `no-verdict` when it holds no verdict lines and otherwise reads as a valid challenge. Either way its latch release never reaches the `ran-as-consult` tag or count.
- A `Stance:`-line stop shows the human that round's return, but the pilot measures first-line deviations only at evaluation, through the count. Nothing acts on them during the window.
- **The steered-`Edit` residual, accepted at every key-on round.** As for a consult, the mode's no-`Edit` rule is charter-only, because `deny-plan-writer-off-plan-writes.sh` cannot see the mode. The challenge reads this branch's findings and diff and is handed the plan file's path on every key-on round with a plan. A steered `Edit` to an existing plan file is therefore possible every such round: an uncommitted one goes unnoticed, and a committed one re-arms the plan-review gate. [The consult-mode record](plan-architect-writes-its-own-plan-sections.md) accepted this residual because the gate limits the `Edit` to repository plan files and git recovers a committed one. Neither bound depends on frequency, so it is accepted here at every key-on round. The engineer confirmed that acceptance by selecting "Accept the residual (Recommended)". The label is the engineer's. The option description it answered was the session's proposal. The acceptance names the gate's two Known gaps, which the bounds omit:
  - An edit to another untracked plan has no git recovery.
  - A session whose hook registrations predate the gate, or a Claude Code older than 2.1.295, may let the `Edit` reach any path the other hooks allow.

  That earlier acceptance also rested on `/review-pr`'s consult passing no plan path beside untrusted PR content. That premise holds only for text from the author of a PR the account only reviews, because the rule does not run in a `/review-pr` pass. A direct `/code-review` round on a branch whose diff, commits or plan file a third party wrote still reaches the mark, the re-evaluation and the `Edit`-holding `plan-architect`, and the no-`Edit` residual is accepted at every key-on round for that text too. The section's no-`Edit` sentence names the plan-file case, as the consult's does. A read-only agent would remove the residual and is rejected above.
- A barred finding the orchestrator fails to mark reaches the architect, and a flip toward DEFER on it can be conceded when the orchestrator's own re-evaluation, with the argument in front of it, reaches it. Whether the diff opens a path around an enforcement invariant, judged from the finding alone, is a harder call than whether a finding names an enforcement surface, so a missed mark is likelier than under a surface-keyed mark. The re-evaluation's concession test is the first backstop for a flip toward DEFER only, and the two missed-mark cases check it on one fixed finding each. The architect's own flip toward ADDRESS may catch such a row when it is an unmarked DEFER. An upheld DEFER never reaches the concession test and stands, tagged `challenge:upheld`. The engineer's pre-merge read of the Deferred table and the safety guardrail's end-of-window DEFER list catch a DEFER that survives, and the 3+ DEFER re-read may catch it only in a round that reaches three DEFERs. The barred cases check the mark on fixed findings only.
- The mark reads finding text, which the diff, the commits and the PR description shape. A finding that frames a weakening as intended or tested can steer the mark, and the row then reaches the architect, whose argument reads the same text. The enforcement-invariant rule says approval is not informed consent, but nothing checks the mark itself. Because the rule skips `/review-pr` passes, the author of a PR the account only reviews never shapes that text through that route. A third party who wrote the diff, commits or plan file of a branch under a direct `/code-review` round can still shape it. The disclosed case checks one such framing only.
- The `layer` mark is judged by the layer's own procedure, which in this repository turns on a gate's tier line and on whether a finding is a regression, facts a finding rarely states. Marking when unsure therefore keeps more gate findings from the challenge. A missed `layer` mark is caught by the concession test, and a flip toward DEFER on it stops for the human.
