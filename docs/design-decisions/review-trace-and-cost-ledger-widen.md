# `review-trace` and `cost-ledger` widen scan scope to subagent transcripts, lifting the detection guard [§48](review-trace-fifth-event-kind.md) left in place

*2026-09-06. Formerly `docs/design-decisions.md` §58.*

[§48](review-trace-fifth-event-kind.md)'s premise was that `review-trace` never loads subagent records, which it named as one of three independent reasons `skill-fidelity-reviewer`'s architect-consult check could never legitimately emit `[SILENT-SKIP]`, and its own "Deliberately out of scope" section explicitly declined `include_subagents=True` on that basis. That premise is corrected here: widening scan scope alone changes nothing, because a separate `isSidechain` guard in `_review_trace_session_events` (`transcript-analysis.py`, then at `:1593`) suppressed skill, reviewer-spawn, and architect-consult detection independent of which records the scope resolver handed it — carrying no equivalent guard on denial or friction detection, which is why an earlier scope-only measurement moved only those two counts. Both had to change together: `cmd_review_trace`'s scope call now passes `include_subagents=True`, and the `:1593` guard is deleted. The *separate* `isSidechain` test that gates the branch/model carry-forward trackers is untouched — lifting it too would attribute a sidechain event to its own record's `gitBranch` instead of the dispatching main-thread record's, which is the attribution a sidechain event actually needs.

Merging a second source file into one stream raised two problems a scope change alone doesn't solve. Records now sort into one chronological stream on a three-part key — the record's own timestamp (forward-filled across an unparseable gap, falling back to `-inf` at the head of the stream), a thread rank (main before sidechain), and the original read order as a final tie-break — rather than being left in the corpus reader's main-block-then-subagent-block concatenation order; main-before-sidechain on a shared timestamp puts a dispatching record ahead of the first record of the subagent it spawned, which is what lets the carry-forward trackers see the correct branch before a sidechain event needs it. Every event dict also gains a `thread` field (`main`/`sidechain`): a `thread=main` row's `line_no` is still the main transcript's own real file line, but a `thread=sidechain` row's `line_no` is only a position in the merged stream, indexing no single file, and prints `line n/a` instead of a number.

**[§25](skill-fidelity-reviewer-widened-scope.md)'s "never assistant prose" bar still holds, re-read as structural rather than literal, the same way [§48](review-trace-fifth-event-kind.md) already read it.** The event dict stores no field derived from either thread's prompt or transcript text — only the classification result plus branch/model/timestamp metadata, unchanged by this widening. Denial and friction events do carry free `message` text, but that text was already in scope for main-thread records before this change; widening adds volume to an already-accepted text class, not a new class of it.

**Accepted count movement**, measured on this repo's own corpus (`--this-repo --since 2026-08-01 --until 2026-09-06`, merge-base vs. this change): denials 341→782 (+441), friction 27→36 (+9), reviewer-spawns 645→658 (+13), skills 214→216 (+2). Architect-consults were checked and found unchanged in this measured window (29→29) — not claimed to have moved. `cost-ledger`'s `denials` column widens in lockstep, so it and `review-trace --deny-summary` cannot drift apart on the same corpus.

**Forward warning.** A later entry narrows `skill-fidelity-reviewer`'s SILENT-SKIP ceiling against this widening, once [§48](review-trace-fifth-event-kind.md)'s other two grounds are also closed. That narrowing and this widening must be reverted together: reverting this widening alone while the narrowed ceiling stays live would make a fully compliant subagent-dispatched consult produce exactly the false positive the narrowing exists to eliminate.
