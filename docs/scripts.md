# Script reference

Full descriptions for utility scripts in `claude/.claude/scripts/` (stowed to `~/.claude/scripts/`). User-facing scripts are installed as wrappers under `~/.local/bin/` — see [README PATH setup](../README.md#requirements).

- **`analyze-context.py`** — inspect context window growth for a Claude Code session. Reads `<config-dir>/projects/<project>/<session>.jsonl` and `<config-dir>/usage-data/session-meta/` locally (`<config-dir>` means `$CLAUDE_CONFIG_DIR` when set, else `~/.claude`), scanning every root declared in `~/.claude/transcript-config-dirs` in addition to the active profile (see [`docs/transcript-analysis.md`](transcript-analysis.md)); no network calls, no writes.

  ```bash
  # Latest session in current project (run from project root)
  analyze-context

  # Heaviest sessions across all projects
  analyze-context --top
  analyze-context --top 20

  # Specific session
  analyze-context <session-id>
  ```

  The per-session view reports start/peak/end token counts, a growth curve
  (context window size per turn), and the ten turns with the largest single-step
  jumps — useful for identifying which tool results or subagent returns are
  expanding the context most.

  The `--top` view ranks sessions by direct token usage (input + output; cache
  reads excluded) from session metadata, and prints the session ID so you can
  drill in with the per-session view.

- **`token-analyzer.py`** — cross-session per-model token breakdown (Opus / Sonnet / Haiku) with cache-hit rates, plus a list of Opus sessions that likely could have run on Sonnet (no plan-mode, no edits, no sub-agent dispatch, no extended thinking, no judgment-skill invocations). Reads `<config-dir>/projects/*/*.jsonl`, scanning every root declared in `~/.claude/transcript-config-dirs` in addition to the active profile; no network calls, no writes.

  ```bash
  token-analyzer             # all-time
  token-analyzer --since 7d  # include token activity from the last N days (e.g. 2d, 7d)
  ```

- **`transcript-analysis.py`** — analysis toolkit for Claude Code transcripts (`<config-dir>/projects/*/*.jsonl`, unioned by default across every root declared in `~/.claude/transcript-config-dirs`, except `cost --summary`, which is scoped to the active account only); local-only reads except `pr-link`, which calls `gh`. Invoked directly: `python3 "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/scripts/transcript-analysis.py" <subcommand>`. See [`docs/transcript-analysis.md`](transcript-analysis.md) for per-subcommand reference; the `/transcript-analysis` skill documents which subcommand answers which question. For where each piece of its logic lives (the `transcript_analysis/` package vs. the script itself), see [`docs/transcript-analysis-architecture.md`](transcript-analysis-architecture.md).

- **`post-crash-sessions.py`** — enumerates Claude Code sessions orphaned by an unclean shutdown (crash, forced reboot) and prints a `cd <cwd> && claude --resume <id>` command for each one that's recoverable. Cross-references three undocumented Claude Code state sources — the session registry (`<config-dir>/sessions/<pid>.json`), scheduled-task lock files (`<project>/.claude/scheduled_tasks.lock`), and the transcript corpus — against last-boot time, so a dead-pid entry written before the last reboot reads as crash evidence while one written after doesn't. A transcript with no registry or lock corroboration at all still surfaces under "Possible crash" when its last activity sits within `--near-boot-hours` of the last boot (default 4h) — widen this to recover sessions from an older crash. `--config-dir DIR` (repeatable) also scans an additional Claude Code config profile; absent this flag, every root declared in `~/.claude/transcript-config-dirs` is scanned by default too, and passing `--config-dir` explicitly overrides that default. `--redact` maps project directories and session ids to ordinals and drops git branch names, for pasting into a public issue or channel — unredacted is the default, and the report always carries a not-publish-safe footer either way. Stdlib-only, no `requirements-dev.txt` dependency; targets Python 3.10+ (the `X | Y` union-type syntax used throughout needs it) — same pre-existing gap as every other script here, since `install.sh` only checks that `python3` exists on `PATH`, not its version. Complements `resume-context.sh` below: this discovers *which* sessions are recoverable at all and prints the raw `claude --resume` invocation, while `resume-context.sh` handles the deliberately-authored `/handoff`/`/brief` continuity-file path. Read-only — writes no file, ever.

  ```bash
  post-crash-sessions                              # scan active profile + every declared root (default)
  post-crash-sessions --config-dir ~/.claude-work   # scan active profile + only this dir — overrides the declared-roots default
  post-crash-sessions --redact                      # ordinal-mapped output safe to paste publicly
  post-crash-sessions --near-boot-hours 72          # recover sessions from a crash up to 3 days ago
  ```

- **`mark-terminal.py`** — resolves a PID's controlling terminal and titles it, so a blocked or stuck session (a stuck lock, a hung command) can be found among many open terminal windows by PID alone. Resolves the TTY via `ps -o tty= -p <pid>` and writes an OSC 0 title-set escape sequence directly to the resolved `/dev/ttysNNN` device. The title is auto-derived from that PID's entry in the session registry (`<config-dir>/sessions/<pid>.json`) when one exists and isn't stale (a `procStart` mismatch means the pid was recycled since the entry was written); an explicit `--title` always wins. `--list` enumerates every currently-live registry entry with its PID/TTY/cwd, for the "many windows open, which one is it" case. `--config-dir DIR` (repeatable) follows the same precedence as `post-crash-sessions.py` above. macOS/BSD only — exits loudly on Linux/WSL2, where the no-tty sentinel and `/dev/ttysNNN` naming this relies on are shaped differently. Complements `post-crash-sessions.py` above: that discovers *which* sessions are recoverable, this answers "which open window is this live PID."

  ```bash
  mark-terminal 12345                    # title PID 12345's terminal, auto-derived from the session registry
  mark-terminal 12345 --title "stuck"    # explicit title, overrides auto-derivation
  mark-terminal --list                   # list every live session's PID/TTY/cwd
  ```

- **`marker.sh`** — write and remove review markers on behalf of workflow skills. `/code-review`, `/skill-review`, `/plan-review`, `/ready-for-review`, `/respond-pr`, and `/ai-instruction-and-memory-files` write or activate markers via `~/.claude/scripts/marker.sh`. The 16 valid invocation shapes are allowlisted in `settings.json` for silent auto-approval; shape validation is enforced by `enforce-marker-script-shape.sh` (see [`docs/hooks.md`](hooks.md)).

- **`cleanup-merged-branches.sh`** — discovers local branches that are safe to delete and cleans them up: removes the worktree, force-deletes the local branch, prunes the remote tracking ref, deletes the remote branch if not auto-deleted, and fast-forwards the default branch. Before classifying a branch as merged, `classify_branch()` first checks for an open PR on that head-branch name — if one exists, the branch is never deleted, since a name can be reused (an old PR merged, then a new PR opened on the same head branch) and neither reachability nor a same-named merged PR alone proves the current tip was part of that merge. A branch is deleted once either of two signals confirms it is merged: `gh pr list --head <branch> --state all` returning a merged row whose `headRefOid` matches the branch's current tip (confirmed merged PR for this exact branch name and commit), or `git merge-base --is-ancestor` showing the branch's commits are all already reachable from `origin/<default>` — which also catches a direct merge with no PR at all. The gh-confirmed signal (Tier A) deletes without an internal per-branch prompt. The reachability-only signal (Tier B) prompts per-branch before deleting — `[y/N]` on a TTY, skipped with a warning when stdin is not a TTY — since reachability by itself is an incomplete argument: a branch can be trivially reachable (freshly branched, not yet diverged) while still representing active work that has no PR to guard it. A same-named merged PR whose tip doesn't match, or a `gh` lookup failure, is skipped rather than deleted (fails closed) and reported with the reason. The destructive invocation forces a Claude Code permission prompt via `permissions.ask`; only the single-repo `--dry-run` is auto-approved via `permissions.allow` — `--all-projects` (dry-run or not) always requires confirmation, since even its dry-run preview enumerates every repo under every configured root and prints their paths, branch names, and PR numbers. `--dry-run` doesn't mutate branches or worktrees, but it still runs `git fetch origin <default> --quiet` per repo and, when `origin/HEAD` is unset, a local `git remote set-head origin --auto`. Before removing a worktree, the script skips any that a live process is working inside — it checks process working directories via `/proc` (or `lsof` where there is no `/proc`) — so a session active in a worktree is not deleted out from under it. That check sees a process's cwd only: it does not catch a worktree held open indirectly (e.g. a container bind-mounted in, whose owning session has already exited) or by another user's process, so still prefer to run cleanup when other Claude Code sessions are idle. `--all-projects` sweeps this same cleanup across every git repo found under a set of user-configured root directories, instead of just the current repo — unlike `update-claude-config-plugins.sh`'s `--all-projects`, there's no existing registry of installed entries to filter, so the roots come from a user-populated config file: `~/.claude/cleanup-merged-branches-roots`, one absolute directory path per line, blank lines and `#` comments ignored, and a leading `~`/`~/` expanded to `$HOME`. Repos are discovered under each root with a depth-bounded `find -type d -name .git -prune` (BSD/macOS-compatible), which stops descending the instant it finds a repo root — so it never mistakes a matched repo's own `.claude/worktrees/<branch>/` subdirectory (a linked-worktree `.git` *file*, not a directory) for a second repo. A configured root that isn't a directory is warned to stderr and skipped; two roots that both reach the same repo contribute it only once (deduplicated by resolved absolute path). Every invocation — a plain single-repo run included, not only `--all-projects` — loads that repo's own environment before querying `gh`: when `direnv` is installed, the script evals `direnv export bash` from that repo's directory (the same substitution direnv's own shell hook applies on an interactive `cd`, which a script's own `cd` never triggers), so a sweep queries every repo with that repo's own credentials rather than the invoking shell's, and a single-repo run picks up whatever that repo's own `.envrc` provides even if it differs from the invoking shell's current state; without direnv, every repo is queried with the invoking shell's environment, unchanged from before this behavior existed. Skip reasons (`gh` lookup failure, open PR, stale name) are aggregated by identical message text into one line per distinct reason, with a count and the branch names, rather than one line per skipped branch. Under `--all-projects` with direnv present, an unauthenticated invoking-shell `gh` no longer causes exit 1 by itself — it's downgraded to a warning and the sweep proceeds, since each repo's own `gh auth` state is what actually governs that repo; without direnv, or in single-repo mode, an unauthenticated `gh` still hard-exits 1. Each repo's cleanup runs in its own subshell so one repo's early exit or unhandled error doesn't end the sweep — a per-repo failure is warned to stderr and the sweep continues, with a nonzero exit at the end if anything failed. Finding zero repos across every configured root is a no-op (exit 0), not an error.

  ```bash
  cleanup-merged-branches                             # run cleanup
  cleanup-merged-branches --dry-run                   # preview without acting
  cleanup-merged-branches --all-projects --dry-run    # preview across every repo under your configured roots
  cleanup-merged-branches --all-projects              # sweep and clean up merged branches across every configured repo
  ```

- **`cleanup-idle-open-pr-worktrees.sh`** — reclaims disk space from git worktrees for open PRs that are ready for review but not currently being worked on, without touching the branch, the remote, or the PR itself. Uses one bulk `gh pr list --state open --limit 100 --json headRefName,number,isDraft,updatedAt` call per repo, rather than a per-branch query, since an idle-worktree sweep is exactly the case where a repo has many open-PR worktrees at once. Classifies each local branch in order: no open PR at all is not this tool's concern and is skipped silently (a candidate for `cleanup-merged-branches.sh` instead); a draft PR is always skipped, since a draft is explicitly WIP by GitHub's own definition; a PR whose `updatedAt` is more recent than `--idle-hours` (default 4) is skipped as "still active" — `updatedAt` is a conservative proxy for owner activity, not a precise one, since GitHub bumps it on any PR metadata change (a bot comment, a CI status transition, a label), so this under-deletes rather than over-deletes; a worktree a live process is working inside is skipped and reported, using the same process-cwd detection `cleanup-merged-branches.sh` uses; a branch with no matching local worktree (never checked out, or it's the worktree the script itself is running from) is skipped silently rather than erroring. Survivors are removed with `git worktree remove` (no `--force` — a dirty working tree makes git itself refuse the removal), with each removal's success or failure captured individually so one refusal doesn't abort the batch. The branch ref lives in the main repo's `refs/`, not inside the worktree, so removal never risks losing committed-but-unpushed work — the commits stay reachable via the branch ref and the worktree comes back with `git worktree add <path> <branch>`. No interactive prompt (unlike `cleanup-merged-branches.sh`'s Tier B): once a worktree passes every check, there's no comparable judgment call to make, and the cost of a wrong call is a `git worktree add` + reinstall, not lost work. The destructive invocation forces a Claude Code permission prompt via `permissions.ask`; only `--dry-run` is auto-approved via `permissions.allow`. `--idle-hours=N` invocations are not pre-authorized either, since this repo's no-globs permissions rule means a non-default threshold prompts for approval on first use.

  ```bash
  cleanup-idle-open-pr-worktrees                    # run cleanup, default 4-hour idle threshold
  cleanup-idle-open-pr-worktrees --dry-run          # preview without acting
  cleanup-idle-open-pr-worktrees --idle-hours=8     # use an 8-hour idle threshold
  ```

- **`claude-auto.sh`** — starts an interactive Claude Code session in auto mode on a model auto mode accepts. Auto mode anchors a session to one concrete model for its whole lifetime, so `opusplan` (a plan-mode/execution pair) is not a valid session model for it — resolving that mismatch, for whoever has `opusplan` set as their own default, is the script's job; the repo's own default, `sonnet`, is already valid. It takes the same `--model` flag as `claude` and passes a caller-supplied one through untouched rather than injecting a competing second flag; with no flag it uses `ANTHROPIC_MODEL`, and with neither it falls back to `sonnet`, whose alias resolves to a model every provider accepts for auto mode. That final fallback is flat rather than a compatibility check — the script cannot read which model the user's settings resolve to, so it also fires when the configured default was already eligible. Scanning stops at a literal `--`, since everything after it is positional text rather than a flag to defer to. See [`docs/auto-mode.md`](auto-mode.md) for the eligible-model set and the rest of auto mode's setup.

  ```bash
  claude-auto                       # auto mode on Sonnet
  claude-auto --model opus          # auto mode on Opus
  claude-auto "summarize open PRs"  # positional prompt passes through
  ```

- **`update-claude-config-plugins.sh`** — checks which `@claude-config` marketplace plugins installed in the current project are behind the marketplace's latest version, and interactively offers to update each one. Refreshes the marketplace first (`claude plugin marketplace update`) so the diff is against the live catalog. Scoped to `@claude-config` plugins only: they carry real semver in `plugin.json` (enforced by the `plugin-semver` plugin), making version comparison clean. Run from the consumer repo's root; project-scope entries from other repos are excluded unless `--all-projects` is passed, which sweeps project-scope installs across every repo on the machine instead — `claude plugin list --json` already tags each entry with its own `projectPath`, so no filesystem walk is needed. Because the `claude` CLI has no cwd-override flag, applying an out-of-repo update requires literally `cd`-ing into that entry's project root first; a repo directory that's been deleted or renamed since install, or an update that fails, is warned to stderr and skipped rather than aborting the sweep, with a nonzero exit at the end if anything was skipped or failed.

  ```bash
  update-claude-config-plugins                       # interactive update, current repo only
  update-claude-config-plugins --yes                  # update all outdated plugins without prompting
  update-claude-config-plugins --dry-run              # preview outdated plugins without updating
  update-claude-config-plugins --all-projects --yes   # sweep and update project-scope installs machine-wide
  ```

- **`relocate-claude-config.sh`** — the single supported command to relocate this claude-config checkout, or to repair `~/.claude` after it was already moved outside any Claude Code session (an out-of-band `mv`, a Finder drag, a sync-tool restore). Installed as a **real file copy** to `~/.local/bin/relocate-claude-config` by `install.sh` (`install -m 755`, not stow) — unlike every other `~/.local/bin/*` wrapper, its whole purpose is to keep working when the exact symlink chain it repairs has already failed, so it cannot itself be a stow-managed symlink into the checkout it may need to fix. Does not source `_lib.sh` or otherwise depend on `~/.claude/` being intact, for the same reason. See [README "Repo relocation"](../README.md#repo-relocation) for the full walkthrough, including the destination-validation security model and the optional `chflags uchg` hardening note.

  ```bash
  relocate-claude-config <new-path>              # repo hasn't moved yet: unstow, mv, re-stow
  relocate-claude-config --repair <new-path>      # repo already moved outside a Claude Code session
  relocate-claude-config --allow-outside-home <new-path>   # permit a destination outside $HOME
  ```

- **`register-marketplace.sh`** — registers the `claude-config` marketplace and installs the user-scope plugins declared in `enabledPlugins`, for one Claude Code config profile at a time. Resolves `<config-dir>/settings.json` through `_lib_config_dir()` in `claude/.claude/hooks/_lib.sh`, the same helper `marker.sh` uses — `CLAUDE_CONFIG_DIR` replaces the whole `~/.claude` directory, not just `$HOME` — exiting 0 with an explanatory message if that profile has no `settings.json` yet, rather than erroring. A **relative** `CLAUDE_CONFIG_DIR` is refused (non-zero exit) — unlike the `claude` CLI, which accepts one — because it resolves against the invocation cwd, so a caller needing a cwd-relative profile path must expand it to absolute before invoking. An unset-or-empty `$HOME` with no `CLAUDE_CONFIG_DIR` override is refused the same way, by its own message. Self-locates its own checkout via `readlink -f` on `$0`, then one `dirname` to strip the filename plus three more `..` hops to reach the repo root — needed because it normally runs through its stowed symlink at `~/.claude/scripts/register-marketplace.sh`, not a direct checkout path — then refuses to proceed if the resolved directory has no `.claude-plugin/marketplace.json`, rather than silently registering the wrong directory. `install.sh` calls this script once, unparameterized, for its own profile; a machine running multiple Claude Code config profiles can invoke it again per profile via `CLAUDE_CONFIG_DIR`. Each of its three registration steps (self-registration, `extraKnownMarketplaces`, `enabledPlugins` install) is independently idempotent, but the whole invocation aborts on the first failing step — `set -euo pipefail` (stricter than `install.sh`'s plain `set -e`: a `claude ... | jq ...` pipeline stage failing now aborts immediately too, not just the pipeline's last stage) — a caller retrying a failed profile from the top is safe, not merely convenient.

  ```bash
  register-marketplace                                        # register for $HOME's own profile
  CLAUDE_CONFIG_DIR=~/.claude-work register-marketplace        # register for a different profile
  ```

- **`resume-context.sh`** — resumes a `/handoff` or `/brief` continuity file: moves it from `<config-dir>/handoffs/` or `<config-dir>/briefs/` to a fresh `mktemp`-created path under `${RESUME_CONTEXT_TMPDIR:-${TMPDIR:-/tmp}}` (permissions re-asserted to `600` via an explicit `chmod` after the move — a same-filesystem `mv` inherits the source file's permissions via `rename(2)`, not `mktemp`'s own mode, so the `chmod` is what actually enforces owner-only), then launches a new interactive `claude` session with the moved file loaded via `--append-system-prompt-file`. Refuses to move a symlink source: `mv` preserves a symlink's identity on a same-filesystem rename, and `chmod` dereferences symlinks by default, so chmodding a moved symlink would silently narrow permissions on whatever arbitrary file it points to. `--cwd <dir>` launches the new session with `<dir>` as its working directory instead of inheriting the invoking shell's — the writing skill embeds the target directory in the command itself rather than relying on the invoker running a separate `cd` first, so `set-session-title-from-branch.sh` (see [`docs/hooks.md`](hooks.md)) sees the right branch regardless of where `resume-context` is actually run from. `--consume-only` performs the move only, without launching anything — used by `consume-durable-continuity-file-on-read.sh` (see [`docs/hooks.md`](hooks.md)) to consume a continuity file read directly in the same session (e.g. after `/clear`), without going through this script's launch path; not valid together with `--cwd`, since that mode never launches a session. Two env-var seams exist: `RESUME_CONTEXT_LAUNCHER` (command to exec instead of `claude`) is used by tests to avoid the real `claude` binary, and doubles as a production seam for fronting `claude` with a wrapper — e.g. `RESUME_CONTEXT_LAUNCHER=claude-auto` resumes in auto mode; `RESUME_CONTEXT_TMPDIR` (temp-dir root override) is tests-only, never touching the real shared `/tmp` otherwise. No kill-switch of its own — the kill-switch lives in the consuming hook, since this script only ever runs when explicitly invoked.

  ```bash
  resume-context --cwd <worktree-path> <config-dir>/handoffs/<slug>-handoff.md  # from a linked worktree
  resume-context <config-dir>/handoffs/<slug>-handoff.md   # move + launch (main checkout)
  resume-context --consume-only <path>                  # move only, no launch
  ```
