# Hook reference

Full descriptions for every hook in `claude/.claude/hooks/`. For the gate summary (which hook blocks which command), see the Hook → Gates → Cleared-by table in the [README](../README.md#workflow).

## Gate hooks

- **`require-plan-review.sh`** — blocks `Write`/`Edit`/`MultiEdit`/`ExitPlanMode` when an uncommitted or modified plan file exists in `.claude/plans/` and no `/plan-review` marker holds the current plan set's hash. Committed, unmodified plan files are treated as historical and pass through. Two-marker pattern: an active marker (`~/.claude/.plan-review-active.d/<session_id>`) bypasses the gate for the skill's own Write/Edit calls during review (but not `ExitPlanMode`, which stays blocked until review is complete); a completion marker (`~/.claude/plan-review-markers/<repo-hash>.<session_id>`) allows through once the review is clean. The completion read is two-tier: it scans this worktree's repo-hash prefix first, then — only on a miss — the repo's sibling worktrees, so a plan copied into a fresh worktree inherits the review that already covers its text. See [Marker keying and gate-release authority](#marker-keying-and-gate-release-authority) and [Gate deadlock recovery](#gate-deadlock-recovery).
- **`require-code-review.sh`** — blocks `git commit` (including chained forms like `git add . && git commit`) until `/code-review` has run on the current staged state. Verified via a sha256 marker in `~/.claude/code-review-markers/<repo-hash>.<session-id>`, which auto-invalidates the moment the staging area changes. The read matches on the marker's stored hash across every session suffix under this repo-hash; the session key in the filename exists so two parallel sessions in the same worktree cannot overwrite each other's markers when staging different diffs.
- **`require-skill-review.sh`** — blocks `git commit` only when staged changes include a `SKILL.md`. Requires `/skill-review` to have produced a behavioral-equivalence audit for any removed or shortened lines. Marker is keyed to the SKILL.md-scoped diff (not the full staged diff), so re-staging non-skill files after a clean review does not invalidate the marker.
- **`deny-private-project-refs.sh`** — blocks `git commit`, `gh pr create`, `gh pr edit`, and mutating `gh api` calls when the staged diff, commit message, or PR title/body/body-source-file contains either (a) tracker-ID tokens (`[A-Z]{2,}-\d+`) outside an OSS-prefix allowlist (`CVE-`, `RFC-`, `GH-`, and similar — see the script for the full list), or (b) a literal substring match against entries in the user's opt-in `~/.claude/private-projects.md` blocklist. Enforces the mechanical categories of the repo-root `CLAUDE.md` redaction rule; structural fingerprints still require review discipline. See [`docs/private-project-redaction.md`](private-project-redaction.md).
- **`deny-pii-in-commits.sh`** — opt-in. Blocks `git commit` (every repo, including chained forms) when the added lines of the staged diff, the commit message, or a referenced `-F`/`--file` message file contain personally-identifying or protected health information. Dormant unless `~/.claude/pii-patterns.md` exists as a readable regular file. Scans built-in generic patterns (US SSN, Luhn-checked credit-card numbers) plus every user `<label>: <regex>` line in that file; `exclude: <glob>` lines drop synthetic-fixture paths from the scan. When `-a`/`--all`, a `--` pathspec, or a bare pathspec argument is present, also scans `git diff HEAD` (working-tree content committed outside the index). Robust against `--no-verify`. The deny message names the matched pattern by label only — never the matched value or the user regex. See [`docs/security-hardening.md`](security-hardening.md).
- **`deny-data-file-reads.sh`** — opt-in. PreToolUse `Read` gate that refuses data-shaped files before their content enters Claude's context. Dormant unless `~/.claude/data-file-read-guard.md` exists as a readable regular file. Once armed, denies `Read` of a data-file extension (`.csv`, `.parquet`, `.sqlite`, `.xlsx`, and similar), a path under a `Downloads/` directory, a file over 5 MB, or any path matching a glob line in the config file. No bypass valve. See [`docs/security-hardening.md`](security-hardening.md).
- **`deny-escaped-backticks-in-pr-body.sh`** — blocks `gh pr create` and `gh pr edit` when the PR body (inline `--body` or any body-source file passed via `--body-file`/`-F`/`--template`/`-T`) contains literal backslash-backtick sequences (`\``). Those sequences appear when a `<<'EOF'` single-quoted heredoc writer unnecessarily escapes a backtick — the backslash survives into the rendered GitHub body and breaks code-span formatting. Fails closed when a body-source file is unreadable or a pseudo-file path (`-`, `/dev/stdin`, `/dev/fd/*`).
- **`block-gh-pr-merge.sh`** — blocks every shape of `gh pr merge` (bare, with flags, `--auto`, `--squash`/`--merge`/`--rebase`, paren-grouped chains, `&&`-chained, trailing-semicolon forms) and instructs the agent to surface the merge intent to the engineer. Enforces the repo-root CLAUDE.md rule **AI agents: don't merge your own PRs** at the tool-call boundary. No bypass marker — the engineer runs `gh pr merge` themselves (or via the `!` shell escape). Word-boundary regex `(^|[[:space:]])gh[[:space:]]+pr[[:space:]]+merge([^a-zA-Z0-9_]|$)` matches verb-anchored, so `gh pr mergefoo` and quoted/commented `gh pr merge` text do not match.
- **`require-stow-reminder.sh`** — scoped to the `claude-config` repo. Blocks `gh pr create` and `gh pr edit` (when the edit changes the body) if the PR adds a new immediate child of `claude/.claude/` (file or directory) and neither the inline command, a referenced `--body-file`/`--template`, nor any `--fill`-sourced commit message mentions `install.sh` or `stow` (case-insensitive). Reason: GNU Stow links each top-level child of `claude/.claude/` individually, so a brand-new child only appears in `~/.claude/` after re-running `install.sh` — `git pull` alone won't materialize the symlink. The reminder lands in the PR body so the post-merge stow step doesn't get forgotten at merge time.
- **`require-respond-pr.sh`** — blocks PR/issue comment reads and posts and redirects to `/respond-pr`, so all three comment types get fetched and replies carry the `[Claude Code]` attribution prefix. The gated surface is `gh api .../pulls|issues/N/{comments,reviews}`, the un-numbered comment-ID endpoint `gh api repos/O/R/pulls|issues/comments/ID`, `gh pr comment`, `gh pr review`, `gh issue comment`, and the GraphQL comment/review mutations plus file-sourced GraphQL bodies. Reads and writes are gated asymmetrically: a command that explicitly names a repo other than the current `origin` is released as external research, but only when it carries no write signal — writes are denied for every repo, because the attribution prefix is owed to readers of any public thread. Honors a per-session bypass marker at `~/.claude/.respond-pr-active.d/<session_id>` that the skill sets on entry and removes on exit; the hook checks `kill -0` against the stored PID on each gate hit; a dead PID evicts the orphaned marker automatically. Per-session keying (rather than a singleton path) keeps parallel Claude sessions from thrashing on cleanup or leaking bypass to unrelated sessions.
- **`require-ready-for-review.sh`** — gates `git push` and `gh pr ready` on branches with an open PR. Requires `/ready-for-review` to have run and passed since the last commit. Verified via a marker whose content is the HEAD SHA the gate ran against — a new commit invalidates the marker automatically and forces a re-run. An active-skill bypass marker (`~/.claude/.ready-for-review-active.d/<session_id>`) prevents the skill's own iteration pushes (fix → push → loop) from self-denying.
- **`require-worktree-for-git-writes.sh`** — opt-in per repo or per machine. When active, denies non-read-only git operations unless the session runs in a linked git worktree. Prevents concurrent Claude Code sessions from racing on the same working tree. See [Worktree enforcement](../README.md#worktree-enforcement).
- **`require-worktree-for-file-writes.sh`** — opt-in per repo or per machine (same sentinel files). When active, denies `Edit`/`Write`/`MultiEdit` on paths in the main working tree; all file edits must land in a linked worktree. Paths under `$HOME/.claude/` are always exempt — the harness and skills write plans, memory, settings, and other infrastructure files there as normal operation, and `~/.claude/` may resolve via stow directory-folding into an opted-in checkout.
- **`deny-reviewer-tree-mutation.sh`** — always on (no worktree-enforcement opt-in required). Denies `Bash`/`Write`/`Edit`/`MultiEdit` from the closed set of review-only agents (`ciso-reviewer`, the seven `staff-*` personas, `skill-fidelity-reviewer`, `Explore`, `Plan`) that would mutate the tree under review: git writes, `Write`/`Edit`/`MultiEdit` outside `/tmp` or an `agent-reviews/` findings path, and a closed in-place-edit-tool family split into two tiers — pure formatters denied on any invocation regardless of flags (`black`, `isort`, `gofmt`, `prettier`, `rustfmt`, `terraform`/`tofu fmt`), and dual-use linters/text tools denied only in their write form (`sed -i`/`perl -i`, `eslint --fix`, `ruff format`/`ruff check --fix`). An `agent-reviews/*` write is exempted only after confirming with `git check-ignore` that the directory is actually ignored in the target repo — a stale worktree-local `info/exclude` or a repo with no ignore entry denies rather than silently allowing an unignored findings file through. Every other agent (main session, `code-writer`, `general-purpose`) passes through unconditionally.
- **`deny-repo-relocation.sh`** — always on (no worktree-enforcement opt-in required; not scoped to this repo — it protects whichever claude-config checkout it is stowed from, regardless of which repo the session is working in). Denies a `Bash` `mv` or `rsync --remove-source-files` command whose resolved source argument is this claude-config checkout's root or an ancestor of it — moving or renaming the checkout breaks every stow symlink under `~/.claude/` and `~/.local/bin/` at once, with nothing left running that could detect or explain the failure. Points at `relocate-claude-config` (see [`docs/scripts.md`](scripts.md)) as the supported command instead. Self-locates the protected root from its own physical path (`readlink -f "$0"`), not from cwd, so it fires correctly no matter which repo's Bash call it's evaluating. Best-effort, not a hard security boundary: a source argument reached only through a shell variable, command substitution, or a preceding `cd` in the same command fails OPEN (allow) rather than deny, and equivalent-relocation forms outside the `mv`/`rsync` pattern (`cp -r && rm -rf`, `python3 -c "os.rename(...)"`, a GUI/Finder move) aren't covered at all — see the [README "Repo relocation"](../README.md#repo-relocation) section and the hook's own header for the full known-gaps list and why the destination-side validation in `relocate-claude-config` is where this design's actual security investment goes.
- **`guard-settings-session-keys.sh`** — blocks `git commit` when `claude/.claude/settings.json` has staged changes to `model`, `effortLevel`, or `skipAutoPermissionPrompt`. These are session-scoped or Claude-Code-auto-written preferences that should not be committed to the shared config; for `model`/`effortLevel`, use `ANTHROPIC_MODEL`/`CLAUDE_CODE_EFFORT_LEVEL` env vars or `/effort max` mid-session instead.
- **`check-skill-length.sh`** — blocks `git commit` when a staged `SKILL.md` exceeds 200 lines and grew vs HEAD. Nudges toward splitting a growing skill or moving reference material to a co-located `REFERENCES.md`.
- **`check-claude-md-length.sh`** — blocks `git commit` when a staged `CLAUDE.md` or `AGENTS.md` (repo root or any `.claude/`-scoped path) exceeds 200 lines and grew vs HEAD. Same shape as `check-skill-length.sh`, but also covers `AGENTS.md`.
- **`require-memory-skill.sh`** — PreToolUse `Edit|Write|MultiEdit` gate on `~/.claude/projects/*/memory/MEMORY.md` and new memory topic files under that path. Requires an active `/ai-instruction-and-memory-files` per-session marker before allowing writes, ensuring index format and frontmatter rules are applied.
- **`require-routing-read.sh`** — PreToolUse `Agent` gate active during a running `/plan-review` session. Denies subagent spawn until `~/.claude/skills/plan-review/ROUTING.md` has been read (tracked by `log-routing-read.sh`), ensuring reviewer routing consults the full ownership table before any specialist is spawned.
## Utility hooks

- **`capture-session-id.sh`** (SessionStart, SubagentStart) — at session and subagent start, writes the session's `session_id` to `~/.claude/sessions/<claude-pid>` so skills running as Bash tool calls (which don't see the hook payload) can look up their own session id via the bash tool's `$PPID`. Used by both `/respond-pr` and `/code-review` to compute per-session marker filenames. The file is removed on session exit by its paired `cleanup-session-id.sh` hook — the create and delete form a lifecycle pair.
- **`cleanup-session-id.sh`** (SessionEnd) — the destructor for the lookup file `capture-session-id.sh` creates. At session exit it resolves the claude-PID by the same `ps -o ppid= -p $PPID` walk and deletes `~/.claude/sessions/<claude-pid>` — but only when the file's content still equals the ending session's `session_id`. That content-match guard handles the `/clear` race, where one session ends and another starts in the same process (same PID, new id): whichever of `SessionEnd` and `SessionStart` runs second wins, and the file is kept whenever it already belongs to the live successor session. Without this hook, `~/.claude/sessions/` would grow by one bare-PID file per session start, resume, and one-shot run, without bound. Registered matcher-less so it runs for every `SessionEnd` reason; fail-open (a missed cleanup is harmless — the file lingers and self-heals when the PID is reused). `claude -p` one-shot invocations do not fire `SessionEnd`, so they continue to leak one bare-PID file each at one-shot rate (self-heals on PID reuse).
- **`nudge-handoff-near-context-cap.sh`** (UserPromptSubmit, advisory) — injects a one-shot `additionalContext` reminder to consider `/handoff` as carried context nears the compaction cap. Opt-out via `~/.claude/.handoff-nudge-disabled`. See [`docs/handoff-nudge.md`](handoff-nudge.md) for the threshold, marker mechanics, and log format.
- **`cleanup-handoff-nudge-marker.sh`** (SessionEnd) — the destructor for `nudge-handoff-near-context-cap.sh`'s per-session fired-marker, mirroring the `capture-session-id.sh`/`cleanup-session-id.sh` lifecycle pair above.
- **`nudge-error-mode-analysis.sh`** (UserPromptSubmit, advisory, opt-in) — injects a one-shot `additionalContext` suggestion to run `/error-mode-analysis` once in-session friction signals cross a threshold. Dormant unless `~/.claude/.error-mode-nudge-enabled` exists. See [`docs/error-mode-nudge.md`](error-mode-nudge.md) for the threshold, signal composition, and marker mechanics.
- **`nudge-worktree-anchor.sh`** (UserPromptSubmit, advisory) — reports via `additionalContext` when the session's working directory is the **main** working tree of a repo with worktree enforcement active while a linked worktree exists on disk. Silent in every other state, including an opted-in repo with no worktree yet (the normal state just before `git worktree add`). Re-arms rather than firing once per session: anchor state is not monotonic, so its per-session state file records the tree last reported and is cleared whenever the condition stops holding, letting a genuine drift-back-out be reported again. Advisory only — a hook cannot change a session's working directory, so re-anchoring is left to the agent's `EnterWorktree` call. Exits 0 on every path and bounds every git call with `_lib_capped`, since a `UserPromptSubmit` hook runs on the per-turn hot path.
- **`cleanup-worktree-anchor-nudge-marker.sh`** (SessionEnd) — the destructor for `nudge-worktree-anchor.sh`'s per-session state file, mirroring the `capture-session-id.sh`/`cleanup-session-id.sh` lifecycle pair above.
- **`advance-past-commit-stall.sh`** (Stop, `turn-gate`) — opt-in. Forces forward progress past a commit/push/PR-open permission-question stall (GH-526) when `_lib_autonomous_shipping_active` holds for the resolved repo. Fires only on the main session (never a subagent), only once per user turn (re-arms on a new `prompt_id`), and only when the final sentence of the last assistant message asks permission to commit/push/open a PR (phrasing-matched, case-insensitive) without also carrying an exclusion phrase (`merge`, `--force`, `failing`, etc.), and work is actually pending (a dirty tree, HEAD ahead of its configured upstream, or — the common state before a branch's first push — no upstream configured at all). Emits `{"decision": "block", "reason": …}` to force the same turn to continue rather than end. Kill switches: `~/.claude/.commit-stall-block-disabled` (always-effective) and `<repo>/.claude/autonomous-shipping-optout` (repo-scoped). See [`docs/commit-stall-block.md`](commit-stall-block.md) for the fire predicate's design history, known limitations, and log format.
- **`cleanup-commit-stall-marker.sh`** (SessionEnd) — the destructor for `advance-past-commit-stall.sh`'s per-session state file, mirroring the `capture-session-id.sh`/`cleanup-session-id.sh` lifecycle pair above; also sweeps entries older than 30 days on every run, since `claude -p` one-shot invocations never fire `SessionEnd` to clean up their own state file.
- **`ask-review-permissions.sh`** — asks before `Edit`/`Write`/`MultiEdit` to `.claude/settings*.json`, nudging toward `/review-permissions` when the edit touches `permissions.allow`.
- **`session-marker-dashboard.sh`** (SessionStart) — at session start, emits a summary of any active bypass markers (`/respond-pr`, `/ready-for-review`) into the resumed session's context so stale bypasses are visible.
- **`check-branch-divergence.sh`** (SessionStart, `matcher: startup`) — surfaces feature-branch divergence from `origin/<default>` as `additionalContext`. Skips silently when not in a repo, on the default branch, on detached HEAD, with no `origin` remote, or with `origin/HEAD` unresolvable. Runs a bounded `git fetch` (`timeout 2 git fetch …` with `GIT_TERMINAL_PROMPT=0` to suppress credential prompts), then `git rev-list --count HEAD..origin/<default>` for the behind count and `git merge-tree --write-tree` for the trial-merge prediction. Falls back to the locally-cached `origin/<default>` ref with a stale-ref suffix when the fetch fails, times out, or no portable timeout wrapper is available (macOS without `gtimeout`). Quiet-on-success — emits nothing when behind = 0. Advisory only; never blocks, never acts. Resolution is delegated to `/git-feature-branch-sync`. Matcher is `startup` only (not `startup|clear|compact`) because divergence is on-disk state, not session-scoped.
- **`enforce-marker-script-shape.sh`** — PreToolUse gate wired on both the `Bash` and `Edit|Write|MultiEdit` matchers, with two jobs. First, it denies writes to review-marker state from any agent type in `_LIB_NO_GATE_RELEASE_AGENTS` — the review-only personas plus `code-writer` — since none of them could have run the review a gate demands. Marker state is reachable two ways and both are gated: a `Write`/`Edit`/`MultiEdit` targeting a path under `~/.claude/*-markers/` or `~/.claude/.*-active.d/` (matched on the resolved path, so shell indirection does not apply), and a `Bash` call carrying `marker.sh write`/`activate`. `deactivate` and `clear-stale` stay available because they re-arm gates rather than release them. Second, on the `Bash` surface only, it denies any `marker.sh` invocation not exactly matching the allowlisted shape pattern (`~/.claude/scripts/marker.sh <subcommand> <skill>`). Chains of individually-valid marker.sh operations joined by `&&` are permitted (capability-neutral — each op is independently allowlisted or harmless); chains to any other command (except the blessed `git commit` tail), `||`/`;` separators, redirects, and extra arguments remain denied. Defense-in-depth against prompt-injection escalation through the `marker.sh` allow rules. See [Marker keying and gate-release authority](#marker-keying-and-gate-release-authority).
- **`deny-env-reads.sh`** — PreToolUse `Read` gate that allows `.env.example`, `.env.template`, and `.env.sample` (including symlink-resolved targets) while denying all other `.env`/`.env.*` paths. Extends the static `permissions.deny` entries documented in [`docs/auto-mode.md`](auto-mode.md) to cover `.env.*` variants not listed there.
- **`log-routing-read.sh`** — PostToolUse `Read` companion to `require-routing-read.sh`. Writes a per-session routing-read marker when `~/.claude/skills/plan-review/ROUTING.md` is read during an active `/plan-review` session.
- **`consume-durable-continuity-file-on-read.sh`** — PostToolUse `Read` hook that moves a `/handoff` or `/brief` continuity file (`~/.claude/handoffs/*-handoff.md`, `~/.claude/briefs/*-task.md`) out via `resume-context.sh --consume-only` whenever it's read directly — the same-session resume path (`/clear` then manually reading the file) that never invokes `resume-context.sh`'s own launch mode. Fail-open (never blocks; a crashed or timed-out consume just leaves the file in place). The `resume-context.sh` call is wrapped in a 5s `timeout` (falls back to a bare call when `timeout(1)` is absent) since it runs synchronously inside the triggering `Read` call — guards against a hung network-backed `$HOME`. On a successful consume the destination is reported on two channels: a `systemMessage` for the human, and `hookSpecificOutput.additionalContext` for the model — the agent that just had its own file moved has no other way to learn where it went, since `systemMessage` reaches the user only. On-by-default; opt out per-machine by touching `~/.claude/.consume-durable-continuity-disabled`, mirroring `nudge-handoff-near-context-cap.sh`'s kill-switch convention. See [`docs/scripts.md`](scripts.md) for `resume-context.sh` itself.

## Marker keying and gate-release authority

Two properties govern every review gate. They pull in opposite directions and are easy to conflate.

**What a marker's filename means vs. what its content means.** A completion marker lives at `<markers-dir>/<repo-hash>.<session-id>`, and its *content* is a hash of exactly the state that was reviewed — the staged diff for `/code-review` and `/skill-review`, the active plan set's paths-plus-contents for `/plan-review`, the HEAD sha for `/ready-for-review`. The content is the authorization: it is what proves a review covered this state, and it is what re-arms the gate the moment the state changes. The session id in the filename is a *write-side* key only — it keeps two parallel sessions in the same worktree from overwriting each other's markers. Gates therefore match on content across every session suffix under the repo-hash, and a review still covering the current state keeps counting after a resume, a `/clear`, or a handoff to a parallel session. The repo-hash stays part of the read: an identical staged diff or plan text in an unrelated repository was reviewed against different code.

`require-plan-review.sh` widens that one step further, to the current repository's own worktrees. A plan's hash covers repo-*relative* paths, so a plan copied into a fresh worktree hashes identically, and the gate honors a review performed in any sibling worktree. Two tiers keep the cost off the common path: the current worktree's repo-hash is checked first (one `sha256sum`), and the worktree enumeration runs only after that misses — i.e. only when the gate is about to deny anyway. A tier-2 hit authorizes content-identity of the plan *text*, not state-identity of the sibling's checkout: two worktrees on divergent branches holding byte-identical plan files do cross-validate.

**Which tree a marker describes.** The repo-hash is derived from a resolved repo root, so one repository checked out at a main tree and at a linked worktree yields two different keys — deliberately, since a review of one tree is not a review of the other. That makes the resolution step load-bearing on both sides of the gate. The reading gates (`require-code-review.sh`, `require-plan-review.sh`, `require-skill-review.sh`) resolve the root from the hook payload's `.cwd` and thread that one root through every subsequent git call, so a hook's marker path and the state it hashes always describe the same tree. `marker.sh` receives no payload and so has no trusted directory to import; it fails closed instead, refusing to write any completion marker while worktree enforcement is active, its resolved root is the repo's main working tree, **and** a linked worktree exists on disk — naming that worktree as the re-anchoring target in the refusal. The worktree-existence condition is load-bearing in both directions. A marker written from the main tree is only wrong when the reviewed work lives somewhere else, so with no worktree there is no second tree to confuse the first with and the marker correctly describes the only tree there is. Refusing unconditionally would instead wedge any repo whose staged state was produced outside Claude Code's gated tool calls: the worktree hooks gate tool calls, not ambient git state, so a hand-staged edit in a terminal or editor, a CI checkout, or work staged before the repo opted in all reach main-tree staged content untouched. Without this pair a session whose shell sat in a different working tree of the same repo would write and then satisfy a gate describing a tree nobody reviewed — writer and readers drifting together keeps the pair self-consistent, so nothing surfaces.

**Who may release a gate.** Releasing a gate requires having run the review it demands. No agent in `_LIB_NO_GATE_RELEASE_AGENTS` — the review-only personas plus `code-writer` — could have run one: the file-backed personas declare no `Skill` tool and cannot invoke a review skill at all, and the two harness built-ins (`Explore`, `Plan`) are dispatched read-only by mandate — which holds whether or not the harness grants them `Skill`, since this repo ships no frontmatter for either and so cannot check. Either way a marker written by one asserts a review that could not have happened. Because `marker.sh` resolves the session id by walking the process ancestor chain to the Claude main process, such a write is indistinguishable from the parent session's and releases the gate for the whole session, not just the subagent.

`enforce-marker-script-shape.sh` enforces this by keying on **marker state**, not on command text, because marker state is reachable from two tool surfaces and gating either one alone leaves the property false:

- **`Write`/`Edit`/`MultiEdit`** targeting a path under `~/.claude/*-markers/` or `~/.claude/.*-active.d/`. This is the load-bearing arm — every agent in the set carries the `Write` tool, so without it a subagent could simply write the marker file directly and never invoke `marker.sh`. It matches the resolved target path (tilde-expanded and normalized), so no shell-level construct evades it.
- **`Bash`** carrying `marker.sh write` or `marker.sh activate`, checked before the hook's own shape validation so wrapped and chained invocations are covered. This arm necessarily matches command text and therefore has a scope limit, stated rather than implied: shell indirection that separates `marker.sh` from the operation keyword — assigning the path to a variable, or wrapping the call in a function — is not matched here, the same carve-out the shape check already documents for wrapped forms. Those forms are not pre-approved in `permissions.allow` either, so they surface as a permission prompt rather than a silent allow.

A subagent that hits a review gate is expected to report the denial upward; the dispatching session runs the skill, or delegates it to a `general-purpose` subagent, which does carry `Skill`. Matching a hash the subagent computed itself is not authorization — an equal hash shows the state is unchanged, not that anyone reviewed it. `test_agent_roster.py` asserts the no-`Skill` property against each file-backed agent's `tools:` frontmatter and pins the harness built-ins as a closed exemption set, so neither grounding can quietly go stale.

## Gate deadlock recovery

With `jq` unavailable (missing from `PATH`, failing, or hung past its 5s timeout backstop), every gate hook hard-blocks by design rather than silently allowing. In an interactive session, the recovery route is the `!` shell escape, which runs outside the tool-call path these hooks gate, to install or repair `jq`. A headless or non-interactive run has no `!` escape, so `jq` must already be installed in the execution environment beforehand.

Active-bypass markers from sessions that crash before cleanup evict themselves automatically: the hooks check `kill -0` against the stored PID and evict dead entries on the next gate hit. The remaining case is a *live session* whose review skill cannot execute — harness-blocked, failing to load, or unable to produce a completion marker due to a tool error.

For three gates, the gating condition is removable via Bash without destroying work:

**`require-plan-review.sh`** blocks Write/Edit when an uncommitted or modified plan file exists in `.claude/plans/` and no completion marker holds that plan set's hash. Committed, unmodified plan files are treated as historical and do not arm the gate.

```bash
# Option 1: remove the plan file to clear the gate. Copy the content first
# if you need to preserve it. If multiple uncommitted plan files exist, all
# must be removed or committed to clear the gate.
rm .claude/plans/<slug>.md

# Option 2: commit the plan file. A committed, unmodified plan is treated
# as historical and does not arm the gate.
git add .claude/plans/<slug>.md && git commit -m "plan: <topic>"
```

**`require-code-review.sh`** blocks `git commit` when no review covers the currently staged diff:

```bash
# Unstage the files. Changes remain in your working tree; re-stage and
# run /code-review once the skill is available.
git reset HEAD -- <files>
```

Alternatively, commit directly from a terminal outside Claude Code — Claude Code PreToolUse hooks only fire for `Bash` tool calls within a session.

**`require-skill-review.sh`** blocks `git commit` when no audit covers the currently staged `SKILL.md` diff:

```bash
git reset HEAD -- <path-to-SKILL.md>
```

Same terminal-outside-Claude-Code fallback applies.

### Gates with no clean escape

Three skill gates have no safe condition-removal path — the gate's intent is to force the skill:

- **`require-ready-for-review.sh`**: escape paths (close the PR, force-push, hard-reset) are destructive. If the skill cannot run in the current session, spawn a subagent.
- **`require-respond-pr.sh`**: the gate ensures the skill fetches all review-comment types before any `gh` PR comment operation. There is no condition to remove short of closing the PR.
- **`require-memory-skill.sh`**: the gate is path-based (fires on writes to memory files). Writing elsewhere defeats the user's intent. Run the skill in a subagent.

### Orphaned active-bypass markers

If a skill's active-bypass gate refuses to release after the skill has finished, use the manual sweep utility:

```bash
~/.claude/scripts/marker.sh clear-stale          # evict dead-PID entries
~/.claude/scripts/marker.sh clear-stale --dry-run # report without removing
```

`activate` resolves the live PID from the process ancestor tree, so a stale `~/.claude/sessions/` entry left by a crashed or restarted session cannot be stamped into a freshly written marker. `clear-stale` remains the tool for markers left behind by sessions that ended without `deactivate`.

## What a gate-backed skill's description may promise

Once a review skill acquires a gate hook, its `DO NOT TRIGGER` clauses stop being routing hints and start being predictions about whether an operation will be allowed. A gate decides on what it can compute — tool name, command shape, staged pathspec, marker hash. So every clause must either name a condition under which the hook's own predicate also declines to fire, or explicitly scope itself to a trigger point that has no hook behind it.

Two clause shapes cannot be honored and must not be written:

- **Judgment predicates** — "cosmetic-only changes", "a trivial one-liner". No hook can compute triviality; `require-code-review.sh` gates on staged-diff emptiness and command shape, never on the nature of the change.
- **Conversational state** — "the user has explicitly said to skip review". A PreToolUse hook sees one tool call, not the transcript.

The failure mode is uniform: the session reads the exemption, declines to run the review, and is then denied by the gate. Because the description is what the model reads *before* the skill fires, no amount of correct prose in the skill body can undo it.
