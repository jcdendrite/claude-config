# Exclude worktrees paths from select-tests.py's test-source predicate

## Context

Fix `_is_test_source_change` in `claude/.claude/scripts/select-tests.py` so it never treats a file under a `worktrees` directory as a real test-source change. `claude/.claude/tests/test_pytest_collection_config.py`'s `TestNestedWorktreeExcludedFromCollection` test deliberately (and necessarily, to exercise pytest's real `norecursedirs` exclusion) writes a transient real file into the live repo tree at `claude/.claude/worktrees/pytest-collection-regression-fixture-{pid}/sub/tests/test_should_never_collect.py` for the duration of a subprocess pytest run. While that file is on disk, `claude/.claude/scripts/tests/test_select_tests.py`'s `test_every_is_test_source_change_match_is_in_test_corpus` — which walks the live repo tree with an unscoped `rglob("test_*.py")` and asserts every match satisfying `_is_test_source_change` is present in `_test_corpus()`'s five hardcoded glob roots — can observe that fixture file and fail, since `_is_test_source_change` matches it but `_test_corpus()` never includes ephemeral worktree paths. No serialization exists between these two tests, and pytest-xdist's default scheduler gives no file/class locality guarantee, so this is reproducible within a single `pytest -n auto` invocation and does not require concurrent Claude sessions, though concurrent sessions widen the window. Root-caused via `/root-cause-analysis` in the prior session (see conversation history — not re-derived here since this plan is provenance for the fix, not the investigation). Intended outcome: the race becomes structurally impossible under every schedule and invocation, without touching the fixture-writing test, which cannot move to `tmp_path` without defeating its own purpose.

## Approach

Add one conjunct to `_is_test_source_change` (`claude/.claude/scripts/select-tests.py:340-345`) so a path carrying a `worktrees` path-segment anywhere is never a test-source change, name the segment as a module constant so the literal has one home, and pin the constant against `pyproject.toml`'s `norecursedirs` entry plus three predicate unit cases. The guard belongs in `_is_test_source_change`, matched component-wise on `Path(path).parts`, scoped repo-wide rather than under `claude/`.

**Root problem:** `_is_test_source_change`'s claimed domain is strictly larger than the set of files any test it selects can actually read, and `test_every_is_test_source_change_match_is_in_test_corpus` (`claude/.claude/scripts/tests/test_select_tests.py:367-378`) walks the live tree against that claim — so any file that appears under `claude/.claude/worktrees/` fails a repo invariant that was never about it.

**Givens** (fixed beyond this plan's reach):

- **G1** — `TestNestedWorktreeExcludedFromCollection` must write a real file inside `claude/.claude/`, because it exercises pytest's actual collection walk over that root and `tmp_path` sits outside it; replacing that strategy is a different test's design decision. [engineer-verified, and consistent with `claude/.claude/tests/test_pytest_collection_config.py:30-78`]
- **G2** — pytest owns `norecursedirs` semantics: it replaces rather than extends the built-in default list, and it prunes a matching directory basename at any depth together with everything below it. Vendor-imposed. [verified: `pyproject.toml:28-35`; `claude/.claude/tests/test_pytest_collection_config.py:89-116` pins the replace-not-extend half, and the fixture at `.../worktrees/<dir>/sub/tests/test_should_never_collect.py` being provably uncollected at 30-78 demonstrates the any-depth half]
- **G3** — pytest-xdist's default `load` scheduler guarantees no file or class locality, so nothing orders the fixture-writing test against the tree-walking test. [engineer-verified for the scheduler contract; verified that no serialization exists — `pyproject.toml:25-27` registers only `timing`, and neither file carries `xdist_group`, a filelock, or a serial marker]
- **G4** — the fixture-writing test and the scanning test can also land in two *separate* pytest invocations against the same checkout, which is routine in this repo's multi-worktree workflow; no in-process mechanism can order those. [verified: `claude/.claude/tests/test_pytest_collection_config.py:36-39` documents concurrent invocations as the reason the fixture directory is pid-suffixed]

**Ledger rows:**

1. **Mechanism — one conjunct in `_is_test_source_change`.** `WORKTREES_DIR_NAME not in Path(path).parts`, placed after the `_is_py_source_under_claude_or_plugins(path)` call, makes the race structurally impossible under every schedule and in every invocation, including G4's cross-invocation case that no marker can reach. `anchors: root`
2. **Mechanism — `WORKTREES_DIR_NAME = "worktrees"` module constant** near `PLUGINS_DIR`/`CLAUDE_SKILLS_TOP_LEVEL_DIR` (`select-tests.py:35-52`), matching that file's convention of naming every path literal, and giving the three sites that currently spell `"worktrees"` a single home. `anchors: row1`
3. **Mechanism — drift test** asserting `_mod.WORKTREES_DIR_NAME` is a member of `pyproject.toml`'s `norecursedirs` list, in `TestRuleTablePathFidelity` (whose charter is already "validate the table against the real tree/config"). Converts a future rename of the worktree-directory convention from a returning intermittent failure into a deterministic one. `anchors: row1`
4. **Mechanism — three predicate unit cases** (fixture-shaped path, stale-nested-checkout-shaped path, `worktrees`-prefixed-but-not-equal near miss). Deterministic coverage of the exact shapes the live-tree walk observes only by accident of timing. `anchors: row1`
5. **Lighter/heavier alternatives weighed** (the over-powered-primitive check; all four are heavier than row 1, which is why row 1 is the choice). (a) Guard in `_is_py_source_under_claude_or_plugins` instead — semantically defensible but widens blast radius to a second `CROSS_DOMAIN_EXCEPTIONS` row and flips a synthetic worktrees `.py` path from domain-selected to `unmatched-path`, buying nothing (see row 6). (b) Filter worktrees paths at the top of `select_pytest_targets` — introduces a silently-contributes-nothing path class, weakening the documented "any path matching no rule falls open to the full suite" totality contract to fix a predicate-domain mismatch. (c) `xdist_group` / filelock serialization between the two tests — a heavier coordination primitive that cannot fix G4 at all, since a second pytest invocation's scanner still sees the first's on-disk fixture. (d) Filter the `rglob` in `test_every_is_test_source_change_match_is_in_test_corpus` — hides a real predicate/corpus mismatch and adds a third copy of the `"worktrees"` literal to the two already at `test_select_tests.py:1401,1432`, which is the compounding-layers tell rather than a fix. `anchors: row1`
6. **Assumption — the broad predicate needs no guard.** Its row selects `TICKET_REFERENCE_DISCIPLINE_TEST_PATH` and `CLAUDE_TESTS_DIR`, and both consumers discover their corpus through `git ls-files`, so neither can ever read a gitignored worktrees path; leaving it unguarded also keeps the rule table total over such a path instead of routing it to a full-suite fall-open. [verified: `select-tests.py:478`; `claude/.claude/hooks/tests/test_ticket_reference_discipline.py:34-37,277-289`; `claude/.claude/tests/test_pytest_collection_config.py:278-287`]
7. **Assumption — no production selection outcome changes.** `.gitignore:13` and `.gitignore:21` ignore both worktree roots, and `compute_changed_paths` sources only tracked diffs plus `git ls-files --others --exclude-standard`, so no worktrees path can reach `select_pytest_targets` from the only production producer. The guard is therefore a domain correction, not a selection change. [verified: `.gitignore:12-21`; `select-tests.py:561-589`] Residual: a deliberate `git add -f` under a worktrees directory would make such a path tracked; it would still be matched by row 6's predicate, so it still domain-selects.
8. **Assumption — the paired forward-direction test cannot break.** `_test_corpus` returns paths relative to `_REPO_ROOT` from five glob roots, none containing a `worktrees` segment, so `test_every_file_test_corpus_returns_matches_is_test_source_change` is unaffected. [verified: `test_select_tests.py:138-154,359-365`]
9. **Assumption — the subset invariant holds.** Adding a conjunct keeps `_is_test_source_change` a strict subset of `_is_py_source_under_claude_or_plugins`, so the header comment at `select-tests.py:445-449` and the docstring at 335-339 stay true, and no test asserts that relation directly. [verified: no subset assertion over these two predicates exists in `test_select_tests.py`]
10. **Assumption — the fix also removes a deterministic failure, not only the race.** A stale linked checkout at `claude/.claude/worktrees/<branch>/` contains `.../claude/.claude/hooks/tests/test_*.py`, which satisfies today's predicate and is absent from the corpus, so the reverse-direction test fails for as long as that directory exists. `.gitignore:15-21` and `test_pytest_collection_config.py:1-9,24-28` both document that directory as a real occurrence, not a hypothetical. [verified]
11. **Assumption — only the `claude/.claude/worktrees/` arm is live today.** A root-level `.claude/worktrees/<slug>/` path is relative-rooted at `.claude/`, which fails `_is_under(path, "claude")`'s boundary test, so that arm is already excluded — by prefix accident rather than by design. Scoping the new guard repo-wide rather than under `claude/` makes it excluded by design and covers a plugin nesting its own `worktrees` directory. [verified: `select-tests.py:246-247,324-332`]
12. **Assumption — component matching, not substring.** `Path(path).parts` membership mirrors G2's basename semantics exactly and follows the precedent at `test_pytest_collection_config.py:72` and the boundary-test precedent at `test_select_tests.py:449-459`; a substring test would wrongly exclude a directory such as `worktrees-helpers/`. [verified]
13. **Assumption — no new dependency.** `tomllib` is stdlib on the `py312` target and is already the repo's way of reading `pyproject.toml` in tests. [verified: `pyproject.toml:3`; `test_pytest_collection_config.py:104,127,145`]

Prescribed comment content for row 2, one durable fact per sentence, no plan-defined terms: `# Directory name .gitignore excludes at both worktree roots. pyproject.toml's norecursedirs prunes it from collection, so no test under one is ever collected.`

Deterministic pre/post reproduction of the reported symptom, run as a single self-contained script (one Bash call, `set -e` plus a `trap` for guaranteed cleanup even if the pytest call fails or hangs, and a `$$`-suffixed directory name mirroring the production fixture's own pid-suffix discipline at `test_pytest_collection_config.py:36-50` — G4 is exactly why a fixed literal name isn't safe here):

   ```
   bash -c '
   set -e
   FIXTURE_DIR="claude/.claude/worktrees/select-tests-race-check-$$"
   trap "rm -rf \"$FIXTURE_DIR\"" EXIT
   mkdir -p "$FIXTURE_DIR/sub/tests"
   printf "def test_x():\n    assert True\n" > "$FIXTURE_DIR/sub/tests/test_should_never_collect.py"

   '
   ```

This is the claim that the fix addresses the observed failure rather than only the unit-level predicate; the seeded path is gitignored, so nothing can be staged by accident, and the `trap` removes it whether the pytest call succeeds, fails, or the run is interrupted.

No per-file-type review dispatch applies: the diff carries no `SKILL.md`, no agent file, no rule file, and nothing under a plugin directory.
