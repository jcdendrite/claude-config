# Make the cumulative-review marker hash what was reviewed

## Context

`/ready-for-review` step 3 caches a clean cumulative code review as a
`cumulative-review` marker, and reads that marker back as licence to skip the
cumulative pass entirely. `marker.sh write cumulative-review`
(`claude/.claude/scripts/marker.sh:355-373`) computes the marker's value by
hashing the PR-vs-base diff *as it exists at write time*; it has no
precondition beyond the hash resolving. On GH-844 a session wrote that marker
immediately after a fix commit whose only review was a narrow staged-diff
`/code-review`, stamping the post-fix cumulative hash over content no
cumulative pass had ever seen. The session caught itself and handed off with a
manual "do not trust that marker" instruction.

A corpus sweep of every root in `~/.claude/transcript-config-dirs` found seven
executed `write cumulative-review` invocations across six sessions and five
branches. All seven fail the documented step-3 standard; zero correct
executions have ever occurred. One downstream session read the resulting cache
as live, skipped step 3, and opened a PR without an unnarrowed cumulative
review.

`docs/design-decisions.md` §44 already names the write as "a zero-evidence
self-attestation" and accepts it, reasoning that every marker kind is
self-attested and that step 2's verification plus CI still run
unconditionally. Intended outcome: a verdict on whether this is a reasoning
failure, a prose defect, or a foundational gap, and whatever change closes it.

## Approach

**The marker stops certifying the present.** `marker.sh write cumulative-review` currently fetches a *fresh* PR-vs-base diff at write time (`marker.sh:366`) and hashes that; the diff that was actually reviewed is never an input. The fix is to make the stored value the diff that step 3 recorded when it produced the diff it was about to review, and to change nothing on the read side. A write issued after a fix commit then stamps the pre-fix hash, `status` recomputes the post-fix hash, they don't match, and the marker reads `historical`. The mistimed write becomes self-defeating instead of harmful.

**Why this is a value-source bug and not a proof bug.** The write and the read call the identical helper (`marker.sh:366` and `:568`). The value the write stores is therefore, by construction, the value the reader will compute — so the write arm is structurally incapable of producing a marker that fails to match. It cannot fail to certify. Every previous round of this plan tried to *detect* the mistimed write; none noticed that the write's own artifact was the wrong artifact. Once the value comes from the recorded review subject, no observer is needed: the two hashes disagree on their own, and disagreement already has a correct, shipped rendering (`historical`).

**There is no adjudication step, deliberately.** The write has exactly one input — the recorded subject. Present: stamp its hash. Absent: refuse, write nothing. It never compares the subject against the current diff, because the reader already does that on every `status`, and adding a second comparison at write time would be the compounding layer.

**Where the subject lives.** `pr-diff-against-base.sh` gains a `--record` flag that `tee`s its own stdout into `<config-dir>/cumulative-review-subject-markers/<repo-hash>`. Step 3's existing fenced block gains the flag — one token, no new recipe, no new subcommand. The flag is opt-in precisely so `_lib_cumulative_diff_hash`'s call from `status` does **not** record: `status` is the recompute-the-present operation, and letting it refresh the subject would restore the tautology through a different door.

**Storing the diff text, not its hash, is load-bearing.** `_lib_cumulative_diff_hash` strips trailing newlines through command substitution before hashing (`_lib.sh:511-514`). A second hashing recipe that strips differently produces a cache that is *permanently and silently* dead — fail-safe, and therefore undiagnosable. Storing the text and hashing it in exactly one shared `_lib.sh` helper makes byte-equality a property of construction rather than of two implementations agreeing. `_lib.sh`'s own header states the rule: "Keep this file the single source of truth for any recipe that must produce byte-identical output on both the read side (hooks) and the write side (marker.sh)."

**The strongest claim this design makes, and the reason it is safe:** in every legitimate run the subject is recorded at step-3 entry and the diff has not moved by the clean-pass write, so the stored value is *byte-identical to what today's write stores*. The read side is untouched. §44's motivating conflict-free rebase therefore behaves exactly as it does today. This change alters the stored value only in runs where the diff moved between the review and the write — which is the defect.

**What it does not establish.** It does not prove a review happened. Record-then-immediately-write with no review in between still produces a live marker. That is left open on purpose: it is the same exposure the other four marker kinds already carry, `docs/design-decisions.md:831` already accepted it, and parity is the right bar. The control for it is the prose fix, not machinery.

**The prose fix carries the rest.** `SKILL.md:81`'s fragment "— not step 3's own cumulative pass —" reads either as "the fix commit's gate is the staged-diff one, not the cumulative one" or as "the fix commit is exempt from step 3's cumulative pass." Seven of seven corpus writes took the second reading. `SCOPE_RULE:ready-for-review-cumulative-unnarrowed` (`SKILL.md:78`) already settles it in the additive direction, so the ambiguous fragment is deleted from `:81` and the write-authority fact — the cache marker is written only from a clean pass of *this step's own* cumulative `/code-review`, never from a fix commit's staged-diff pass — moves into that block. The block is already exact-text-pinned by `test_skills.py:3161-3166`, so the pin is one constant update, not new test machinery.

### Assumption ledger

**Root:** `marker.sh write cumulative-review` (`marker.sh:355-373`) computes its own artifact at write time, so it stores the value the reader will recompute and can never produce a non-matching marker — it certifies whatever exists at the moment it runs, regardless of what was reviewed.

**Given** (fixed beyond this design's reach):

- **G1.** `_lib_cumulative_diff_hash` costs a `gh pr view` network round trip under a 15s cap (`_lib.sh:505-517`). The vendor imposes the round trip, so "call the producer twice and compare" is not available as a correctness mechanism. This is the sole given; the design's response is to make the write arm call it *zero* times.

## Out of scope

- **The record-then-write case with no review in between.** Recording the subject and writing the marker with no review in between still yields a live marker, and no in-session mechanism can distinguish it. This is routinely reachable, not only via deliberate hand-forging: `--record` sits inside step 3's own routine diff command, so a session that re-enters step 3 after a fix commit and proceeds straight to the write reaches it through the ordinary flow (row 28). This is the exposure all five marker kinds carry — `marker.sh write` *is* that capability, exposed by design, with CLAUDE.md §Safety's "never write `<config-dir>/*-markers/*` by hand" as its only control — and `docs/design-decisions.md:831` already accepted it. Parity is the bar. Row 5 forbids machinery here.
- **Any mechanism that observes reviewer dispatches.** Row 1. The proxy over-accepts and under-accepts; a fourth attempt to condition it is the compounding layer.
- **A stale subject recorded by an abandoned run.** A session that records the subject and abandons before reviewing leaves a subject that a later write could consume. Bounded three ways — consume-on-write, `deactivate ready-for-review` cleanup, and overwrite on the next record — and reaching it requires running `write` without running step 3's own diff command, which is hand-forging territory. Named, not engineered against.
- **Completion-marker retention.** `_lib.sh:316-321` documents an unbounded-growth ceiling that fails closed with no diagnostic. Real, pre-existing, unrelated.
- **Two concurrent sessions in one worktree.** They share one subject file, but the same worktree means the same HEAD and therefore the same diff, so the shared value is identical; the loser's write refuses and it runs an extra pass. Pre-existing shape for the marker itself, named so a reviewer does not read it as introduced.
- **Narrowing the post-fix re-review legitimately.** "Re-spawning the same specialists would be ritual, not discovery" is substantive, and the prose fix makes the cost explicit rather than answering it. Trigger for the follow-up: any branch observed reaching a third step-3 re-entry, or any session observed abandoning `/ready-for-review` for a trivial fix loop.
- **The four other kinds' self-attestation.** Each hashes an artifact the session necessarily held (row 6), which is a materially different exposure from an artifact fetched by a subprocess the session never saw — and after this change, `cumulative-review` joins them rather than remaining the exception.
- **Post-hoc review of the already-merged branches among the five.** Outside this plan's reach; the engineer's judgment call.
