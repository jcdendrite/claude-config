**The problem.** On 2026-09-24 a `ciso-reviewer` dispatched with closed questions built a test harness in a `/tmp` scratch directory, created a symlink there to the repo's real interpreter, and later ran a scratch script that redirected output onto that link. The write followed the link chain and replaced a machine-wide shared interpreter with a shim that re-executes itself, hanging every process that used it. The review hook had denied an earlier compound command, but the agent moved the same steps into a script; the hook sees only top-level command strings.

**Why now.** The interim control (PR #1106) is prose: a `## Scratch execution` section in each persona. A sweep after that merge found a `staff-sdet` dispatch violating several of its clauses, and the ticket's re-run over this repository's own reviewer transcripts since 2026-09-25 (qualitative, no figure published) found the drift recurring: replica probe scripts and `ln -s` in scratch directories, directory-tree copies into `/tmp`, reviewer `Bash` runs of the test suite, and no write into the reviewed tree beyond `sed -i` edits of a persona's own findings file. The sandbox spike (#1102, `docs/case-studies/claude-code-sandbox-write-boundary.md`) found that the sandbox blocks the incident's symlink shape but not pre-created hard links, cannot be scoped per subagent, and has an escape hatch silently auto-approved under a bare `Bash` grant. Nothing structural stops a recurrence today.

**Intended outcome.** Every reviewer persona carries only `Read`, `Grep`, `Glob`, and `Write`, and the hook gates its `Write` to its own `<agent>-*.md` file in an ignored `agent-reviews/` directory. The orchestrator writes each reviewer's diff, base and history inputs via `pr-diff-against-base.sh`, so only file paths and a changed-path listing enter its context. Reviewers request checks instead of running them: a `Check:` line on an ordinary counted finding, and the fix `code-writer` for that finding writes the failing test first. The hook's Write arm stops exempting `/tmp` and tightens to the caller's own findings file, with one added case: a new `<agent>-*.md` file in this session's `/review-pr` findings directory (see the amendment in the Write arm bullet). The containment scope for `code-writer`, the main session, `Explore`, and `Plan` is decided and recorded: `code-writer`, the main session and `Plan` still hold `Bash`, and so do `review-orchestrator` (outside the hook roster) and `general-purpose`; the follow-up issue owns containment for the first three. A lane is the changed paths one reviewer is asked to review (a whole-diff lane is all of them, a listed lane a named subset), and a lane's index lists every changed path, marks which are the lane's, and names the lane's diff, base and history files.

## Approach

All ten reviewer personas end up holding exactly `Read`, `Grep`, `Glob` and `Write`, and the Write arm lets each write only `<its own name>-*.md` in an ignored `agent-reviews/` directory. Whatever reviewers used `Bash` for now comes from outside them: two `pr-diff-against-base.sh --context-files` calls per round list the changed paths and write every spawn's inputs, and a claim a reviewer cannot settle by reading is a `Check:` line on an ordinary finding.

**Failure rule: optional context degrades, required content halts (row 79).** A failed read of a base or history body is noted `unavailable` and the call exits 0. The lane diffs and the index are required content: any failure producing them, or a shared diff whose `diff --git` headers do not match the index rows, exits 1 with one stderr line, no token lines and no file left behind. Withholding is not required content: its predicates are boolean, as the hook's are, so a failure of a predicate's tool reads as no match and fails open. There is no degraded whole-diff mode. The cost is accepted: a deterministic script defect on a repository shape the fixtures miss halts `/code-review` for that repository until fixed, and the escape is a commit from the engineer's own terminal (Verification, "When the review path itself is broken"). Every exit-1 stderr line ends with a pointer to `docs/scripts.md` § "When --context-files halts".

**Write-arm depth (row 28, decided).** The Write arm keeps allowing a write into an ignored `agent-reviews/` directory at any depth. Binding to the repo root would close nested writes, but `findings-path-suffix.sh` writes an unanchored ignore pattern (row 47), so a session started in a subdirectory relies on nested directories being ignored, and the reach is any directory of that name. That reach includes an `agent-reviews/` directory under `.claude/rules/`, `.claude/agents/` or `.claude/plans/`, which a session started in one of those directories would produce. Whether the harness loads any such directory is unverified, and no such write has been seen. The engineer reconfirmed this after the config-root consequence was named: "Keep, accept as debt (Recommended)". The alternatives of a `.claude/` exclusion and of binding the Write arm to the repo root (with a path-naming denial) were set aside as touching about 23 files against 5, and as needing read-back edits in three dispatcher skills. The own-name check limits a persona to `<its own name>-*.md`; the header and the PR body quote the answer and name the reach, a test pins it, and under `docs/hooks.md:32` this answer is the stop-and-ask record for findings against this gate, which this PR's tracking-pointer edit makes regression-class.

**Reviewer inputs (rows 1–6, 13, 47, 57–61, 64, 65, 67, 75, 79, 80, 120, 123, 125, 127, 133, 136, 138, 139, 142, 145, 146, 149, 154, 155, 157–159, 162, 164, 165, 167).** Before the first spawn of each round, `/code-review` makes two Bash calls, each with `timeout: 600000`.
- **CLI.** `pr-diff-against-base.sh [--staged | --working-tree | --expect-diff <path>] --context-files <suffix> (--list | [--listing <id>] -- <lane>...)`. `<suffix>` is the round's `findings-path-suffix.sh` output, validated against `^[0-9]{1,20}-[A-Za-z0-9-]{0,20}$`; a spawn's file stem is `<agent-name>-<suffix>` (the stem of its `findings_path`), with `<agent-name>` matching `^[a-z][a-z0-9-]{0,63}$`. The orchestrator single-quotes every argument by the rule at `code-review/SKILL.md:409` (a pre-edit anchor, +4 after the insertion; step 1 of Delivery re-resolves citations).
- **Call 1, `--list` (row 146).** It runs the source resolution, the `--expect-diff` compare, the status check and the empty check, and writes nothing under the repository (git's own stat refresh of `.git/index` on a stat-dirty checkout aside, row 164). On stderr, with stdout empty, it prints `LISTING: <id> <count>` and one line per changed path: `CHANGED_PATH: <n>`, a TAB, then TAB-separated `<status>`, `withheld` or `-`, `<path>`, and for a rename or copy `<old path>` as its own field. `<n>` starts at 1 and numbers the index rows in index order: the `--raw -z` rows, then untracked paths. Paths follow the index's C-quoting. The listing is uncapped and is the orchestrator's changed-path source for Step 0 (`code-review/SKILL.md:11` leaves it open) and Step 0.6. A tool result above the harness's output limit arrives as a truncated preview (row 158), so the `:290` note has the orchestrator check `<count>` and `LANE_ROW_COUNT:` and read the full output file on a mismatch and halt the review, quoting both numbers, when the full file still disagrees. An empty source prints `DIFF_EMPTY:` and exits 0.
  - **`<id>`** is the sha256 of the mode, the base sha, the `HEAD` sha, the raw rows and the untracked-list temp, streamed to `sha256sum` and never through `$(…)`, which drops NULs and lets distinct listings collide. Outside `--working-tree` the raw rows are the `--raw -z --no-abbrev` temp file itself. Under `--working-tree` they are rebuilt from the parsed row arrays with each new-side blob id zero-filled, and the raw temp is not read (row 164). Call 2 computes the id from the same temps and parsed rows its header check uses, so no third read window opens. Blob ids in the raw output catch a staged change under `--staged`; content drift under `--working-tree` is not caught, which is acceptable because call 2 is self-consistent. The mode adds no write of its own, but git's own stat refresh of `.git/index` on a stat-dirty checkout is the one write under the repository that it cannot prevent (row 164). The base sha is in the digest so the index's `base:` header and base bodies match the base the listing named. A `gh` flap between the calls (one resolves the base, the other falls to the guess) can therefore give a false `LISTING_STALE:`, which the one re-list recovers. Call 2 alone prints `BASE_GUESSED:`. The core temps hold only paths, modes and blob ids and live in the private temp directory (Temps).
- **Call 2, lanes.** Each `<lane>` is `<agent-name>` (a whole-diff lane with base and history), `<agent-name>:diff` (a whole-diff lane with no base or history, row 6) or `<agent-name>=<n>,<n>` (a listed lane; each `<n>` is a listing number). `--listing <id>` is required with a listed lane and checked whenever given: a mismatch with the recomputed id exits 2 with `LISTING_STALE:`, the orchestrator re-lists once and repeats the Step 0.6 classification, the spawn set and every lane from the new listing, and a second stale halts the round. A `--listing` value that is not 64 lower-case hex digits is a usage error with no `LISTING_STALE:`, so the re-list path is not taken. One argument per agent (a repeated agent exits 2); duplicate numbers in one lane collapse; a number outside 1..count exits 2. On exit 0 the script prints `LANE_ROW: <agent> <n> <path>` for each row of each listed lane, after every other token and after one `LANE_ROW_COUNT: <total>` line; the orchestrator compares those lines with the paths it meant and, on a mismatch, runs call 2 once more with the same `<id>`, and a second mismatch halts. When `ciso-reviewer` spawns, the orchestrator puts every `withheld` row in its lane, and call 2 exits 2 if a listed `ciso-reviewer` lane omits one. A spawn's prompt names no number.
- **No changed-path text in any command (row 146).** `deny-credential-bash-reads.sh` matches a path token alone (`:4-5`), so its built-in path regex and ssh-directory check cannot match either call, and its opt-in user-glob check never sees a changed path. The `--expect-diff <path>` source can still be denied by a user glob, so a hook denial of either call is a halt: the orchestrator quotes the denial and never re-forms the command. A prompt is not Bash, so the orchestrator may name a credential-named path to `ciso-reviewer`. Only `LANE_ROW:` detects a wrong in-range number, through the orchestrator's comparison, which is judgment; a check digit and ordinal ranges were rejected (Alternatives).
- **Which call each context makes.** *Staged commit-gate round:* `--staged`, base and history from `HEAD`. *Presentation-path review of uncommitted changes:* `--working-tree`, the diff being `git diff HEAD` (staged and unstaged together), with untracked files from `git ls-files --others --exclude-standard -z` as `?` rows with no bodies; the source is empty only when both are empty. *The cumulative file `/ready-for-review` step 3 hands over:* `--expect-diff <that path>`, the only use of the flag; the script resolves the merge-base as default mode does and, before any emptiness check, compares the handed file with a recompute that reuses default mode's own capture (the one shared cumulative-diff command, `_cumulative_diff_argv` in `pr-diff-against-base.sh`, through `$(…)`; the rule is under Structure), both with every trailing newline stripped. This is the one place the mode captures diff text through `$(…)`: the handed file was written from that capture, so a NUL-bearing block would otherwise mismatch on every run and re-running step 3 could not clear it. Invariant: the recompute and a file default mode wrote agree for the bytes `$(…)` alters (`test_expect_diff_agrees_with_default_mode_over_nul_fixture`). Two empty forms print `DIFF_EMPTY:`; any other difference, a non-empty handed file against an empty diff included, prints `DIFF_MISMATCH:` and exits 1 (remedy: re-run `/ready-for-review` step 3). *Ad hoc review of this branch with no handed file:* no source flag (cumulative), same merge-base. *Contexts where the script does not run* (any other handed diff file, `/review-pr` in either mode, a pasted snippet): each spawn gets the invoker's file path or the text verbatim, with its lane and any tree root named in the prompt, and in `diff-only` mode the prompt says no local tree exists. `/review-pr` spawns get no index, base or history (row 5), and its own base-read rule governs base content (row 57).
- **Structure.** One unrestricted `git diff` per round (the shared diff, no pathspec) is checked header by header against the index rows and cut by byte offset into per-lane `.diff` files. Handing every reviewer the whole diff would multiply it by the reviewer count (row 145), and one call keeps the worst-case time sum under the Bash timeout.
  - **Revision arguments** for every diff-class call except the `--expect-diff` recompute: `--staged` takes `--cached`; `--working-tree` takes `HEAD`; cumulative and `--expect-diff` take `"<merge-base>...HEAD"`. The raw, numstat and shared calls follow it with `--`. The `--expect-diff` recompute runs the same `_cumulative_diff_argv` command as default mode (a pinned plumbing `git diff-tree`, `$(…)`, stderr to `/dev/null`), wrapped only in `_lib_capped_for "$CONTEXT_DIFF_CALL_SECONDS"`: the handed file was written by that command, so one definition keeps the compare byte-exact whatever `GIT_DIFF_OPTS` or porcelain `diff.*` setting the caller has. A cap kill or failure exits 1 at `expect-diff`, never `DIFF_MISMATCH:`. Every other `git diff` passes `-c core.quotePath=false` and `--no-color --no-ext-diff --no-textconv --no-relative -M --src-prefix=a/ --dst-prefix=b/ --submodule=short --ignore-submodules=none` (the shared diff adds `-U3`, because `diff.context=0` changes patch output and leaves the raw and numstat calls unchanged; P4), runs through `_lib_capped_for "$CONTEXT_DIFF_CALL_SECONDS"` with its status checked (a failure exits 1, never `DIFF_EMPTY:`), and redirects its own stderr to `/dev/null` as default mode's `--staged` and cumulative captures do (`pr-diff-against-base.sh:60` before the mode's edits, and the `_cumulative_diff_argv` capture); enrichment `git log` calls do the same. Statuses, modes, blob ids and paths come from `--raw -z --no-abbrev`, and binary detection from `--numstat -z`.
  - **Shared diff.** `git diff <pinned flags> -p --full-index -U3 <revision> --` writes a 0600 file in the private temp directory (Temps). It holds withheld paths' blocks, so it never sits under the repository and is removed immediately after the last slice, before enrichment. The pathspec-less call is unaffected by the `GIT_*_PATHSPECS` variables, and the script unsets them anyway (Write discipline).
  - **Header check.** One pass over the shared temp extracts every `^diff --git ` line with its byte offset (`grep -a -b` under `LC_ALL=C`, so a NUL in a text diff cannot turn the match into a binary-file message) into a file in the private temp directory; the expected headers go to another file there; both are removed with the shared diff.
    - A `T` row expects two adjacent identical headers; an untracked row expects none, even when also withheld; every other row expects one, withheld rows included, because the unrestricted diff holds their block.
    - Multiset equality over headers built from the index rows, each side quoted as git quotes it: each found header equals an expected one, none appears more often than expected, none is missing, and a header string produced by two different rows halts as ambiguous. A block runs from its header to the next header or EOF. An empty expected set passes only for a zero-byte temp (the untracked-only `--working-tree` round). A mismatch halts at step `header-check`.
    - *Why header keying is not the removed splitter:* a content line starts with a space, `+`, `-`, `\` or `@@`, never `diff --git` (P15 check 3), so a header line marks a block start. Attribution needs no assumed order between raw and patch output and no range tiling (row 136).
  - **Slicing.** A lane's `.diff` is its preamble plus the blocks of its rows in whole-diff order, byte for byte, and withheld bytes appear in no lane file. Adjacent kept blocks copy as one run with `head -c <end> <file> | tail -c <len>`, appended as a plain statement. `tail -c +N | head -c M` is never used: it exits 141 under `pipefail` once more than a pipe buffer follows the slice. The process budget is one `head`/`tail` pair per contiguous run. Withheld and untracked rows have no block to copy. The test oracle is an independent per-path `git diff` reference (test and probe only, never production), so a short or shifted slice fails. The two P15-ambiguous rows' blocks are the exception: their expected bytes are the shared-diff slice itself, checked by the header-multiset and offset-slice tests.
  - **P15 is the stop gate.** It checks the header property and the slices on the installed git before Phase 1a. A failed check stops Phase 1a and returns to the engineer, who chooses among the earlier designs under Alternatives. P15 passed on git 2.43.0: 18 checks over six sources (staged, working-tree, range, each also under `diff.renames=copies`), `[verified: probe 2026-10-19, git 2.43.0]`. The 2.31 minimum is not run `[unverified]` (row 127).
  - A status outside the index grammar (an unmerged `U`) exits 1 in both calls, because the orchestrator must not classify from a listing holding one; the detail line names the status and the C-quoted path. For a conflicted index `--staged` (`--cached`) lists the path as `U`, while `--working-tree` (against `HEAD`) lists it as `M`, so only `--staged` can carry a `U` `[verified: probe 2026-10-19, git 2.43.0]`. Only a both-modified (`UU`) conflict was probed, not `DU`, `UD` or `AA`.
  - **Precedence.** (1) A failed `_lib_repo_root` (`repo-root`), a `TMPDIR` that is relative, resolves into the repository or cannot make the private directory (`temp-dir`), an unborn `HEAD` (row 80) or a failed `rev-parse`, `merge-base`, base-resolution, `ls-files`, raw call or (call 2 only) numstat call exits 1. (2) A `--expect-diff` mismatch exits 1, in both calls. (3) An empty source prints `DIFF_EMPTY:` and exits 0, even where `agent-reviews/` is not ignored. (4) A status outside the index grammar exits 1, in both calls. (5) `--list` prints the listing and exits 0. (6) In call 2, a stale id, an out-of-range number or a `ciso-reviewer` lane omitting a `withheld` number exits 2, so exit 2 wins over any later exit 1 or 3. (7) The ignore check exits 3, or exits 1 at `ignore-check`. (8) `agent-reviews/` is validated or created. (9) The shared diff call, header check, slicing, enrichment and writes run.
  - **Caps.** Every `git` and `gh` call goes through a cap and every status is checked, except `gh pr view` (failure falls to the guess) and enrichment calls (they degrade). 5 s: `_lib_repo_root`, `git rev-parse`, the default-branch guess, each ignore check. `_lib_gh 15` for `gh pr view` (row 75). `CONTEXT_GIT_CALL_SECONDS=20`: this mode's `git merge-base` (default mode's stays uncapped) and each enrichment call. `CONTEXT_DIFF_CALL_SECONDS=60`: the core calls, the shared diff, the `--expect-diff` recompute and `git ls-files --others`.
- **Body files**, absolute paths under `<repo root>/agent-reviews/`:
  - `<stem>.diff` opens with one `# omitted <reason>: <path>` line per lane path whose block it lacks (`<reason>` is `withheld` or `untracked`; `withheld` wins), then a blank line when any exist; `<path>` is C-quoted as in the index. After that come the lane's blocks, whole and untruncated, in git's path order.
  - `<stem>.base` holds each lane path's pre-image (`git cat-file blob <pre-image id>` after `git cat-file -s` checks its size; a missing final newline is added and noted `no-eol`).
  - `<stem>.history` holds, per lane path, `git -c core.quotePath=false --literal-pathspecs log -n "$HISTORY_COMMITS_PER_PATH" --no-merges --no-color --no-ext-diff --no-textconv --follow -p --src-prefix=a/ --dst-prefix=b/ --submodule=short --ignore-submodules=none -U3 --format='commit %H%n%ad %s%n%n%b' --date=short <history base> -- <pre-image path>`, the five flags after `-p` being what P4 added (`diff.noprefix`, `diff.submodule`, `diff.ignoreSubmodules` and `diff.context` each change `git log -p` output otherwise); `HISTORY_COMMITS_PER_PATH=5`, with subjects and bodies and no author fields, following renames from the old name (row 4).
  - A `:diff` lane writes `.index` and `.diff` only, and its header names `-` for base and history.
- **Enrichment.** Base and history are computed once per path per call into files in the private temp directory and copied into every lane that names the path, history only after its withheld check. Only paths of lanes other than `:diff` lanes are enriched: paths a listed lane names first, in index order, then paths only a whole-diff lane reaches.
- **Index grammar, `<stem>.index`.**
  - *Header lines, in order:* `lane-index: 1`, `mode: staged|working-tree|cumulative`, `root: <abs repo root>`, `base: <full sha>`, `head: <full sha>|-`, `generated: <UTC YYYY-MM-DDTHH:MM:SSZ>`, `lane: whole-diff|diff-only|listed`, `diff-file: <abs>`, `base-file: <abs>|-`, `history-file: <abs>|-`, then one blank line. Under `--staged` and `--working-tree`, `base:` is `HEAD`'s sha and `head:` is `-`; under cumulative and `--expect-diff`, `base:` is the merge-base sha and `head:` is `HEAD`'s.
  - *Rows,* one per changed path in listing order, TAB-separated: `<status>`, `lane|-`, `<base range>`, `<history range>`, `<notes>`, `<path>`, and `<old path>` for renames and copies only. Status is `A`, `M`, `D`, `T`, `R<nnn>`, `C<nnn>` (kept in the grammar though `diff.renames=copies` yielded no `C` row with `-M` pinned on git 2.43.0, row 138) or `?` for untracked.
  - *Ranges* are `<start>+<count>`, a 1-based start line and a line count as `Read`'s `offset` and `limit` take them; `-` means the body is absent, and context rows carry `-` in both. There is no diff range: a reviewer reads its whole lane diff (row 123).
  - *Notes:* `-`, or a comma-joined subset of `binary`, `gitlink`, `symlink`, `mode`, `empty`, `no-eol`, `withheld`, `over-cap`, `commits-only`, `unavailable`, `skipped`, `untracked`.
  - *Paths.* A path holding a control byte, or beginning with `"`, is written C-quoted, so a leading `"` always means C-quoted; every other path is raw bytes. The preamble's `<path>`, every `CHANGED_PATH:` and `LANE_ROW:` path and every absolute path in an index header follow the same rule. The C-quoted form is the path in double quotes, with `"` and `\` backslash-escaped and each control byte (0x00–0x1f, 0x7f) written as git writes it (`\a \b \t \n \v \f \r` for 0x07–0x0d, a three-digit octal escape for every other); bytes of 0x80 and above stay raw. The script implements this itself because `-z` output arrives unquoted.
- **Bounds.** Only base and history degrade; the `.diff` is never truncated. A degraded body, a failed `git cat-file` or `git log` read included, leaves a note in its row and never a non-zero exit. Base is omitted, noted `over-cap`, above `BASE_BYTES_PER_PATH=262144`. History is replaced by its commit list, noted `commits-only`, above `HISTORY_BYTES_PER_PATH=131072`. Once a lane's base and history reach `CONTEXT_BYTES_PER_LANE=1048576`, later bodies are omitted, noted `over-cap`. `CONTEXT_ENRICHMENT_SECONDS=120` runs from the first enrichment call (bash `$SECONDS`) and is checked before each call; after it, remaining bodies are noted `skipped`. A non-zero status from an enrichment call, a cap kill included, discards its output and notes the row `unavailable`. At exit 0 a `CONTEXT_DEGRADED: <n>` line counts bodies noted `over-cap`, `commits-only`, `unavailable` or `skipped`, printed when n > 0.
  - **Time.** The constants are local budgets with no external spec.
