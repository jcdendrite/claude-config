# Record config-key state per session in a per-account log

## Context

Goal: every Claude Code session start, `/clear`, compaction and resume appends a row to a per-account log file holding the resolved value of every key in `claude/.claude/hooks/config-keys.psv`, keyed by session id, so a later tool can join the row to the session's transcript and tell which keys were on or off for that session.

## Approach

Add one informational SessionStart hook, `claude/.claude/hooks/record-session-config-keys.sh`, registered with no matcher. At every SessionStart event it appends one JSON row to `<config-dir>/.session-config-keys-log.jsonl` and prints nothing. When it cannot, it prints one fixed notice, which puts a line on the engineer's screen and tells the agent to report the problem and do nothing else unless the engineer asks (rows 112, 122). The notice prints when the append's retry also fails (row 140), and on every stow consumer (row 141). The row holds the session id, the event's source, a timestamp and the resolved value of every `config-keys.psv` key. A later analysis joins rows to transcripts by session id, and a subagent's transcript joins through its parent's session id. The reader rules live in a new `docs/session-config-keys-log.md`, which the hook's `docs/hooks.md` bullet links to. Under that doc's coverage rule, a session that begins after its account's coverage start and has no row is a recorder failure, and an event whose hook attachment carries the notice is a lost event (M12). Every append starts with a newline, so a line an earlier failed write left unfinished never costs a later row (row 135). Before merge, the engineer runs a live check that real sessions' rows join to their transcripts at startup, compaction, `/clear`, resume and in a `claude -p` run, and that a no-row event's notice reaches the screen and the agent. Critical files names the dispatch split.

One decision stays conditional: if step 9's headless run writes no row, row 111's third case goes to the engineer. The lost-event count takes no coverage-start bound, and the PR body states the probe's notice sessions (rows 146, 147).

**The record.**
- A row is one line: `{"session_id": ..., "source": ..., "logged_at": ..., "keys": {<key>: <value>, ...}}`. Every field and every value in `keys` is a JSON string. `logged_at` is `now | todateiso8601`, the permission-prompt log's field name and format (row 92).
- The keys come from `_config_schema_known_keys` (row 9), split with `IFS=' ' read -r -a`. A duplicated schema row yields one entry holding the first row's value, with no dedup code in the hook: both reads return the first row's value (row 87), and the encode's `from_entries` keeps one entry (row 108). A key added to `config-keys.psv` is recorded with no hook edit.
- Each value is the stdout of `_config_value <key>`, captured by `$(...)` in a plain assignment so that `$?` is the call's own. The capture also confines a `set -u` abort inside the library to its subshell. The call passes no config-dir override, so a `config-dir-or-home` key keeps the union a gate sees (row 89).
- The hook records the value only when the call exits 0 and the value matches `^[-abcdefghijklmnopqrstuvwxyz0123456789_]+$`. The class spells out each character, as `_LIB_SESSION_ID_COMPONENT_CHAR_REGEX` does, so no locale's collation widens it (row 110). Anything else, an empty value included, records `unreadable`. The check keeps paths and free text out of the log, because a schema default can reach the hook as raw text (row 11). An exit-0 read can still carry the library's fail-safe value, which the hook cannot mark as substituted (row 10).
- `source` is the payload's `source` under the same token check, else `unreadable`.
- The row holds every schema key with its value, and a reader filters to the keys it wants, the on ones included (row 60).
- The hook writes no row, and exits 0, when the payload is empty, malformed, not an object, without `hook_event_name`, naming any event other than `SessionStart`, or without a valid session id. It also writes none when `_lib.sh` fails to source, `jq` is missing, the config dir is unresolvable, no key list is available, the row encode fails, the log path is not a regular file the invoking user owns, the log's mode cannot be set to 600, or the append and its one retry both fail. The reader doc counts each such event as a lost event, and its coverage rule tells a session with no row from one that never ran the hook (M12).

**The notice.** Every no-row exit above prints one fixed line. The hook is registered only on SessionStart (case 1), so under the harness each no-row exit, the payload ones included, is an event that lost its row. A payload that names another event, or none, means a harness change to that field, and printing the notice there is the cheap fix row 122 records (G1). The `_lib.sh` and `jq` failures print the notice too, because it is a plain `printf` of fixed bytes (row 120). Only an event at which the hook never runs loses a row and prints nothing. The coverage rule reports it when the session holds no other row, and the reader doc states that it shows in no count otherwise (G1, M12).

The line is `{"systemMessage":"<screen text>","hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"<agent text>"}}` and a newline.
- `systemMessage` shows the screen text to the engineer, and `additionalContext` gives the agent text to the agent, which reports it in its next reply (rows 115, 116).
- Both texts name the repository, so the pointer resolves from a session in any project, as the library's own `jq` message does (row 129).
- Neither text holds `"`, `\` or `'`, so each sits unescaped in the JSON and in the single-quoted shell literal that holds it.
- Nothing from the payload, the environment or the config reaches the line, so its bytes are the same on every no-row path.
- The agent text limits the agent to the report. A hand-written row would claim values no hook read, a repair edits a file every stow consumer shares, and an issue or a read of a file in the session's project is not the agent's call. "Unless the engineer asks" leaves a session whose task is fixing this hook free to fix it.
- The notice prints at every event until its cause is fixed, and the reader doc says so.
- This plan did not check whether the harness caps a hook's output. The line is the hook's only output, and only a no-row event prints it.

**Hook mechanics**, in order:
1. `set -uo pipefail` without `-e`, then `exec 2>/dev/null`. The `exec` discards stderr for the whole process before anything is sourced, so no library warning reaches the transcript, which keeps a hook's stderr (rows 12, 85). Stdout stays the harness's, because every call that can print runs inside `$(...)` and the notice is the hook's only uncaptured output (row 126). Next come:
   - `no_row_notice_due=1`.
   - The constants `NO_ROW_SCREEN_TEXT` and `NO_ROW_AGENT_TEXT`, single-quoted, holding the two texts The notice quotes.
   - A function `print_no_row_notice`, which is one `printf '{"systemMessage":"%s","hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"%s"}}\n' "$NO_ROW_SCREEN_TEXT" "$NO_ROW_AGENT_TEXT"`.
   - `trap '[ "$no_row_notice_due" = 0 ] || print_no_row_notice; exit 0' EXIT`, the hook's only `EXIT` trap. A later `trap ... EXIT`, such as the one `_lib_acquire_append_lock` sets (row 91), would replace it and drop the notice, and case 21, whose append fails after the point a lock would be taken, then fails.

   Then `INPUT=$(cat) || exit 0` and `[ -n "$INPUT" ] || exit 0`. Every exit before a successful append therefore prints the notice. The hook adds no per-call redirect beyond the source line's own. Everything up to the source line runs before `_lib.sh`'s bash floor check, so it must parse and run on bash 3.2 (`.claude/rules/shell-floor.md`, row 128). Case 22 runs it there where a below-floor bash exists.
2. The source line is exactly `if ! . "${0%/*}/_lib.sh" 2>/dev/null; then`, and its branch exits 0 (row 41).
3. `event_name=$(printf '%s\n' "$INPUT" | _lib_jq -r '.hook_event_name // empty') || exit 0`, then `[ "$event_name" = SessionStart ] || exit 0`, is the hook's own event filter (repo `CLAUDE.md`, "Hook defense-in-depth"), in the shape of `track-permission-prompts.sh:46-47` (row 119). An absent field and any other value both exit with the notice (row 122). Next, `session_id=$(printf '%s\n' "$INPUT" | _lib_jq -r '.session_id // empty')`, then `_lib_valid_session_id_component "$session_id" || exit 0` (row 78). A third call, `_lib_jq -r '.source // empty'`, reads the source, as `record-session-end.sh:62-63` reads its two fields (row 76).
4. `config_dir=$(_lib_config_dir) || exit 0` (row 73). The log path is `$config_dir/.session-config-keys-log.jsonl`.
5. `key_list=$(_config_schema_known_keys) || exit 0`, then the per-key loop from The record, which collects names and values in two arrays.
6. The encode is one call, `row=$(_lib_jq -c -n --arg session_id "$session_id" --arg source "$source" --arg key_names "$key_names" --arg key_values "$key_values" '<filter>') || exit 0`, then `[ -n "$row" ] || exit 0`, which keeps an encode that exits 0 with no output from clearing the notice for a lost row (case 17).
   - `$key_names` and `$key_values` are the two arrays joined with newlines. Names cannot hold a newline, because the schema is read line by line, and values cannot, because of the token check.
   - The filter is `{session_id: $session_id, source: $source, logged_at: (now | todateiso8601), keys: ([($key_names | split("\n")), ($key_values | split("\n"))] | transpose | map({key: .[0], value: .[1]}) | from_entries)}`.
   - `_lib_jq` adds no `-c`, so the call passes it (row 40). Every field enters through `--arg`, so the row is valid JSON whatever the token check admits.
   - The filter carries a `# shellcheck disable=SC2016` line with a one-line rationale, as `record-session-end.sh:90` does (row 42).
7. The write guard sits immediately before the append, so no key read falls between the checks and the write (rows 74, 102):
   - `umask 077`.
   - When the path neither exists nor is a symlink, `( set -o noclobber; : > "$log_file" ) || true` creates it exclusively at mode 600. Losing that race to another session's create is harmless, because the next check accepts that session's file. The create never runs on an existing path, because `noclobber` opens an existing FIFO without `O_EXCL` and would block on it (row 104).
   - `[ ! -L "$log_file" ] && [ -f "$log_file" ] && [ -O "$log_file" ] || exit 0`. A symlink, dangling or not, a non-regular file and a file another account owns each write no row, and the hook opens none of them. `-O` is the control against another local account's pre-created file, as in `_lib_resume_context_index_dir` (row 102).
   - `chmod -- 600 "$log_file" || exit 0`, so a mode the hook cannot set writes no row.
   - A new log whose `chmod` or first append then fails stays behind with no row, and the hook leaves it. The reader doc reads a log with no row as no log, and case 19 pins the file left behind.
   - The append is one line, `printf '\n%s\n' "$row" >> "$log_file" || printf '\n%s\n' "$row" >> "$log_file" || exit 0`, and `no_row_notice_due=0` follows it, so only a successful attempt silences the notice (row 140). There is no lock and no loop (rows 91, 125). Each attempt writes its leading newline in one `write` and its row line in the next, so every write ends at a line boundary, and under row 81's bound the row line is one write. Concurrent appends therefore interleave only as whole rows and blank lines (rows 81, 136).
   - Every attempt starts with a newline, so the row begins a line of its own even after a line a failed write left unfinished, whether this event's first attempt or an earlier event's, and readers skip that unfinished line (rows 134, 135). After a complete line, the newline leaves one blank line before the row, which readers also skip. A new log therefore begins with a blank line, which the reader doc's skip rule and its trim recipe both handle (row 138).
   - The retry repeats the same line. It helps only a write error that clears at once. It cannot help a full or read-only filesystem or a permission refusal, which are the persistent causes the notice reports.
8. Every path exits 0 through the trap while the harness still reads stdout. A harness that has closed its end kills the trap's `printf` with SIGPIPE before `exit 0`, and no reader sees that status (round-4 ciso-reviewer R3, as handed over). The file mode is 100755.

The reader doc, `docs/session-config-keys-log.md`, in full:

````markdown
# Session config-keys log

`record-session-config-keys.sh` adds a row to `<config-dir>/.session-config-keys-log.jsonl` at each startup, resume, `/clear` and compaction. A later analysis reads the rows to tell which `config-keys.psv` keys were on for a session.

`<config-dir>` is `$CLAUDE_CONFIG_DIR`, or `~/.claude` when that is unset. Each account has its own `<config-dir>`, which holds that account's log and its `projects/` transcript tree.

If the hook's no-row notice sent you here, go to [Notice](#notice).

## Rows

Each row is one line holding a JSON object. Skip blank lines, and skip a line that does not parse.

- `session_id`, `source` and `logged_at` are strings.
- `source` is the SessionStart source the harness sent, such as `startup`, `resume`, `clear` or `compact`. `unreadable` means the hook could not read it.
- `keys` maps every schema key at that event to a string value.

## Values

A value is the key's resolved value at that event. A key nobody set shows its schema default, so a row cannot tell a default from an explicit setting.

- `false` means off.
- `unreadable` means the hook could not read the key, so its state is unknown.
- Any other value means on, an enum literal such as `dollars` included.
- A key absent from a row has no state in that row.

A value can be the fail-safe value `_config.sh` substitutes for a state file it cannot read. A gate in that state gets the same value, and the row does not mark it as substituted.

## Joining a row to its transcript

Check `session_id` against `^[A-Za-z0-9_-]+$`, the grammar `_lib_valid_session_id_component` enforces, before building a path from it. Then join the row to `<config-dir>/projects/*/<session_id>.jsonl`.

A subagent's transcript records carry its parent's `sessionId`, so a subagent takes its parent's rows.

## State at a transcript record

To find the key state at one transcript record, use the rows whose `session_id` equals the record's `sessionId`:

- Take the latest row whose `logged_at` is at or before the record's `timestamp`. Compare the two as times, not as strings. `logged_at` has whole seconds, as in `2026-05-19T10:00:00Z`, and a record's `timestamp` has milliseconds, as in `2026-05-19T10:00:00.000Z`. `jq`'s `fromdateiso8601` accepts only the first shape, so drop the fraction before parsing a `timestamp` with it.
- Among rows with equal `logged_at`, take the later line in the file.
- A record earlier than every such row has unknown state.
- A record after a lost event, as Coverage defines it, has unknown state unless a row has a `logged_at` between that event's attachment `timestamp` and the record's `timestamp`.
- Do not count on one row per event. Each row is a full snapshot, so a duplicate row is harmless.

The row taken is the newest evidence of the state at that transcript record, not proof of it:

- Gates reread their keys on every call, so a key flipped mid-session governs at once.
- A row shows that flip only from the next SessionStart event. `/compact` adds that row to the same session, and `/clear` or a plain restart starts a new session with its own row.

## Coverage

Report four counts, each on its own: sessions of each of the two recorder-failure kinds below, lost events, and sessions with unknown state. Do not fold unknown state into a recorder-failure count.

Apply these rules once per session id, pooling every transcript file whose records carry that id, subagent transcripts included.

A hook attachment is a transcript attachment of type `hook_success` whose `command` basename is `record-session-config-keys.sh`. A hook attachment with a non-empty `stdout` is a lost event: that event wrote no row, even in a session that holds other rows.

The coverage start is the earliest `logged_at` among the log's rows. On an account whose log holds no row, or that has no log, it is the earliest hook attachment `timestamp` in the account's transcripts. Compare these times as State at a transcript record says.

An account with neither a row nor a hook attachment has no coverage start. Report it as an account where the hook has not run, not as one with no failures, and tell the engineer to run the `ls` check in `README.md` § "Updating after git pull", which says when to re-run the installer.

A session is covered when either of these is at or after the coverage start:

- The earliest record `timestamp` in its transcripts.
- The `timestamp` of a hook attachment in its transcripts.

A covered session with no row is a recorder failure of one of two kinds:

- The hook ran and wrote no row: its transcripts hold a hook attachment.
- The hook did not run: they hold none. Usual causes are a `<config-dir>/hooks` directory that leaves the hook unlinked, a session started without the user-layer settings, an IDE or desktop session if those skip SessionStart, and a Claude Code release that stops firing SessionStart hooks.

A session that is not covered has unknown state. It predates the coverage start, or its rows were trimmed or deleted.

An event at which the hook did not run leaves no hook attachment. In a session that holds another row, such an event shows in no count.

## Notice

A notice means that event wrote no row. A missing notice does not show that a row was written, and Coverage is the check for that.

The engineer runs the checks below and files any issue. An agent that sees the notice reports it and does nothing else unless the engineer asks. In a `claude -p` run, the agent's report can land in the run's output.

To find the cause, the engineer runs these checks in the shell that launches Claude Code, on the same account, because the hook discards its own error output:

- `bash` on that shell's `PATH` meets `README.md` § "Requirements". `docs/hooks.md` § "Bash version" says what a lower `bash` stops.
- `jq` is on that `PATH`.
- `timeout`, or `gtimeout`, on that `PATH` accepts `-k`.
- `CLAUDE_CONFIG_DIR`, if set, is an absolute path.
- `<config-dir>` exists.
- The account can write `<config-dir>`.
- The filesystem holding `<config-dir>` has free space.
- That filesystem is not read-only.
- That filesystem accepts `chmod`.
- Any file already at `<config-dir>/.session-config-keys-log.jsonl` is a regular file.
- The account owns that file.
- The account can write that file.
- `bash -c '. ~/.claude/hooks/_lib.sh && _config_schema_known_keys'` prints the key list, or the error that stops the hook reading `config-keys.psv`.

If every check holds, the engineer files an issue on the claude-config repository with the notice text and the Claude Code version, and with no session id, path or key value.

The notice prints at every event until its cause is fixed. Until then, the engineer can quiet it only by removing the hook's entry from `claude/.claude/settings.json` in the claude-config checkout. `<config-dir>/settings.json` links to that file. Removing the entry changes a tracked file, so a later pull that touches the file can conflict with it.

To record the session that showed the notice, the engineer gives it a new event after the fix, because the hook writes a row for the session only at its next event:

## Retention

The log holds a session id and time for every session on the account. It outlives transcript cleanup. Nothing trims it automatically, so old rows stay available as a baseline.

After a deletion, or a trim that keeps no row, read Coverage only after the next event writes the log's first row, because until then the account has no row. With no hook attachment either, Coverage reports that the hook has not run. With one, Coverage starts at the earliest hook attachment and counts each later session whose row was removed as a recorder failure. A session from before the deletion or trim that gets no later row has unknown state.

Only the engineer runs the trim, because an agent's own session stays open while it runs. To trim:

1. Pick `<days>` no shorter than `cleanupPeriodDays`, because a shorter cutoff gives unknown state to sessions whose transcripts still exist. `cleanupPeriodDays` is the Claude Code setting for how long transcripts are kept.
2. Close every Claude Code session on the account, because a row a session adds during the trim is lost.
3. In a terminal, replace `<days>` in the command below and run it. It keeps the rows that parse and fall inside the window, and drops blank lines.

```bash
(cd "${CLAUDE_CONFIG_DIR:-$HOME/.claude}" && trimmed=$(mktemp .session-config-keys-log.XXXXXX) && jq -cR --argjson days <days> 'try (fromjson | select((.logged_at | fromdateiso8601) >= now - $days * 86400))' .session-config-keys-log.jsonl > "$trimmed" && mv "$trimmed" .session-config-keys-log.jsonl)
```

Afterwards `ls -l "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.session-config-keys-log.jsonl"` shows the log as `-rw-------`.
````

**Root problem:** No record ties a session to the `config-keys.psv` values in force for it, so the routing-gate dogfood reads a hand-written per-branch note that the engineer cannot reconstruct (row 26). The record has eight requirements:
- A later session can join it to each session's transcript by session id and extract it with a plain JSON read.
- It covers every schema key.
- It prints nothing when it writes a row, so a working recorder stays off the screen and out of the model's context.
- When the hook runs and writes no row, the engineer sees a short notice and the agent reports it, and the notice carries no key value, path or payload field (rows 112, 122).
- It exists on accounts where every key is off.
- It never shows a read that the library reports as failed as a value.
- Its values carry no path and no free text.
- Every session that begins after its account's coverage start has a usable row, or a reader counts it as a recorder failure, a session that never ran the hook included (rows 93, 94, 112, 132). An event that ran the hook and wrote no row counts as a lost event, even in a session with other rows. The requirement claims nothing for an event at which the hook did not run in a session that has another row (G1).
