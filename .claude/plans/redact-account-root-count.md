# Redact per-account/per-project cardinality and raw pooled cost figures repo-wide on main

## Context

`main` publishes two distinct classes of forbidden figure across 59 committed files — reference docs, seven case studies, three design-decision entries, the changelog, one source comment, and 43 plan files.

**Class 1 — cardinality.** The exact or bounded count of this machine's Claude-Code accounts, `transcript-analysis.py` roots, client engagements, or private working-set repositories. Root `CLAUDE.md` states without qualification: "Never publish a figure carrying a per-project, per-account, or per-engagement dimension — this is absolute, not a factor to weigh, no borderline case." A count is the literal cardinality of the dimension that rule forbids.

**Class 2 — raw pooled cost.** `docs/private-project-redaction.md:118-131` requires dollar or token spend drawn from the mixed corpus to be reported as a rate per tool call, session, or dispatch, or as a dimensionless share of pooled spend split along any dimension but project, account, or engagement. A raw pooled total is "barred outright — it scales with pool volume, and, unlike a rate or a share, it can be converted to an engagement-value estimate using public day-rate references." Two further clauses bind: `:135-137` bars a time series, so successive whole-period totals compose into one; `:138-145` bars a permitted rate published alongside a permitted pool-size count, because they multiply back to the barred total.

Neither class is caught by any hook. The only mechanism that could license a class-2 figure is the pooled-measurement carve-out at `docs/private-project-redaction.md:91-154`, whose two closed lists neither extend by analogy — counts of tool calls, sessions, and dispatches are permitted as totals; cost never is.

**A narrower third pattern, addressed only where found in this sweep.** The same carve-out's count list is closed at "tool calls, sessions, and agent dispatches," so a pooled count of a different artifact or event type — a branch, a PR, a hook denial, a finding, a nudge fire — drawn from the mixed corpus is not licensed by that list either, for the identical mixed-provenance reason class 2 is barred. `.claude/plans/redaction-carveout-followups.md` row 9 names this as "the inventory's largest scope question, not settled here." This plan does not attempt a from-scratch repo-wide sweep for this pattern — that is a separate, larger undertaking the followups plan already owns. It fixes the specific instances a targeted search of the 59 already-in-scope files surfaced (category L in Critical files), because leaving a known instance unfixed inside a file this PR is already editing would be worse than not having looked.

The plan originally scoped one file. Four things changed it. The engineer reversed the deferral and authorized fixing every file carrying a live violation. A comprehensive non-head-limited search found 40 cardinality files against the prior estimate of about eleven. The original target file is verified clean in the current tree and drops out entirely — the sibling branch's fix appears to have landed on `main` ahead of this one. Finally, the engineer authorized folding class 2 into the same PR rather than deferring it, and searching for class 2 exposed ten further class-1 sites in a noun family the first sweep did not cover.

Several sites disclose more than a bare figure: a per-account data table, a per-account distributional spread published twice, a single private project's account-level monthly spend, a per-engagement account composition, and a client-repo-plus-engagement count in one sentence. Several others justify their own disclosure by citing another file's figure as already-public, so the sweep makes those justifications stale unless rewritten semantically rather than numerically.

This does not retract the exposure already in `main`'s history — per `docs/private-project-redaction.md`'s Remediation section only a history rewrite would, and that stays the owner's to run personally, never an agent's, even if told to. The engineer did not authorize one.

Intended outcome: a `main`-targeted PR that removes every live cardinality figure and every barred cost figure from the working tree, reviewed by `/plan-review` before implementation and `/code-review` before commit.

## Approach

Rewrite each offending figure into the register its own surrounding prose already uses — for cardinality, the unnumbered forms ("every declared root," "every account on this machine," `account-N`); for cost, the rate or share the same passage's argument already turns on. The rewrite is per-site and semantic, never a global substitution: the same digit means a list length at one site, a fixture size at another, and the corpus cardinality at a third, and the same dollar figure is compliant when this-repo-scoped and barred when machine-wide. No `sed`, no scripted substitution.

**The scope test, applied per cost site.** Read the command, flags, or scope sentence that produced the figure.

- Resolves to **this repository** (`--this-repo`, "this repo's own `pr-cost` ledger", a named claude-config branch): the figure is this public repo's own history and stays. `docs/private-project-redaction.md:147-150` places a figure already outside the per-project exclusion beyond the carve-out's reach, and `.claude/plans/pin-explore-to-sonnet.md:275-276` is the repo's own worked precedent for exactly this reasoning.
- Resolves **wider** — machine-wide, corpus-wide, every declared root, a named account, or every repo the accounts have activity in: the dollar or token total is the barred class and is replaced by the rate or share.

A companion constraint comes from the same precedent: never publish a this-repo total and an account-wide total in one artifact, because the difference is private-engagement spend. This sweep removes every account-wide total, which is what makes the surviving this-repo totals unambiguously safe rather than merely tolerated.

Twelve rewrite categories cover every site. A reviewer checks the category's semantic, not the wording.

**Cardinality categories:**

- **A — Corpus-scope statement.** "Measured across the machine's account/root set." Replace with "every declared root" / "every account on this machine." The scope claim must stay non-narrowable, not degrade to "multi-account."
- **B — Machine-roster assertion.** "This machine resolves *n* roots," used to establish that a multi-root code path is unconditional here. Replace with "resolves more than one root" — the whole load-bearing content.
- **C — Per-account breakdown or distributional split.** A per-account table, an *m*-of-*n* subset, or a min–max spread across accounts. Remove every per-account cell; keep the qualitative finding. A number swap does not fix this category — the structure is the disclosure.
- **D — Pasted tool-output header.** A verbatim `<NAME> SOURCES (...)` line stating a real run's root count. Elide the digit to the file's own ordinal placeholder register and add a one-line elision note. Do not delete the header: `docs/transcript-analysis.md:49` and `claude-skills/skills/transcript-analysis/SKILL.md:20` both teach that it always prints and must be quoted verbatim, and re-running the sample to obtain a single-root header would invalidate every other figure in the block.
- **E — Reproduction-command placeholder count.** A command repeating `--config-dir <profile-K>` once per non-default account, where the repetition count *is* the account count. Collapse to one flag plus "repeated once per declared account profile."
- **F — Cross-file "already public" justification.** Prose licensing its own disclosure by citing another file's figure. The citation dies with this PR, so re-derive the argument against the post-fix text; usually the clause goes rather than gets reworded.
- **G — Per-engagement or private-working-set composition.** "Personal plus *n* client accounts," "*n* client repos across *n* engagements," "*n* other clients' profiles," "the *n* cross-account target repos," "across ~*n* repos." Replace with an unnumbered form carrying no engagement or project dimension.
- **H — Incidence across accounts or repos.** A sentence of the form "observed *n* times across *m* repos and *m* Claude accounts." The test is what unit *n* counts, not what topic the sentence discusses. The incident count *n* survives only when it counts this repo's own tooling use (a session, tool-call, or dispatch count, per row 17) — including a session count *in which* some other event (a bug report, a pushback) occurred, since that is still a session count, not an event count. When *n* counts the event itself instead — a bug recurrence, a finding — category L's closed list does not exempt it regardless of magnitude, so drop it or convert it to a qualitative register rather than keeping it. Either way, replace the repo and account counts *m* with "more than one repo and more than one account."

**Cost categories:**

- **I — Raw pooled cost total from a wider-than-this-repo corpus.** Drop the dollar or token total. Where a share column already sits beside it, the share carries the finding and the dollar column simply goes; where no share exists, convert to a rate per session or dispatch, or to a percentage change. In every table this sweep touches, the surrounding prose already reasons from the share or ratio, not the total — `docs/case-studies/handoff-hard-block-position.md:117` says so explicitly ("the *ratio* … is the figure this study treats as load-bearing"), and `docs/case-studies/handoff-threshold-impact.md:47,119` reason purely from shares. Removing the totals costs no argument.
- **J — Per-account or per-engagement cost figure.** A named single account's spend, or one private project's account-level monthly spend. Barred by `CLAUDE.md`'s absolute rule directly, not by the carve-out's conditions — strictly worse than a pooled total, and the closest thing in the repo to a disclosed engagement value. Replace with the qualitative claim the passage needs.
- **K — Composition and time-series hazard.** Not a site type but a check applied after every I-rewrite: confirm no surviving permitted rate multiplies against a surviving permitted pool-size count to reconstruct the removed total (`:138-145`), and that no file publishes two whole-period totals as a before/after pair (`:135-137`).

**Pooled artifact/event-count category:**

- **L — Pooled count of an artifact or event type outside the carve-out's permitted list.** The carve-out at `docs/private-project-redaction.md:108-117` closes its permitted-total list at "Claude Code tool calls, sessions, and agent dispatches" and states neither list extends by analogy (`redaction-carveout-followups.md` row 9). A branch count, PR count, hook-denial count, friction-event count, finding count, nudge-fire count, block count, or review-round count is therefore not a permitted pooled total when it is pooled wider than this repo or this machine — across multiple machines, or across a cross-account repo set that itself spans machines. A single machine's own multiple accounts stay inside the safe boundary; only crossing a machine boundary trips this bar (`/plan-review`'s ciso-reviewer dispatch traced this against `handoff-hard-block-position.md:111-115` and `handoff-threshold-impact.md:60-68`, both correctly kept as single-machine multi-account pools, and found the prior wording here — which named "multiple accounts" alongside "multiple machines" as if either alone were sufficient — inconsistent with that applied practice). Session, tool-call, and dispatch counts stay exempt regardless of pooling breadth; nothing else does. Treatment mirrors category I: drop the count, or where the surrounding prose already reasons from a ratio or share built on it, keep that ratio and drop only the raw count. A this-repo-scoped or single-machine count of any of these same artifact types — including that machine's own multiple accounts — is unaffected: the gap is cross-machine pooling breadth combined with the count type, not the count type or single-machine account-pooling alone.

**Scope follows the bug, not where it surfaced.** `CLAUDE.md` § Engineering Judgment requires auditing structural siblings before scoping a fix narrowly and applying the identical fix to each affected arm. That is the argument for one 59-file PR over three partial ones, and `:138-145`'s cross-artifact composition rule reinforces it: a partial sweep leaves figures in separate files that compose back into the barred total, so a half-done sweep is not half-safe.

**This plan file's own prose — not only its citations — must not republish the figures it exists to remove.** A plan under `.claude/plans/` ships in the same PR as the implementation and carries the same redaction rules as any other public-repo content. The rule binds every prose section here — Approach's category definitions and illustrative examples, the assumption ledger, Critical Files' citations and their justification text, Verification, and Out of scope — not citations alone: no prose in this file states a figure carrying a per-account, per-root, per-engagement, or per-private-project dimension, nor a barred pooled total, rate, or count. A dimensionless share, a permitted carve-out count (tool calls, sessions, agent dispatches), or a this-repo-scoped figure may be quoted — those are not what this rule bars. Where a citation's justification needs to explain why a site is barred, point at the file's own scope-establishing line (e.g., "the cardinality `:36` establishes") instead of restating what that line says. The same constraint binds the commit message and PR body. The diff's own `-` lines unavoidably show the removed text and that text is already in history; the plan's own prose is different, because it would be *new* standalone republication and is avoidable.

**Alternatives set aside.** *Deleting offending passages wholesale*: destroys design rationale for no redaction gain, and committed plans and case studies are records under `CLAUDE.md` Axis 3 — this PR edits the disclosing figure, not the record. Two structural removals are the exceptions that prove it (a per-account table and several dollar columns), and each survives only because there is no way to keep the structure without the figure, and because the passage's own conclusion is preserved. *Splitting into several PRs*: each re-litigates the identical rules with a fresh reviewer pass, and a partial sweep both recreates the reversed deferral and leaves `:138-145` compositions live. *Recomputing the removed totals as rates rather than deleting them*: rejected where the pool-size count is published in the same table, since the rate reconstructs the total. *A history rewrite*: excluded by the engineer and by the Remediation section. *A mechanical detector*: rejected on merits below.
