# Unblock code-writer model measurement via subagent-mix redaction fix

## Context

Make `subagent-mix`'s per-branch, per-agent-type dispatch and cost breakdown readable under `--this-repo`, so `code-writer`'s model mix and cost can actually be measured. Today, `subagent-mix` (and its structural sibling `subagents`) redact both branch names and `subagent_type` values whenever more than one Claude Code config root is in scope — and on a machine with a populated `~/.claude/transcript-config-dirs`, more than one root is in scope on *every* invocation, with no existing flag combination that reduces it. That makes every row in the output an opaque `account-N/agent-type-M` label, so a `code-writer` row can never be identified — blocking a pending measurement of `code-writer`'s model mix and per-tier cost, which a reactive-effort-escalation design decision needs.

## Approach

Under `--this-repo`, `subagents` and `subagent-mix` stop replacing branch names with `account-<K>/branch-<N>` placeholders and print `account-<K>/<real branch>` instead; `subagent-mix` does the same for a `subagent_type` that is tracked in this repo's own `claude/.claude/agents/` tree (or is a Claude Code built-in), and keeps today's fully-opaque `account-<K>/agent-type-<N>` for every other value. `subagents` additionally discloses a branch only when a non-sidechain record attested it, because that subcommand reads subagent transcripts whose `gitBranch` can name a different repo. Everything else about multi-root behavior — the `DO NOT PUBLISH` banner, the `--per-session` refusal, the `account-<K>/` namespace, the redaction of every non-`--this-repo` run — is unchanged.

The justification for the branch half is a parity argument, not a new risk judgment. `--this-repo` resolves its scope from `git worktree list` alone, so the *set* of session files it reads is root-count-independent (`_repo_scoped_project_slugs` matches project dirs by exact basename across whatever roots are in play). A single-root `--this-repo` run — reachable today by any operator with no `transcript-config-dirs` file — already prints raw branch names and raw `subagent_type` values with no banner and no redaction. Adding a second root does not change what *kind* of content is in scope; it only adds more accounts' copies of this repo's own worktree sessions. The redaction that fires at root count two is therefore withholding a class of value the same flag already discloses at root count one.

The parity argument covers the *file's* repo identity, which is all `--this-repo` establishes. Two gaps sit outside it, and each gets its own gate rather than riding on the parity claim:

- A `claude-config` session can dispatch a subagent whose own cwd is a different, possibly private repo. That subagent's transcript is stored under the parent's project directory and carries the foreign repo's branch in `gitBranch` (G6). `cmd_subagent_mix` never reads those records; `cmd_subagents` does. Mechanism 2 is the gate for that subcommand.
- A session running in a `claude-config` worktree can dispatch an agent whose definition came from the operator's own config dir or an installed private plugin (G4), so a raw `subagent_type` is not repo-identity-bound the way an attested `gitBranch` is. Mechanisms 3 and 4 are the gate for that.

### Assumption ledger

**Root problem.** Under `--this-repo`, `subagents` and `subagent-mix` redact branch names and `subagent_type` values that carry no private-project identity, which makes the only instrument that can attribute cost and dispatch counts to a named subagent type unreadable on a machine with more than one declared transcript root.

**Givens**

- **G1.** `multi_root` is true on every invocation on the target machine, with no flag combination that reduces it. `_resolve_cost_roots`'s unconditional union serves all thirteen `_SUBCOMMANDS_WITH_OWN_CONFIG_DIR` members; changing it is a decision outside this plan's scope, and the dispatch bars touching it. `[verified: scope.py:526-561]`
- **G2.** `--this-repo` guarantees, fail-closed, that every session *file* read comes from one of this repo's own worktree project directories. `_repo_scoped_project_slugs` owns that guarantee, `sys.exit(1)`s on every non-repo path, and is out of this plan's reach by constraint. The guarantee is about the file's project directory only — it says nothing about the repo identity of an individual record inside that file (G6). `[verified: scope.py:47-152]`
- **G3.** This repository is public, so a pushed branch name is already visible to anyone with the URL. A repository-visibility fact the plan cannot change. `[verified: CLAUDE.md, opening line]`
- **G4.** A `claude-config` session can dispatch an agent defined outside this repo's `agents/` tree — user-scope files the operator added by hand, or agents contributed by an installed plugin. Agent resolution is Claude Code harness behavior this script does not control. `[unverified]`
- **G5.** `_DO_NOT_PUBLISH_BANNER`'s wording is shared across roughly a dozen subcommands. Retargeting its text is a change to a shared constant whose other callers this plan does not read. `[verified: scope.py:471-473]`
- **G6.** A subagent's transcript is stored under its *parent's* project directory regardless of the subagent's own cwd, and its `gitBranch` can name the repo that subagent ran in rather than the parent's. Where the harness writes a subagent file and what it stamps into `gitBranch` are harness behavior this script does not control. `[verified: docs/transcript-analysis.md:30 — "a subagent's gitBranch field can silently disagree with the branch actually checked out in a pre-existing different-repo cwd"]`

1. **Print `account-<K>/<real branch>` for a branch name when `args.this_repo` is set, in both `cmd_subagent_mix` and `cmd_subagents`.** `anchors: root`. The single-root `--this-repo` path already prints the same raw values today, so multi-root parity discloses nothing new in kind. `[verified: transcript-analysis.py:2404-2411 and :909-917 — both take the raw-`branch` arm whenever `root_idx is None`]`

It leaves the structural sibling asymmetric for a reason no reader of the code could reconstruct, and the byte-per-branch table is unreadable for the same reason the mix table is.
   - Lighter primitive B, rejected: exclude sidechain records from `cmd_subagents` entirely, matching `cmd_subagent_mix` literally. The main-vs-sidechain byte split *is* that subcommand's output; excluding sidechain records deletes half of every table.
   - Heavier primitive, rejected: verify each branch against `git branch`/`git worktree list`. It over-redacts exactly the historical branches the measurement reads, since merged branches are deleted and their worktrees pruned, and it adds a git call whose failure mode is a silently emptier table.
   - The attestation set is populated before the `--since` and `--branches` filters, so narrowing an unrelated flag never flips a branch from disclosed to opaque. Attestation is a provenance fact about the corpus, not a windowed statistic.
   - Residual, accepted: attestation is keyed on `(root_idx, branch)` — a same-account, same-string check, not a same-repo check. A foreign private repo dispatched to under the same account, checked out on a generically-named branch (`main`, `master`) that coincidentally matches a genuine `claude-config` main-thread branch, discloses as if it were this repo's own, folding that foreign repo's byte/turn counts into a row that now carries a real label. This is bounded to generic/default branch names — a distinctively-named foreign branch (the exploit shape this mechanism exists to close) cannot coincidentally collide. Closing it fully would require per-record repo provenance the harness does not stamp (G6), which is out of reach.
3. **Gate `subagent_type` disclosure on an allowlist; fall back to today's opaque `account-<K>/agent-type-<N>` for anything not on it.** `anchors: root`. G4 is the reason a `subagent_type` needs a gate that an attested branch name does not. The fallback is the current label verbatim, so a withheld value is indistinguishable from a value withheld in a run with no allowlist at all — no hybrid label narrows a guess.
4. **Build the allowlist from `git ls-files` run against `Path(__file__).resolve().parent.parent / "agents"`, taking the stems of top-level `*.md` entries.** `anchors: row3`. Every account config dir on the target machine symlinks both `scripts/` and `agents/` into the same shared checkout, so `.resolve()` lands in the repo's own tracked tree whichever account invoked the script. `[verified: stow symlink layout inspected across every account config dir on the machine]` Top-level entries only, matching `_declared_pin`'s own flat `agents_dir / f"{agent_type}.md"` resolution — a nested tracked file over-redacts, the safe direction. `[verified: transcript-analysis.py:2539]` Stems rather than parsed `name:` frontmatter, because a stem/name divergence fails safe in both directions — a missed name over-redacts, a stem matching no real agent never matches any transcript value — and parsing would otherwise pull `validate_skill_structure.parse_frontmatter` across from the hooks tree into the scripts tree. All thirteen files currently agree stem-to-name. `[verified: claude/.claude/agents/ listing plus `^name:` grep across all 13 files]`
   - Lighter primitive A, rejected: a bare `Path.glob("*.md")` directory listing. It allowlists any file physically present, tracked or not, which is precisely the untracked-WIP exposure this row exists to close.
   - Lighter primitive B, rejected: a hand-written tuple of agent names plus a test asserting it equals the directory's stems. The roster then has two homes and the test exists only to reconcile them, which CLAUDE.md's single-source-of-truth rule calls a defect absent a named exception, and none applies.
   - Lighter primitive C, rejected: reuse the on-disk probe `_declared_pin` already performs (file exists implies allowlisted). It reads `agent_dirs[root_idx]` — the *dispatch's own account's* agents directory — so a foreign account's private agent file would allowlist its own name, which is precisely the disclosure this gate exists to prevent.
   - Residual, accepted: `git ls-files` reports the invoking checkout's index, so a file that is `git add`ed but never committed or pushed is allowlisted. Closing that would need a ref-pinned read (`git cat-file`/`git ls-tree` against a remote-tracking ref), which fails on any checkout with no fetched remote and buys nothing against the failure mode named above — a file staged for commit in this public repo is a file the operator has already decided to publish.
   - No separate "unreadable agents directory" test case is needed: a missing directory, a permission-denied directory, and a directory that exists but isn't a git repo all raise the identical `CalledProcessError` (exit 128) from the same `git -C <dir> ls-files` call, caught by the same `except` clause, producing the same built-ins-only fallback — unlike `_iter_scoped_sessions`'s unrelated `Path.iterdir()`-based directory walk, where those failure modes genuinely diverge. The Critical files test list's "a directory outside any git repo yields the built-ins alone" case already exercises this exact path.
5. **Add a named constant for Claude Code built-in agent types (`general-purpose`, `claude-code-guide`, `Plan`) and treat them as allowlisted.** `anchors: row3`. Without it the largest row of `subagent-mix`'s first table — the `Top subagent types` column, where `general-purpose` dominates — reads as an opaque placeholder, which degrades the table the measurement is being run to read. A built-in name is present in every Claude Code install and cannot identify a project. The three names come from `_declared_pin`'s own docstring, which already lists them in prose; move that list into the constant and have the docstring reference it, so the set has one home rather than two. Drift is fail-safe: a built-in added later and not recorded here is over-redacted, never under-redacted. `[verified: transcript-analysis.py:2525-2527]`
6. **Factor the decision into one helper in `redaction.py`, immediately after `_assign_root_scoped_redact_label`.** `anchors: row1, row3`. Signature `_root_scoped_display_label(kind, ordinal, value, redact_map, *, disclose)`; `disclose` returns `f"account-{ordinal}/{value}"`, otherwise it delegates unchanged. Three call sites share one policy and one label format, and `redaction.py` is where the `account-<K>/` namespace convention already lives. The allowlist predicate and the attested-branch set both stay in `transcript-analysis.py` next to their own call sites, since one depends on that script's location on disk and the other on `cmd_subagents`' own record loop. The disclosed path must not write into `redact_map` — the per-ordinal counter `n` counts map entries, so a disclosed value stored there would inflate the placeholder numbering of genuinely-redacted values in the same run. `[verified: redaction.py:225-229]`
7. **Keep the `account-<K>/` prefix on every disclosed label.** `anchors: row1, row3`. Reason: correctness, not only collision-safety. `cmd_subagent_mix`'s `data` dict and its `model_mix` dict are both keyed on the *label*, so dropping the prefix would silently merge two accounts' `main` rows and two accounts' `code-writer` rows into one, losing per-account attribution the current table has. The ordinal itself discloses nothing the resolved-scope header does not already print as a root count. `[verified: transcript-analysis.py:2413 and :2376; scope.py:441-457]`
8. **Print the `DO NOT PUBLISH` banner unconditionally and unchanged, and name the newly-disclosed fields in the operator-facing notes instead.** `anchors: root`. A non-allowlisted `subagent_type` and an unattested branch may still be redacted row-by-row, so the banner remains true; it costs nothing and blocks nothing. Making it conditional on `--this-repo` would fork a constant shared by roughly a dozen subcommands (G5) for the benefit of two. Its literal text ("real project names and session IDs") is already inaccurate for these two subcommands today, since neither prints a project name and session IDs appear only under `--per-session`, which multi-root refuses. That inaccuracy is pre-existing, but this change raises its stakes: an operator reading the banner's specific wording to decide what is safe to paste would not learn from it that branch names are now in the output. The Verification section's operator notes carry that statement, since the banner constant itself stays out of scope.
9. **Leave the `--per-session` multi-root refusal exactly as written.** `anchors: root`. G2's guarantee is about repo identity; a session-ID prefix is an account-scoped identifier that guarantee says nothing about, and it is a stronger cross-run correlation key against that account's other outputs than anything else this table prints. The `disclose` flag is threaded only into the two label sites, never into this check. `[verified: transcript-analysis.py:2254-2262]`
10. **Correct the two `--config-dir` help strings and the two doc lines that claim `--config-dir` is refused together with `--this-repo`.** `anchors: root`. After this change, `--this-repo` plus multiple roots is the exact invocation the measurement runs, so a help string telling the operator that combination is refused actively obstructs the feature being shipped. It is also already contradicted inside the same document by the canonical statement at `docs/transcript-analysis.md:34` ("`cost --config-dir` does not refuse `--this-repo`: since `--this-repo`'s identity match is derived from `git worktree list` alone, it is root-independent"), so the fix is deletion of a false clause, not new prose. Scope stays at the two Arm-B subcommands.
11. **Do not change any column width.** `anchors: row1`. A real branch name plus the ten-character `account-<K>/` prefix will overflow `subagent-mix`'s `Branch:<45}` and `subagents`' `Branch:<40}` fields, producing ragged rows. The single-root path already overflows for long branch names today, so matching it is the consistent choice, and widening the fields would churn the header-anchored `_table_cols` assertions across the existing suites. New tests must assert on substring presence rather than column position so they do not encode the ragged layout. `[verified: transcript-analysis.py:2424, :2432, :920, :935]`

Three operator notes on the output:

1. **What a `--this-repo` run now discloses, by field.** Branch names print raw — every branch in `subagent-mix`'s table, and in `subagents` only branches a non-sidechain record attested. Agent-type names print raw when tracked in this repo's `agents/` tree or on the built-in list. Everything else stays opaque, and every disclosed value keeps its `account-<K>/` prefix.
2. **A row now ties a named branch to an exact-cent dollar figure.** That correlation is the point of the measurement and is an accepted tradeoff, not an oversight — `redaction.py`'s own docstring already flags the dollar columns as a stronger cross-run correlation key than the spawn counts beside them, and a real branch name makes each such row specific to one piece of work.
3. **The banner still prints and still means what it says for the table as a whole.** Its literal wording predates this change and never mentions branch names, so read note 1 rather than the banner for what a given run exposes. A non-allowlisted agent type or an unattested branch may be redacted in the same run, and the row set discloses that more than one account did work in this repo. Quoting a specific figure into a PR body or plan is a separate judgment the operator makes under CLAUDE.md's provenance rule, and the figure needs its source command named alongside it wherever it lands.

## Out of scope

- **The same sidechain-branch exposure on the *single-root* `--this-repo` path of `subagents`.** It exists today, predates this plan, and mechanism 2 leaves it untouched because the single-root path never reaches the new helper. Closing it would change existing behavior, invalidate the single-root regression pin, and belongs in its own change. Worth raising to the reviewer as a real, if low-likelihood, pre-existing leak.
- **A `--no-redact` escape hatch for `subagents`/`subagent-mix`.** It would not solve the problem regardless: `_resolve_cost_roots:553-559` refuses `--no-redact` under the same permanently-true multi-root condition. It has independent merit as a follow-up only if an operator later needs raw output for a scope `--this-repo` cannot express.
- **`_DO_NOT_PUBLISH_BANNER`'s text accuracy.** It claims the output contains "real project names and session IDs"; `subagents` and `subagent-mix` print neither, today or after this change. Fixing it means either forking the constant per subcommand or auditing all of its callers (G5). The Verification section's operator note 1 is the interim mitigation. Candidate follow-up.
- **`read-scope`'s identically-stale help string** at `transcript-analysis.py:10759`, which also claims `--config-dir` is refused together with `--this-repo`. Not verified whether that subcommand enforces the refusal, so it's unknown whether it is stale or accurate. Worth a separate check.
- **`_dispatch_usage_summary`'s known usage over-counting (discovery-audit finding C1)**, which prices `cmd_subagent_mix`'s `Actual $`/`Counterfactual $` columns — the exact columns this plan's own Verification section instructs the operator to read. `_dispatch_usage_summary` (`transcript-analysis.py:2593-2644`) never calls `_dedup_turns_by_request_id`, unlike the eleven-plus other pricing call sites in this file, so any `code-writer` dispatch whose turn spans multiple JSONL records sharing a `requestId` is priced multiple times for input and cache dollars. This is a pre-existing, already-triaged defect (`docs/reports/2026-08-22-discovery-audit/findings.md`, finding C1) that predates this plan and is unaddressed in the current tree; fixing it is a separate, already-scoped item. An operator reading a `code-writer` dollar figure this plan makes newly legible should treat it as a possible over-count before quoting it into a design decision, PR, or plan under CLAUDE.md's provenance rule.
- **`_declared_pin`'s `Declared` column**, which reads a per-account, possibly non-repo-tracked `<config-dir>/agents/<stype>.md` frontmatter `model:` value with no validation against the known model-ID set, printing whatever token is present raw. This is pre-existing and this plan's Critical files section deliberately leaves it untouched (`_declared_pin` must keep reading raw `stype`). It sits beside the row label this plan makes newly legible for an allowlisted `subagent_type`, so a reader's trust in a now-readable label (e.g. `account-K/code-writer`) may extend further than warranted to the unvalidated `Declared` cell next to it. Validating that column against `_MODEL_BASE_INPUT_RATES` is a separate, out-of-scope fix.
- **Arm A subcommands** (`cost`, `context-distribution`, `context-composition`, `edit-format`, `read-scope`, `cache-efficiency`, `cost-trend`, `cache-rebuild`, `plan-boundary`, `instrument-authoring`, `pr-cost`). They redact project names and session IDs, already have a manual `--no-redact` opt-in, and the parity argument in mechanism 1 is weaker for session IDs, which are not repo-identity-bound.
- **Any change to `_resolve_cost_roots`, `_repo_scoped_project_slugs`, or `main()`'s top-level `--config-dir` refusal.** All three are correct and out of scope.
- **A narrowing scope flag or a `--summary`-style aggregate mode** for these two subcommands. It would drop the per-branch and per-agent-type dimensions the measurement exists to read.
- **`--per-session` under `--this-repo`.** Deliberately left refused per mechanism 9, not merely unaddressed.
- **Column-width changes for the `Branch` and `AgentType` fields.** Per mechanism 11. Revisit only if the ragged output actually proves unreadable in practice.
- **Cross-run label stability.** Disclosed labels are stable by construction; opaque placeholder numbering shifts between a `--this-repo` run and a non-`--this-repo` run, because allowlisted and attested values no longer consume counter positions. `_assign_root_scoped_redact_label`'s docstring already scopes placeholder stability to a single run, so no new guarantee is being broken.
