# Shrink PR #351 to dispatch-id only — drop the hook file-read guard

## Context

PR #351 (`feat/check-runner-dispatch-id-read-guard`) shipped two layered changes on top of `check-runner` after the Incident-6 prose-drift event: (1) a **dispatch-id contract** binding spool identity to a parent-supplied UUID; (2) a **hook file-read guard** denying `cat|head|tail|less|more|view|grep|awk|sed|rg|fd|find -print|-exec` inside the check-runner subagent, with a positive-match carve-out regex for the per-command-template `tail -<N> "$SPOOL"` shape. Reviewing the implemented branch against the check-runner design docs (`docs/design-decisions.md §10`, `docs/case-studies/check-runner.md`) makes the second layer read as the compounding-defensive-layers tell those very docs name as a wrong-foundation signal: stacking command-string regexes on a hook whose own header comment admits its bypasses (`c''at`, `python3 -c`) is the exact pattern §10 says is the wrong instrument. The dispatch-id, by contrast, is a single short primitive — one UUID threaded through three files as a filename prefix and verdict echo — and gives the parent a deterministic spool-recovery handle that doesn't require trusting agent-emitted verdict text. **Intended outcome:** PR #351 ships dispatch-id only; the hook file-read guard and its tests revert; `docs/case-studies/check-runner.md` Incident 6 updates to record dispatch-id as the sole structural fix; the failure-tail in the verdict stays (a separate concern, deferred deliberately).

## Approach

Two reverts and one doc edit on the open branch — additive `git revert` commits, not a force-push:

1. **Revert hook file-read guard** (`claude/.claude/hooks/check-runner-bash-guard.sh`): the `GLOBAL_FILE_READ_PATTERNS` array, the `deny_file_read` function, the per-command-template carve-out regex, the file-read header comment, and the known-gaps note about shell-quoting / scripting-language bypasses all go. `GLOBAL_DENY_PATTERNS`, the project-layer extension, the git-allowlist arm, and the `agent_type == "check-runner"` discriminator stay — those are unchanged pre-existing arms.
2. **Revert agent-side enforcement prose** (`claude/.claude/agents/check-runner.md`, line 35 paragraph): the "Hook-enforced read restriction" paragraph reverts to the pre-c6d99b6 prose ("Never read back the spool in a separate Bash call. Never locate a spool file with a glob or `ls` pattern..."). The Dispatch-ID paragraph (line 15), the template-line change at line 26 (`<dispatch-id>-<slug>-${EPOCH}.txt`), and the dispatch-id verdict-field bullet (line 47) all stay.
3. **Revert hook tests** (`claude/.claude/hooks/tests/test_check_runner_bash_guard.py`): the `TestFileReadDenies` class from c6d99b6 and the file-read test additions in 9da7ee3 (less/more/view, egrep/fgrep, fd, find -exec, the `then tail` carve-out cases) revert. Pre-existing tests on the git-allowlist, mutation-pattern, and project-layer arms stay.
4. **Update case-study Incident 6** (`docs/case-studies/check-runner.md`): rewrite the resolution to record only the dispatch-id contract as the structural fix. Per `claude/.claude/CLAUDE.md` Axis 3, the postmortem-record exception lists "historical incident records" as read-only — but the explicit exception is correcting a record that documented the wrong fix. Note dispatch-id was kept, the hook read-guard was withdrawn, and the failure-tail-in-context issue is a known live concern deferred to a future plan.

### Rationale

- **§10 explicit guidance:** *"Stacking command-string regexes is the compounding-defensive-layers tell ... The durable fix was always to change what the agent is, not to filter what it is handed."* The hook's `GLOBAL_FILE_READ_PATTERNS` array (5 patterns + 1 carve-out regex + 2 acknowledged-bypass categories in the header comment) is exactly the shape §10 says is the wrong instrument.
- **Agent-prose authoritative-home:** `check-runner.md` already states *"Never read back the spool in a separate Bash call. Never locate a spool file with a glob or `ls` pattern."* The hook duplicates that constraint imperfectly (admitted shell-quoting + scripting-language bypasses) and creates two sources of truth for the same rule. Per `claude/.claude/CLAUDE.md` "Single source of truth," the prose is the natural locus.
- **Dispatch-id is a light primitive:** one UUID, used as filename prefix, echoed back in verdict. No regex, no carve-out, no project-layer extension. The parent's recovery instrument (`ls "${TMPDIR:-/tmp}/<dispatch-id>"-*.txt`) is deterministic because UUIDs don't collide, even across concurrent sessions — which resolves the Incident-4 stale-glob problem more cleanly than any prose rule could.
- **Failure tail stays in the verdict** by deliberate choice: §10 closes with *"What check-runner adds is a curated verdict — per-command pass/fail plus the failure tail ... It earns its place as a signal-quality and verdict-ergonomics tool."* Removing the failure tail would collapse check-runner toward "subprocess that emits a spool path" and lose its signal-quality justification. The risk that haiku free-forms against in-context failure tails is real (the original-plan diagnosis named it), but the recovery primitive — read the spool the verdict mentioned, or `ls` the dispatch-id glob if the verdict text is garbled — is now deterministic. If a verdict-shape constraint becomes warranted, that is a separate foundational plan and gets its own ticket.

### Lighter alternatives considered

The current PR is the heavier instrument among these (it adds both dispatch-id and the hook layer). The lighter alternatives considered:

- **Dispatch-id only** *(this plan's choice)* — keeps the parent-side deterministic spool primitive; trusts agent prose against free-form drift; failure tails stay in verdict. Lightest instrument that closes Incident-4's stale-glob and gives Incident-6 a recovery handle without compounding the hook.
- **Agent prose only, no dispatch-id** — even lighter. Rely entirely on existing "Never read back the spool / never glob" prose plus mtime-newest spool lookup. Set aside because Incident 4's concurrent-sessions case can produce same-slug spools at near-identical mtimes; the UUID prefix eliminates that ambiguity at near-zero cost.
- **Revert PR #351 entirely** — lightest. Set aside because Incident 6 was a real event, the agent prose alone didn't fence it, and the dispatch-id (without the hook layer) is the smallest instrument that gives the parent a recovery primitive immune to verdict-text drift.

### Branch handling

The branch name `feat/check-runner-dispatch-id-read-guard` includes "read-guard" which the shipped diff no longer matches. Two options the user picks at execution time:
- **Add revert commits, keep branch name** (recommended): two `git revert` commits land on the branch; PR history honestly shows the design-trajectory; branch name remains misleading but is unlikely to be referenced after merge.
