# Design-decision SSOT duplication check

## Context

Add a cross-file single-source-of-truth duplication check to the code-review pipeline, covering record-style markdown docs (decision records, ADRs, RFCs, postmortems) that restate normative rules already stated canonically in another file, instead of citing them. The motivating case is `docs/design-decisions/round3-consult-verdict-routing.md`, which restated `code-review/SKILL.md`'s verdict-routing and spawn-obligation rules near-verbatim instead of citing them per `.claude/rules/citation-grammar.md`. The same prose defects were independently re-flagged by `comment-discipline-reviewer` across multiple review rounds. Only an Opus-level `plan-architect` consult caught the duplication itself; the ordinary review loop never did. The intended outcome is to catch this pattern earlier and cheaper than an architect consult, without weakening the existing comment-discipline bar.

## Approach

Add the check as a **new review angle in `comment-discipline-reviewer`**, and make that angle reachable from the two surfaces that currently cannot see it: a routing row in `code-writer`'s self-review domain table (earliest catch, authoring-time, zero dispatch cost) and a one-line index bullet under `code-review/SKILL.md`'s existing item 12a. No new checklist item, no new Change-type row, no new reviewer agent, no lexical-duplication test. The angle's wording lives once, in the agent file. Its design is stated once, in "How the check locates the canonical home". Every other surface is a pointer to it or a distinct face of it (authoring convention vs. review predicate). The one index duplication the design knowingly creates is pinned by a test so it cannot drift.

The prior decision this must clear is `docs/design-decisions/single-source-of-truth-rule.md`, which rejected a `/code-review` checklist item because it "would be a second copy of an always-loaded rule on a surface that can drift from it," while accepting item 9 (repeated logic) as an operationalization of the same principle for code. This plan takes the item-9 route, not the rejected one: the angle states a **named surface**, a **named predicate**, and a **named remedy**, all defined in "How the check locates the canonical home". None of those three facts appears in CLAUDE.md's single-source-of-truth bullet, so the angle is new information rather than a second copy. `single-source-of-truth-rule.md` is **not** superseded and is not edited.

### Assumption ledger

**Root problem.** A record-style markdown doc (the motivating case is a `docs/design-decisions/*.md` file) that restates a normative rule stated canonically in another file is currently invisible to every review surface: `code-writer`'s self-review table has no route to any prose reviewer, `comment-discipline-reviewer`'s six angles all pass a restatement cleanly, and no test checks it — so the defect is detectable today only by an Opus-level `plan-architect` consult, and each surviving copy re-attracts the same prose findings independently on every later round.

**Givens** (conditions the design treats as fixed, beyond its own reach):

- **G1.** No include/partial/extends mechanism exists for skill or agent bodies, so a single angle statement cannot be textually shared across the agent file, the rule file, and the skill's checklist index. *Reason: the platform provides no such field* — `.claude/rules/skill-and-agent-self-review.md` § "Skill and rule authoring conventions". Every additional surface is therefore a pointer or a distinct face, never a shared fragment.
- **G2.** `comment-discipline-reviewer`'s Change-type row does not spawn during staged-diff commit-gate rounds; its exhaustive pass runs once per branch in `ready-for-review`'s cumulative review. *Reason: another decision owns it* — `docs/design-decisions/comment-discipline-reviewer-deferred-to-cumulative-pass.md`, landed in `83174e5a`. Reversing it would need dispatch-economics evidence this plan does not have.
- **G3.** The `docs/design-decisions/` corpus holds no current instance of the defect — both dedupe commits already landed — so no in-corpus regression fixture exists. *Reason: dissolving this needs a decision outside the plan*; re-introducing a violation to test against is not an option.

**Rows:**

The locate-the-canonical-home question is therefore answerable inside the agent's existing tool grant — no new tool, no author-supplied target, no new agent.

**Mechanisms:**

- **M1 — New angle `Restated canonical rule` in `comment-discipline-reviewer`.** `anchors: root`. The agent already has record-style docs in scope as "doc files," is already dispatched by the existing Change-type row on any diff touching one, already holds the corpus-search tools (row 1), and its How-to-work step 4 already prescribes the enumerate-every-site sweep whose absence was the motivating incident's actual cost. Adding an angle costs no new dispatch.
- **M2 — Widen the agent's framing sentence and `description` Focus list to name §Engineering Judgment's single-source-of-truth bullet alongside §Code Comments.** `anchors: row2`. This is the heaviest mechanism adopted (a charter change), so two lighter primitives were checked and rejected:
  - **File the angle under the existing "Prose at the wrong altitude" angle.** Altitude is about reader and placement, and its prescribed fix is relocation. A restatement can sit at exactly the right altitude in the wrong file, and its fix is replacement-by-citation. Folding them would blur two angles with different remedies.
  - **File it under "Survives-the-PR self-test".** That test asks whether a paragraph is self-contained without PR context. A near-verbatim restatement passes it perfectly, which is why the motivating defect survived multiple rounds.

  A dedicated new reviewer agent is *heavier*, not lighter: new dispatch, new findings file, new roster row, new per-commit cost.
- **M3 — One routing row in `code-writer`'s self-review table: durable in-repo docs (any markdown file) → `comment-discipline-reviewer`.** `anchors: root, row8`. Pure routing, zero content: step 4 of the self-review pass ("mine each reviewer file for its review angles") then picks up every angle automatically and forever, with no second copy. This is the earliest and cheapest catch point in the pipeline — inside the authoring agent's own context, before any dispatch — and is the direct answer to catching the defect earlier and cheaper than an architect consult.
- **M4 — A one-line bullet for the new angle under `code-review/SKILL.md` item 12a.** `anchors: row9`. Index maintenance, matching the existing one-line bullets. No new numbered checklist item (the shape `single-source-of-truth-rule.md` rejected) and no new Change-type row (the existing comment/durable-doc row already matches every design-decision-doc diff and already dispatches the agent — a second row would be the over-powered primitive). The Item-ownership row for 12a needs no edit: `comment-discipline-reviewer` is already its primary owner.
- **M5 — A test pinning item 12a's bullet list to the agent's angle headers.** `anchors: row9`. M4 knowingly creates one duplication; this makes it mechanically non-driftable, which is what licenses it. Repo precedent for exactly this move: `test_rule_file_filename_grammar_matches_enforced_regex` and `test_rule_file_closed_legacy_upper_bound_matches_module_constant` pin `.claude/rules/design-decisions.md` to the enforcing constants, and `test_ready_for_review_shares_the_same_literal` pins a deliberately duplicated line. Two lighter primitives were rejected:
  - **Reciprocal pointer comments in both files.** Comments do not fail CI.
  - **Omit the 12a bullet entirely so there is nothing to pin.** That leaves the index stale, and the index is what the orchestrator reads on the rounds where G2 keeps the agent unspawned.
- **M6 — One authoring bullet in `.claude/rules/design-decisions.md`: a decision record cites the rule's canonical home and records only why the rule exists; it does not restate the rule.** `anchors: root, row5`. The rule file is currently silent on content entirely. Per `ai-instruction-and-memory-files/SKILL.md` § "Where does a given rule belong?", a rule that applies whenever a specific path pattern is open routes to `.claude/rules/*.md` — lazy-loaded, no always-loaded budget. This is the only surface that fires at the keystroke for a **human** author or a session writing the doc inline; M3 covers only the `code-writer` path. It states the authoring convention and a pointer; the predicate and remedy stay in M1. Given G1, these two faces cannot share a fragment, and this is the plan's highest-risk row for a "you just made two copies" reading — keep the bullet to convention + pointer, never the predicate.
- **M7 — A new `docs/design-decisions/<slug>.md` recording this choice.** `anchors: row3`. Without it, `single-source-of-truth-rule.md` reads as still standing against this change. The record must state that the angle operationalizes rather than supersedes, cite `single-source-of-truth-rule.md` by relative link per the directory's convention, and cite — never restate — the angle. It is the plan's own dogfood test of M1.

**Rejected outright, with reasons on the record:**

- **Un-deferring the Change-type row for design-decision docs** — see G2. The incident's cost profile does not argue for it either. The defect was authored once and then survived, so what failed was authorship-time discipline and the total absence of any angle, not the reviewer's dispatch frequency. Per-commit dispatch of a nonexistent angle catches nothing. M3 plus the once-per-branch cumulative pass catches it before human handoff, which is already far earlier than a round-3 consult.
- **A fifth Step 1.5 inline tripwire** — the lighter per-commit alternative to un-deferring, and still rejected. All four existing tripwires fire on a self-evident diff surface decidable from the diff alone (a suppression token, an out-of-scope path, a bare literal, a comment narrating history). "This paragraph restates a rule stated canonically elsewhere" requires locating a candidate home across a multi-file corpus, so putting it in the unconditional inline list imposes a multi-grep search on **every** commit for a rarely-firing defect class — the exact cost profile G2's deferral exists to avoid. Step 1.5 stays untouched.
- **A mechanical lexical-duplication test** (shingle or n-gram overlap between design-decision docs and the skill corpus) — rejected for three independent reasons:
  - The predicate is semantic. The near-verbatim shape is catchable and the paraphrased shape is not, so the test would license paraphrase as the evasion. A paraphrased restatement is the same defect.
  - Legitimate short quotation is the corpus norm. Every citation quotes the target's exact heading text, and `## Sources` sections quote section names. Any threshold low enough to catch a restated two-sentence rule fires on citations.
  - Per row 6, no threshold can be grounded here. Testing a proxy without measuring its over-accept and under-accept behavior first is the failure shape this repo has hit before.
- **Routing `docs/design-decisions/*.md` to `ai-instruction-and-memory-files`** (which already owns "duplication" for instruction files) — genre mismatch: that skill's entire body reasons about always-loaded context budget, per-session cost, and the 200-line cap, none of which applies to a record found by `git grep`. Its own `description` excludes non-instruction surfaces deliberately.

### How the check locates the canonical home

The angle's scope is record-style docs, with instruction surfaces exempt for row 4's reason (the exempt list lives in the agent's "Restated canonical rule" angle). Its predicate is a paragraph stating a normative rule in the imperative where the same rule is stated canonically in another file. Its remedy is to cite the file and heading holding the rule, in the repo's own citation form, keeping the record's own content.

Locating the home is a bounded search inside the agent's existing grant (row 1), in three steps, and no finding without a located home:

1. **Read the files the doc itself names.** A doc restating a rule almost always already names the canonical file in its body or a sources section — the motivating file names `claude-skills/skills/code-review/SKILL.md` in both. `Read` alone covers this step.
2. **Where the doc names no file,** `Glob` for whichever instruction surfaces the repo has, then `Grep` the rule's distinctive two-to-four-word noun phrase across them. One or two greps, not a corpus read. No repo-specific path is baked into the angle, because the agent stows to every consumer.
3. **Where neither finds a home, there is no finding** — the doc *is* the canonical home, which is the legitimate and common case.

The angle must require the finding to name the file and heading it located, cited in the repo's own citation form, mirroring item 6's "Check with grep before flagging" discipline. Step 3's fail-open is what keeps a precision-sensitive angle from becoming a false-positive machine on a corpus that already leans toward citation by convention. The angle goes **last** in the angle list and stays at about a dozen lines, so the agent's `effort: medium` pass runs the six established angles before it and the existing comment-discipline bar is not crowded.

### Dispatch split

**One `code-writer` dispatch, not phased.** The exact angle header literal and the angle's definition are shared state that both the agent edit and the 12a/test edits consume; splitting would force that context to be restated in every prompt, which `plan-it` Step 5 names as the do-not-split condition. Six files, one sequenced dispatch.

## Out of scope

- **Flagging instruction surfaces** — the surfaces exempted in the agent's "Restated canonical rule" angle. They fall under §Engineering Judgment's named exception for instructional prose that must stand alone, and `.claude/rules/skill-and-agent-self-review.md`'s no-shared-partials rule requires each to stand alone; flagging them would contradict a standing decision. Widening the angle to README sections or `REFERENCES.md` is a separate change with its own false-positive profile.
- **Reversing G2's deferral**, for this angle or any other. See G2 for why the plan deliberately does not make that change.
- **Any mechanical lexical-duplication test** and any hook enforcing the angle. Rejected on the three grounds under "Rejected outright"; revisitable only with a measured corpus overlap distribution behind a grounded threshold.
- **Editing `docs/design-decisions/single-source-of-truth-rule.md`** to add a forward pointer to M7's record. It is not superseded, so the in-place supersession convention does not apply, and Axis 3 makes a preserved record read-only absent a ticket asking. The directory's established citation direction is backward; M7 cites it.
- **Adding `comment-discipline-reviewer` to `code-review/SKILL.md`'s Domain-routing block or the dispatcher's per-file-type routes.** The existing Change-type row already dispatches it on every design-decision-doc diff; a second route is the over-powered primitive.
- **Fixing the pre-existing gap** that `code-writer`'s domain table maps no row to `ciso-reviewer` for documentation-only diffs carrying private-project-identifying prose. Noticed while reading the table; a real observation, distinct defect, raise separately rather than bundle.
