# Design-decision SSOT duplication check

## Context

Add a cross-file single-source-of-truth duplication check to the code-review pipeline, scoped to `docs/design-decisions/*.md` files that restate normative rules already stated canonically in a skill file (e.g. `code-review/SKILL.md`), instead of citing them per `.claude/rules/citation-grammar.md`. On merged branch `round3-gate-executable-plan` (PR #1029), `docs/design-decisions/round3-consult-verdict-routing.md` restated `code-review/SKILL.md`'s verdict-routing and spawn-obligation rules near-verbatim, causing the same prose defects to be independently re-flagged by `comment-discipline-reviewer` across multiple review rounds and requiring two separate "dedupe" commits (`444df592`, then `42786801`) months apart on the same file — the duplication itself was only ever caught by an expensive Opus-level `plan-architect` consult, never by the ordinary review loop. The intended outcome is to catch this pattern earlier and cheaper than an architect consult, without weakening the existing comment-discipline bar.

## Approach

Add the check as a **seventh review angle in `comment-discipline-reviewer`**, and make that angle reachable from the two surfaces that currently cannot see it: a routing row in `code-writer`'s self-review domain table (earliest catch, authoring-time, zero dispatch cost) and a one-line index bullet under `code-review/SKILL.md`'s existing item 12a. No new checklist item, no new Change-type row, no new reviewer agent, no lexical-duplication test. The angle's content is stated once, in the agent file; every other surface is a pointer to it or a distinct face of it (authoring convention vs. review predicate), and the one index duplication the design knowingly creates is pinned by a test so it cannot drift.

The prior decision this must clear is `docs/design-decisions/single-source-of-truth-rule.md`, which rejected a `/code-review` checklist item because it "would be a second copy of an always-loaded rule on a surface that can drift from it," while accepting item 9 (repeated logic) as an operationalization of the same principle for code. This plan takes the item-9 route, not the rejected one: the angle states a **named surface** (`docs/design-decisions/*.md`), a **named predicate** (a normative imperative also stated in a canonical rule surface), and a **named remedy** (replace with a `` `target` § "Heading" `` citation per `.claude/rules/citation-grammar.md`, keeping only the decision-record content). None of those three facts appears in CLAUDE.md's single-source-of-truth bullet, so the angle is new information rather than a second copy. `single-source-of-truth-rule.md` is **not** superseded and is not edited.

### Assumption ledger

**Root problem.** A `docs/design-decisions/*.md` file that restates a normative rule stated canonically in a skill, agent, rule, or CLAUDE.md file is currently invisible to every review surface: `code-writer`'s self-review table has no route to any prose reviewer, `comment-discipline-reviewer`'s six angles all pass a restatement cleanly, and no test checks it — so the defect is detectable today only by an Opus-level `plan-architect` consult, and each surviving copy re-attracts the same prose findings independently on every later round.

**Givens** (conditions the design treats as fixed, beyond its own reach):

- **G1.** No include/partial/extends mechanism exists for skill or agent bodies, so a single angle statement cannot be textually shared across the agent file, the rule file, and the skill's checklist index. *Reason: the platform provides no such field* — `.claude/rules/skill-and-agent-self-review.md` § "Skill and rule authoring conventions". Every additional surface is therefore a pointer or a distinct face, never a shared fragment.
- **G2.** `comment-discipline-reviewer`'s Change-type row does not spawn during staged-diff commit-gate rounds; its exhaustive pass runs once per branch in `ready-for-review`'s cumulative review. *Reason: another decision owns it* — `docs/design-decisions/comment-discipline-reviewer-deferred-to-cumulative-pass.md`, landed in `83174e5a`. Reversing it would need dispatch-economics evidence this plan does not have.
- **G3.** The `docs/design-decisions/` corpus holds no current instance of the defect — both dedupe commits already landed — so no in-corpus regression fixture exists. *Reason: dissolving this needs a decision outside the plan*; re-introducing a violation to test against is not an option.

**Mechanisms:**

- **M1 — Seventh angle `Restated canonical rule` in `comment-discipline-reviewer`.** `anchors: root`. The agent already has `docs/design-decisions/*.md` in scope as "doc files," is already dispatched by the existing Change-type row on any diff touching one, already holds the corpus-search tools (row 1), and its How-to-work step 4 already prescribes the enumerate-every-site sweep whose absence was the motivating incident's actual cost. Adding an angle costs no new dispatch.
- **M2 — Widen the agent's framing sentence and `description` Focus list to name §Engineering Judgment's single-source-of-truth bullet alongside §Code Comments.** `anchors: row2`. This is the heaviest mechanism adopted (a charter change), so two lighter primitives were checked and rejected: **(i) file the angle under the existing "Prose at the wrong altitude" angle** — rejected because altitude is about reader/placement and its prescribed fix is relocation, whereas a restatement can sit at exactly the right altitude in the wrong file and its fix is replacement-by-citation; folding them would blur two angles with different remedies. **(ii) File it under "Survives-the-PR self-test"** — rejected because that test asks whether a paragraph is self-contained without PR context, and a near-verbatim restatement passes it perfectly, which is precisely why the motivating defect survived multiple rounds. A third option, a dedicated new reviewer agent, is *heavier* not lighter: new dispatch, new findings file, new roster row, new per-commit cost.
- **M3 — One routing row in `code-writer`'s self-review table: durable in-repo docs (doc files, `docs/design-decisions/*.md`, README sections, `REFERENCES.md`) → `comment-discipline-reviewer`.** `anchors: root, row8`. Pure routing, zero content: step 4 of the self-review pass ("mine each reviewer file for its review angles") then picks up all seven angles automatically and forever, with no second copy. This is the earliest and cheapest catch point in the pipeline — inside the authoring agent's own context, before any dispatch — and is the direct answer to catching the defect earlier and cheaper than an architect consult.
- **M4 — A seventh one-line bullet under `code-review/SKILL.md` item 12a.** `anchors: row9`. Index maintenance, matching the six existing one-line bullets. No new numbered checklist item (the shape `single-source-of-truth-rule.md` rejected) and no new Change-type row (the existing comment/durable-doc row already matches every design-decision-doc diff and already dispatches the agent — a second row would be the over-powered primitive). The Item-ownership row for 12a needs no edit: `comment-discipline-reviewer` is already its primary owner.
- **M5 — A test pinning item 12a's bullet list to the agent's angle headers.** `anchors: row9`. M4 knowingly creates one duplication; this makes it mechanically non-driftable, which is what licenses it. Repo precedent for exactly this move: `test_rule_file_filename_grammar_matches_enforced_regex` and `test_rule_file_closed_legacy_upper_bound_matches_module_constant` pin `.claude/rules/design-decisions.md` to the enforcing constants, and `test_ready_for_review_shares_the_same_literal` pins a deliberately duplicated line. Two lighter primitives rejected: **(i) reciprocal pointer comments in both files** — comments do not fail CI; **(ii) omit the 12a bullet entirely so there is nothing to pin** — leaves the index stale, and the index is what the orchestrator reads on the rounds where G2 keeps the agent unspawned.
- **M6 — One authoring bullet in `.claude/rules/design-decisions.md`: a decision record cites the rule's canonical home and records only why the rule exists; it does not restate the rule.** `anchors: root, row5`. The rule file is currently silent on content entirely. This is the only surface that fires at the keystroke for a **human** author or a session writing the doc inline; M3 covers only the `code-writer` path. It states the authoring convention and a pointer; the predicate and remedy stay in M1. Given G1, these two faces cannot share a fragment, and this is the plan's highest-risk row for a "you just made two copies" reading — keep the bullet to convention + pointer, never the predicate.
- **M7 — A new `docs/design-decisions/<slug>.md` recording this choice.** `anchors: row3`. Without it, `single-source-of-truth-rule.md` reads as still standing against this change. The record must state that the angle operationalizes rather than supersedes, cite `single-source-of-truth-rule.md` by relative link per the directory's convention, and cite — never restate — the angle. It is the plan's own dogfood test of M1.

**Rejected outright, with reasons on the record:**

- **Un-deferring the Change-type row for design-decision docs** — G2 owns that decision, and the incident's cost profile does not argue for it: the defect was authored once and then survived, so what failed was authorship-time discipline and the total absence of any angle, not the reviewer's dispatch frequency. Per-commit dispatch of a nonexistent angle catches nothing; M3 plus the once-per-branch cumulative pass catches it before human handoff, which is already far earlier than a round-3 consult.
- **A fifth Step 1.5 inline tripwire** — the lighter per-commit alternative to un-deferring, and still rejected. All four existing tripwires fire on a self-evident diff surface decidable from the diff alone (a suppression token, an out-of-scope path, a bare literal, a comment narrating history). "This paragraph restates a rule stated canonically elsewhere" requires locating a candidate home across a multi-file corpus, so putting it in the unconditional inline list imposes a multi-grep search on **every** commit for a rarely-firing defect class — the exact cost profile G2's deferral exists to avoid. Step 1.5 stays untouched.
- **A mechanical lexical-duplication test** (shingle or n-gram overlap between design-decision docs and the skill corpus) — three independent reasons. The predicate is semantic: the near-verbatim shape is catchable, the paraphrased shape is not, and a paraphrased restatement is the same defect, so the test would license paraphrase as the evasion. Legitimate short quotation is the corpus norm — every citation quotes the target's exact heading text and `## Sources` sections quote section names — so any threshold low enough to catch a restated two-sentence rule fires on citations. And per row 6 no threshold can be grounded here. Testing a proxy without measuring its over-accept and under-accept behavior first is the failure shape this repo has hit before.
- **Routing `docs/design-decisions/*.md` to `ai-instruction-and-memory-files`** (which already owns "duplication" for instruction files) — genre mismatch: that skill's entire body reasons about always-loaded context budget, per-session cost, and the 200-line cap, none of which applies to a record found by `git grep`. Its own `description` excludes non-instruction surfaces deliberately.

### How the check locates the canonical home

Bounded search inside the agent's existing grant (row 1), in three steps, and no finding without a located home:

1. **Read the files the doc itself names.** A doc restating a rule almost always already names the canonical file in its body or `## Sources` — the motivating file names `claude-skills/skills/code-review/SKILL.md` in both. `Read` alone covers this step.
2. **Where the doc names no file,** `Grep` the rule's distinctive two-to-four-word noun phrase across `claude-skills/skills/**/SKILL.md`, `claude/.claude/agents/*.md`, `claude/.claude/CLAUDE.md`, and `.claude/rules/*.md`. One or two greps, not a corpus read.
3. **Where neither finds a home, there is no finding** — the doc *is* the canonical home, which is the legitimate and common case.

The angle must require the finding to name the specific `` `file` § "Heading" `` it located, mirroring item 6's "Check with grep before flagging" discipline. Step 3's fail-open is what keeps a precision-sensitive angle from becoming a false-positive machine on a corpus that already leans toward citation by convention. The angle goes **last** in the angle list and stays within the six-to-eight-line budget of its siblings, so the agent's `effort: medium` pass runs the six established angles before it and the existing comment-discipline bar is not crowded.

### Dispatch split

**One `code-writer` dispatch, not phased.** The exact angle header literal and the angle's four required elements are shared state that both the agent edit and the 12a/test edits consume; splitting would force that context to be restated in every prompt, which `plan-it` Step 5 names as the do-not-split condition. Five files, one sequenced dispatch.

## Out of scope

- **Widening the angle beyond `docs/design-decisions/*.md`** — to README sections, `REFERENCES.md`, or skill/agent bodies. Skill bodies are covered by §Engineering Judgment's named exception for instructional prose that must stand alone, and by `.claude/rules/skill-and-agent-self-review.md`'s no-shared-partials rule; flagging them would contradict a standing decision. A README or `REFERENCES.md` widening is a separate change with its own false-positive profile.
- **Reversing G2's deferral**, for this angle or any other. It is a change the plan could make and deliberately will not: reopening a decision that landed in `83174e5a` needs dispatch-economics evidence this plan does not have.
- **Any mechanical lexical-duplication test** and any hook enforcing the angle. Rejected on the three grounds in the Approach; revisitable only with a measured corpus overlap distribution behind a grounded threshold.
- **Editing `docs/design-decisions/single-source-of-truth-rule.md`** to add a forward pointer to M7's record. It is not superseded, so the in-place supersession convention does not apply, and Axis 3 makes a preserved record read-only absent a ticket asking. The directory's established citation direction is backward; M7 cites it.
- **Adding `comment-discipline-reviewer` to `code-review/SKILL.md`'s Domain-routing block or the dispatcher's per-file-type routes.** The existing Change-type row already dispatches it on every design-decision-doc diff; a second route is the over-powered primitive.
- **Fixing the pre-existing gap** that `code-writer`'s domain table maps no row to `ciso-reviewer` for documentation-only diffs carrying private-project-identifying prose. Noticed while reading the table; a real observation, distinct defect, raise separately rather than bundle.
