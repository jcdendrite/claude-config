# SCOPE_RULE causal-reach test uses regex heuristics instead of the model-based fidelity eval

## Context

The goal is to close a test-fidelity gap in `claude/.claude/skills/tests/test_skills.py`'s coverage of `SCOPE_RULE:` anchors. `test_scope_rule_region_states_causal_reach` verifies that the `SCOPE_RULE:code-review-staged-diff-only` clause reads as mandatory to the consuming model using hand-rolled regex heuristics over English prose (`_MANDATORY_MODAL_RE`, `_ADVISORY_DISQUALIFIER_RE`, `_NEGATION_DISQUALIFIER_RE`) — a materially weaker guarantee than the model-based disposition-fidelity eval (`evals/run_skill_evals.py`'s `extract_governing_rule()` / `run_disposition_case()`) that the `DISPOSITION_RULE:` namespace already gets. The `SCOPE_RULE:` anchor namespace is deliberately excluded from that eval today (`_extract_scope_anchor_region()`'s own docstring: reusing `extract_governing_rule()`'s `DISPOSITION_RULE:` prefix "would silently enroll a scope rule in the disposition-fidelity eval"). The test's own comments concede the regex approach is fragile — a benign reword ("stays" → "remains") can false-fail, and an unanticipated softening phrase can false-pass while genuinely weakening the guarantee — and two of the three regexes (`_MANDATORY_MODAL_RE`'s absence branch, `_ADVISORY_DISQUALIFIER_RE`'s positive-match branch) have no dedicated fixture test proving they catch what they claim to, unlike `_NEGATION_DISQUALIFIER_RE` (covered by `TestNegationDisqualifierMatchesBypassPhrasing`). Surfaced by `staff-sdet` during `/code-review` on PR #770's origin/main sync merge; tracked as issue #772 since the content originated on `main` via a separately-reviewed PR. The user has flagged a hard project constraint going in: CI cannot run the model-based evals because each sample bills real money off-subscription (`evals/README.md`'s "why local only — never CI" section), so whatever fix is chosen must keep a zero-cost, deterministic check as the thing CI actually gates on.

The intended outcome is a plan that closes the fidelity gap — via some combination of hardening the regex test's own coverage, enrolling `SCOPE_RULE:` in the (local-only, non-CI) model-based eval, and/or narrowing the pytest check to presence-only per `test_disposition_rule_anchors_present`'s Layer-1 precedent — reached with `plan-architect`'s judgment on the tradeoff, not a default assumption baked in here.

## Approach

Replace the prose-modality heuristics with an **exact-text pin on the smallest anchored region that is entirely normative**, and delete the regex apparatus outright. The deterministic CI-gated layer stops trying to *infer* that a clause reads as mandatory — a claim no zero-cost check can actually make — and instead guarantees that the exact clause a human already judged mandatory is still verbatim present and still nested inside its governing rule; any reword, softening or otherwise, fails loudly and shows up as a reviewer-visible diff in the same PR.

**root:** A normative clause inside a `SCOPE_RULE:` region can be silently reworded into weakness while every existing check (region presence, anchor-set exactness, 20-char minimum) still passes; the current defense against that is three hand-rolled regexes over English prose that are unsound in both directions, and the model-based eval that could genuinely test comprehension cannot be the CI gate.

**Mechanisms:**

- **M1 — Add `<!-- SCOPE_RULE:code-review-causal-reach start/end -->` inline around the single causal-reach sentence in `code-review/SKILL.md:32`.** *anchors: row4* — the clause ciso-reviewer required a dedicated content-level assertion for becomes independently extractable, which is what lets the pin target one sentence instead of a 2000-character region. Uses the `SCOPE_RULE:` prefix per row9 (free discovery) and the inline mid-paragraph form per row10 (established shape). This also removes `_sentences()` from the path entirely — the anchor *is* the extraction, retiring the naive splitter the code itself flags as fragile at `test_skills.py:2421-2424`.
- **M2 — Add `_PINNED_SCOPE_CLAUSES: dict[tuple[str, str], str]` mapping `(skill_name, marker_name)` to exact expected text, plus a `_normalized_anchor_text(skill_md_path, marker_name)` helper and one `pytest.mark.parametrize`d test over the table.** *anchors: root, row7* — one shape covering both sites; equality on normalized text (row8) is the strongest claim available under row2, and it is *sound*, unlike anything that infers modality. Two rows at ship time: `("code-review", "SCOPE_RULE:code-review-causal-reach")` and `("ready-for-review", "SCOPE_RULE:ready-for-review-cumulative-unnarrowed")` — the latter needs **no** SKILL.md edit, because its existing region already *is* the minimal entirely-normative unit (row11).
- **M3 — Delete `_CAUSAL_REACH_KEYWORDS`, `_MANDATORY_MODAL_TOKENS`, `_MANDATORY_MODAL_RE`, `_ADVISORY_DISQUALIFIER_RE`, `_NEGATION_DISQUALIFIER_RE`, `_sentences()`, `test_scope_rule_region_states_causal_reach`, and `TestNegationDisqualifierMatchesBypassPhrasing`.** *anchors: row5, row7* — strictly dominated by M2 and contained; leaving them would be a compounding defensive layer over a mechanism that already subsumes them, and would carry forward the "expect the disqualifier list to need broadening" maintenance debt the docstring concedes.
- **M4 — Generalize `test_scope_exempt_row_nested_within_outer_rule` into a parametrized test over a `(skill, inner_marker, outer_marker)` table covering both `SCOPE_EXEMPT_ROW` and the new causal-reach anchor, checking full containment (both inner start and inner end offsets) rather than the existing test's start-offset-only check.** *anchors: M1's introduction of a second nested anchor; root* — the pin alone would still pass if the anchored sentence were relocated *outside* the governing rule region, and CLAUDE.md's audit-structural-siblings rule requires abstracting once two arms share the shape rather than copy-pasting a second nesting test. `parametrize` is the file's dominant idiom (25+ existing uses). The existing test's start-only assertion has a real gap — an inner end marker that drifts outside the outer region while the start stays correctly nested passes silently (`staff-sdet` finding, `/plan-review` this session) — so the generalization also fixes this pre-existing hole in the pattern it's copying, not just the two new rows.
- **M4a — Add permanent fixture tests for `_normalized_anchor_text()`'s comparison machinery**, mirroring `TestExtractScopeAnchorRegion`'s branch-by-branch pattern. *anchors: M2* — an exact-equality assertion needs no fixture test for the pinned values themselves, but the normalization and comparison wiring around it does: a mismatched-text fixture proves the comparison actually fires, and a multi-line-reflow fixture proves the whitespace-collapsing (row8) actually normalizes reflowed text to match — neither is exercised by the live corpus today, since both live anchor regions currently sit on one unwrapped line (`staff-sdet` finding, `/plan-review` this session).
- **M5 — Add `("code-review", "SCOPE_RULE:code-review-causal-reach")` to `_EXPECTED_SCOPE_ANCHORS`.** *anchors: M1, row9* — the exact-set assertion at `test_skills.py:2361` fails otherwise; this is the entire integration cost of the new anchor.
- **M6 — Docstring on the new pinned test states two durable facts, one sentence each: (a) the pin is exact because a clause's mandatory-vs-advisory reading is not deterministically derivable from its text, and the model-based check that could derive it is local-only by cost; (b) on failure, re-read the guarantee and update the constant only if the new wording preserves it.** *anchors: row1, row2* — per CLAUDE.md §Code Comments, this must read for a contributor who never saw this PR: no narration of what the test previously did, no "Layer 1/Layer 2" shorthand unless spelled out, no plan or issue reference.

**Over-powered-primitive check (why not the model-based eval).** A scope-fidelity eval — a parallel local-only method spawning the real model against the scope rule with a scenario and judge rubric — is the heavier mechanism in play. Lighter primitives, from this repo's own machinery: (1) **exact pin on an anchored clause** — chosen; sound, zero-cost, CI-gateable, and it addresses the issue's actual defect (an unsound deterministic check) rather than a different question. (2) **Region-level presence plus minimum length** — already exists (`test_scope_rule_anchors_present`); fails because row4 rejected exactly that granularity for this clause. (3) **Regex modality heuristics** — the incumbent; fails per row6/row7. The eval fails on top of all three for a distinct reason: under row1 it cannot be what CI gates on, so it could only ever *supplement* the deterministic check, never replace it — it would not remove one line of the mechanism this plan ships. It also answers a different question (does the model *behave* per the rule) than the issue's (is the rule's text still intact). Named as a deliberate non-fix in Out of scope rather than silently dropped.

**Alternatives set aside.** *Keep the regexes and add the missing fixture tests* (the issue's literal third option) — set aside on row7's dominance argument; investing in fixture coverage would raise confidence in an apparatus whose every true positive M2 already catches, while its two documented error classes survive. *Narrow to presence-only per `test_disposition_rule_anchors_present`* (the issue's second option) — set aside on row4; note that M2 *is* a presence check, just at sentence granularity instead of region granularity, which is precisely the gap ciso-reviewer identified. *A hook or lint policing reflexive updates of the pinned constant* — declined as a compounding defensive layer; row2 caps what enforcement can achieve here, and the reviewer-visible diff is the mechanism.

**Scope note on row11 (a reviewer could reasonably draw this line differently).** The issue scopes the *regex apparatus*, which lives only on the `code-review` side; CLAUDE.md's audit-structural-siblings rule scopes the *mechanism*, which has exactly two applicable sites. This plan takes the second reading because the marginal cost is one table row and one quoted constant with **no** second SKILL.md edit, and because shipping a one-instance mechanism plus a follow-up ticket is the more expensive path. Dropping the `ready-for-review` row is a clean one-line reduction if a tighter scope is preferred; it does not change any other part of the design.

**Dispatch split.** One `code-writer` dispatch. The SKILL.md anchor name (M1) is shared state with the test tables (M2, M4, M5), so splitting would mean restating the same anchor-naming context in every prompt and risking two agents resolving it differently — exactly the case `plan-it` Step 5 says not to split.

## Out of scope

- **A scope-fidelity model eval** (a `run_skill_evals.py` method parallel to `disposition-fidelity`, with its own scenario file and judge rubric, spawning the real model against the scope rule). Deliberate non-fix, not an oversight: under row1 it can never be the CI gate, so it would supplement rather than replace anything this plan ships, and it answers a different question — whether the model *behaves* per the rule, not whether the rule's text survived. Revisit only if scope-boundary *efficacy* (not text fidelity) becomes a live concern; if so, it should be its own eval method with its own anchor handling, and this plan deliberately does not rename or restructure anchors in anticipation of it.
- **Enrolling `SCOPE_RULE:` under `extract_governing_rule()`'s `DISPOSITION_RULE:` prefix.** Fixed by row3; changing it would silently enroll a scope rule in the disposition-fidelity eval, the exact outcome the originating design excluded.
- **Fixture tests for `_MANDATORY_MODAL_RE`'s absence branch and `_ADVISORY_DISQUALIFIER_RE`'s positive-match branch.** The issue asks for these conditionally — "if the regex approach is kept regardless." It is not kept (M3), so the antecedent is false and writing them would mean testing deleted code.
- **Adding a causal-reach clause of its own to `ready-for-review`'s SCOPE_RULE region.** That region defers content to `code-review/SKILL.md` by design; restating the guarantee there would create a second copy to drift, against CLAUDE.md's single-source-of-truth rule. Its *deferral wording* is what this plan pins (row11), which is the right unit.
- **Pinning `docs/design-decisions.md:458`'s paraphrase of the causal-reach rule.** Knowingly left unpinned: that file is the rationale record, not the operative instruction the model reads, and pinning it would make a second text a source of truth to keep in sync with the first.
- **Extending the pin mechanism to `DISPOSITION_RULE:` regions.** Those already have a Layer-2 model-based eval and a documented deliberate choice not to assert exact text; the tradeoff that justifies a pin here (no Layer 2 exists, and none can gate CI) does not hold there.
- **Any hook or lint policing whether the pinned constant was updated thoughtfully.** Declined on the compounding-defensive-layers tell — row2 caps what enforcement can achieve, and adding a layer to guard the guard is the wrong-foundation shape.
- **Rewording the causal-reach sentence or the `ready-for-review` region prose.** Both are copied into the pin verbatim; changing them is a separate, deliberate act with its own review, not a side effect of this change.
