# Make the PR cost disclosure trustworthy (GH-870)

## Context

Make the `## Cost` block that `pr-description` embeds in PR bodies say only true things, and stop it dropping a model family on the floor. The block currently fails on four axes at once, all on one rendering path:

1. A locally-computed list-price estimate is presented under a heading that reads as an invoice.
2. Maintainer-only stderr diagnostics have reached public PR bodies verbatim, carrying raw API request IDs.
3. Three by-design stdout lines read to a PR reviewer as alarms when they are routine.
4. Fable — used on some projects — is absent from the price table, so every Fable turn is silently excluded from the dollar total.

This is worth fixing now because the block is published to reviewers who cannot check any of it, and because the excluded-Fable defect grows quietly as more work moves onto that family. The intended outcome is a Cost block a reviewer can read without being misled about what the number means, and a price table that announces its own gaps instead of hiding them.

A percentage-of-subscription-allotment mode was investigated and dropped: Anthropic publishes no seat-allowance denominator in tokens or dollars, and cross-project model-allocation tracking belongs to the `pr-cost --record` ledger rather than a per-branch PR body. The ledger's per-family column split is deferred to GH-871.

## Approach

Move every fact a PR reader needs about the cost figure into `cost.py`'s own stdout, change the *heading text* where the heading already lives (`pr-description/SKILL.md`), fix the one process boundary where maintainer stderr leaks into that stdout, and make excluded spend and format drift loud instead of silent. Concretely:

- `cost.py` starts emitting the caveat sentence in both render paths and stops emitting three by-design diagnostic lines under `--summary`.
- `pricing.py` gains Fable rates, a shared "is this unpriced ID real spend?" predicate, and a drift-detected flag.
- Two conditional banners, `EXCLUDED SPEND` and `PRICING INTEGRITY`, carry the facts the pruned lines and the discarded stderr used to carry.
- `pr-cost-section.sh` discards the child's stderr so a merged-stream caller cannot capture it.

**The engineer's four settled decisions**, cited by number throughout this plan:

1. No percentage-of-subscription-allotment mode. Anthropic publishes no seat-allowance denominator, so cross-project model-allocation tracking belongs to the `pr-cost --record` ledger rather than a per-branch PR body.
2. Relabel the block and add a one-line caveat, using the exact heading and sentence quoted in rows 1 and 2.
3. Prune three by-design noise lines from `--summary`: the per-root scan line, the branch-filter exclusion line, and the unconditional unpriced-tokens line.
4. Price Fable, and make the signal loud whenever real (non-`<synthetic>`) tokens are excluded from the total.

**Root problem.** The published `## Cost` block presents a locally-computed list-price estimate as if it were a bill, carries maintainer-only stderr diagnostics (including raw API request IDs) into public PR bodies, surfaces three by-design lines that read to a PR reviewer as alarms, and silently drops every Fable turn from the dollar total.

**Givens** (conditions this design treats as fixed, each beyond its own reach):

- **G1.** Anthropic publishes no seat-allowance denominator in tokens or dollars, so no percentage-of-allotment figure is computable from transcripts — the vendor owns that denominator and does not expose it. `[engineer-verified]` *(tag unchanged)*
- **G2.** The exact string in `message.model` is written by Claude Code, and `_MODEL_BASE_INPUT_RATES` matches it exactly (`dict.get`, no prefix/regex) — the harness owns that string, so a rate row is only correct if the string is observed, not inferred. `[verified: pricing.py:36-47, 116-120]` *(tag unchanged)*
- **G3.** The Bash tool returns merged stdout+stderr to the model as one blob; the harness owns that merge, so stream separation can only be enforced by the process that spawns the child. `[unverified]` — the merge is standard harness behavior but I did not measure it this session; Verification step 5 settles it. *(tag unchanged)*
- **G4.** Everything under `claude/` installs to every stow consumer, so "the user surface" is every consumer's PR readers, not this engineer's. `[verified: CLAUDE.md § "Working in this repo"]` *(tag unchanged)*

**Not a given: which artifact authors the `## Cost` heading.** `pr-description/SKILL.md` is this repo's own artifact and Dispatch 3 edits it, so heading ownership is inside this plan's reach, not a fixed condition. *(Tag change from the prior version: this row previously argued the design should strip the skill's last authored string and move the H2 into `cost.py`.
