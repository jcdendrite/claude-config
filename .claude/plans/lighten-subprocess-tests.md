# Lighten subprocess-only bash tests via lib extraction

## Context

The user hypothesized that many of this repo's (claude-config, a public repo of Claude Code hooks/skills/scripts) tests could be converted from heavy full-subprocess invocation to lighter-weight unit tests, where a cheaper in-process-style seam exists. The trigger was a deferred `staff-sdet` finding on a separate, still-open PR (#1025, branch `ci-watch-ghe-host-resolution` — NOT touched by this plan, per explicit user decision) that rationalized away adding a unit-test seam for a piece of pure boolean gate logic in `ci-watch.sh` by claiming "this file's pre-existing subprocess-only test convention" — with the caveat "no in-process unit-test seam exists for bash without extraction." The user found it concerning that an agent believed "subprocess-only" was this repo's convention.

Investigation this session confirmed: the "subprocess-only" claim is false as a repo-wide characterization. A real, working precedent already exists — `claude/.claude/scripts/_worktree-lib.sh` is a sourceable library of pure bash functions, unit-tested directly via `bash -c '. lib.sh; call_function'` in `claude/.claude/scripts/tests/test_worktree_lib.py`, entirely bypassing the heavier full-script/git/gh/direnv subprocess path. The same shape exists for `_stow_migration_lib.sh`/`test_stow_migration_lib.py`, and `claude/.claude/hooks/_lib.sh` has six of its own lib-level test files (`test_lib.py`, `test_lib_reviewer_round_state.py`, `test_lib_append_line_locked.py`, `test_lib_worktree_collision_guard.py`, `test_marker_lib.py`, `test_config_lib.py`).

However, that pattern is NOT written down anywhere — not in `claude/.claude/rules/shell-script-conventions.md` (the file that already governs shell script conventions and is loaded automatically for `**/*.sh` changes), not in `claude-skills/skills/test-conventions/SKILL.md` (the generic cross-language testing-conventions skill). Because it's undocumented, it gets reinvented or misjudged per file — exactly what produced the wrong "subprocess-only convention" claim on PR #1025.

The investigation also found the pattern is real but drastically underused:
- `claude/.claude/scripts/`: of 26 non-lib scripts, only 1 (`migrate-legacy-config.sh`) has even a partial/hybrid seam (sources itself via a `BASH_SOURCE` guard inside `bash -c`, not a true separate lib file). 24 of 26 are subprocess-only for every test case; 13 of those 24 have genuine, non-manufactured pure-logic extraction candidates.
- `claude/.claude/hooks/`: 48 hook files define 165 named functions (excluding trivial `emit_deny` wrappers) across 23 files. Only ONE function anywhere — `_mask_shell_quotes()` in `deny-invisible-commit-content.sh:248` — gets function-level unit testing outside `_lib.sh` itself, and it uses a more fragile mechanism than `_worktree-lib.sh`'s: `test_deny_invisible_commit_content.py:20-40` regex-extracts the function's source text out of the hook file at test time, then sources the extracted fragment plus `_lib.sh` in a `bash -c` subprocess. Its sibling function `_trim_fragment()` (same file, line 310) gets no such treatment at all. ~15 hooks have genuine extraction candidates by the same non-manufactured-candidate standard.

Intended outcome: (1) document the real pattern explicitly so it stops being reinvented/misjudged, standardizing on the clean `_*-lib.sh`-file-plus-direct-source shape rather than the fragile regex-extraction shape; (2) as concrete proof and actual debt paydown, extract and unit-test a bounded batch of the highest-value, cleanest candidates, spanning both `scripts/` and `hooks/`; (3) leave the remaining candidates as a documented backlog. This plan does not touch PR #1025 or its branch.

## Approach

Write the repo's existing bash unit-test seam down in two places — the general convention in the stowed shell rule, the claude-config-specific mechanics in a new project rule — and prove it with four extractions that each also pay down a named defect: a four-way duplicated function, a fragile regex-extraction test helper, an unseamed security check, and a twice-inlined path canonicalizer. Nothing in `claude/.claude/hooks/` gets a new `_*-lib.sh` sidecar file, because `test_hook_alignment.py` sweeps every `*.sh` in that directory as a hook; both hook-side extractions therefore land in the already-excluded `claude/.claude/hooks/_lib.sh`, and widening that sweep is deferred with the blocker named.
