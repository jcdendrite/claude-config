# Test suite unit/integration boundary and CI selective execution

## Context

Give claude-config's test suite an enforceable unit/integration boundary and decide, with primary-source grounding, whether CI's always-run-everything behavior should change. The engineer's working hypothesis was that the suite mixes unit and integration tests with no clear boundary, that a shared helper module forces a full-suite run on any edit, and that CI is "just not designed properly" for always running everything regardless of what changed — this plan exists to test that hypothesis against the actual code and the repo's own prior decisions before designing a fix, since discovery found two of the three suspected flaws are deliberate, documented tradeoffs rather than oversights. The intended outcome is a design that either closes a genuine gap or explains, with citations, why the current behavior is already the right tradeoff — not a reflexive "add more selectivity" change.

**Discovery findings (verified against the repo, not assumed):**

- `claude/.claude/tests/helpers.py` (1,165 lines) does mix two kinds of functions: pure, no-I/O input builders (`bash_input`, `edit_input`, `write_input`, etc.) and subprocess-spawning functions that invoke real hook scripts end-to-end (`run_hook`, `run_hook_advisory`, `run_skill_command`, etc.). It is imported by 95 test files across all 4 test domains (`hooks/tests/`: 79, `scripts/tests/`: 9, `skills/tests/`: 4, `plugins/lovable-cloud/tests/`: 3). No pytest marker or directory convention anywhere in the repo currently distinguishes unit from integration tests — the only registered marker (`pyproject.toml`) is `timing`, an isolation/performance marker unrelated to test tier.
- `select-tests.py` (`claude/.claude/scripts/select-tests.py`) already treats `helpers.py` as a `GLOBAL_TRIGGER_PATH`, by deliberate design, per its own comment: "imported by every domain's own test dir... this script's own table can't be trusted to correctly select tests for itself once changed." This is the plan built by `.claude/plans/selective-test-runs.md`, which explicitly scoped CI out: "Modifying CI's own gating... is out of scope; CI remains the unconditional full-suite backstop." A later plan, `select-tests-fallback-audit.md`, hardened that into a standing invariant: select-tests.py's skip-set must stay a *subset* of CI's skip-set, because select-tests.py has documented precision-not-recall gaps (some already found and fixed: containment-dedup bugs, cross-domain-read completeness gaps that are structurally undetectable in the general case).
- CI (`.github/workflows/tests.yml`) always runs the full suite (two passes: `-m "not timing"` parallel, `-m timing` serial) on every push/PR, gated only by a coarse deny-list regex (`SKIP_REGEX`) that skips only pure-docs/license changes. `select-tests.py` is explicitly documented (README, root `CLAUDE.md`) as local/agent-only, never invoked by CI. This is the same deliberate "CI is the backstop" design as above, not an independent oversight.
- A directly relevant prior rejection: `select-tests-handoff-drift.md` proposed inferring "did this diff really need a full run" by pattern-matching a command/diff against a canonical form; `/plan-review` rejected it as foundationally unsound because `CLAUDE.md`'s legitimate-full-suite-exception is an intent-based condition, not a machine-checkable predicate. Any design here that tries to *infer* full-suite necessity from diff shape, rather than using an explicit, auditable rule table (select-tests.py's existing model) or a structural correctness check, risks the same rejection.

**Primary-source research (via `verify-sources`), used to ground the design rather than reinvent it:**

- Every credible "affected"/selective-test-execution system either fails open on an incomplete signal or is a stronger correctness primitive than diff-heuristics: Turborepo's `--affected` treats a too-shallow checkout as "all packages... considered changed" (fail open); GitHub Actions' `paths` filter docs name an explicit fail-*closed* edge case (>3,000-file diffs) and separately warn that combining path-filtered required checks can deadlock a PR, i.e. GitHub's own docs caution against treating a path-filtered workflow as an unconditional sole gate; pytest-testmon's coverage.py-based selection inherits coverage.py's own documented blind spots (dynamic code, C extensions) as an undocumented false-negative risk, which is why it's positioned as a local dev-loop speedup, not a CI merge gate, in its own materials; Bazel's `--cache_test_results` is not diff-heuristic at all but content/action-hash based, a fundamentally stronger correctness primitive than any of the above, and Bazel's own docs name a race condition it does *not* fully close (concurrent input mutation) as a known caveat even for that stronger model. Nx's `affected` docs name scale (over-triggering on a widely-depended-on file) as the documented weak spot, not correctness.
- Google's "Test Sizes" post (Small/Medium/Large) gives a concrete, citable line for the unit/integration boundary: Small = no network, no database, no filesystem access, single-threaded, no subprocess; Medium = localhost-only network, database/filesystem allowed; Large = unrestricted. This maps directly onto `helpers.py`'s actual two halves — the pure input builders are unambiguously Small, the `run_hook*` subprocess-spawning functions are at least Medium.
- pytest's own official docs describe both directory-based conftest.py scoping and marker-based selection (`-m`) as general, supported mechanisms, but take no position on which one is the canonical way to keep a unit/integration boundary enforceable — confirmed absent, not assumed. Martin Fowler's TestPyramid.html doesn't address a shared helper spanning tiers; his UnitTest.html treats "no I/O" as a strong guideline for the sociable/solitary distinction, not an absolute rule.

**User's own framing on the two open design questions (verbatim):**

- On CI's full-suite-backstop invariant: "Can we take a step back and figure out what is standard practice here? Maybe /verify-sources?" — resolved by the research above; the user has not pre-committed to a specific option (selective / faster-but-full / hybrid) and wants the choice made from that grounding.
- On the `helpers.py` split: "I'm honestly not sure. What does plan-architect think? I feel like we don't need to reinvent the wheel and that this is already a solved problem. We just need to apply the standard principles." — delegated to the architecture design below, using the Google Test Sizes framing and pytest's documented mechanisms rather than a bespoke scheme.

## Approach

Both of the engineer's proposed fixes are rejected, and the one real gap they were reaching for is fixed instead. CI keeps running the full suite unconditionally on every push and PR — no path filter, no selective pre-check, no new job. `helpers.py` is not split, and its `GLOBAL_TRIGGER_PATHS` membership is not narrowed; the plan *strengthens* it with a regression test, because the third change makes it load-bearing for the first time. That third change is the actual work: `claude/.claude/tests/` becomes a selectable `select-tests.py` domain instead of a directory whose every edit falls open to the full suite through the unmatched-path branch — the narrowing `fix-conftest-module-collision.md` deferred with "Raise separately," and the one the discovery findings support.

### Why CI does not become selective

`select-tests.py` is a hand-authored path→domain table over a `git diff`. Making it CI's merge gate would put a table with documented precision-not-recall gaps in the position that today catches those gaps. Three quoted findings from Context, each pointing the same way:

- pytest-testmon is the closest analogue in the field — selection over a Python suite — and it carries a *stronger* signal than this repo has, coverage.py-measured per-test dependencies rather than a path table. Context records that it "inherits coverage.py's own documented blind spots (dynamic code, C extensions) as an undocumented false-negative risk, which is why it's positioned as a local dev-loop speedup, not a CI merge gate, in its own materials." A tool whose maintainers decline the merge-gate role for a stronger signal does not license a weaker one taking it.
- The only researched system that *does* skip work in a gating position is Bazel, and Context records that its `--cache_test_results` "is not diff-heuristic at all but content/action-hash based, a fundamentally stronger correctness primitive than any of the above," while "Bazel's own docs name a race condition it does *not* fully close (concurrent input mutation) as a known caveat even for that stronger model." Content hashing is the entry price for correct skipping. This repo has no such primitive and building one is not in scope.
- The systems that skip on a diff signal fail open when the signal is incomplete: Turborepo's `--affected` treats a too-shallow checkout as "all packages... considered changed," and Nx's documented weak spot is "over-triggering on a widely-depended-on file... not correctness." Both are calibrated to over-run. `select-tests.py` already matches that calibration; CI already is the over-run.

The repo-specific argument is sharper than any of those. Context records that GitHub's `paths`-filter docs "separately warn that combining path-filtered required checks can deadlock a PR, i.e. GitHub's own docs caution against treating a path-filtered workflow as an unconditional sole gate" — and `.github/workflows/tests.yml:1-7` states that the `tests` **job id** is exactly the status-check context branch protection requires on `main`. The current workflow already solves this, deliberately: it gates *steps* with `if: steps.detect.outputs.changed == 'true'`, so the job always runs and always reports, and a docs-only PR reports green rather than reporting nothing. A workflow-level `paths:` filter is the shape GitHub warns about and it is already avoided. Any selectivity added here would have to preserve that step-level shape, which means the runner, the checkout, `pip install -r requirements-dev.txt` and the apt `stow` install are paid regardless — the fixed cost, not the test wall-clock, is what a selective CI would leave untouched.

The hybrid (fast selective pre-check plus full gate) is rejected on top of that: it produces no information the full gate does not already produce, cannot fail a merge, and pays a second job's fixed cost to learn a subset of what the first job learns. It is also the compounding-defensive-layer shape — a second layer whose only job is to compensate for the first being slow.

Nothing changes about CI's *cost* either. `.github/workflows/tests.yml:26-43` records that the two-pass split (parallel `-m "not timing"`, serial `-m timing -n0`) replaced a single invocation measured at ~4m7s and is "not yet re-measured end to end here." Choosing a shard count or a matrix width against an unmeasured baseline would be a numeric literal with no primary source behind it. The measurement is named in **Out of scope** as the thing that would reopen this.

### Why `helpers.py` is not split

The split does not do what it was proposed to do, for a reason that is structural rather than a matter of degree.

`claude/.claude/tests/helpers.py` matches no `DOMAIN_RULES` row and no `CROSS_DOMAIN_EXCEPTIONS` row today — `_is_py_source_under_claude_or_plugins` excludes it explicitly through `DELIBERATELY_UNMAPPED_TOP_LEVEL_DIRS` — so it reaches `select_pytest_targets`' `unmatched-path` branch and returns `FULL_SUITE_TARGETS` whether or not it is in `GLOBAL_TRIGGER_PATHS`. Any second module placed beside it inherits the identical outcome. A split changes the reason string printed on stderr and nothing else.

Even setting that aside, the fan-out argument the engineer already identified holds: both halves are imported by all four domains, so the narrowest honest rule for either half targets `(HOOKS_TESTS_DIR, SCRIPTS_TESTS_DIR, SKILLS_TESTS_DIR, LOVABLE_CLOUD_TESTS_DIR)` — which is `FULL_SUITE_TARGETS` minus two files. Nothing is saved.

The `pytest --collect-only` structural check floated as the enabling argument does not close the gap either, and it fails on its own terms rather than on the `select-tests-handoff-drift.md` grounds. Collection imports each test module; it does not execute test bodies. A payload builder's contract *is* the dict it returns, so changing a key, a default, or a nested shape in `bash_input` leaves every signature and every name intact, passes collection, and fails at run time in whichever domains consume that key. Collection catches a call-shape change only where the call sits at module scope — inside a `@pytest.mark.parametrize` argument, say — which is a subset, not the class. "Cheaply caught" is true; "reliably caught" is not, and a check that does not imply the property it is relied on for cannot license narrowing.

Google's Test Sizes line does apply — Context quotes "Small = no network, no database, no filesystem access, single-threaded, no subprocess; Medium = localhost-only network, database/filesystem allowed" — but it applies as a description of this suite rather than as a lever on it. The systems under test here are shell scripts under `claude/.claude/hooks/` and CLI entry points under `claude/.claude/scripts/`, invoked by path as subprocesses; testing them end to end is the point, not an accident. A repo-wide grep for `run_hook|run_skill_command|subprocess\.run|subprocess\.check` across `**/tests/test_*.py` matches 120 files. There is no substantial Small tier to extract, and marking the one that exists would change nothing about what CI or `select-tests.py` runs.

The decisive point runs the other way from the request. Once `claude/.claude/tests/` becomes a selectable domain (below), `helpers.py` stops reaching the unmatched-path branch: `_is_py_source_under_claude_or_plugins` and the new domain rule both match it, yielding a selection of `claude/.claude/tests` plus `test_ticket_reference_discipline.py`. For a module imported by 95 test files across all four domains that is a severe under-selection, and `GLOBAL_TRIGGER_PATHS` becomes the only thing preventing it. Its membership converts from redundant belt-and-braces to the single load-bearing guard, so this plan pins it with a test instead of relaxing it.

### Root problem

**Root.** `claude/.claude/tests/` holds two collected test modules and a shared helper module, and `select-tests.py` has no rule that names it. Every edit anywhere in that directory therefore reaches the `unmatched-path` fail-open and runs the full suite — including edits to `test_pytest_collection_config.py`, the file this repo's own test-infrastructure work most often touches. The fix is an explicit, auditable rule-table entry for that directory, paired with the cross-domain exceptions its two test modules' actual reads require, not a heuristic that infers when a full run is needed.

### Givens

*(Not listed as a given: keeping CI an unconditional full-suite backstop is this plan's own reachable, deliberately-declined choice — `.github/workflows/tests.yml` sits in this repo and this plan could edit it. - **G1. `select-tests.py`'s empty-target set must stay a subset of CI's `SKIP_REGEX` set.** Anything CI declines to skip is not confirmed-unread, so `select-tests.py` must not route it to `()`. *(Owned by `select-tests-fallback-audit.md`; the one-level-up fix for any new candidate is to add it to CI's deny-list first.)* This plan adds no empty-target rule, so the invariant is untouched rather than revised.
- **G2. `claude/.claude/tests/` must not become a Python package.** `.claude/rules/test-tree-packaging.md:20-23` states it directly: "Do not add `claude/.claude/tests/__init__.py`. That directory stays unpackaged deliberately." The `__init__.py` requirement from `fix-conftest-module-collision.md` is scoped to a test directory that carries its own `conftest.py`; this one carries none. *(Owned by that rule file and enforced by `TestNoBareSameDirectorySiblingImports`, which exempts unpackaged directories by design.)*
- **G3. pytest's collection semantics, marker filtering, and `--collect-only` behaviour are pytest's own.** This repo selects among what pytest offers and cannot change what any of it does. *(Vendor-imposed.)*

### Mechanisms

- **M1 — `CLAUDE_TESTS_DIR = "claude/.claude/tests"` plus a `DOMAIN_RULES` row mapping any path under it to itself.** *anchors: root, row 1, row 2* — converts a fail-open into an explicit table entry, which is the auditable shape `select-tests-fallback-audit.md` endorsed and the opposite of the inferential shape `select-tests-handoff-drift.md` was rejected for.
- **M2 — Delete `DELIBERATELY_UNMAPPED_TOP_LEVEL_DIRS` and `_is_under_deliberately_unmapped_claude_dir`; add `Path(CLAUDE_TESTS_DIR).name` to `MAPPED_TOP_LEVEL_DIRS`.** *anchors: row 1, row 3* — `"tests"` is that set's only member, so M1 empties it; an escape-hatch set nothing populates is dead code, and removing it restores `_is_py_source_under_claude_or_plugins` to matching every `.py` file under the three roots without a carve-out.
- **M3 — Add `CLAUDE_TESTS_DIR` to `_is_py_source_under_claude_or_plugins`' target tuple.** *anchors: row 4* — `test_pytest_collection_config.py` collects the whole `claude/.claude/` tree in a subprocess and AST-parses every tracked test module under three directories, so any `.py` change under the three roots can break it. This is a genuinely wide dependency and it is declared as one rather than approximated.
- **M4 — Add `claude/.claude/statusline-command.sh` as a cross-domain exception targeting `(HOOKS_TESTS_DIR, SCRIPTS_TESTS_DIR, CLAUDE_TESTS_DIR)`.** *anchors: row 5* — `test_statusline_command.py` (now selectable) reads it, `test_shellcheck.py` lints every tracked shell script, and `test_no_bash4_constructs.py` / `test_default_branch_resolution_is_shared.py` recursively glob `claude/.claude/` for `*.sh`.
- **M5 — Widen `TestCrossDomainReadCompleteness`' scanned corpus to include `CLAUDE_TESTS_DIR`.** *anchors: row 4, row 6* — a new selectable domain whose test files the completeness scanner does not read is a domain with no machine check on its declared reads, which is the precision gap this rule table is otherwise protected against.
- **M6 — A `test_select_tests.py` case pinning that `select_pytest_targets(["claude/.claude/tests/helpers.py"])` returns `is_full_suite=True` with `reason == "global-trigger"`.** *anchors: row 7* — `GLOBAL_TRIGGER_PATHS` short-circuits before domain matching, so this assertion already holds today and does not flip red-to-green across Phase 1. Its value is prospective: after M1–M3, it is the only guard against a future removal of `helpers.py` from `GLOBAL_TRIGGER_PATHS` silently narrowing a 95-importer module's selection to two files. State that in the test's own docstring rather than implying a before/after pin on this diff.
- **M7 — Two `docs/design-decisions/` records and one README clause.** *anchors: row 8* — three prior plans have now re-opened the CI-selectivity question; a fourth session finding no recorded answer will re-derive it. The decision plus its primary-source grounding is the durable output, and `docs/design-decisions/` is this repo's existing home for exactly that, with `full-suite-pytest-drift-traced-to.md` as the nearest precedent.

Lighter primitives considered for M1 and set aside. **Do nothing, keep the fail-open:** correct today and costs nothing, but it leaves the deferred item deferred and leaves a real collected test directory unnameable by the tool the repo requires agents to run — and `select-tests-fallback-audit.md` already recorded it as a **given** it could not reach rather than as correct-by-design. **Add only a `statusline-command.sh` exception and leave the directory unmapped:** strictly smaller, and it fixes the one shell file, but the two `.py` files in the directory keep falling open, which is where the friction actually is — `test_pytest_collection_config.py` is the file this repo's infrastructure work touches. Neither is enough; both are cheaper, and that is why they are named here rather than assumed away.
