# Widen plan-architect's dispatch scope beyond /plan-it Step 5

## Context

Widen `plan-architect`'s dispatch scope so it can also be invoked ad hoc, mid-conversation, outside `/plan-it` Step 5 — when the user explicitly asks for Opus's architectural judgment on a decision — without adding a new agent (a new agent has a real, permanent, unconditional per-session context cost with no way to avoid it — confirmed against Claude Code's own subagent docs, no lazy-load/opt-in mechanism exists) and without silently discarding `docs/design-decisions.md` §30's cost-isolation rationale for the existing single-caller, bounded-frequency exception. Why now: the user finds themselves asking Opus for architectural review frequently in Sonnet-anchored sessions ("ask Opus this, ask Opus that"), currently via ad hoc `general-purpose` + `model: opus` dispatches that carry unneeded `Write`/`Bash`/`Skill` and restate instructions on every call, when `plan-architect` already has the right shape (read-only, opus-pinned, xhigh effort, no `Agent` tool so no cascade risk) — it's just hard-scoped to one caller and one output grammar. Intended outcome: `plan-architect`'s frontmatter (`TRIGGER`/`DO NOT TRIGGER`) and system prompt support two distinct invocation modes — the existing Step 5 plan-authoring mode (unchanged, structured plan-file-section grammar) and a new ad hoc conversational-review mode (freeform review text, never plan-file grammar) gated on an explicit user ask — with every reference site that encodes the old single-caller premise updated to match.

**Decisions already settled with the user (do not re-open):**
1. Widen `plan-architect` itself rather than add a new agent or merely document the existing `general-purpose` + `model: opus` path — zero new base-context cost was the deciding factor.
2. The new ad hoc call site fires only on an explicit user ask for Opus's take — never on the session's own unprompted judgment.
3. The ad hoc call site is always conversational — never plan-file grammar, never a plan-file write.
4. The §30-mandated Opus spend-share check is included as a real Verification step, not skipped.

## Approach

`plan-architect` gains a second, explicitly-selected invocation mode instead of a second agent: the dispatch prompt's first line names the mode (`MODE=plan-sections` for `/plan-it` Step 5, `MODE=consult` for an ad hoc architectural consult the user asked for), the agent body splits into a shared preamble plus one section per mode, and every reference site that currently states "dispatched only from `/plan-it` Step 5" is reworded to describe two independently frequency-bounded call sites. Nothing about Step 5's structured-section contract, `plan-architect`'s tool set, or its `model`/`effort` pins changes.

The load-bearing argument for accepting the widening against `docs/design-decisions.md` §30's cost-isolation rationale: **this change does not create new Opus dispatches, it re-points existing ones.** The user already makes these calls via `general-purpose` + `model: opus`. Routing them to `plan-architect` instead is a privilege *reduction* (drops `Write`/`Bash`/`Skill` from a dispatch that needs none of them) and a token saving (the charter stops being restated per call). §30's isolation was never "one caller" as an end — it was "no unbounded Opus escalation," and that survives: each call site carries its own bound, and `plan-architect` still holds no `Agent` tool, so no dispatch can cascade. What is genuinely given up is named in row 12 below, not hand-waved.

**Root problem.** `plan-architect` already has the right shape for ad hoc Opus architectural judgment — read-only, `model: opus`, `effort: xhigh`, no `Agent` tool — but its `description`, its body's unconditional "read `plan-it/SKILL.md` for the grammar your return must follow" instruction, and five reference sites all hard-scope it to one caller and one output grammar, so those consults route to a strictly more privileged generalist instead.

**Givens** (conditions this design treats as fixed because they lie beyond its reach):

- **G1** — A subagent's `description` is loaded into every session's base context, with no flag, plugin-scoping, or lazy-discovery mechanism to avoid it; the only documented mitigation is keeping the `description` short and pushing detail into the body, which loads on dispatch. Vendor-imposed by Claude Code. `[verified: WebFetch against code.claude.com/docs/en/sub-agents, this session]`
- **G2** — The harness makes every named agent dispatchable from any session; nothing technical can restrict which caller dispatches `plan-architect`. Vendor-imposed. `[verified: docs/design-decisions.md:389, §30 residual risk 1]`
- **G3** — A subagent cannot observe the conversation that produced its own dispatch. It receives the dispatch prompt plus its startup load and nothing else, so it cannot itself verify that a user asked for it. Vendor-imposed by the subagent context boundary. `[verified: docs/design-decisions.md:376, which documents the startup-context load as the full extent of what a subagent inherits]`
- **G4** — Everything under `claude/.claude/**` installs to every stow consumer and goes live on `git pull` with no re-install, so the widened `description` and the CLAUDE.md routing line ship to all of them, not to this operator alone. Owned by the distribution model. `[verified: repo-root CLAUDE.md, "Working in this repo"]`
- **G5** — `transcript-analysis.py cost`'s default multi-root union currently aborts with `AssertionError: cost: redact map has no entry for a project label under root 6`. 7. `[mechanism]` The literal uses `=` rather than `:` because an agent `description` is an unquoted YAML plain scalar where `': '` is the mapping separator and breaks strict parsing — a colon-free token stays quotable in any of the three files without escaping. `[verified: test_agent_roster.py:305-320, test_frontmatter_parses_strictly, whose docstring names this exact failure]` — anchors: row6.
