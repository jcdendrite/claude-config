# Deny a no-op Agent dispatch at the tool-call boundary

## Context

Build a `PreToolUse` hook on the `Agent` tool that detects and denies a no-op dispatch — a subagent spawned solely to wait, occupy the turn, or report back immediately while other dispatches are in flight — and points the denied session to CLAUDE.md's existing Agent Briefing rule for what to do instead (end the turn with no tool call). This is needed now because two advisory-only fixes for this exact anti-pattern have both been confirmed to fail: a skill-body prose rule (merged 2026-09-02, PR #819) and a promotion of that rule into always-loaded `claude/.claude/CLAUDE.md` (merged 2026-09-05, PR #856). Two further occurrences happened after the second fix shipped — one on 2026-09-06, one on 2026-09-08 — the second of which is the reported incident: the model quoted the CLAUDE.md rule back at itself in a self-diagnosis *after* having violated it, meaning the rule was in context and understood, not merely unloaded. The intended outcome is a mechanical gate that denies this dispatch shape at the tool-call boundary, per `docs/design-decisions/no-op-dispatch-guard.md`'s own "Revisit" clause, which named exactly this lever as the next step "if the behavior recurs after this rule ships" — accepting the prompt-content-matching and false-positive cost that both prior decisions explicitly declined to take on.

A transcript-corpus search this session (via a `general-purpose` subagent using `~/.claude/scripts/transcript-analysis.py` plus raw JSONL grep, per the user's request to measure recurrence before committing to a fix) confirmed both post-fix occurrences directly in claude-config's own history, and established that the two post-fix occurrences used two *different* `subagent_type` values (`fork` and `general-purpose`) — evidence that shaped the design below. Given that evidence, the user chose (via `AskUserQuestion`) a hard deny gate over two alternatives: an allow-with-context nudge, and gathering more data before building anything.

## Approach

Ship `claude/.claude/hooks/deny-no-op-dispatch.sh`, a `PreToolUse` gate on the `Agent|Task` matcher that denies a dispatch when **both** conditions hold: the prompt is shorter than a fixed ceiling, **and** the prompt-or-description matches one of a small closed set of no-work idioms. The conjunction is the whole design — a prompt long enough to carry a real task specification is structurally out of this gate's reach, no matter what words it contains, so the false-positive surface is bounded to short prompts that also say they do no work. The deny message names CLAUDE.md's Agent Briefing rule as the compliance path and names the rephrase path for a false positive. No disable sentinel, no bypass marker, no `subagent_type` filter.

Two decisions the evidence forces, stated up front because they diverge from the nearest sibling hook. First, the gate evaluates **every** dispatch regardless of `subagent_type` — the two post-fix occurrences used two different types (`fork`, `general-purpose`) and one pre-fix occurrence recorded no `subagent_type` field at all, so `require-architect-consult.sh`'s reviewer-persona self-filter would have missed the majority of the corpus. Second, the gate reads **nothing from disk** — no config dir, no git, no transcript, no marker. It is a pure function of `tool_input`, which makes it the cheapest gate in the directory and removes every allow-on-state-failure branch its two `Agent`-matching siblings carry.

**Why a length ceiling rather than phrase-matching alone.** The reported 2026-09-08 incident's prompt is a four-sentence paragraph (order of 300 characters), not a one-word stub — so a bare-length predicate cannot reach it, and the design needs content matching. But content matching alone is what both prior plans rejected as brittle, and the rejection was correct on its own terms: this repo's own workflows write dispatch prompts constantly that legitimately contain "do nothing," "report back," and "placeholder." The ceiling is what converts an unbounded false-positive surface into a bounded one. It also closes the self-hit this change would otherwise create: a `code-writer` dispatch implementing this hook, a `plan-architect` consult about it, and this very dispatch prompt are all far over the ceiling, so the gate cannot deny the work that builds it.

**Why the idiom list is closed, and to what.** Every entry must trace to one of exactly two primary sources, cited per entry in the hook's own header: (a) a phrase appearing verbatim in a confirmed no-op dispatch from the corpus, or (b) a phrase `claude/.claude/CLAUDE.md`'s Agent Briefing bullet itself names as a prohibited shape. Source (b) is not speculation — the 2026-09-08 incident had the model quoting that bullet at itself in self-diagnosis, so its wording is demonstrably in context when the impulse fires, and a no-op prompt echoing "occupy the turn" or "hold while other dispatches finish" is a live shape rather than a hypothetical one. Anything grounded in neither source does not go in the list. That rule is what keeps this from becoming the open-ended phrase-upkeep problem `guard-placeholder-wait-forks.md` row 1 rejected: additions are auditable against a source, not against a maintainer's imagination.

**Proposed match set** (POSIX ERE, case-insensitive via `grep -qiE`, evaluated against whitespace-collapsed text — no `\s`, no bash-4 `${var,,}`):

- Degenerate-stub arm, anchored against the **prompt alone**: the entire prompt is one no-op token (`noop`, `no-op`, `placeholder`, `wait`, `nothing`, `standby`, `stand by`, `ack`), optionally with trailing punctuation. Source (a): two confirmed prompts are exactly `noop` and `placeholder`. Anchoring is what stops `Find every no-op dispatch` — a legitimate short `Explore` prompt — from matching.
- Phrase arm, unanchored against **prompt + description**: `do(ing|es)? nothing`, `just wait`, `report back immediately`, `do not (read|run|investigate) any`, `exists only (so|to)`, `no action` — all source (a); plus `occupy the turn` and `hold while` — source (b). Description is included because one confirmed occurrence carried its giveaway text there (`"Wait handling — no action, agents still running"`) with a one-word prompt.
- `placeholder` appears only in the anchored stub arm, never as a free substring — a short legitimate prompt like "Replace the placeholder on line 12" would otherwise deny.

**Ceiling value.** Proposed `NOOP_MAX_PROMPT_LEN=600`, roughly twice the longest confirmed no-op prompt and well under a structured multi-paragraph task prompt. This number is not yet measured and the implementation must derive it (row 9) before finalizing.

**Alternatives set aside.** A `PostToolUse` logger that records occurrences for later analysis, and an `_lib_emit_allow_with_context` nudge on the same predicate, were both put to the user via `AskUserQuestion` this session and rejected in favor of the hard deny. Transcript parsing for "another dispatch is in flight" was considered as a false-positive-narrowing conjunct and rejected: it is strictly heavier than the chosen mechanism, it is version-fragile, and it would miss the two one-word-prompt occurrences, which carry no stated in-flight context. Extending one of the three existing `Agent`-matching hooks was rejected on `no-op-dispatch-guard.md`'s own reasoning — both are gates with unrelated activation conditions, and the prompt-content matching would be net-new either way.

## Critical files

**Create:**

- `claude/.claude/hooks/deny-no-op-dispatch.sh` — the gate. `#!/bin/bash`, `# hook-class: gate` on line 2, `set -uo pipefail`, `DENY_GATE_LABEL="no-op-dispatch"`. Structure follows `require-routing-read.sh` exactly through the bootstrap: stub `emit_deny`, source `_lib.sh` with the `# shellcheck disable=SC2218` comment on the stub-then-override redefinition, re-point `emit_deny` to `_lib_emit_deny`, call `_lib_parse_tool_input_or_deny`. Then: `case "$TOOL_NAME" in Agent|Task) ;; *) exit 0 ;; esac`; two separate `_lib_jq -r` calls for `.tool_input.prompt` and `.tool_input.description` (two calls, not one delimited call — `_lib_parse_tool_input_or_deny`'s 0x1f scheme carries an overflow guard this hook should not hand-roll); length check on the prompt; whitespace-collapse via `tr -s '[:space:]' ' '`; the two `grep -qiE` arms; `emit_deny`. Header comment carries a **Failure direction** block (deny on payload failure; no state-failure branch, since the hook reads nothing from disk) and a **Known gaps** block (rows 27 and 12).

  The `deny-*` prefix is deliberate over `guard-*`: both mandate `hook-class: gate` (`test_hook_alignment.py:102-109`), but this repo's `guard-*` names a hook protecting a file or config value (`guard-settings-session-keys.sh`), while `deny-*` names a hook refusing a tool-call shape (`deny-network-installs.sh`, `deny-reviewer-tree-mutation.sh`, `deny-credential-bash-reads.sh`). This refuses a tool-call shape.

  Both idiom sets (the anchored stub-token list and the unanchored phrase list) are named shell variables (e.g. `NOOP_STUB_TOKEN_RE`, `NOOP_PHRASE_RE`) defined near `NOOP_MAX_PROMPT_LEN` at the top of the script, not inlined anonymously into the `grep` calls — a future contributor extending the list per row 11's grounding rule needs one clear place to add an entry, not a regex to parse out of a `grep -qiE` invocation.

  **Deny message** (`_lib_emit_deny` prefixes `Blocked by no-op-dispatch gate: `):

  > this dispatch's prompt is short and instructs the agent to do no work. CLAUDE.md §Agent Briefing bars dispatching an agent — of any type — whose instructions are to report back immediately, occupy the turn, or hold while other dispatches finish. A no-op agent returns at once, so it waits for nothing, and still pays a full agent's context cost for an empty return. When pending dispatches are all that remain, end the turn without a tool call and let their completion drive the next one. If this dispatch does have real work to do, state that work in the prompt and retry — a prompt that specifies a task does not trip this gate. If you are a subagent, report this denial to your dispatcher rather than attempting to resolve it yourself.

- `claude/.claude/hooks/tests/test_deny_no_op_dispatch.py` — module docstring, `from helpers import HOOKS_DIR, agent_input, bash_input, run_hook, run_hook_reason`. Malformed-input, empty-stdin, non-object-`tool_input`, and missing-`_lib.sh` deny cases are **not** repeated here — `test_hook_alignment.py`'s Layer 2 already parametrizes every gate-class hook over them.
