# Routing-gate cost guard subcommand

## Context

Goal: ship the `transcript-analysis` subcommand that the routing-gate design record promises, one that captures each sampled branch per account and computes the guard's net cost per review loop with its 95% bootstrap interval, so the key-on/key-off cost guard can run instead of counting as failed.

Ask: the engineer answered "Yes but handoff first yes?" to starting the guard subcommand, and the acceptance criteria are the four live DEFER rows in PR #1321's body (cited, not quoted here). The engineer's two plan-time answers: capture gate "Reuse pr_cost_recording (Recommended)"; design-doc scope "Edit line 90 only (Recommended)".

Why now: PR #1321 made cost a pre-registered guard in `docs/design-decisions/review-orchestrator-routing-gate.md` and deferred the tool to a follow-up. GH-1312 (merged as PR #1336) fixed the round-window bias, so readings made with current code no longer carry the task-notification early-close error. Transcripts age out after `cleanupPeriodDays`, and the key-off arm ages out first until a capture runs, so the capture half is time-sensitive.

Intended outcome: a subcommand section in `docs/transcript-analysis.md` states how each figure is read. The definitions it implements are fixed in the design record and are not revised here:
- A loop ends at the clean `code-review` round that writes the marker.
- The net is the in-round overhead difference (`total $` of the loop's `code-review` rounds, reviewer, `code-writer` and `plan-architect` spend included, a key-on loop's denied round-open counted with its `review-orchestrator` round) less the carry.
- The carry prices the key-off minus key-on gap in main-thread context growth at the `pricing.py` cache-read rate of each later turn's model, over the key-off session's main-thread turns after the loop that fall outside every round window.
- The interval is a percentile bootstrap of 10,000 replicates that resamples branches within each arm, and each replicate re-estimates the growth gap.
- The sample is every merged branch the engineer's step 1 note lists for the key-on arm, plus each key-on account's most recent pre-key branches for the key-off arm, skipping branches worked under a different `round_consult_round2_pilot` or `architect_fix_plan_pilot` state.

The four deferred acceptance criteria:
1. What "captured whole" means, and checking step 1's branch list against the gate's deny records, so an unlisted or missing branch cannot silently shrink an arm.
2. The capture store is local, untracked, per account and opt-in per account, or cites the pr-cost ledger rules in `docs/pr-cost.md`.
3. The subcommand reads only step 1 config dirs, one root per run, never enumerates declared roots or switches container credentials, and its multi-account check is a boolean existence test.
4. Pilot-key state has no transcript record, so the subcommand owns recording it from an engineer note, as step 1 does for the routing key.

Constraints from the session:
- No quantity the guard computes is published. `docs/private-project-redaction.md` § "A wider corpus goes to the owner, never into a public artifact" governs it, so a public artifact states only whether the guard passed and whether the default flipped.
- Design doc line 80 (the GH-1312 sentence) stays unedited, per the engineer's earlier decision. Only line 90 may change.
- `claude-config` is public, and the plan, tests and fixtures use placeholder names and synthetic data only.

## Approach

Ship one subcommand, `transcript-analysis.py routing-guard`, in a new module `transcript_analysis/routing_guard.py`. With a top-level `--config-dir` and `--capture`, it reads that one account's transcripts of this repo, checks the engineer's note against the routing gate's denies, and publishes each sampled branch it can capture whole as its own write-once file in that account's config dir. A file holds token counts rather than dollars, is named by a digest of the branch and the capture revision, and is never rebuilt once it exists. Without `--capture`, it reads the note, opens each listed branch's file by name, prices every loop at the current rate table, and prints only PASSED, FAILED or NOT RUN. The net per loop, its 10,000-replicate interval and the counts go only to a new owner-only `--out` file.

**The note.** The engineer's step 1 note becomes a file the subcommand reads. It is the one source for each branch's arm and pilot state, because no transcript records either key (rows 3, 4). It is also the one source for the `off` sample, because recency needs a merge order this checkout lacks (row 6). The engineer writes it outside any git work tree, one tab-separated row per branch:

```text
<config-dir>	<branch>	<on|off|unmerged>	<round_consult_round2_pilot: on|off|->	<architect_fix_plan_pilot: on|off|->
```

- `on` is a merged branch worked with `review_orchestrator_routing` on. `off` is a merged key-off branch in the sample: each account lists exactly as many as it has `on` rows, its most recent eligible pre-key branches. `unmerged` is a branch with routing denies that has not merged. `unmerged` rows carry `-` in both pilot columns, and `on` and `off` rows carry `on` or `off` in both.
- `#` lines and blank lines are skipped, and a trailing `\r` is dropped. Cells are not trimmed. A leading `~/` expands to `$HOME`, and every other config dir must be absolute. Config dirs compare by resolved path, so two spellings of one directory name one account.
- The parser refuses (exit 2) a wrong column count, an unknown value, a relative config dir, a `~/` with `$HOME` unset, a branch in `scope._DEFAULT_BRANCH_CANDIDATES`, and a branch listed twice anywhere in the note. A note that is missing, unreadable, a directory or not UTF-8 is refused (exit 2) with a fixed message. Each message names the note line and never echoes a cell or a path, since a config dir can name a private account.
- `--note` must be an absolute path outside any git work tree, checked with `ledger_common._ledger_path_is_git_tracked` on its resolved path. A note with any group or other permission bit prints a notice in both modes.

**Capture (`--capture`).** One run reads one account (criterion 3 as row 49 reads it):
1. It refuses (exit 2) unless a top-level `--config-dir` is given and resolves to a config dir the note lists. Its one root is `Path(args.config_dir) / "projects"`, built directly, so it never calls `declared_transcript_roots()`. It makes no `gh` call and sets no environment variable (rows 7, 21).
2. It refuses (exit 1) unless that account's `pr_cost_recording` resolves true through `_config.config_enabled(..., config_dir_override=...)`. One module function handles `ConfigSchemaEmptyError` and `ConfigSchemaRowTruncatedError` before the generic `KeyError`, then `None`, in `pr_cost.py:566-630`'s order, and compute reuses it (rows 19-21, 59). That function returns an outcome (opted in, not opted in, or a named config fault) and never calls `sys.exit`. Capture maps not-opted-in and every config fault to exit 1 and its own messages, as `pr_cost.py` does. The function runs its whole classification, `config_enabled` and the `_config.schema()` probe in the `KeyError` handler alike, under `contextlib.redirect_stderr` into a discarded `io.StringIO`, because `_config` prints the config file's path and up to 80 characters of a rejected line (row 86). It prints one fixed, digit-free, path-free notice when anything was captured. Capture then refuses (exit 2) when its captures directory sits inside a git work tree (Captures store, below), before any transcript is read.
3. Its scope is this repo's project directories on that root. `scope._repo_scoped_project_slugs("routing-guard")` gives the live worktree slugs, the first of them the main checkout's (row 48). A cwd outside a worktree of a git repo gets `scope`'s own exit 1 and message. Capture then refuses (exit 1, as `scope`'s own cwd refusal exits) with one fixed, path-free message unless `scope._path_to_project_slug(str(_CHECKOUT_ROOT))` is among those slugs, so a run from another repo's worktree cannot publish that repo's spend under a listed branch name (row 87). `_CHECKOUT_ROOT` is the module value `Path(__file__).resolve().parents[4]`, the root of the checkout holding the running module, read when the check runs so a test can patch it. Every directory on the root whose name is the main checkout's slug followed by `--claude-worktrees-` and more is added, so a removed worktree's sessions stay in scope (rows 9, 10). The capture makes no git call of its own. Sessions come from `scope._iter_scoped_sessions(slugs, False, [root], scan_gaps=...)`, with `include_subagents=False` because every term reads main-thread turns (row 55). Any scan gap refuses the run (exit 2) before anything is published (row 11).
4. One pass per session dedups records, detects windows for every review skill, and takes each record's branch from `review_rounds._session_record_branches`, never reading `gitBranch` itself (rows 52, 64). It prices each `code-review` window through `review_rounds._price_session_rounds(..., collect_tokens=True)`. It keeps only derived facts per round: branch, open and window-end times, whether its span holds a marker write, the two context scalars, later-turn counts by model, the token map and whether it is degraded. It also keeps the session's routing denies, and for each branch whether it has a timestamped record and its last record time. The session's records are dropped before the next session is read, and loops are assembled from the facts alone. Before reading each project directory, it prints one stderr line, `routing-guard: scanning project directory <k> of <n>`. The line carries no directory name, because a project directory's name encodes the checkout's path and a worktree's branch.
5. Deny reconciliation runs before any publish (criterion 1, rows 12-14). Denies dedup by `tool_use_id` across both deny shapes:
   - A `review-orchestrator routing` deny on an `off` row refuses the run (exit 2), naming that row's note line, because the branch was worked with the key on.
   - A deny on a branch the note does not list refuses the run (exit 2). The message gives the deny's UTC time to the minute instead of the branch, and the engineer finds the branch with the design record's step 3 `review-trace --deny-summary` read.
   - A deny on an `unmerged` row passes, and the row is not captured.
   - A deny on an empty branch or a default-branch candidate prints a notice, because no sampled branch can carry it.
   - An `on` row this run builds with no deny prints a notice, because a typed `/code-review` and the four `unrouted` cases leave none.
   - An `off` row this run builds with a record later than this account's first routing deny prints a notice, because the key may have been turned off again.
   - A branch the note lists for another config dir that has records on this root, a deny included, prints a notice naming that note line, because its rounds are split across accounts (row 49).
6. For each `on` and `off` row of this account, it first opens that row's file by its exact name with `O_NOFOLLOW`, and only `ENOENT` means the file is absent. An existing file is never rebuilt. It is read through the validator and reported `already captured`, or `invalid` when the open fails any other way, as it does for a symlink, dangling or live, or when the file fails the validator. For every absent row, it builds a row, checks it is whole, validates it and publishes it. A publish that finds the name taken reads the standing file the same way. It prints one line per row, named by note line:
   - `captured`, with its rounds, its loops, its loops whose growth is defined, how many denied round-opens joined an orchestrator round in their loop, and whether any loop is degraded;
   - `already captured`, with the file's loops, its loops whose growth is defined, and whether any loop is degraded, all read from the validated file;
   - `invalid`, or `missing (<reason>)`.

   It also prints a digit-free PRICING INTEGRITY line when `pricing._format_drift_detected()` holds.
7. It exits 0 when every row is `captured` or `already captured`, and 3 when any row is `missing` or `invalid`. Files published in a run that exits 3 stay, and a re-run reports them `already captured`.

**What "captured whole" means.** A row is whole when every condition below holds, and the first that fails, in this order, is its reason (rows 17, 52, 53):
1. The branch has at least one record on this root with a parseable timestamp. Otherwise `no-records`.
2. Some round on this root writes the marker, so the branch has at least one complete loop. Otherwise `no-complete-loop`, which the doc words as "no round on this root writes the marker", with records elsewhere as one possible cause (row 17).
3. No session holding one of its `code-review` rounds has an orchestrator transcript `_orchestrator_spawns` could not read. Otherwise `orchestrator-unreadable`, because a missed marker write would merge two loops (row 53).

No condition reads the clock or `cleanupPeriodDays`, and whole does not prove that nothing was lost:
- A branch whose earliest sessions aged out before its first capture reads whole while a later session still writes the marker (row 18).
- A lost dispatch transcript shows only as a degraded loop (row 56).

A missing row leaves its arm short, so the guard does not run (design record line 78). A file is never rebuilt, so the per-row line printed when it is published is the owner's one check while the transcripts still exist. The doc says to add a branch to the note once its sessions end, oldest `off` rows first, to list a branch still in progress as `unmerged`, and to read each `captured` line against what the owner knows of that branch.

**Captures store.** Each account's store is the directory `<config-dir>/routing-guard-captures`. It holds one file per captured branch per capture revision, named `<digest>.r<rev>.json` (criterion 2, rows 19, 20, 70, 71). `<digest>` is the SHA-256 hex digest of the branch name's UTF-8 bytes, from `hashlib`, and `<rev>` is `_CAPTURE_REVISION`. Capture and compute digest the note's branch to find its file (row 51). A file holds one JSON object whose one key, `loops`, is a non-empty list. The name carries the branch key and the revision, so the object repeats neither. Each loop holds exactly four keys:
- `overhead_tokens`, shaped `{model: {variant: {class: tokens}}}` over every turn of the loop's rounds whose model is not `<synthetic>`, priced or not, since compute decides what it prices (rows 57, 84).
- `growth_tokens`: the context at the first main-thread turn at or after the window end of the loop's last round, minus the context at the first main-thread turn at or after its first round-open. It is signed, because compaction can shrink context, and `null` when the two turns are not in one session or either is absent.
- `later_turns`, shaped `{model: count}`: the main-thread turns in the last round's session, at or after that window end, that fall outside every review window, for every model, priced or not, since compute decides what it prices. A turn after a later loop in the same session counts for both loops, as design record line 77 reads. A `<synthetic>` record is not a turn here (row 57).
- `degraded`: true when a round in the loop has a dangling dispatch (row 56). Unpriced turns and later turns never set it, because compute counts a model its table cannot price as degraded.

No field without a compute reader is stored: no not-whole rows or reasons, no capture time, no record times, and no unpriced or dangling counts. `later_turns` is stored on every loop, though compute prices it only for `off` rows, so a file does not depend on the arm the note gives its branch.

Writing and reading files:
- The directory's path is resolved, and `_ledger_path_is_git_tracked` runs on that resolved path joined with a file name, so the check sees the directory itself (row 69). A path inside a git work tree is refused (exit 2), per `docs/pr-cost.md` § "Data".
- The directory is created `0700` just before a run's first publish, so a run that publishes nothing creates nothing.
- One validator, `_parse_capture_bytes`, reads a file's bytes: in capture, a built row before publishing and a standing file, and in compute, each file it opens. It refuses bytes that are not UTF-8 and any parse that raises `ValueError` or `RecursionError`, which covers invalid JSON, an integer past Python's digit limit and nesting past the recursion limit. It also refuses a non-object, duplicate keys, `NaN` or `Infinity`, a missing or extra key, an empty `loops`, a boolean or float where an integer belongs, a negative token or turn count, a `growth_tokens` that is neither an integer nor `null`, a non-boolean `degraded`, and an unknown variant or class. Each refusal is a fixed reason that never echoes the rejected cell.
- Capture serializes a row with `allow_nan=False` and `json.dumps`' default ASCII escaping, so the text the core writes through `os.fdopen(fd, "w")` encodes the same under any locale. It passes that text's UTF-8 bytes through the validator before publishing it. A row the validator rejects marks a builder defect and stops the run (exit 4).
- Publishing goes through `ledger_common`'s create-new core (M17). The text goes to a `0600` `mkstemp` file in the directory, which is flushed and fsynced, and `os.link` then gives it its final name (rows 72, 82). A process or kernel crash therefore leaves at most an orphaned `.routing-guard-*.tmp` file, never a partial file at a final name. The claim has two limits, which the doc states:
  - The directory is not fsynced, so a kernel crash can drop a name just linked, and the next run captures that row again.
  - On macOS `os.fsync` does not flush the drive cache, so a power loss there can still leave a zero-length file at a final name, which reads `invalid`.

  When the core returns `EXISTS`, another run published the name first, and the row reads the standing file as step 6 says.
- Both modes open a file `O_NOFOLLOW`, so a symlink at a file's name, a dangling one included, fails as unreadable, like any other `OSError` on read.
- A `WRITE_FAILED` or `LINK_FAILED` outcome stops the run (exit 4) with one of two fixed, path-free messages: the file could not be written, or it could not be linked into place, as on a filesystem without hard links. Each says how many files this run published. An `OSError` creating the directory also exits 4, printing only its `strerror`. A re-run is safe, because those files report `already captured`.
- Re-capture is one owner action the doc states: delete that branch's file, then run capture again, only while every session of the branch is inside `cleanupPeriodDays`. pr-cost's re-record contract states the same bound for its forced re-capture (row 73).

**Loops.** A branch's `code-review` rounds sort across sessions by timestamp, path and open index, the order `compute_review_round_costs` uses. A loop is the run of rounds up to and including the first round whose outcome span holds a marker write. That signal comes from `author_outcome._code_review_rounds`, `author_outcome._orchestrator_spawns` and `author_outcome._round_has_marker_write`: the marker-write signal `author-outcome` computes for every round and consults when a round has no ledger rows (rows 26, 79). `_orchestrator_spawns` gets `_AUTHORING_AGENT_CODE_WRITER` and a fresh `Counter` per session, whose unreadable-transcript count feeds condition 3. On a key-on account, the denied `Skill(code-review)` opens its own window and the `review-orchestrator` spawn opens the next. Both land in the loop's overhead, as design record line 76 requires (row 13). Rounds after a branch's last marker write belong to no loop and are not counted (row 27). `author-outcome` emits no per-branch count of marker-write rounds, so no cross-subcommand reconciliation test is added.

**Compute (no `--capture`).** It refuses a top-level `--config-dir` (exit 2) with its own message (row 41). It reads no transcripts. It opens only the note, the config schema and the key's config files through `_config`, and, for each `on` and `off` row of a config dir with an `on` row, the one file its branch digest and the current revision name (row 49). It never lists a captures directory, so a file for a branch the note does not list, or at another revision, is never opened. Each file is read through the validator, and a missing, unreadable or invalid file fails only its own row. Its multi-account check, criterion 3 as row 49 reads it, is one boolean per config dir with an `on` row: the key resolves true through capture's opt-in function, and the captures directory exists. The order per config dir is the key check, then the captures-directory check, then the by-name opens. A config dir whose key is off, or whose captures directory is missing, has none of its capture files opened, so turning the key off withdraws consent for compute as it does for capture. The opt-in function's stderr capture and fixed notice apply here too. Compute maps every outcome other than opted in, a config fault included, to a NOT RUN reason (exit 3) or exit 4, never to exit 1, so a config fault cannot read as FAILED. It never counts accounts and never reads a declared-roots file (row 8).

It prints NOT RUN (exit 3) with every reason that holds. Each reason is a fixed, digit-free string from one module tuple, `_NOT_RUN_REASONS`, followed by a note line where one applies:
- fewer `on` rows than `_MIN_ON_BRANCHES`, 10 (design record line 79), read at call time so a test can lower it;
- a config dir with `on` rows whose key is off or hits a config fault, or whose captures directory is missing;
- an `on` or `off` row with no file at the current revision;
- an `on` or `off` row whose file cannot be read, a symlink included, or fails the validator;
- an account whose `on` rows mix pilot states, which leaves no reference state (row 5);
- an `off` row whose pilot states differ from its account's `on` rows;
- an account whose `off` row count differs from its `on` row count (rows 6, 32);
- an arm with no loop whose growth is defined;
- a point net or lower bound that is not finite.

`off` rows of an account with no `on` row, and every `unmerged` row, are ignored.

**Figures.** Each branch's scalars are computed once, before any replicate (rows 22, 23, 54):
- overhead dollars: each `overhead_tokens` leaf is rebuilt into a usage dict, with the nested `cache_creation` block and the `speed` and `inference_geo` values its variant label implies, and priced by `pricing._price_turn`. A model the current table does not price is skipped, and its loop counts as degraded. A model unpriced when its branch was captured is priced once the table lists it.
- the loop count, the growth sum, and the count of loops whose growth is defined;
- for `off` branches, the rate sum: each `later_turns` count times `pricing._model_rates(model)["cache_read"]`, per token, with a model the current table does not price skipped and its loop counted as degraded. An `on` row's `later_turns` is never priced (rows 29, 57).

Over a multiset of branches in one arm, overhead per loop is total overhead over total loops, and mean growth is total growth over the growth-defined loops. The key-off rate sum per loop runs over all key-off loops. The gap is key-off mean growth minus key-on mean growth. The net per loop is key-on overhead per loop minus key-off overhead per loop, less the gap times the key-off rate sum per loop.

The bootstrap sorts each arm's branches by digest and draws from a local `random.Random(0)` (rows 33, 36). Each replicate resamples each arm with replacement, to its own size, and recomputes every term, the gap included. A replicate whose resample leaves an arm with no growth-defined loop has no gap, so it has no net. It is never redrawn. It stays one of the 10,000 replicates and ranks above every defined net, entering the sorted replicates as `math.inf`, so the loop runs exactly the replicate count. The rule can only raise the lower bound, so a PASSED holds whatever net an undefined replicate could have had (row 67). What the rule implies, which the doc states (row 74):
- With a fraction u of replicates undefined, the lower bound sits at about the defined replicates' 0.025/(1 − u) quantile.
- Call a branch growth-defined when at least one of its loops has defined growth. An arm of n branches, d of them growth-defined, leaves a resample without one with probability (1 − d/n)^n. At ten branches that is about 0.35, 0.11, 0.028 and 0.006 for d from 1 to 4.
- The sample-level NOT RUN reason keeps d at least 1 in each arm, so u stays below about 0.60 at any arm size, and the lower bound below about the 6.3rd percentile of the defined replicates. At ten branches per arm, the lower bound sits at about the 5.9th percentile with d = 1 in both arms and about the 2.65th with d = 3 in both.
- So a thin growth sample runs to a status rather than stopping as NOT RUN, and a borderline net can read FAILED.
- When the upper bound falls on an undefined replicate, `--out` reports it as unbounded. The status never reads the upper bound, so an infinite upper bound alone is not a NOT RUN reason.

The bounds come from `review_rounds._resample_percentile(..., level=_GUARD_CI_LEVEL)`. The status is FAILED (exit 1) when the lower bound is above zero, else PASSED (exit 0). `_bootstrap_net` takes the replicate count and the RNG as required keyword parameters, with no defaults. Compute passes `_BOOTSTRAP_REPLICATES` and `random.Random(_BOOTSTRAP_SEED)`, and `_bootstrap_net` passes `level=_GUARD_CI_LEVEL`. Each module constant is read when the call runs, never bound as a default argument, so a test can inject or patch each one.

**Output** (rows 37, 38, 50):
- Compute's stdout and stderr carry the status, its digit-free reasons and its notices, and no figure. The only digits are:
  - `note line <n>` locators;
  - the operator's own `--out` string, which the shared `--out` messages echo, as pr-cost-export's do;
  - the shared git-tracked check's exit-code diagnostic.
- The notices are yes-or-no and per arm: some loops degraded, and some replicates undefined. A loop is degraded when its stored `degraded` is true or compute skipped one of its models. A digit-free STALE PRICING line prints when `pricing._rate_expired` holds for a model compute priced. A public artifact may state the status.
- `--out PATH` writes the figures: the net with its interval, an upper bound that falls on an undefined replicate written as unbounded, the overhead difference, the carry, the gap, branches and loops per arm, growth-defined branches and loops per arm, and the undefined-replicate count. It follows `pr-cost-export --out`'s rules through the helpers both share (M17): the path must not exist, must sit outside any git work tree, and is published `0600`. A refusal exits 2 before any work. The one exception is a dangling symlink at the path, which the publish step refuses (exit 2) after compute and before any status prints, as pr-cost-export's does. A NOT RUN run writes no file, and otherwise the file is published before the status prints.
- After publishing, compute prints one digit-free stderr line saying the file is DO NOT PUBLISH and is read only outside an agent session. The line lives in `routing_guard.py`. The shared helpers carry no notice and no count, and pr-cost-export's own success and notice lines stay in its caller.
- Capture's output and the `--out` file open with one DO NOT PUBLISH banner constant. It cites `docs/private-project-redaction.md` § "A wider corpus goes to the owner, never into a public artifact", says a public artifact states only whether the guard passed and whether the default flipped, and says to run and read both outside any agent session.
- No line in either mode carries a branch name, a config-dir path, an account label or an account count. That covers text `_config` prints. Rows are named by note line. Capture's per-row lines carry this account's round, loop, growth-defined loop and join counts, and its progress lines carry an ordinal and a count of project directories, which the banner covers.

**Flags and exits** (row 75). `--note` is required, so argparse refuses a run without it (exit 2), and `--out` with `--capture` is refused (exit 2). The exit codes mean:
- 0: capture left every row `captured` or `already captured`; compute PASSED.
- 1: capture's account is not opted in or its key read hits a config fault, or capture refused its cwd, through `scope` or because the cwd's repo is not the checkout running the module; compute FAILED.
- 2: a refusal of a flag, the note, a scan gap, a deny, the captures directory or the `--out` path.
- 3: capture left a row `missing` or `invalid`; compute NOT RUN.
- 4: an `OSError` the handler does not otherwise expect, a failed publish, a built row the validator rejects, or any other unexpected exception. One `except Exception` around the handler body maps the last to exit 4 with one fixed message, so a crash never reads as FAILED or as not opted in. `SystemExit` is not an `Exception`, so argparse's and `scope`'s own exits pass through. The run prints only a fixed message or an `OSError`'s `strerror`, so no traceback carries a path or a cell. The repo's ruff selection has no blind-except rule, so the handler needs no suppression (row 85).

`cmd_routing_guard` ends every nonzero exit with `sys.exit`, because `main()` ignores a handler's return value (row 83). Compute exits 1 only for FAILED, never for an opt-in outcome or a config fault, as the Compute paragraph states.

**Windowing provenance.** GH-1312's fix lives in `render._is_fresh_user_prompt`, and the capture applies it when it runs. So no capture this subcommand makes carries the early-close bias, however old the transcript (row 30). Each file name carries `capture_revision`, a module constant starting at 1 that lands with capture, so a later compute fix never bumps it. Compute opens only files at the current value. A golden-file test captures a minimal fixture and compares the published file's name and whole text to literals. Its failure message says to bump `_CAPTURE_REVISION` only when the change alters what a stored row means, and otherwise to update the literal, because a bump leaves every earlier file unpoolable. A file stays valid at the revision of the build that wrote it, so the doc says to run capture only from a tree where this subcommand has merged, never from a branch whose capture logic review may still change. Two loop tests pin the windowing facts the definitions rest on: a task notification does not close a round, and a denied `Skill(code-review)` joins its orchestrator round's loop. A shared-helper change such as a GH-1131 fix fails one of them and prompts the bump (row 31).

**`review_rounds.py` and `pricing.py` changes** (rows 24, 25, 65, 84):

**Alternatives set aside.**
- Storing as-priced dollars with a rate stamp. Refusing mixed stamps makes captures unpoolable across a rate re-verification that changed no rate, and an aged-out branch can never be re-captured. Warning instead compares dollars across stamps, which `docs/pr-cost.md` forbids (row 22).
- Duplicating the window walk in the new module. The guard's overhead could then drift from the `review-round-cost` rounds line 76 names. Calling `compute_review_round_costs` unchanged returns dollars only, which cannot be re-priced (row 24).
- Scoping the capture with `--this-repo` alone. A removed worktree's sessions drop out with no signal, and the branch reads low. Refusing whenever an orphaned worktree directory exists blocks capture in a way the engineer cannot undo (row 9).
- One shared append-only capture file per account, re-derived on every run with the latest row winning. Once a branch's sessions end, its transcripts only lose records (row 81), so a re-derivation can only know less. That design needed a per-loss-route "never replace a fuller row" comparison, which still missed a re-capture that lost only dispatch transcripts. It also needed a strict pre-read, a write-time round trip, newline repair and a short-write loop so one torn line could not corrupt the rest.
- A frozen-header TSV rewritten under a lock, like the pr-cost ledger. Nested per-loop token data does not fit flat columns. One file per branch needs no lock, because `os.link` lets exactly one writer claim a name.
- Writing each file with `O_CREAT | O_EXCL` directly. A crash mid-write leaves a torn file at the final name, which reads `invalid` until the owner deletes it. An fsynced `mkstemp` file plus `os.link` leaves only a temp file.
- An fsync flag on the publish core that only capture sets. pr-cost-export's `--out` and the machine identity gain the same durability at no cost to their messages, exits or temp prefixes, so a flag would add a parameter and a second path for no reader.
- Scoping the "never a partial file at a final name" claim to a process crash instead of adding the fsync. In a write-once store, a torn file left by a kernel crash is permanent once the branch's sessions age out, and one fsync call prevents it.
- A preview mode with a separate write flag. Deleting one file undoes a capture while the branch's sessions are inside retention, so the per-row line read after the run serves the same check. A forgotten write flag could also pass for a capture that never happened.
- A retention-edge condition from `cleanupPeriodDays`. Under last-write retention it flags resumed sessions that lost nothing and misses an older session deleted beside a newer survivor. Under from-creation retention it never fires (row 15).
- An as-of window like pr-cost's `--asof-window-days` (`docs/pr-cost.md:165`). The note decides when a branch is listed, and the doc says to list it once its sessions end.
- Listing the captures directory in compute. Opening each note row's file by name means a stale or unlisted file is never read, so it needs no reader rule.
- Refusing an existing captures directory with group or other permission bits. Each file is created `0600`, so a wider directory exposes only digests. A group- or other-writable one would let a second local user plant a schema-valid file, and this owner-run tool does not defend against a second local user. The doc says a wider existing directory is not tightened.
- A commit SHA or a source hash as the windowing stamp. The SHA changes on every commit, and the hash changes on a docstring edit. Either makes captures unpoolable with no behavior change.
- Choosing key-off branches automatically. Merge status needs `gh` or a branch-to-squash join this checkout does not carry, and pilot state needs the note anyway (row 6).
- A new config key, set aside by the engineer (row 20). Two subcommands, set aside because one with a `--capture` mode mirrors `pr-cost --record` (row 2).
- Raw branch names as file names. Finding a branch's file across runs needs only a stable key, which a digest gives, and `docs/pr-cost.md` keeps the original string out of its ledger (row 51). pr-cost's own `account-N/branch-M` label is set aside too, because it is stable only within one run. A keyed digest would need a per-account secret file and has no reader a plain digest lacks. A plain digest hides a name only from a reader who does not already suspect it, and the doc says so.
- Storing not-whole rows. Compute treats a missing row and a not-whole row alike, and capture prints the reason when it runs.
- Ranking `off` candidates by recency inside compute. Every candidate would need a capture, and the oldest candidates age out first and stop the run (row 6).
- Printing the figures on stdout. Session stdout lands in that session's transcript, which is why `pr-cost-export` has no stdout fallback (row 50).
- Leaving capture unpinned from the checkout's repo. A run from another repo's worktree reads that repo's sessions. A listed branch name that also exists there, such as a generic `fix-typo`, is then published write-once with that repo's spend, and a corrective re-run from the right cwd reports the row `already captured`. The pin's one cost is the patchable `_CHECKOUT_ROOT` that temp-repo tests need.
- Comparing the cwd repo's `git rev-parse --git-common-dir` with the running checkout's. The live slugs `scope` already returns answer the same question with no git call of capture's own, and the comparison would need its own fail-closed handling of each git failure, which `scope` already carries.
- Deriving the slugs from `_CHECKOUT_ROOT` instead of the cwd, so any cwd works. It needs either a `cwd` parameter on `scope._repo_scoped_project_slugs`, which other subcommands share, or a git call of capture's own, and the refusal costs the owner only a `cd`.
- Admitting an orphaned worktree directory only when its sessions' `cwd` sits under `.claude/worktrees/`. A foreign clone under that directory passes the same test, and its sessions count only on a note-listed branch name.
- A `.gitignore` entry for the captures directory. The resolved-path git-tree refusal already refuses a stow-folded config dir before any transcript is read, and the pr-cost ledger carries no such entry. `.gitignore` also matches no `select-tests.py` rule, so the edit would widen every later run to the full suite (row 60).
- Refusing on a deny that falls on a branch listed for another config dir. The branch is listed, so its arm does not shrink silently, and no note edit could clear the refusal, so this account's capture would stay blocked.
- Redrawing a replicate whose resample leaves an arm with no growth-defined loop, with redraws capped at a chosen 5% of the replicate count. Redraws condition the interval on both arms holding a growth-defined loop, which can move the lower bound either way. The 5% had no derivation, and at ten branches per arm with three growth-defined branches in both arms, redraws would pass it and stop the run as NOT RUN. Dropping such replicates conditions the interval the same way. Ranking them below every defined net can only lower the bound, so a PASSED it gave might not hold for the nets those replicates could have had (row 67).
- An upper bound on each count in the validator. It needs a chosen ceiling with no source to cite, and the exit-4 rule already keeps an overflowing count from reading as FAILED.
- The earliest record's age on the `captured` line. It reads the clock, which would date the per-row literal tests, and the round count already gives the owner a figure to read against what they know of the branch.
- Literal-message tests for both `--out` helper callers. Verification 1's `_move_fidelity.py capture` and `compare-captures` steps check pr-cost-export's refusals, the publish-time refusal of a dangling leaf symlink included, and review-round-cost's output against the unmodified tree in one step.
- Dropping the memory test for the plan's statement that records are dropped per session. The measured risk is record dicts kept alive through derived facts, and only a failing test catches that regression.
