# Terraform enum-typing rule + feature-flags layering skill

## Context

A Terraform change modeled a provider-native string-enum argument as a
`bool` variable mapped through a ternary, and a separate conversation
reached toward a dedicated feature-flag platform for a runtime toggle
need that did not yet exist — two defaults this repo's guidance should
surface automatically but does not. The goal is to make both automatic:
a path-scoped Terraform rule so a future `.tf`/`.tfvars` diff gets the
native-enum-typing default, a review-angle bullet on
`staff-platform-engineer` so the same miss is caught at plan/prose time
before any `.tf` file exists in a diff, and a new `feature-flags` skill
carrying the deploy-time-vs-runtime layering test plus an escalation
ordering that instantiates CLAUDE.md's "Default-suspect over-powered
primitives" rule for the toggle domain. Now, because the guidance is
freshly distilled and otherwise decays into a one-off correction; the
intended outcome is that neither question has to be re-derived by a
future session.

A genuinely cold freeform question about toggle placement — no `.tf`
file open, no `/plan-it` dispatch, no `config-environments`
conversation, no review dispatched — is reachable only by the model
recognizing the bare skill name `feature-flags` in its listing, which
is weaker than description auto-trigger. This plan accepts that gap
rather than adding a third, heavier surface to close it: the same
listing-budget arithmetic that rules out an auto-triggering
`feature-flags` (see row 15) also forecloses a fourth always-loaded
surface to close the residual gap it leaves.

## Approach

Ship two independent, automatically-firing surfaces, then one sequenced private-repo follow-up. For Terraform: a stowed path-scoped rule that fires on any `.tf`/`.tfvars` file read, plus one review-angle bullet on `staff-platform-engineer` so the same default is applied at plan/prose time when no `.tf` file exists in the diff yet. For toggles: a new `feature-flags` skill, `skillOverrides: name-only`, reached by name from `config-environments`, a Terraform rule cross-reference, and two reviewer-agent pointers rather than by description auto-trigger — a surface `config-environments` structurally cannot own itself, because its own trigger is env-var naming and credential sourcing — carrying Fowler's four toggle categories, a deploy-time-vs-runtime layering test, and a three-step escalation ordering that instantiates CLAUDE.md's "Default-suspect over-powered primitives" rule for this domain.

**Root:** Two design defaults — model a provider-native string enum as its native type, and reach for the lightest toggle layer that satisfies the need — have no surface in this repo that fires at the moment the choice is made, so each recurs silently until a reviewer happens to catch it.

**Givens** (fixed beyond this plan's reach):

- **G1 — A path-scoped rule loads only when a matching file is read.** Claude Code owns the loading mechanism (`code.claude.com/docs/en/memory` § "Path-specific rules"); no hook or settings key in this repo changes it.
- **G2 — A `SKILL.md` body may carry no `http(s)://` citation outside a code region.** Enforced by `test_skill_bodies_carry_no_citation_urls`; that contract is already committed and is not this plan's to relax — it is a repo-wide structural test applying to every skill, not a rule scoped to this one, so relaxing it here would mean relaxing citation discipline everywhere.
- **G3 — Default `SKILL.md` cap is 200 lines.** `check-skill-length.sh`'s `*` case; a new file over the cap is denied immediately (previous committed length is 0). Raising the cap is a separate policy decision.
- **G4 — Committing any `SKILL.md` requires a `/skill-review` marker.** `plugins/skill-management/hooks/require-skill-review.sh` gates `git commit`; a brand-new `SKILL.md` triggers it identically to an edit — a repo-wide gate on every skill commit, not specific to this diff, so bypassing it here would be inconsistent with every other skill's commit path.
- **G5 — The aggregate skill-listing budget is 8,000 chars and is a hard-failing test.** `SKILL_LISTING_BUDGET_CHARS` is derived from constants extracted from the Claude Code binary; the harness sets the bound.
- **G6 — The private playbook repository referenced in Phase C has its own Proprietary-Information guardrails and no release process this plan controls.** Its edit is therefore a separate commit in a separate session, not a phase of this PR.

- **Layering test and escalation ordering — the skill's substance.** `anchors: root, row10`
  - Test, three questions in order: (1) Does flipping it require a deploy anyway, because it changes infrastructure shape or a provider argument? → deploy-time; it is a typed IaC variable, not a flag. (2) Must it flip faster than the deploy cycle, by a human, during an incident? → runtime. (3) Must it differ for *different subjects at the same instant* — per-user, per-org, per-cohort, percentage? → runtime **with targeting**; only this answer can reach step (c).
  - Escalation: **(a)** deploy-time → a Terraform variable with a `validation` block, set per-environment in `.tfvars` (the same default the new rule enforces); **(b)** runtime with a single global or per-subject boolean → a field in a datastore the team already runs, read behind one accessor, owing the disciplines a platform gives for free (audit trail, default-off, a removal date).
