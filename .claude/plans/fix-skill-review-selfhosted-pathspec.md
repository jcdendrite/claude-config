# Fix skill-review's SKILL.md pathspec for repo-root plugin layouts

## Context

`require-skill-review.sh` — the commit-time gate requiring `/skill-review` before a staged `SKILL.md` change can be committed — scopes its staged-diff check, corpus-budget check, and marker hash to only two SKILL.md layouts: `claude-skills/skills/**/SKILL.md` (this repo's own stowed skills) and `plugins/*/skills/**/SKILL.md` (a project-scoped plugin skill inside this repo). A third valid layout is used by at least one real consumer of the `skill-management` plugin: a repo whose `.claude-plugin/marketplace.json` declares `"source": "./"` (plugin root equals repo root) lays its skills out at repo-root `skills/<name>/SKILL.md`. That layout matches neither existing pathspec, so `SKILL_DIFF` is always empty for such a repo's staged skill changes, and the hook's own early-exit (`if [ -z "$SKILL_DIFF" ] && [ -z "$ROUTING_DIFF" ]; then exit 0`) lets every commit through with no error or denial — a silent no-op, not a loud failure.

This work originated as a fix already implemented, in a worktree in this repo, by a prior session anchored in a different, private consumer repo that is wiring this plugin in as its own commit gate and uses exactly this repo-root layout. That prior session left a handoff brief claiming the fix was complete, tested, and had no open decisions. The engineer asked for an independent `/plan-it` pass over that existing diff rather than trusting the brief at face value, since a session anchored outside this repo may be skewed toward that repo's needs rather than this repo's own conventions.

The intended outcome: the gate correctly covers all three SKILL.md layouts (stowed, project-scoped plugin, repo-root), with any same-file literal-pathspec duplication this diff already touches collapsed into a single shared array per file (per CLAUDE.md's single-source-of-truth rule), verified by existing and new test coverage, reviewed via `/code-review`, and shipped through this repo's own pipeline.

## Approach

Extend the skill-review gate's pathspecs to a third SKILL.md layout (repo-root `skills/<name>/SKILL.md`, used when a marketplace declares `"source": "./"`), and — inside the two bash files the fix already touches — replace every repeated literal pathspec list with a single named constant per distinct list. The pathspec extension is already implemented and verified; the constants are the part that still needed designing, and they are not cosmetic: one of the hook's three pathspec sites had no test covering it, and a named constant is what removes that site's drift risk.

**plan-architect overrode the draft consolidation design as incorrect.** The draft's premise — that `require-skill-review.sh` "repeats the same pathspec list literally at 3 call sites" — is false. Lines 108 and 186 carry three SKILL.md globs; line 221 carries those three **plus** `'claude-skills/skills/plan-review/ROUTING.md'`. A single shared array referenced at all three sites would drop ROUTING.md from the marker hash, breaking the gate for a ROUTING.md-only edit. The correct shape is three constants, with the marker set *derived* from the SKILL set so a future fourth layout reaches both sites by construction:

```bash
SKILL_CONTENT_PATHSPECS=('claude-skills/skills/**/SKILL.md' 'plugins/*/skills/**/SKILL.md' 'skills/**/SKILL.md')
ROUTING_PATHSPEC='claude-skills/skills/plan-review/ROUTING.md'
MARKER_PATHSPECS=("${SKILL_CONTENT_PATHSPECS[@]}" "$ROUTING_PATHSPEC")
```

Each of the four literal occurrences in that file then appears exactly once. `marker.sh` gets one file-scope array rather than a second per-arm one — see Critical files.

The draft's first "given" (that three layouts are the complete set) is dropped rather than carried: its only cited evidence was the SKILL.md prose inside the diff under review, which is circular, and the design does not need it. A fourth layout discovered later is an additive follow-up, not a defect in this change.

### Assumption ledger

**Root problem:** `require-skill-review.sh`'s pathspecs cover two SKILL.md layouts, so in a repo laying skills out at repo-root `skills/<name>/SKILL.md` the staged-diff check returns empty and the gate's own early exit lets every commit through silently.

**Givens:**

- Where a plugin's skills live on disk is fixed by Claude Code's marketplace/plugin resolution, not by this repo — a vendor mechanism imposes it, so the gate can only enumerate layouts, never relocate them. `[verified: .claude-plugin/marketplace.json]` — every entry here uses the `"./plugins/<name>"` subdirectory form; the repo-root form is the same field with `"./"`.
- The plugin's hook cannot source the stowed `marker.sh` or its library — the plugin boundary forbids it, and that constraint is owned by the harness's plugin packaging, not by this change. `[verified: plugins/skill-management/hooks/_lib.sh:9-16]`, which states the rule and records that the repo already answers this class by duplicating function bodies and asserting parity mechanically in tests.
- `claude-skills/skills/plan-review/ROUTING.md` stays a hardcoded single-file exception in the gated set. `[engineer-verified]`

**Per mechanism:**

- **Add `'skills/**/SKILL.md'` to every site that already enumerates SKILL.md layouts** — `anchors: root`. Extends an already-tested git-pathspec match rather than introducing layout detection. Two lighter primitives rejected: (1) reading `source` from `marketplace.json` at hook time — adds a JSON parse and a missing/malformed-file failure mode to a gate whose posture must be fail-closed, and the file can be stale relative to the staged paths it would be used to interpret; (2) a single bare `**/SKILL.md` — rejected for the reason already recorded at `require-skill-review.sh:181-182`, that it sweeps in vendored and fixture files. The `skills/`-anchored form avoids both: git matches a wildcard pathspec against the full repo-relative path, so it cannot reach `plugins/*/skills/...` or any nested vendor tree that does not start at `skills/`.
- **One named constant per distinct pathspec list, within each touched file** — `anchors: row3`. Two lighter primitives rejected: (1) leave the literals and add a test at the untested corpus site — heavier in total, since it buys coverage for one site while leaving the drift class alive at the others; (2) leave the literals and rely on reviewer discipline — this is the failure mode the change is fixing, and the corpus site has no test to catch a recurrence. The array is not a new abstraction: `marker.sh` already uses exactly this shape at line 701, and already holds file-scope constants at line 15.
- **Widen `check-skill-length.sh`'s staged-path pattern with a `^skills/.+/SKILL\.md$` alternative** — `anchors: row8`. Two lighter primitives rejected: (1) add a bare `skills/` branch to the existing alternation — rejected because `grep -E` is unanchored, so an unanchored branch would also match `vendor/x/skills/y/SKILL.md` and `plugins/p/skills/s/SKILL.md`, the same vendored-file sweep already rejected for the pathspec side at `require-skill-review.sh:181-182`; (2) fix only the skill-review gate and leave this one — rejected because the two gates enforce unrelated properties (review-performed vs. length), so the silent no-op survives in the length gate regardless. No override-config mechanism is built alongside this — see ledger row 8's premise correction; that would have been a materially heavier primitive (a new repo-local hook-config-file precedent) solving a problem the corrected premise shows doesn't exist yet.
