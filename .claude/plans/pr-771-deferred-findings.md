## Approach

Three independent fixes, one dispatch-shape change and two test-coverage gaps, plus two tracking issues for the residuals we are deliberately not closing.

**Finding 1 — dispatch mismatch.** `require-ready-for-review.sh` stops depending on `settings.json` `if`-prefix globs for its coverage. The three `if`-scoped entries (`Bash(git push *)`, `Bash(gh pr ready *)`, `Bash(gh pr create *)`) collapse into one entry with no `if`, so the hook fires on every Bash call and self-filters internally — the shape `block-gh-pr-merge.sh`, `require-respond-pr.sh`, `deny-private-project-refs.sh`, and `deny-pii-in-commits.sh` already use, and the shape the repo's own rules require ("Hooks must filter their own input by tool name and matcher; do not rely solely on settings.json `if` conditions" — repo `CLAUDE.md`; "The script's internal regex is the authoritative gate… A drift between `if`-pattern and internal regex creates silent coverage gaps" — `plugins/claude-hook-review/skills/claude-hook-review/SKILL.md:120`). All three arms are fixed together, not just `gh pr create`: the `git push` arm is the worst of the three, since its in-script tokenizer is explicitly built for `git -C <path> push`, `GIT_DIR=… git push`, and `eval git push` — shapes a `git push ` prefix glob cannot deliver. No script-internal detection logic changes; the in-script regexes already handle these shapes, as the existing wrapper-shape tests show. The hook header's "Separately, the settings.json `if`-dispatch entries are prefix globs…" paragraph is replaced by a `Dispatch:` paragraph in the sibling hooks' established form. The "cooperative, not adversarial" threat model this gate family shares (per `require-respond-pr.sh`'s header) holds for this gate specifically because `block-gh-pr-merge.sh` prevents the agent from self-merging and CI reruns the full suite on push — a deliberately-evaded gate still cannot land unreviewed code on `main` without a human clicking merge. State that backstop explicitly in the `Dispatch:` paragraph, not only in this plan, so a future reader doesn't mistake this gate for the actual security boundary (`ciso-reviewer` finding).

**Finding 1 residual — ticket only.** The `--dry-run` bypass's whole-`$COMMAND` grep is filed as a GitHub issue, not fixed. Engineer-decided.

**Finding 2 — `code-writer.md` self-review scope.** A whitespace-normalized substring pin in `test_skills.py`, following the `_agent_body(name)` pattern `TestConventionSkillWiring` already uses for the same agent file. There is no in-repo harness for behaviorally testing an agent's instruction-following, so a prose pin is the available shape, not a compromise.

**Findings 3 and 4 — `_NEGATION_DISQUALIFIER_RE`.** The regex stops matching bare independent keywords and instead binds the negation to the construction it is meant to catch — the sentence's own mandatory modal, or a conditional carve-out — mirroring how `_ADVISORY_DISQUALIFIER_RE` (defined three lines above it, applied to the same sentence in the same test) already solves this class by matching full multi-word phrases. Two fixture tests bracket it: the existing true-positive test is widened so each arm is proven independently, and a new non-match test proves a strengthening reword survives the whole three-check tripwire.

### Mechanisms, and the lighter primitives rejected

Removing the `if` conditions is the widest available dispatch, so it needs the over-powered-primitive check (**anchors: row5**). Three lighter primitives exist and each fails:

- **Broaden the existing globs to cover wrapper shapes.** Fails on G1: coverage would rest on matcher semantics this repo treats as unverified, and every new shape needs a new entry kept in sync with the in-script regex — the drift `claude-hook-review/SKILL.md:120` names as producing silent coverage gaps.
- **Add one `if` entry per wrapper word** (`Bash(eval *)`, `Bash(env *)`, `Bash(xargs *)`, …). Fails on unbounded enumeration: an env-var prefix is an arbitrary token, so `GH_TOKEN=x gh pr create` and any sibling of it have no finite prefix set.
- **Keep the `if` dispatch and have a separate always-on hook forward to it.** Fails on cost and on principle: it pays the same per-Bash-call dispatch the `if` was meant to save, and it is a second defensive layer added to close the first layer's gap — the wrong-foundation tell in global `CLAUDE.md` §Working Style.

For `_NEGATION_DISQUALIFIER_RE` (**anchors: row17**), two lighter options were weighed: keeping the broad disjunction and subtracting an exemption list of reinforcement idioms (`not merely|not just|not only`), rejected because its failure mode is a silent false *pass* — "not only is it out of scope…" would be exempted, losing exactly the guarantee the tripwire protects; and dropping the negation check entirely, rejected because it is the only one of the three checks that catches the "keeps the modal, negates it into an exception" reword.

### Prescribed regex

```python
_NEGATION_DISQUALIFIER_RE = re.compile(
    r"\b(?:" + "|".join(_MANDATORY_MODAL_TOKENS) + r"|does|do|will|would|can|may)\s+not\b"
    r"|\bno longer\s+(?:" + "|".join(_MANDATORY_MODAL_TOKENS) + r"|in scope)\b"
    r"|\bunless\b",
    re.IGNORECASE,
)
```

Reusing `_MANDATORY_MODAL_TOKENS` is deliberate: the check is "this sentence's own mandatory modal is not negated," so adding a modal to that tuple should extend both checks together. `unless` stays unbound because any `unless` in this one sentence makes the guarantee conditional, and a strengthening reword has no use for it. The comment above the definition (currently the "Known false-positive class…" paragraph) is replaced — it describes current behavior, not a historical record, so it must not go stale — stating one fact per sentence: the match is bound to the sentence's mandatory modal; a negation attached to a trailing reinforcement clause is not a carve-out and must not match; `unless` matches unbound and deliberately over-triggers.

The `does|do|will|would|can|may` disjunct is net-new — none of `_MANDATORY_MODAL_TOKENS`' 3 tokens (`stays`, `is`, `remains`) exercise it, and neither the widened true-positive test nor the new non-match test (below) builds a fixture using it. At least one true-positive fixture must exercise this branch specifically (e.g. "…stays in scope, though it does not apply when X."), the shape it exists to catch (`staff-sdet` finding).
