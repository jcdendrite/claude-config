# Orphaned ledger-citation guard

## Context

Give `/plan-review` a mechanical, fail-closed check that every ledger-style
citation in a plan resolves to a defined row, and constrain `plan-architect`
so it cannot style its own inference with engineer authority.

A `/plan-review` round on a private repo let a reviewer's explicitly
hedged speculation get promoted into an authoritative-looking assumption-ledger
citation that no ledger row ever defined. Round 1's reviewer raised a
correctly-hedged concern about an unresolved implementation detail.
Between rounds, `plan-architect` revised the plan to answer that
concern and converted the hedge into a flat, unhedged assertion, citing it
inline with a ledger-style label formatted exactly like the plan's real
`[engineer-verified]` rows — but the label was never added to the ledger with a
quote or tag. Round 2's five specialists, including a security reviewer who
built a Critical/BLOCKER finding on top of it, all treated it as established
engineer-confirmed fact; none traced it to a source. Round 3's revision patched
around the citation rather than through it. When the engineer was finally asked
directly, the claim was flatly false.

Why now: nothing structural requires a ledger-style citation to resolve to
anything real, so this recurs by default. `plan-review/ROUTING.md`'s existing
"Ledger cross-check" diffs a revision against every `[verified]` /
`[engineer-verified]` row — it assumes every citation already *has* a row to
diff against, and fires only on a re-review round. A citation that never got a
row in the first place falls through it entirely. It was caught in round 3 only
because several specialists happened to converge on the same angle.

Intended outcome: an *orphaned* citation — one that resolves to no ledger row at
all — stops being a thing a reviewer has to notice. `/plan-review` Step 3 runs a deterministic check before any specialist is
spawned, and that is the only layer protecting the round in progress; CI
re-runs the same check on any plan file in a pushed diff, which is a post-hoc
catch on the merged artifact, so a round where Step 3 itself is abbreviated
has no coverage until the plan is committed and pushed (Row 20 gap 1). The harder sibling variant, where an author fabricates the citation *and* a
matching ledger row to receive it, is not closed mechanically by anything in this
plan: the checker resolves labels and never judges whether a row's content is
true or its tag honest, so that variant exits 0. What this plan offers against it
is a fourth ledger tag plus two prose carve-outs — a constraint on the authoring
agent's own compliance, not a gate. Both halves are stated here so no reader has
to reach Out of scope to learn which one is mechanical.

## Approach

Add one deterministic script that proves every intra-plan ledger citation resolves to a label the plan actually writes down; invoke it from `plan-review` Step 3 so it runs before any specialist is spawned; back that prose trigger with a CI pytest scoped to the plan files in the current diff; and add a fourth ledger tag — `[author-inferred]` — so a plan author has a truthful place to put its own reasoning instead of borrowing `[engineer-verified]`'s authority. The script and the CI test close the symptom (a citation pointing at nothing). The tag and the two prose carve-outs constrain the laundering mechanism (an inference dressed as a human-sourced fact) without gating it.

**Root:** A ledger-style citation in a plan file can resolve to nothing, so a plan author's own inference acquires engineer authority and propagates unchallenged through every downstream review round.

**Givens:**
- **G1** — Plan-file label vocabulary is per-plan and open: `Row N`, `G N`, `U N`, `A N`, `M N`, `S N`, `I N` all appear across the committed corpus, each plan inventing its own alphabet, and some plans number their rows positionally with no written label at all. Beyond reach: the committed plans are preserved records under `CLAUDE.md` §Scope discipline Axis 3, so normalizing their labels is a decision outside this plan; the checker accommodates the shapes that exist and reports the ones it cannot resolve. Corpus size: 262 files carry an `anchors:` line, re-measured this dispatch; the 373-file denominator is `staff-platform-engineer`'s round-2 re-measurement, not this dispatch's.
- **G2** — The originating incident's plan lives in a private repo and may not be quoted, named, or characterized in anything committed here. Beyond reach: root `CLAUDE.md`'s redaction policy is repo-wide and this plan does not revisit it. Consequence: every fixture in this PR is synthetic.

**Rows:**

**Row 1** [mechanism]: Site-discriminated citation grammar — the discriminator is *which site a token sits at*, not whether backticks surround it — anchors: root — a ledger citation's defining property is that it appears at one of the grammar's own citation sites, and the three sites are not alike: site (a) is structural (an `anchors:` key and its value), while sites (b) and (c) are lexically ambiguous with ordinary prose. Backticks mean different things at each. Two derived texts, both line-preserving (each stripped span is replaced by an equal count of newlines and spaces, never deleted, so a reported line number is the file's real line):

- `fence_stripped` — fenced code blocks removed. **Site (a)** scans this: after an `anchors:` key, consume comma-separated label-shaped tokens until the first stop boundary (em-dash, backtick, `]`, newline, or sentence-final period), skipping `root` and `givens`; a non-label-shaped word such as `value` or `line` is itself a stop, so prose like "every row's anchors: value" yields nothing. This handles the comma-separated multi-target form (`G4, row12`) that the corpus already writes.
- `span_stripped` — `fence_stripped` with inline code spans additionally blanked. **Sites (b) and (c)** scan this: (b) the literal word `row`/`rows` immediately preceding a number, case-insensitive; (c) a bare label alone inside square brackets, `\[\s*[A-Za-z]{1,3}\s?\d+[a-z]?\s*\]`.
- `find_citations` returns unique `(line, normalized-token)` pairs, so a plain `— anchors: row2 —` matching at both (a) and (b) is reported once.

The resulting rule is one sentence with one escape hatch: **an `anchors:` clause outside a fenced block is a citation; a fenced block is how a plan quotes one as an example.** `check-handoff.py:94-99`'s `strip_code_spans()` is the model for the fence half and for line-preserving substitution generally — its own substitution collapses lines, which this script cannot do because it reports them. `[verified: claude/.claude/scripts/check-handoff.py:94-99 — "Remove fenced code blocks and inline code spans -- the natural way a draft would quote a literal string it's citing rather than proposing as a real next step, so a placeholder or anchor-shape scan does not fire on it"; its `_FENCED_BLOCK_RE` at :77 and `_INLINE_CODE_RE` at :78 are separate compiled patterns, so splitting their application is a use of that file's own structure rather than a departure from it; called from check_placeholder_text at :165 and check_section3_anchor_shapes at :191]`

**Over-powered-primitive check on Row 1's grammar (anchors: row1).** Three lighter primitives named and rejected, each against a measurement rather than an argument:
- (a) **Uniform code-span stripping across all three sites** (the round-2 design). Rejected: measured this dispatch, 179 of the 262 `anchors:`-bearing plan files wrap the clause in an inline code span (1,413 of 2,261 `anchors:` lines corpus-wide). Several files are entirely in that style — `detect-noop-fork-dispatch.md` and `hook-family-standardization-phase4.md` are 30 of 30 each, `claude-md-conventions-rule.md` and `hook-standardization-guideline-fixes.md` 27 of 27 — so uniform stripping switches site (a) off completely for them, and a fabricated citation in the corpus's dominant authoring style exits 0.
- (b) **No stripping at all.** Rejected: site (b) then fires on every quoted token a grammar-documenting plan writes, including this plan's own `` `row12a` `` test-fixture reference, and site (c) reinstates round 1's bracketed-literal false positive. Stripping is load-bearing at (b) and (c) precisely because it is wrong at (a).
- (c) **Drop sites (b) and (c), keep only site (a) on raw text** — the genuinely lightest option, and the one I looked hardest at. Rejected because it drops the incident's own shape: per Context, the fabricated label was cited *inline in prose*, not as an `anchors:` value, so site (a) alone would not have caught it. Sites (b) and (c) are not decoration — (b) has 98 corpus files carrying a `see/per/in row <N>` prose reference, re-measured this dispatch.

**Row 2** [mechanism]: Lenient collector of *written* labels, scoped to the plan's ledger region — anchors: row1 — a strict collector is the dominant false-positive source, because the documented grammar string is the least common shape in practice; an *unscoped* collector is a false-negative source, because a short code defined elsewhere in the file for an unrelated purpose silently becomes a valid citation target. Shape leniency: a line defines a label when, after stripping leading whitespace, list markers (`-`/`*`/`+`), blockquote `>`, an optional leading table pipe `|`, and optional `**`/`__`, it starts with `Row <N>` (optional space, optional alphanumeric suffix) or `<1-2 letters><digits>`, followed by a boundary (`**`, `|`, `:`, `—`, `-`, `(`, backtick, or end of line). Site scoping: definitions are collected only from a **ledger region** — every level-2 (`##`) section of `fence_stripped` containing at least one `anchors:` line, plus the pre-heading preamble if the `anchors:` line sits above the first `##`. Citations are scanned file-wide, since a plan legitimately writes `see row 4` in Critical files. Matching normalizes by lowercasing, removing spaces, stripping a leading `row`/`rows` word before a letter-label, and stripping a sentence-final period, so `Row 1` and `row1` are one label and a G2-targeting anchor resolves to the `G2` given. `root` and `givens` always resolve. A file with no `anchors:` line has no ledger region: it defines nothing, cites nothing, exits 0. The collector reads labels the plan *writes*; it never infers one from a row's position in a list — Row 15 carries that call and its measurement.

A Base item would run at Step 5 — after specialists spawn, which is exactly when the incident's fabricated claim was inherited by five reviewers. **Row 4** [mechanism]: A CI pytest scoped to the plan files in the current diff, as a second layer under Step 3, **failing rather than skipping when it cannot determine what to check** — anchors: row3 — Step 3's trigger is prose, and the realistic failure path is Step 3 being abbreviated under the same pressure that produced the originating incident, not a session bypassing `/plan-review` outright (`require-plan-review.sh` already blocks that at the Write/Edit/ExitPlanMode boundary). ### Script contract

`claude/.claude/scripts/check-ledger-citations.py`, stowing to `~/.claude/scripts/check-ledger-citations.py`, so it reaches every stow consumer. Python 3, standard library only (`re`, `sys`, `pathlib`) — no new dependency, mirroring `check-handoff.py`. Unlike `check-handoff.py` it needs no `parents[3]` repo-root resolution, because it reads only its argument.

- **File metadata:** first line `#!/usr/bin/env python3`, and the file is committed with the executable bit via `git add --chmod=+x`. Production invocation is a bare path with no interpreter prefix, so both are load-bearing; `check-handoff.py` carries both and is the precedent. Nothing in CI enforces this for a `.py` script today (see Out of scope), so the bare-path CLI test below is what proves it.
- **CLI:** `check-ledger-citations.py [--quiet] <path-to-plan-file>` — exactly one positional argument, with an optional leading `--quiet`.
- **`--quiet`:** print nothing at all when the file passes; output is unchanged when it fails. It exists for the corpus sweep, where the default output is thousands of lines of PASS and residual-block text. `plan-review` Step 3 never passes it. The lighter alternative — redirecting the sweep's output and grepping it back — was rejected because it reintroduces exactly the discard-then-triage problem Row 23's bucket assignment depends on not having.
- **Exit codes:** `0` no orphan citations, including a plan with no `anchors:` line at all; `1` at least one orphan; `2` CLI-level error (wrong argument count, unknown flag, missing file, non-UTF-8) with an actionable stderr message naming the path. Mirrors `check-handoff.py:214-283`.
- **stdout on pass:** `PASS: every ledger citation resolves (<N> labels defined, <M> citations checked)`.
- **stdout on failure:** one line per orphan — `FAIL: <path>:<line>: citation '<token>' resolves to no defined ledger label` — followed by one `Defined labels: <comma-separated sorted list>` line, so an author can diagnose a false positive without reading the script. That line is also the affordance Row 15 relies on: a plan whose rows carry no written label gets back `Defined labels: givens, root`, which names the real problem in one line. The path prefix is what makes a sweep's output self-describing without a wrapper echoing filenames.
- **Always printed, pass or fail** (unless `--quiet` suppressed a pass), a `Not checked by this script:` block in `check-handoff.py`'s `RESIDUAL_CHECKLIST_ITEMS` spirit (`check-handoff.py:50-59`), listing exactly what the script's silence does not cover: whether a defined row's content is true (a fabricated row carrying a real label passes); whether a row's tag matches its actual provenance; citations to sources outside this file (`file:line`, doc sections, ticket IDs); any citation inside a fenced code block, which is treated as quoted rather than asserted; and whether a plan's rows carry written labels at all — a ledger numbering its rows by list position defines none, and the `Defined labels:` line is the only signal of it. Printing it on every non-quiet run is what stops the exit-0 from being read as a truth claim.
- **Module surface, for direct unit testing and for the diff-scoped test's import:** `strip_fenced_blocks(text) -> str` and `strip_inline_spans(text) -> str` (both line-preserving, and separate because Row 1 applies them to different sites), `normalize_label(token) -> str`, `collect_defined_labels(text) -> set[str]`, `find_citations(text) -> list[tuple[str, int]]`, `find_orphan_citations(text) -> list[tuple[str, int]]`, and `main(argv) -> int`. Each is importable without side effects, matching `check-handoff.py`'s own shape.
- **Deliberately not attempted:** truth-checking a row's content; tag-correctness; inferring a label from a row's list position; the transitive anchors-reach-root parse; cross-file resolution.
