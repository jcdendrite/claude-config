# Script plan-it Step 5's file-state checks and scaffold

## Context

Goal: replace three prose procedures in `/plan-it` Step 5 (the "Plans without the four headings" shape test, the three-condition Check, and the scaffold append) with one read-mostly Python script that gives a deterministic answer, so the agent stops hand-counting `## ` headings outside fenced code and hand-typing scaffold bytes.

Ask: "I'd like you instead to focus on the follow ups for the plan architect edit PR, namely turning prose into scripts, abstracting out the linting and the scaffolding" and "let's do plan-it on the shape test and check plus the scaffold". Origin: a non-blocking comment on the merged plan-architect edit PR (#1299) asking whether Step 5's deterministic checks should be a script. Earlier the engineer framed the principle as "anything that doesn't require judgment… anything that's mechanical, whether it can be checked or written, those can be candidates for scripts."

What exists today, all in `claude-skills/skills/plan-it/SKILL.md` Step 5:
- **Scaffold:** at first authoring, append one blank line and exactly `## Approach\n\n(pending: plan-architect)\n\n## Critical files\n\n## Verification\n\n## Out of scope\n`.
- **Plans without the four headings:** before the first dispatch, a file with more than the title and Context but no `## Approach` heading line, or whose region from `## Approach` on carries a heading line other than the four, is a failed Check and goes to the engineer via `AskUserQuestion`.
- **Check:** after any dispatch or splice, three conditions must hold: the first non-blank line under `## Approach` is not `(pending: plan-architect)`; the heading lines from `## Approach` on are exactly the four headings in order; each heading has at least one non-blank line before the next heading or end of file. Every heading test counts only line-start `## ` lines outside fenced code.
- **Context hash:** `sed -n '1,/^## Approach$/p' "<plan path>" | sha256sum`, compared across dispatch, return and splice. This stays a shell command. The gate it backs is untrusted-input tier, so its trust root should not move into a script.

Constraints and session proposals (mine, not the engineer's words):
- Precedent for shape: `claude/.claude/scripts/plan-push-preflight.py` (stdlib Python, `KEY: value` stdout lines, exit 0 on a decision, 2 on usage error) with tests in `claude/.claude/scripts/tests/` and a bullet in `docs/scripts.md`.
- Proposed modes: `scaffold <plan>` (writes), `preflight <plan>` (read-only shape test), `check <plan>` (read-only three-condition Check).
- An optional Effort section above `## Approach` is allowed by Step 5 today. Proposed: it is not a legacy shape, because the shape test examines the region from `## Approach` on and the title-and-Context region above it.
- Existing tests in `claude-skills/skills/tests/test_skills.py` (`TestPlanItStep5ContextCheckAndGrammarLiterals`) extract the scaffold bytes and the hash command from the SKILL.md prose and run them. Scaffold and Check extraction tests move to direct script tests; the hash-command tests stay; the `plan-architect.md` wiring tests stay unchanged.
- Out of scope for the script: the splice, re-dispatch triggers, open-decision handling, and the `AskUserQuestion` itself, all of which need judgment.

## Approach

Add one stdlib Python script, `claude/.claude/scripts/plan-shape.py`, with two modes. `prepare` runs before a run's first dispatch: it appends the four-heading scaffold when the file holds only its title and Context, and only reads any other file. `check` runs after every dispatch and only reads. Both accept only a file directly under a `.claude/plans/` directory. Both print `KEY: value` lines, and the verdict is positive only when no `REASON` line prints. Before every dispatch, Step 5 runs the script after its last edit above `## Approach` and before the Context hash, so the script's file-level conditions cover the bytes each hash covers. Step 5 keeps only when to run each mode and how to read its output, and the script's docstring owns the exact path, heading, fence and file rules.

Alternatives set aside:
- **Three modes (`scaffold`, `preflight`, `check`), the session's proposal (row 3).** `scaffold` must re-run the shape test as its own guard, so a separate `preflight` call only feeds it, and nothing consumes a dry run. One `prepare` mode removes the session-side branch where the scaffold could be skipped or misordered. It is idempotent: on an already-scaffolded file it writes nothing and prints the same state.
- **A `grep -n '^## '` one-liner in the skill.** It cannot skip fenced lines.
- **An `awk` one-liner that tracks fence state.** It carries its own control flow, which `claude/.claude/rules/shell-script-conventions.md` (last bullet) routes to a `.py` file with its own tests.
- **Reusing an existing fence scanner.** `test_skills.py`'s `_closed_fence_line_indices` is uninstalled test code that reads an unclosed fence as prose (row 13). `_review-ledger-lib.sh`'s scanner is jq inside a shell library, and it strips a trailing CR where this script stops on one (row 12). The script reimplements the ledger library's fence rule in Python. That two-language duplicate is accepted, because sharing it would need one language to shell out to the other.
- **Folding the Context hash into the script.** The hash is already one deterministic command with no hand judgment left in it, and the Ask names the shape test, the Check and the scaffold. A fence-blind range computed apart from the parser cross-checks it. The session also compares digests across calls, state a stateless script does not hold. The script instead refuses a file where the two ranges would start at different lines (M3 `hash-range`).
- **Pinning the stdout keys with a duplicated tuple in `test_skills.py`, as `plan-push-preflight.py` does (row 7).** Its two copies are never compared, so a key renamed in the script and the script's own test passes while the skill still names the old key. The script's own test reads the skill instead, as `resume-context`'s does (row 6).
- **`prepare` printing the scaffold for the session's own `Edit`.** That keeps the write on the tool path the hooks see, but the session would copy the bytes into `new_string` by hand, the transcription the Root removes. The append stays, confined by M3's path rule.
- **Accepting any path ending in `.md`.** It admits any skill, agent, rule or memory file whose only heading line is `## Context`, outside both nearby path rules (row 31).
- **Confining the path to the repository root, as `_lib_is_repo_plan_file` does.** Its callers find the root with `git rev-parse` (row 31), a subprocess this script does not run. A `.git` probe beside `.claude` would need none, but it refuses the plan-mode harness path, which sits under the config directory (row 24). Step 5 dispatches on that path today, because `plan-architect` returns its sections as text there and the session splices them (row 30). A name rule on the resolved parent admits a repository's `.claude/plans/` and the plan-mode path under a config directory named `.claude`, and still excludes the standard skill, agent, rule and memory locations. Under a config directory with another name it refuses the plan-mode path, a stop Step 5 routes to the engineer (M8, Out of scope).

**Root:** `/plan-it` Step 5 has the session apply mechanical rules by hand. It counts `## ` heading lines outside fenced code, types the scaffold bytes, judges whether a file holds "more than the title and Context", and judges whether the placeholder is still present. A script gives one deterministic answer to each, and Step 5's prose shrinks to when to run it and how to read what it prints.

**Mechanisms:**
- **M1 — The script.** `claude/.claude/scripts/plan-shape.py`: `#!/usr/bin/env python3`, committed with mode `100755` as `plan-push-preflight.py` is, stdlib only, no subprocess, no network, Python 3.11 grammar and only stdlib names 3.11 has. Usage: `plan-shape.py prepare|check <absolute plan path>`. The session runs `python3 ~/.claude/scripts/plan-shape.py <mode> '<plan path>'` (G1). The module docstring owns every rule in M2-M7, every key, every reason code and the exit status. It lists the keys on one `Keys:` line and the codes on one `Reason codes:` line, each comma-separated. Each line is tested once against anchored patterns with no nested quantifier, so the scan is linear in the file's size, a constraint reviewed with the diff rather than tested. The lighter primitives (a grep line, an awk line, an existing scanner, printing the scaffold for an `Edit`) fail as the Approach says. anchors: root, row1, row2, row3, row20
- **M2 — Bytes, lines, headings and fences.**
  - The script reads the file's bytes through the descriptor M3 opens and decodes them as strict UTF-8. It never reads through text-mode `open`, which translates line endings. Lines are the text split on `\n` only, numbered from 1 as `sed` numbers them. A final `\n` ends the last line rather than starting an empty one. anchors: row14, row21
  - A blank line holds nothing but U+0020 and U+0009, so a line of U+00A0 or U+000C is not blank. anchors: root
  - A heading line is a line outside fenced code whose first three characters are `## `, the rule Step 5 states today. Heading identity is exact line equality, so `## Approach ` with a trailing space is a heading line but not `## Approach`. The docstring says this rule is narrower than a CommonMark ATX heading: ` ## X`, `##` followed by a tab and `X`, and a bare `##` render as headings but are not heading lines here. anchors: root, row13
  - Opener: up to three spaces, then three or more backticks or three or more tildes. For a backtick run, the rest of the line holds no backtick, while a tilde run's rest may hold one. A tab in the indentation disqualifies the line. anchors: row12
  - Closer: while a fence is open, up to three spaces, then the opener's character at least as many times as the opener's run, then only spaces or tabs. Every line from opener to closer is fenced, and an opener-shaped line inside is content. anchors: row12
  - A fence still open at the end of the file is the file-level `unclosed-fence` (M3), which cites the opener's line number. This departs from CommonMark (row 13) on purpose, because under its rule a forgotten closer hides every later heading. anchors: row12, row13
  - One pure function computes, from the lines, the fenced line numbers and the opener's line of any fence still open at the end. Every branch that tests heading lines reads its result, and M9 tests it directly. anchors: row12
  - Not modeled: list items, block quotes, HTML blocks, indented code and setext headings. A column-0 `## ` line inside a list-item fence that CommonMark would end early therefore reads as fenced. This is accepted, because `/plan-review` reads the plan next. anchors: row13
- **M3 — File-level conditions, both modes, checked first in this order.** Each of the first five ends evaluation, so the output is the negative verdict and that one `REASON` line.
  - `plan-path`: the argument must be absolute, with every segment after the leading `/` non-empty and neither `.` nor `..`. Its last segment must fullmatch `[A-Za-z0-9][A-Za-z0-9._-]*\.md`. Its parent, resolved with `os.path.realpath`, must be a directory named `plans` whose own parent is named `.claude`. The script then opens the resolved parent joined with that name. This admits a repository's `.claude/plans/` and the plan-mode path under a config directory named `.claude`, and none of the standard skill, agent, rule or memory locations. Under a config directory with another name it refuses the plan-mode path (row 24), and Step 5 routes that stop to the engineer (M8). The docstring says in one line that the `.claude` test is what keeps an arbitrary `plans` directory out, so dropping it is not the repair for that stop (Out of scope). The file is never opened when this fails. anchors: row24, row30, row31, row32, row33
  - `unreadable`: the script opens the file once, with `O_NOFOLLOW | O_NONBLOCK` plus `O_RDONLY` for `check` or `O_RDWR | O_APPEND` for `prepare`. It then requires `fstat` on that descriptor to show a regular file. A missing file, a symlink at the last component, a directory, a FIFO (which `O_NONBLOCK` keeps from blocking), a failed open and a failed read all land here. The read and any append use that one descriptor. The fixed sentence names the access the mode needed. anchors: root
  - `not-utf8`: the bytes do not decode as strict UTF-8. anchors: row23
  - `carriage-return`: a CR appears anywhere, a lone CR and a fenced CR included, cited by the first CR's line number. The script never rewrites line endings. The stop is diagnostic, not a safety rule. A CRLF plan still fails closed without it, because its hash range runs to the end of the file (row 14) and the digests differ after the dispatch. But the engineer would then see a digest mismatch instead of its cause, after an Opus dispatch was spent. anchors: row14, row23
  - `unclosed-fence`: M2.
  - `hash-range`: Step 5's Context hash ends at the first line from line 2 on that reads exactly `## Approach`, fenced or not, or at the end of the file (rows 15, 25). The condition holds when that end is not the `## Approach` heading line: the heading line is line 1, a line reading exactly `## Approach` comes before it, or the file has no heading line but has such a line. It cites those line numbers. It is reported with the mode's own conditions rather than ending evaluation. This makes Step 5's "Context never carries a line reading exactly `## Approach`, fenced or not" mechanical, so the hash range and the parsed region start at the same line.
