# Disable Artifact/Workflow by default, with per-session opt-back-in

## Context

Default `disableArtifact` and `disableWorkflows` to `true` in the shared, tracked `claude/.claude/settings.json`, so every stow consumer's session skips loading the `Artifact` and `Workflow` tool schemas — the two largest eagerly-loaded tool schemas in every session's system prompt (9,432 and 19,371 characters; `docs/design-decisions.md` §28) — by default rather than opt-in. §28 (2026-08-21) investigated this and deliberately chose *not* to set either key repo-wide, reasoning that publishing Artifacts and running Workflows are legitimate for many stow consumers and the shared config shouldn't impose the choice; it shipped a personal-shell-profile env var instead, which reaches nobody who merely installs this repo. The engineer has now decided the tradeoff should flip: the schema cost is unconditional and paid every session, the benefit is occasional, and pairing the new default with a one-command per-session opt-back-in (`claude-workflow`, `claude-artifact`, analogous to the existing `claude-auto` wrapper) removes the downside §28 was avoding. This plan documents that reversal, ships the default, ships the two wrappers, and gates the whole change behind a pre-committed `/context` measurement since §28 explicitly left "does disabling actually strip the schema, or only block invocation" unverified.

## Approach

Flip `disableArtifact`/`disableWorkflows` to `true` in `claude/.claude/settings.json`, and ship `claude-workflow`/`claude-artifact` as thin wrappers over one shared script that re-enables one tool for one session by passing `claude --settings '{"disableWorkflows": false}'` (respectively `disableArtifact`) — CLI scope, which outranks the User-scope default. Gate the whole change behind a pre-committed `/context` before/after measurement.

### Assumption ledger

**Root:** every session a stow consumer starts pays for the eagerly-loaded `Artifact` and `Workflow` tool schemas (9,432 and 19,371 characters, `docs/design-decisions.md:337`) whether or not it uses either tool, and the only per-user escape §28 shipped — an env var exported from a personal shell profile — reaches nobody who merely installs this repo.

**Givens** (fixed conditions beyond this plan's reach):

- **G1.** For a stow install, the User-scope settings file (`~/.claude/settings.json`) *is* this repo's shared tracked `claude/.claude/settings.json`; Claude Code's documented scope list contains no second globally-scoped file. Vendor-imposed scope model. `[verified: docs/design-decisions.md:341; CLAUDE.md's "claude/.claude/ maps 1:1 to ~/.claude/" layout rule]`
- **G2.** `CLAUDE_CODE_DISABLE_ARTIFACT` / `CLAUDE_CODE_DISABLE_WORKFLOWS` are independent disable triggers OR-combined with the settings key, not overrides of it — so no env var can re-enable a settings-file `true`. Vendor-imposed. `[engineer-verified: /docs/en/artifacts "Disable artifacts" and /docs/en/workflows "Turn workflows off", fetched this session]`
- **G3.** `enableArtifact` is scope-restricted to User-or-managed, and by G1 the User file is the shared tracked one — so it cannot express a personal override for a stow consumer. Vendor-imposed. `[engineer-verified: settings reference Scope column, this session]`
- **G4.** Whether these settings strip the tool schema from the system prompt or only block invocation is undocumented; §28 recorded the distinction as explicitly unverified and nothing has closed it since. Vendor-owned. `[verified: docs/design-decisions.md:339]`
- **G5.** A new `claude/.local/bin/` entry does not materialize on `git pull` — only `./install.sh` re-stows it — while a `claude/.claude/settings.json` change is live on pull, because the symlink already exists. `[verified: README.md:107; install.sh:275]`
- **G6.** The precedence of two `--settings` flags on one command line is undocumented. Vendor-owned.

**Mechanisms:**

- **M1 — `"disableArtifact": true` and `"disableWorkflows": true` in `claude/.claude/settings.json`.** The only file that reaches every consumer's session unconditionally. `anchors: root`
- **M2 — `claude/.claude/scripts/claude-enable-tool.sh <artifact|workflow>` invoked by two `~/.local/bin` wrappers, injecting `--settings` with an inline JSON string.** CLI scope (precedence 2) is the only scope that outranks the User-scope default from outside a specific repository. `anchors: G1, G3`
  - *Over-powered-primitive check* — three lighter primitives, each rejected: **(i)** document the raw `claude --settings '{"disableWorkflows": false}'` invocation in README and ship no script — fails because a shared default that every consumer inherits should ship its escape hatch rather than requiring each consumer to reconstruct a shell-quoted JSON literal per invocation; **(ii)** a documented shell alias or function for the consumer's own profile — fails because stow cannot deliver it, and this repo's established mechanism for a user-facing command is exactly the `~/.local/bin` wrapper (10 already exist); **(iii)** `enableArtifact`/`enableWorkflows` keys — fails by G3. A `--settings` *file* was also weighed against the inline JSON string and rejected as the heavier of the two: a file needs to be created, stowed, and referenced by path, where the string keeps the whole mechanism inside the one script.
- **M3 — refuse (non-zero exit, no `claude` launch) when the caller passes `--settings` before a literal `--`.** Both resolutions of G6 fail silently; refusing is the only behavior that does not depend on which. `anchors: G6`
- **M4 — a pre-committed `/context` go/no-go gate run before any file is edited.** G4 leaves the change's entire justification unverified, and this repo fixes go/no-go rules before the measurement rather than after (§27's ≥25% fixture gate; `delegate-instrument-authoring.md`'s pre-committed concentration rule). `anchors: G4, root`
- **M5 — a new appended `docs/design-decisions.md` entry; §28 untouched.** `anchors: root`
- **M6 — one new section in `docs/cost-levers-considered.md`.** That register is the named home for a closed cost lever, and it currently has no row for this one at all. `anchors: root`
- **M7 — `CHANGELOG.md` entries under both `### Changed` and `### Added`, with a Migration line naming `./install.sh`.** G5 creates a window where a consumer has the tools off and no wrapper yet. `anchors: G5`

**Pre-committed go/no-go rule (M4).** Before any file is edited, measure `/context` in a plain session against `/context` in a session started with `claude --settings '{"disableArtifact": true, "disableWorkflows": true}'`. **Proceed** only if the Tools category drops by at least 5,000 tokens — roughly 70% of the 7,200-token figure implied by §28's 28,803-character schema total at 4 chars/token, with the 30% margin absorbing that estimate's own imprecision. **If the drop is below that floor,** the default flip does not ship: neither `settings.json` nor the wrappers are worth a shared-config change whose benefit did not materialize, and the plan reduces to a single `docs/cost-levers-considered.md` section recording the falsification (verdict: *Rejected, premise falsified*) plus a `docs/design-decisions.md` entry closing §28's open question. That reduced outcome is a real result, not a failure — `plan-it` Step 7's no-files branch governs it.

**Not re-litigated.** `permissions.deny: ["Artifact"]` was considered and rejected in §28 (it gates *calling* a tool, not schema loading); a settings-file `env` block setting the disable env vars is strictly worse than the key by G2, since an env-var trigger cannot be cancelled from CLI scope. Both are named in the new decision entry as already-closed, citing §28, rather than re-argued.

**One note, not a blocking question.** The default flip reverses a position README:462 states explicitly and in the consumer's interest. The plan implements the flip as asked, and the honest argument for the reversal — the cost is unconditional and per-session while the benefit is occasional, and the change ships a one-command opt-back-in that did not previously exist — is what the new decision entry must carry. If the softer variant is preferred (ship the wrappers plus documented opt-in, leave the default alone), that is a one-line reduction of this plan; it is recorded under Out of scope rather than asked as a question, since the ticket settles it.

## Out of scope

- **Widening `require-stow-reminder.sh` to cover `claude/.local/bin/`.** The gate's new-top-level-entry scope genuinely misses this class (ledger row 12), and this change is a live instance of the hazard it exists to catch. It is a hook change needing its own `claude-hook-review` pass and its own PR; raised here for the reviewer rather than bundled.
- **Adding a `select-tests.py` domain rule for `claude/.local/bin/`.** The current unmatched-path fallback runs the full suite, which is the safe direction; narrowing it is a separate optimization with its own rule-table-fidelity tests to update.
- **The softer variant of this change** — ship the two wrappers and document the opt-in, leaving the shared default alone. Deliberately not taken: the ticket settles the default flip, and the wrappers' main value is that they make a shared default reversible per session. Recorded here so a later reader sees it was weighed, not missed.
- **A combined wrapper that enables a tool *and* starts auto mode.** `claude-workflow --permission-mode auto` composes for anyone on the repo's `sonnet` default, but not cleanly for an `opusplan` user — the exact mismatch `claude-auto` exists to resolve. A third wrapper would need to reimplement `claude-auto`'s model-eligibility logic; not worth it until someone asks.
- **Naming.** `claude-workflow` is singular while its setting (`disableWorkflows`) and the vendor's own page are plural. The ticket's names are kept for pair symmetry with `claude-artifact`; the README bullets and the script's usage block say "starts a session with the `Workflow` tool enabled" so the reading is unambiguous regardless.
- **The available-agent-types listing** (11,207 characters, §28) — still has no configuration lever, and §28 already records that gap. Nothing here changes it.
- **Re-measuring §28's schema-size figures.** They stand as recorded; this plan measures the reclaim, which is a different question.
