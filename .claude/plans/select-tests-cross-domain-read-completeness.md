# select-tests.py: close undeclared cross-domain reads and enforce table completeness

## Context

Make every diff select the tests that actually read the files it touches, and let CI catch the next gap instead of a hand audit. `claude/.claude/scripts/select-tests.py` maps a diff's changed paths to the pytest target directories that must run, and this repo's `CLAUDE.md` requires agents to run it rather than the full suite. GitHub issue #847 reports that its `CROSS_DOMAIN_EXCEPTIONS` table routes `claude/.claude/skills/code-review/SKILL.md` to `HOOKS_TESTS_DIR` — because `test_reconciliation_block_consistency.py` reads it — but has no matching entry for `claude/.claude/skills/plan-review/ROUTING.md`, which the same test also reads, so a diff touching only `plan-review/ROUTING.md` never runs the test guarding its own `## Reconciliation` block. A sibling audit found seven more unmapped reads of the identical shape. Why now: the gap surfaced during the `findings_path` branch (PR #848), which pulled in the hooks tree via other mapping rules and so never exercised it; it is pre-existing and otherwise untracked.

## Approach

Close every undeclared cross-domain read in one set-membership row plus one target addition to an existing row, and add a CI-enforced completeness test that derives the table's required entries by scanning test sources for module-level repo-path constants — so the next such read fails a test instead of waiting on the hand audit the table's header comment currently asks for.

The scanner resolves paths as **repo-relative prefix strings**, never as filesystem `Path` objects. Every root shape in the corpus is then string arithmetic on a prefix the walker already knows: `Path(__file__)` is the scanned file's own repo-relative path, `.resolve()` is a no-op, `.parent`/`.parents[N]` pops segments, `/ "literal"` appends them. No filesystem resolution, no import following, and no root-name allowlist for anything built in-file. Only five names genuinely need seeding, because they are defined cross-module and imported.

**The resolver's grammar, stated completely.** Corpus: every `test_*.py` under `claude/.claude/hooks/tests/`, `claude/.claude/scripts/tests/`, `claude/.claude/skills/tests/`, and `plugins/*/tests/`. Each file is `ast.parse`d and its `tree.body` walked in source order — module level only, never descending into a `FunctionDef`, `ClassDef`, or `If`. For each `ast.Assign` with exactly one `ast.Name` target, the value resolves to a repo-relative prefix string by these rules and no others:

| Node | Resolves to |
| --- | --- |
| `Path(__file__)` (single arg, `Name` `__file__`) | the scanned file's own repo-relative path |
| `<expr>.resolve()` | the value of `<expr>` — prefixes are already normalized |
| `<expr>.parent` | `<expr>` less its last segment |
| `<expr>.parents[N]`, `N` an int `Constant` | `<expr>` less its last `N` segments |
| `<expr> / <str Constant>` (`ast.Div`) | `<expr>` with the literal's segments appended; the literal may itself contain `/` |
| `ast.Name` | the name's value in the environment — file-local bindings recorded earlier in this same pass, else the seed map |
| anything else | unresolvable |

"Anything else" is load-bearing and covers every non-target shape in the real corpus: a bare string `Constant` (`test_log_routing_read.py:19-20`'s absolute synthetic hook-payload path), a `BoolOp` (`_BASH = shutil.which("bash") or "/bin/bash"`), a call that is neither `Path(__file__)` nor `.resolve()` (`test_skills.py:3381`'s `_skill_file("plan-review").parent / "REFERENCES.md"`, `test_select_tests.py:31`'s `_mod.resolve_repo_root(...)`), a `ListComp`, and a `List` of glob results (`test_hook_alignment.py:42`). Two further rules: a name bound earlier in the file to an unresolvable value **stays** unresolvable and shadows any seed of the same name; and popping more segments than the prefix holds is unresolvable, since the target lies above the repo root.

Seed map — the five names imported from `claude/.claude/tests/helpers.py`, and nothing else: `REPO_ROOT` → `""`, `CLAUDE_DIR` → `claude/.claude`, `HOOKS_DIR` → `claude/.claude/hooks`, `SKILLS_DIR` → `claude/.claude/skills`, `SCRIPTS_DIR` → `claude/.claude/scripts`. There is no `AGENTS_DIR` in `helpers.py`; `test_agent_roster.py:18` defines its own from `CLAUDE_DIR`, which the in-file environment already handles.

Candidate filter: drop the empty prefix (the repo root itself, which several files bind), then drop anything that does not exist on disk. For each survivor, `select_pytest_targets([path])` must either return `is_full_suite` or return a target covering the reading test file — equal to it, a directory containing it (`_is_under`), or a glob whose `_expand_target` expansion contains it. Reusing `_expand_target` rather than `fnmatch` keeps the coverage check on production's own glob semantics.

**Mechanism justifications:**

- *AST scanner over test sources* — `anchors: root`. Heavier than the task's surface suggests, so three lighter primitives were weighed. (a) Import each test module and introspect its attributes: fails because test modules carry module-level side effects and package-relative imports (`test_select_tests.py:20` does `from .conftest import ...`; `:22-26` mutates `sys.path` and `exec_module`s `select-tests.py`), turning a completeness check into unrelated import errors. (b) A regex over test sources: fails because it cannot resolve a file-local root without reimplementing assignment tracking, cannot do `.parent` arithmetic, and misses multi-line chains — the exploration grep that scoped this work missed `test_require_skill_review.py:26` for exactly those reasons. (c) Drop the scanner and broaden a `SKILL.md → HOOKS_TESTS_DIR` predicate: fails because the eighth gap is `claude/.claude/settings.json` read from a scripts test, which no skill-file predicate reaches.
- *Repo-relative prefix strings rather than resolved `Path` objects* — `anchors: root`. The lighter primitive for the same job: every root the corpus uses becomes segment arithmetic on a string the walker already holds, so the resolver needs no filesystem access, no import following, and no allowlist of permitted root names beyond the five cross-module ones. The existence filter is the only disk touch.
- *Set-membership row rather than seven lambdas* — `anchors: row1`. One target tuple, one rationale, one comment; the fidelity, audit-parity, and completeness tests all key on the set, so a stale member fails more than once.
- *`_is_test_source_change` rather than a second target on `_is_py_source_under_claude_or_plugins`* — `anchors: row10`. The lighter of the two despite adding a predicate: only a test-file change can introduce a new module-level constant, so the broad row's extra ~155-file reach (counted in the alternatives paragraph above) is over-selection with no invariant behind it, and it would add a target already subsumed by `SCRIPTS_TESTS_DIR` on every scripts-directory `.py` change.
- *Hand-written `_KNOWN_CROSS_DOMAIN_READS` audit list* — `anchors: row1`, `anchors: row2`. Both frozenset-derived tests are true by construction against the production predicate; the audit list is the one expectation not derived from the code under test, which is why it is a duplicated site rather than a DRY violation (DAMP test data, per CLAUDE.md's named exception).
