# Skill-review gate: diff against the merge base

## Context

Goal: stop `plugins/skill-management/hooks/require-skill-review.sh` from denying the `git commit` that completes a merge whose only `SKILL.md` / `claude-skills/skills/plan-review/ROUTING.md` changes came in untouched from the default branch (GH-1076).

The hook derives its trigger, its structural-validator input, its empty-diff exit and its marker hash from a HEAD-relative `git diff --cached`. During a merge, every gated file the other parent brought in therefore reads as unreviewed staged content, and the only route past the gate is a `/skill-review` pass over content the committer did not author. The code-review gate (`_lib_gate_diff_base`, `claude/.claude/hooks/_lib.sh`) and the plan-review gate (#1075) already diff against a novel-content base. `git-feature-branch-sync` prescribes merge over rebase when review is in flight, so the trigger is routine. Intended outcome: allow that commit, and still deny when the merge resolution itself edits a gated file.

The engineer asked for the port in these words: "I'm hoping we can port the fix for plan review over to it."

`.claude/plans/merge-aware-review-gates.md` (#994) already specifies this port as its Phase 4; only Phases 1-2 shipped. This plan implements Phase 4 narrowed to what GH-1076 needs, and departs from that plan on the empty-diff sentinel (see Approach).

## Approach

Give the skill-review gate the same novel-content base the code-review gate already uses, and let it **disarm** — rather than consult a marker — when no gated file is novel to the commit, *except* mid-revert, where the synthesized base is a subtraction rather than a union of reviewed trees. Concretely: duplicate `_lib_gate_diff_base`'s six-function closure into the plugin's trimmed lib, add a seventh shared function that **brackets** the copied `_lib_gate_diff_base` call with the revert exclusion (M-8, row 29), thread one resolved base through the plugin hook's trigger, structural-validator input and marker hash, and move `marker.sh`'s two `skill-review` arms onto the same `_lib_staged_diff_hash` the code-review arms already use, so write side and read side compute a byte-identical preimage.

Three departures from the obvious symmetric port are deliberate and stated here so they are not "fixed" later:

1. **No empty-base sentinel on the skill-review path.** `.claude/plans/merge-aware-review-gates.md` (#994) Phase 4's Verification bullet ("the same assertion, mirrored for `require-skill-review.sh:116`") assumed this hook's empty-diff exit is structurally identical to `require-code-review.sh`'s. It is not. This hook disarms one exit earlier, at the trigger, on a name-only diff scoped to exactly the pathspec set the marker hash uses (rows 3, 9, 10). The correct precedent is `docs/design-decisions/plan-review-gate-disarms-on-empty-active-plan-set.md`, not its "Why `_lib_code_review_marker_value` keeps its sentinel" section.
2. **Mid-revert the gate keeps today's HEAD-relative behavior**, on both the read and the write side (rows 19-21, M-8), and the exclusion is sampled *before and after* the base computation rather than following it (row 29). `[settled at round 1: the ciso finding "the disarm's reach across in-progress states is not justified per state" — revert is excluded, not accepted-and-pinned.]` `[settled post-implementation, /code-review ciso-reviewer finding on Dispatch A's staged diff: the trailing single re-probe is a TOCTOU against the same mutable gitdir — the bracket replaces it.]`
3. **The whole-diff empty exit (`require-skill-review.sh:123`) is deleted, not threaded.** It is unreachable on an honest result after the trigger and its only reachable effect is a one-config-write fail-open (rows 3, 18). `[settled at round 1: ciso's defense-in-depth finding — deletion, not a base-conditioned second exit.]`

**Root problem:** `require-skill-review.sh` derives its trigger, its structural-validator input set and its marker preimage from a HEAD-relative `git diff --cached`, so during a merge every `SKILL.md` / `plan-review/ROUTING.md` the other parent brought in unchanged reads as unreviewed staged content — and the `git commit` that completes the merge cannot be released without a `/skill-review` pass over files already reviewed on their own PRs (GH-1076).

The exclusion must therefore bracket the computation — sampled once before and once after — not follow it. No single-determination design exists at any scope: `_lib_gate_diff_base` is already internally non-atomic against the same gitdir (state probed at `:882`, `$gitdir/$ref_file` read at `:897`, then `merge-base --is-ancestor` and `merge-tree` run against a repo anyone with write access can mutate in between), so threading its internal state outward would relocate the window rather than close it. The bracket's failure mode on a **single** state flip is a false **deny**: a legitimate state change across the call yields the HEAD-relative answer, i.e. today's over-gating, in the safe direction. That is not an unconditional safe-direction guarantee. The bracket holds **three** temporally distinct reads of the same mutable gitdir, not two — the wrapper's pre-sample, `_lib_gate_diff_base`'s own internal probe at `:882`, and the wrapper's post-sample. A revert that both starts and ends inside the bracket's own window still yields a false **allow**, but only when the pre-sample read a union state (merge, cherry-pick or rebase). A pre-sample reading no state returns without entering `_lib_gate_diff_base` (M-8). On a commit outside any in-progress state, which is the ordinary gated commit, no double flip reaches the subtraction formula. This residual is disclosed rather than closed. It is materially narrower than the pre-fix trailing-probe bug, which needed one flip at any point after the internal probe and did not require the revert to both begin and end inside the hook's own execution. **Mechanisms**

- **M-1 Duplicate the six-function closure (row 6) into `plugins/skill-management/hooks/_lib.sh`, byte-identical bodies, pinned by `declare -f` definition-equality (M-9).** The heavy choice: it makes a state machine, not a one-liner, into two maintained implementations across a boundary. Two lighter primitives were checked and both fail. *Source the stowed `_lib.sh` when it exists, fall back otherwise* fails because the preimage recipe would then depend on whether `./install.sh` ever ran on that machine, so the same tree yields two different marker values and a gate that can never be released on one of them (G-1). *Compute a merge-only base inline in the hook* (`git diff --cached MERGE_HEAD`, or path intersection) fails twice: it drops the trust-anchor check that keeps a stale, forged, octopus or exotic-topology ref from narrowing the authorization hash (G-3), and the write side already uses `_lib_gate_diff_base`, so any inline variant is a guaranteed write/read mismatch (row 4). `anchors: root, G-1`
- **M-2 Route both `marker.sh` skill-review arms onto `_lib_staged_diff_hash` and delete `_hash_staged_diff`, accepting a two-artifact release with a skew window.** `[settled at round 1: the platform reviewer's Foundation concern — a read-side-only release was weighed and declined.]` The engineer chose the full port (row 21); the design reason it is worth the skew is that the lighter read-side-only variant (base-aware trigger and validator, marker hash left HEAD-relative) leaves GH-1076's complaint standing in miniature for the subcase where the resolution itself edits a gated file — the review is still over-scoped to upstream's content there — and leaves the preimage recipe with three homes (`_hash_staged_diff`, `_lib_staged_diff_hash`, the plugin's copy) of which the plugin can parity-test only one, so write/read agreement would rest on a human comparing two different function bodies. Using the same function on both sides is what makes the parity test meaningful for the value that actually authorizes the commit. `anchors: row4, row7, row8, row21`
- **M-3 No empty-base sentinel anywhere on the skill-review path; the trigger exit disarms instead, and it fires only on a *successful* empty name-only listing.** Row 3 makes the degenerate case unreachable at the hash, and row 9 shows the code-review sentinel's stated justification does not transfer. The disarm's residual exposure — a forged anchor that makes upstream's gated content look identical to the base — is dominated by G-2's zero-gate clean merge, which needs no forgery, no engineered conflict and leaves no marker. The one alternative that would close it (row 10's declined successor: fall back to the HEAD-relative trigger set when the base-relative one is empty) reinstates GH-1076 exactly. `anchors: row3, row9, row10, G-2`
- **M-4 Scope the structural validator's input to the base-relative path list.** The lighter-looking alternative — keep the validator HEAD-relative, on the "never narrow a scanner" rule from #994 bucket 2 — was checked and set aside: the trigger exit sits *above* the validator, so a HEAD-relative validator would fire only in the already-armed case, and it would deny a merge for a defect in a blob the merger did not author while the conflict-free merge of the same two trees validates nothing at all (G-2). What is given up is the auto-merge-of-two-valid-files-into-an-invalid-one case mid-conflicted-merge, bounded by row 12's CI check **in this repo only**. `anchors: root, row12, G-2`
- **M-5 Copy `_lib_capped` into the plugin lib rather than rewriting the copied bodies' calls to `_lib_capped_for 5`.** The rewrite would scatter a bare `5` across roughly ten call sites inside functions whose whole value is being byte-comparable to the stowed originals, turning every future stowed-side edit into a manual re-translation and breaking M-9's equality check by construction. `anchors: row6`
- **M-6 The terminal deny builds its reason in a variable and appends up to two conditional notes.** When `BASE` is non-empty: name the two-artifact requirement (the stowed `marker.sh` and the installed plugin must both be current, with the `claude plugin install skill-management@claude-config --scope project` command) and point at `docs/hooks.md` § "Gate deadlock recovery" — without it, a skew-window deny is indistinguishable from the GH-1076 symptom the release claims to fix, and no in-session action satisfies it. When the base was undetermined or a gated-path listing failed: say the commit was gated against HEAD, so a mismatch mid-merge is expected rather than a review gap. **Assertion strength, applied to every case below.** Each allow asserts returncode 0, empty stdout, and stderr free of shell-error text (`line NN:`, `command not found`, `unbound variable`); on a disarm with a non-empty base, stderr is exactly M-10's one trace line, and with an empty base stderr is empty. ## Out of scope

Each is accepted with a reason, not overlooked.

1. **`git merge --continue`, `git rebase --continue`, `git cherry-pick --continue` and `git revert --continue` stay ungated by this hook.** `_lib_command_concludes_marker_gated_commit` exists in the stow-tree `_lib.sh` with zero production callers — #994 Phase 3 never landed, so `require-code-review.sh:66` still matches `git commit` only. Wiring the plugin arm alone would make the skill-review gate strictly stricter than the code-review gate on the same command, and would require duplicating the whole fragment-matcher dependency chain into the plugin lib. This is an under-gating defect (#994 defect 2), the inverse of GH-1076, and belongs to that plan's coordinated sweep.
2. **The plugin's `_lib_chains_marker_write_before_commit:271-286` keeps its `git commit`-only regex.** It fails closed, so it is friction rather than a bypass, and it only starts mattering once item 1 lands.
3. **`"if": "Bash(git commit *)"` stays in `hooks.json:10`, and the hook's own matcher keeps its adjacency regex.** Dropping the `if` is #994 Phase 4's item, coupled to the matcher change in item 1. The matcher gap it leaves — `git -C … commit`, `git -c … commit`, `env git commit` and absolute-path `git commit` match neither the `if` nor the hook's regex, where the stowed code-review gate uses the fragment-aware `_lib_command_invokes_git_subcmd` — is pre-existing and unchanged in either direction here, and gets a sentence in the design-decision doc rather than a fix in this change.
4. **`_guard_staged_vs_unstaged` stays HEAD-relative.** Consequence, stated rather than hidden: mid-merge it cannot notice a forgotten `git add` on a gated file, because upstream's incoming content keeps the HEAD-relative staged diff non-empty. It matches the shipped code-review arm (`marker.sh:428` runs before the base resolves at `:434`), and the failure mode is a later marker mismatch and a re-review, never a false release.
5. **A conflict-free merge, cherry-pick or revert still reaches a commit with no gate firing at all** (G-2). Unchanged in either direction by this plan, and load-bearing: it is the dominating bypass that makes M-3's disarm and G-3's anchors admissible.
6. **With neither `timeout` nor `gtimeout` on PATH the copied closure runs uncapped, so a stalled `git` inside this gate exits only by the harness's own hook timeout, which does not block the tool call** (G-5, row 17). That is the whole hook family's existing posture on stock macOS without coreutils, not something this change introduces; `install.sh`'s warn-rather-than-block choice is #994 residual 20. Where a cap *does* fire, or a capped call is killed or unexecutable, the base is undetermined and the merge is over-gated exactly as today, with M-6's deny note as the only mitigation.
7. **An auto-merge that combines two gated files into a tree no reviewed state ever contained is no longer caught at commit time** during a conflicted merge. Two shapes: the structural one M-4 gives up (two valid files merging into an invalid one), and behavioral drift between two independently-reviewed edits to the same gated file. Both were never caught at all during a conflict-free merge of the same two trees (G-2), which dominates them; row 12's CI check catches the structural shape in this repo before a branch can land, and **plugin consumers get no compensating check for either** (row 12).
8. **Conflict markers in the computed reference blob over-scope the novel diff** for a hand-resolved gated file — the review then spans marker-text→resolution rather than the resolution alone. Over-scoped in the safe direction, and only inside files the reviewer must read anyway (#994 residual 5).
9. **Octopus merges, `cherry-pick -m 2`, `rebase --rebase-merges`, and git older than 2.38 fall back to the empty base** and get today's behavior (#994 residual 4, residual 6). Inherited from `_lib_gate_diff_base`, not introduced here. The version floors come with it: `merge-tree --write-tree` needs git 2.38, and the cherry-pick/rebase/revert arms' `--merge-base=` needs 2.40; the routine trigger, a merge, needs only 2.38, and CI runs `ubuntu-24.04`.
10. **The content-addressed marker scheme itself is not revisited** (`docs/hooks.md` § "Marker keying and gate-release authority"). Decoupling authorization from the preimage would make any future base change a non-event and is still declined: it is a rewrite of the mechanism all five marker kinds depend on.
11. **The `_lib_jq` fold onto `_lib_capped_for 5` is dropped from this change.** `[settled at round 1: both reviewers flagged it; it is not merely deferred but declined for this release.]` The plugin's `_lib_jq` today probes `timeout` only and passes no `-k`; folding it would add `-k 2`, which a BusyBox `timeout` older than 1.35 rejects outright — turning a failure confined to commits that stage a `SKILL.md` into one that fails closed on *every* Bash call reaching this hook, and falsifying `CHANGELOG.md:37`'s standing claim that the plugin's exposure is narrower. That is a widened blast radius bundled into an ergonomics cleanup, and it would need its own plugin-side `-k`-rejection test to ship safely. Dropping it also makes Dispatch A purely additive. The two-timeout-idioms inconsistency it would have fixed gets one line in the plugin lib header instead.
12. **A hash-computation failure denies with the ordinary marker-gate text**, indistinguishable from a real mismatch. Pre-existing — today's inline pipeline has the same property and `test_marker_gate_blocks_without_sha256sum[skill_review]` pins it — and a third conditional deny note would add a branch for a case a contributor cannot act on differently anyway.
13. **`test_default_branch_resolution_is_shared.py` is not widened to the plugin copy.** It scans `claude/.claude/` only, so the plugin's second `refs/remotes/origin/HEAD` read escapes the "exactly one home" invariant it states. Widening it would require teaching it a copy-with-parity-test exemption; M-9's definition-equality *is* the plugin-side enforcement of that invariant, and that is the better home for it.
14. **`require-code-review.sh:112-117`'s structurally identical whole-diff exit is left alone**, even though this change deletes the skill-review twin (row 18). Its own comment records that the branch is load-bearing for `deny-invisible-commit-content.sh`, so the sibling audit ends in "different reason, leave it", not in "same bug, fix both" — flagged here so the asymmetry reads as deliberate.
15. **Write-side and read-side base resolutions are independent and each hits its own cap**, so a marker can fail to match on read despite unchanged staged content mid-operation. `marker.sh:435-440` already documents this for the code-review arm; the skill-review arm inherits the identical gap. It is an availability gap producing a false re-review, never a false accept.
16. **Multi-marker gitdirs keep `_lib_gate_diff_base`'s existing formula choice.** `revert` is *last* in `_lib_git_inprogress_state`'s precedence (`_lib.sh:827-842`), so the subtraction formula is selected only when no other state marker is present — and under M-8 the wrapper calls the identical function on the identical gitdir, so its exclusion decision and the gate's formula selection cannot disagree on any single read of that gitdir. They are not one shared computation, though: under the bracket they are three reads separated in time (row 29). The accurate claim is therefore the narrower one — multi-marker precedence contributes no divergence mechanism of its own, beyond row 29's already-disclosed residual, which is not multi-marker-specific. What remains is `_lib_gate_diff_base`'s own formula choice under a crash-left or hand-planted multi-marker gitdir — shipped, identically live on the code-review and plan-review gates, and dominated by G-3, since planting a second marker file is strictly harder than forging the `MERGE_HEAD` G-3 already admits. Stated rather than omitted so a later sibling-symmetry sweep meets the reasoning instead of the conclusion. `[settled at /plan-review on the bracket revision, ciso-reviewer finding: the closure claim is qualified to row 29's residual rather than asserted outright.]` `[unverified, and this item does not rest on it: git is believed to refuse starting a revert, cherry-pick or merge while another is in progress, so a multi-marker gitdir would arise only from a crashed git or a hand-planted file, and the one legitimate shape — `rebase --rebase-merges` replaying a merge commit, leaving `MERGE_HEAD` beside `rebase-merge/` — resolves to `rebase` and therefore to a union formula. Not executed this session; stating it as fact would need an execution or a citation.]`
