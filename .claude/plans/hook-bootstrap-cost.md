# GH-978 Unit 1: cut the shared per-invocation hook bootstrap cost

## Context

Every Claude Code hook in this repo pays a 17-19ms shared bootstrap per invocation. On a single Bash tool call, 12 hooks fire unconditionally (8 of the 20 Bash PreToolUse entries already carry `if` gates), so that bootstrap is paid 12 times in 12 parallel processes. Why now: a root-cause investigation into local machine saturation (GH-978) found the hook chain is the largest continuous CPU load on the machine, ahead of the test suite. Intended outcome: cut the shared bootstrap cost for all 48 hooks across every event type, without touching the per-hook conformance architecture and without weakening any gate. This is Unit 1 of four; Units 2-4 (test timeout-cap boundaries, `select-tests.py` concurrency, and a `git_repo` fixture cost) are independent of this unit and tracked separately on issue #978.

Claude Code runs all matching hooks in parallel (primary source: `code.claude.com/docs/en/hooks-guide.md` "Claude Code runs all matching hooks in parallel"; `hooks.md` "All matching hooks run in parallel"), so the full-chain figure below is summed CPU, not latency. Timeouts on PreToolUse fail open (600s default), and one hook returning `deny` does not stop sibling hooks from executing; conflict resolution is most-restrictive-wins in the order deny, defer, ask, allow.

**Measured baseline.** Full serial chain, 18 hook scripts, standard payload (`{"tool_name":"Bash","tool_input":{"command":"ls"}}`): 695/707/711ms across three runs, 27-57ms per hook, uniform, no outlier. 12 unconditional hooks = ~372ms summed CPU per Bash call; wall-clock per Bash call is ~50ms. Bootstrap/logic split (feeding a non-Bash `tool_name` completes bootstrap then exits at the hook's own tool-name filter): bootstrap+exit 17-19ms, full Bash path 28-35ms, so own-logic is 9-18ms.

**Phase 0 decomposition** (bash-native interleaved ABAB `EPOCHREALTIME` harness, 200 iterations/arm, 3 repetitions; min is the trustworthy statistic, medians tracked min within 0.15-0.3ms). Shares are of a ~17.5ms bootstrap:

| Component | Median ms | Min ms | Share |
|---|---|---|---|
| bash process startup | 1.62 | 1.41 | 9% |
| `_lib.sh` source (marginal) | 5.83 | 5.46 | 33% |
| `$(dirname "$0")` substitution (marginal vs param expansion) | 1.15 | 1.01 | 7% |
| — subshell fork alone | 0.59 | 0.50 | 3% |
| — dirname exec alone | 0.70 | 0.58 | 4% |
| timeout wrapper marginal (1 exec) | 0.89 | 0.75 | 5% |
| printf-pipe-jq pipeline subshell (vs herestring) | 0.13 | 0.14 | <1% |
| `_lib_parse_tool_input_or_deny` total (marginal vs source-only) | 7.49 | 6.91 | 43% |

**Kill criterion cleared = GO.** Criterion was 0.4ms/hook (derived from the chain runs' own 2.3% spread). End-to-end, absolute-path invocation, byte-identical exit code and stdout verified before timing:

- `require-code-review.sh`: min 22.06 → 20.75, delta 1.31ms
- `deny-network-installs.sh`: min 24.01 → 22.70, delta 1.31ms
- `deny-credential-bash-reads.sh`: min 26.14 → 25.11, delta 1.03ms

Delta 1.0-1.3ms/hook clears the criterion by ~2.5-3x.

**Engineer-verified decisions — settled, not reopened by this plan:**

1. A single dispatcher process replacing the 18 Bash hooks is rejected. Payoff is only ~2x (372ms → 186ms CPU) against: breaking `ALL_HOOKS`/`GATE_HOOKS` glob discovery and the per-file line-2 `# hook-class:` contract; breaking `test_hook_alignment.py::test_missing_lib_sh_denied`, which copies each hook into a tmp dir and structurally assumes one self-contained copyable `.sh`; breaking `_pretooluse_entries_for`, which matches hooks to settings.json entries by exact last-shlex-token equality; rewriting all nine `run_hook*` variants in `claude/.claude/tests/helpers.py`; and collapsing 12 independent fail-open timeouts into one.
2. Adding `if` gates to the 12 unconditional hooks is rejected. `test_hook_alignment.py::test_self_filtering_bash_gate_has_no_if_matcher` asserts five named hooks carry no `if` key — an `if` is early dispatch, so a non-match means the gate never runs against the obfuscated command forms it exists to catch.
3. Splitting or reorganizing `_lib.sh` is rejected by prior decision (`.claude/plans/lib-sh-perf-audit.md`), on four counts, recording as given that "the harness invokes each hook as a fresh process per tool call."
4. Generating a comment-blanked `_lib.sh` at install time is rejected: it breaks the property that changes under `claude/.claude/**` go live on `git pull` with no re-install.
5. Scope is the shared bootstrap, chosen by the engineer over both the dispatcher and dropping the unit.

The Approach section below prices a new candidate this session identified (the `cat` exec inside `_lib_parse_tool_input_or_deny`) and resolves the central design risk (whether to replace the `jq` parse of `.tool_input` with hand-rolled bash).

## Approach

**Size first, because you asked.** The whole unit is worth **1.03–1.31 ms per hook invocation** — one subshell fork plus one `dirname` exec, replaced by a bash parameter expansion. On a Bash tool call with 12 unconditional hooks that is **~12–16 ms of the ~372 ms summed CPU, i.e. 3–4%**; across the full 18-hook serial chain it is ~21 ms of ~700 ms, also ~3%; per hook it is 3.9–5.9% of that hook's own wall time. Wall-clock per Bash call moves ~1.2 ms of ~50 ms, and only when the saving lands on the critical-path hook — no human will perceive it. The `cat` exec priced below does **not** add to this: reading `_lib_parse_tool_input_or_deny` shows it cannot be replaced safely, so the win does not double. The analysis is sunk either way; the remaining question is whether a ~60-file diff is worth 3–4% of the machine's largest continuous CPU load. **Recommendation: ship it** — the edit is mechanically trivial, permanently conformance-tested, strictly fail-closed-improving for the `hook-class: gate` subset (the non-gate subset sees no change to its already-documented fail-open contract), and the saving recurs on every hook fire of every event type for every stow consumer, compounding with each hook the repo adds. But that is a judgment on review surface versus 3–4%, and it is the engineer's call.

**The design.** Replace `. "$(dirname "$0")/_lib.sh"` with `. "${0%/*}/_lib.sh"` in the 51 hook files that carry the byte-identical source line, add a static conformance test pinning the new form and a behavioral test proving the one changed edge case fails closed, and update the two canonical-skeleton occurrences in `claude-hook-review`'s SKILL.md so the documented pattern and the codebase do not diverge.

`$(dirname "$0")` is a command substitution: bash forks a subshell (0.50 ms min) and execs `/usr/bin/dirname` (0.58 ms min), and the measured marginal cost of the whole construct (1.01 ms min) matches that sum. `${0%/*}` is a POSIX parameter expansion evaluated inside the already-running shell — zero forks, zero execs. It is the lightest primitive that solves the problem, which is why no over-powered-primitive enumeration is owed for the mechanism itself; the enumeration that *is* owed sits on the rejected JSON-parse target below.

**What changes semantically, and in which direction.** The `$0` differential corpus is identical for every shape a real executed file produces (absolute, via a whole-directory symlink — this repo's own stow mechanism, `~/.claude/hooks` — doubled slash, relative `./name`), and `${0%/*}` is strictly *more* correct on the trailing-slash row, where `dirname` composes a path that does not exist. That row is noise — no `$0` for an executed file carries a trailing slash. Exactly one shape diverges in a reachable way: a slash-free `$0`, where `dirname` yields `.` (sourcing `./_lib.sh` from the caller's cwd) and `${0%/*}` yields the filename unchanged (sourcing `name.sh/_lib.sh`, which fails). The consequence is a **deny**, not an allow — every gate blocks rather than opening. No documented configuration produces a slash-free `$0`: `claude/.claude/settings.json:223,301` invoke hooks as `~/.claude/hooks/<name>.sh`, and `plugins/*/hooks/hooks.json:9` as `"${CLAUDE_PLUGIN_ROOT}"/hooks/<name>.sh`. The only reachable way to produce a slash-free `$0` for one of these scripts is a literal `bash <bare-filename>` invocation with `cwd` already inside the hook's own directory — e.g. a contributor `cd`ing into `claude/.claude/hooks/` and running `bash require-code-review.sh` directly — not a `PATH`-based dispatch: both `PATH`-search resolution (`execvp`-style) and an explicit `executable=` invocation rewrite `argv[0]` to the resolved absolute path before bash ever sees it, so neither reaches the vulnerable case. Under that one reachable scenario the new form fails closed, which is the correct direction for a security surface and is loudly diagnosable from the deny text. The old form's behavior in that same scenario is not merely less correct: it sources whatever `_lib.sh` happens to sit in the invoker's cwd, which could redefine `emit_deny` as a no-op and silently defeat every downstream gate check in that process — a latent cwd-relative source-injection primitive, unreachable via any invocation this repo configures, that the new form removes outright.

**That edge case gets a test, and the obvious test is vacuous.** `subprocess.run([hook.name], executable=str(hook))` does not produce a slash-free `$0` for a shebang script — the Linux kernel's `#!` handling replaces `argv[0]` with the resolved executable path before bash ever sees it, so both the old and new forms are ALLOWED under that construction and the test passes for the wrong reason. The construction that produces a genuine slash-free `$0` is `bash <bare-relative-filename>` with cwd set to the hook's own directory: bash assigns its script argument to `$0` verbatim and never PATH-searches it. Under that invocation on the standard payload the old form exits 0 with no output and the new form exits 2 with `could not source _lib.sh`. The test's docstring must state why the `executable=` construction is wrong, or a maintainer will simplify it back into vacuity. The test also needs a **paired control** — the same hook, same payload, same cwd, invoked by absolute path, asserted to allow — or it degenerates into "this hook denied for some reason."

**Why the source-form change is now in scope at all.** `.claude/plans/lib-sh-perf-audit.md:111` put "changing the `. "$(dirname "$0")/_lib.sh"` source contract" out of scope on the stated ground that it "would slow the hot path or force a 48-file change," and its Approach (`:37`) asserts the form is what `test_hook_alignment.py:1030` "pins verbatim." Both premises are now superseded by reading rather than assumption: the 48-file change is justified by a measurement the earlier plan did not have, and `test_emit_deny_defined_before_lib_source` matches on the regex `[.]\s+.*_lib\.sh` at `test_hook_alignment.py:1020` — the *assertion message* at `:1030` names the old form, not the matcher. The new form passes that test unmodified; only the message text needs editing.

**Scope of the sweep: all 51, including the three plugin hooks.** The three plugin gates (`plugins/npm-semver/hooks/require-npm-version-bump.sh`, `plugins/plugin-semver/hooks/require-plugin-version-bump.sh`, `plugins/skill-management/hooks/require-skill-review.sh`) fire at commit frequency, so they gain no meaningful CPU. They are included anyway for two reasons. First, the fail-closed property is uniform across all arms of the structure, and CLAUDE.md's sibling-audit rule scopes a fix to the bug shape rather than to where it surfaced. Second, the SKILL.md skeleton this PR must update governs plugin gates too, so leaving three plugin gates on a form the same PR marks obsolete manufactures exactly the drift the PR exists to close — and the alternative, a named exemption list in the new conformance test, cannot meet this repo's own exemption discipline (`_BARE_JQ_EXEMPT_HOOKS` at `test_hook_alignment.py:600` is a reason-carrying dict whose every entry must still structurally violate; "we did not want three version bumps" is not such a reason). The cost is named rather than hidden: **four `plugin.json` versions must be strictly raised** — `claude-hook-review` (for the SKILL.md edit) plus those three — each gating `git commit` through `require-plugin-version-bump.sh`.

**Comment placement.** `${0%/*}` reads as a golfing tic and needs its rationale recorded, but 51 copies would be a single-source-of-truth defect. The rationale goes in exactly two places: `claude/.claude/hooks/_lib.sh`'s file header (lines 1–5, which already owns the source contract) and the new conformance test's docstring. **The 51 hook lines carry no comment, and neither do the three plugin `_lib.sh` files** — their headers already defer to the stowed `claude/.claude/hooks/_lib.sh` as the byte-identity authority (`plugins/skill-management/hooks/_lib.sh:9-14`), and the conformance test docstring parametrizes over them, so it is their shared home. This must be stated explicitly in the `code-writer` dispatch or it will add 51 comments.

**The sweep must be an exact-line match, never a `dirname "$0"` regex.** The repo carries 96 occurrences of `dirname "$0"` across 81 files; only 57 match the full source line, and of those, 2 are in `claude/.claude/hooks/tests/fixtures/gh564-incident.diff` (Axis-3 preserved incident content), 2 are in historical `.claude/plans/*.md` records, and 2 are the skeleton in SKILL.md. Non-source `dirname "$0"` sites that must not be touched: `nudge-handoff-near-context-cap.sh:620`, `require-worktree-for-git-writes.sh:277`, `ask-new-dependency-disclosure.sh:204`, `claude/.claude/scripts/skill-fidelity-report.sh:7`, and `install.sh:44` (`REPO_DIR="$(cd "$(dirname "$0")" && pwd -P)"`), plus the ten `claude/.claude/scripts/*.sh` sourcing `../hooks/_lib.sh` and `plugins/lovable-cloud/scripts/new-migration:38`.

**Two things gated to Phase 0, not resolved by a read-only pass.** ShellCheck's `.shellcheckrc` sets `external-sources=true` and `source-path=SCRIPTDIR`, and CI has no `severity=` floor, so a single new SC1090 ("can't follow non-constant source") on 51 files turns CI red. Whether ShellCheck resolves `"${0%/*}/_lib.sh"` under SCRIPTDIR the way it resolves `"$(dirname "$0")/_lib.sh"` is unverified. The named fallback is a `# shellcheck source=./_lib.sh` directive on the converted line — a machine-readable directive, not prose rationale, so it does not violate the comment ruling above. Convert **one** hook and run ShellCheck before converting the other fifty.

**The central design risk, resolved rather than glossed.** The obvious next move — parse the stdin JSON with bash builtins and keep `jq` as a fallback — is rejected, and rejected on security ground alone. `_lib_parse_tool_input_or_deny` (`_lib.sh:265-330`) populates `TOOL_NAME`/`COMMAND`/`CWD`/`SESSION_ID`/`FILE_PATH`/`AGENT_TYPE`, and `deny-credential-bash-reads.sh`, `deny-pii-in-commits.sh`, and `deny-private-project-refs.sh` decide whether to DENY from those values. A bash path would need full JSON string unescaping (the six two-character escapes plus `\uXXXX` with surrogate pairs), nested-object traversal, jq's last-key-wins duplicate-key semantics, and non-string stringification — in bash 3.2, with no `declare -A` and no `mapfile`. `COMMAND` is model-authored text and these gates exist to catch obfuscated forms, so any divergence between the two paths is a gate bypass, not a bug. Root `CLAUDE.md` requires searching the standard library before hand-rolling in a non-trivial domain and justifying the absence of a standard alternative; `jq` is that alternative, already installed and already the single call. Six lighter primitives were enumerated and all six fail:

1. **Make the single `jq` call cheaper** — no flag reduces jq's startup, which dominates at this payload scale.
2. **Extract only constrained-grammar fields in bash** — the `jq` fork remains, so the saving is zero while a second divergent parse path is added.
3. **Fail-closed divergence check** — runs `jq` anyway; the arithmetic fails on its own terms.
4. **Cache the parse across hooks** — the 12 hooks run in parallel, so no hook can warm a cache and all 12 miss concurrently; worse, a shared file every gate reads `TOOL_NAME`/`COMMAND` from is a universal gate bypass.
5. **Runtime-generated comment-stripped `_lib.sh` cached by mtime** — same poisoning shape as (4) against a worse target (executable bash sourced by every gate), and it re-litigates the already-rejected install-time generation.
6. **`LC_ALL=C` to cut locale init** — it changes `grep -qEi`'s non-ASCII case-folding inside gates that fold case deliberately. `deny-credential-bash-reads.sh:75` carries its own comment explaining that an uppercase spelling of a private-key filename still opens the real file on a case-insensitive filesystem such as APFS, which is exactly why that gate folds case. Changing gate semantics for an unmeasured gain.

### Assumption ledger

**Root:** Every hook invocation forks a subshell and execs `dirname` purely to locate its sibling `_lib.sh`, costing 1.0–1.3 ms that a bash parameter expansion removes outright — paid 12 times in parallel on every Bash tool call and on every fire of all 48 hooks across every event type.

**Givens** (fixed, beyond this plan's reach):

- The harness invokes each hook as a fresh process per tool call, runs all matching hooks in parallel, and never short-circuits on a deny. *Reason: harness-owned; already recorded as a given at `.claude/plans/lib-sh-perf-audit.md:46`.*
- macOS ships `/bin/bash` 3.2, so `mapfile`/`readarray`, `declare -A`, and `local -n` are unavailable. *Reason: OS vendor; stated at `_lib.sh:300-304` and enforced by `test_no_bash4_constructs.py`.*
- `jq` is the JSON parser for `.tool_input`, and sourcing `_lib.sh` whole costs 5.46–5.83 ms (33% of bootstrap). *Reason: splitting `_lib.sh` is rejected by `.claude/plans/lib-sh-perf-audit.md:37,111` on four counts, and install-time comment-blanking breaks the go-live-on-`git pull` property; dissolving either needs a decision outside this plan.*
- `_lib_jq`'s 5s cap (`_lib.sh:16-17`, `_lib_capped_for` at `_lib.sh:38-48`) stays, and with it exactly one `timeout` exec per hook. *Reason: pinned by real wall-clock assertions against a hung-jq stub — `test_hook_alignment.py:1365`, `test_record_session_end.py:272`, `test_lib.py:492,560,588,1470,1520`; removing it weakens a gate's hang backstop, which this unit is barred from doing.*

- Edit only the assertion message at `test_hook_alignment.py:1030`; leave its matcher and the four unmodified-test proofs untouched. `anchors: row2, row3`

## Critical files

**One `code-writer` dispatch** for the whole unit, not a split. The file sets (hooks, tests, skill, manifests) are disjoint on paper, but the shared background — the exact replacement form, the two-homes comment ruling, the exemption-free sweep boundary, and the non-vacuous test construction — would have to be restated in every prompt, and two agents re-reading the same files can resolve the sweep boundary differently. `plan-it` Step 5's do-not-split condition applies directly.

## Out of scope

- **Replacing `INPUT=$(cat)` with a builtin read (`_lib.sh:267`).** Priced, not assumed, and it cannot be done safely. Two candidates exist and both fail. `IFS= read -r -d '' INPUT` changes `INPUT`'s bytes in two ways that feed values three DENY-deciding gates consume: it preserves the trailing newline that command substitution strips, and it truncates at the first NUL rather than dropping NULs and keeping the remainder, so a payload carrying a NUL yields a different `INPUT` than today — and `INPUT` has a second consumer class that compares its byte length against `_LIB_SIZE_THRESHOLD_BYTES` (5 MB) at `track-permission-prompts.sh:56-61`. It also carries an unverified but adverse performance property: a non-newline delimiter makes bash read unbuffered from a non-seekable fd, which on a payload near that same 5 MB ceiling would trade a 0.6 ms win for an unbounded loss, in the exact dimension this unit exists to improve. `INPUT=$(</dev/stdin)` has identical string semantics, but its failure mode is undetectable by this repo's tests: `_run_hook_raw` passes stdin through Python's `subprocess.run(input=…)`, which is a real `os.pipe()`, whereas the harness is a Node process whose child stdio may be an `AF_UNIX` socketpair — and `open()`ing `/proc/self/fd/0` for a socket fails. Whether it is actually a socket is unverified, and that is the point: the test suite structurally cannot cover the production stdin type, so the risk cannot be retired by testing, and the downside is every gate denying every tool call for every stow consumer. Neither candidate is worth 0.6 ms on a fail-closed security surface. `mapfile` is separately barred by bash 3.2.
- **Removing the `timeout` wrapper (~0.75–0.9 ms/hook, one exec).** It is a gate's hang backstop, pinned by real wall-clock assertions (`test_hook_alignment.py:1365` asserting elapsed < 12s against a hung-jq stub, plus five `test_lib.py` sites and `test_record_session_end.py:272`). Removing it weakens a gate, which this unit is barred from doing, and the only way to keep the cap without the exec is hand-rolled background-kill timeout logic — heavier and riskier than what it replaces. Note the 3% figure is a floor: it reflects only the early-exit path on the standard payload, and git-heavy branches touch more `_lib_capped` call sites.
- **Converting the `printf | jq` pipeline to a herestring (`_lib.sh:293`).** 0.13–0.14 ms, well below the 0.4 ms/hook kill criterion, and a herestring is backed by a temp file, so the saving is not obviously real.
