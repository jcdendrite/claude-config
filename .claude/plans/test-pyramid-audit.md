# Fix test-pyramid violations in TestReviewTrace and one token-analyzer test

## Context

Rewrite the confirmed capsys-as-logic-proxy tests in `test_transcript_analysis.py`'s `TestReviewTrace` class (and one matching instance in `test_token_analyzer.py`) so each asserts on the structured accessor's return value directly instead of scanning `cmd_review_trace`'s printed stdout — decoupling logic assertions from print-formatting so a future formatting-only change can't break a test that has nothing to do with formatting.

This follows up a `staff-sdet` finding from PR #650 (merged, `c1db722`), tagged DEFER at the time because fixing it meant touching ~26 pre-existing tests the PR's own diff didn't need. A repo-wide `test-evaluation` sweep this session (two background subagents, one deep-diving `TestReviewTrace`, one sweeping the other four `capsys`-using test files) found the actual scope is larger than the deferred estimate: **58 of 61** `TestReviewTrace` tests are confirmed logic-proxy (not 26 — the exact-substring grep that produced the original estimate only caught one of several shapes the same anti-pattern takes here), while the other four files are almost entirely clean (**1** confirmed instance, in `test_token_analyzer.py`). A separate, differently-shaped smell surfaced in `test_post_crash_sessions.py` (7 tests) and is intentionally out of scope for this plan — written up as its own follow-up brief (`~/.claude/briefs/post-crash-sessions-capsys-wiring-smell-task.md`) per the engineer's direction this session, since it isn't the same anti-pattern (no accessor is being ignored there).

## Approach

Rewrite each confirmed test to call the existing structured accessor (`_review_trace_session_events` or `_compute_deny_summary_data`, both in `claude/.claude/scripts/transcript-analysis.py`) directly and assert on the returned dicts/Counters, replacing the `cmd_review_trace(...)` + `capsys.readouterr()` + line-prefix/regex text-scan currently used. This is the direct application of `test-conventions` §9's documented fix for "regex-parsing specific field values from runtime output... instead of... calling the production parser": call the production function, assert on its result. Ship as two PRs (one per file) rather than splitting `TestReviewTrace` further, per the engineer's explicit choice this session — the class's 58 fixes are mechanical and follow the same two-accessor pattern throughout, so a single reviewable diff is preferable to three PRs that would each need to rebase on the last against the same file.

**Root problem:** `TestReviewTrace` tests couple business-logic assertions to `cmd_review_trace`'s print-formatting layer via stdout text-scanning, when the logic they're meant to verify is already available as structured data from a directly-callable accessor.

**Givens:** None beyond the platform itself (pytest's `capsys` fixture shape and `argparse.Namespace` are imposed by their respective libraries, not by this design). This is a self-contained internal test refactor with full control over every file it touches — there is no vendor, protocol, or other-party constraint the design accepts as fixed. The feasibility fact this plan leans on — `_review_trace_session_events` and `_compute_deny_summary_data` already return all the structured data the 58 confirmed tests need (event dicts with `kind`/`branch`/`model`/`hook_name`/`message`/`tool_use_id`/`friction_kind`/`subagent_type`; summary dicts with `hook_counts`/`command_shape_counts`/`hook_shape_counts`/`friction_counts`/`corpus_min_ts`/`corpus_max_ts`/`pre_regime_tool_result_count`) — is stated as evidence for the Mechanism row below, not as a given, since the plan could in principle extend those accessors and chooses not to because it doesn't need to, not because it can't. [verified: subagent read `transcript-analysis.py` lines 1723–2153 this session]. Whether to leave `cmd_review_trace`'s printed output format unchanged is a real in-reach choice this plan declines — see Out of Scope, not Givens.

**Mechanism — call the accessor directly (anchors: root):** This is already the lightest available primitive; the two heavier alternatives considered and rejected were (a) keep running the CLI and scanning stdout but with a more tolerant parser — still couples the test to the print layer, just less exactly, so it doesn't dissolve the actual coupling; (b) write a new dedicated test-only accessor duplicating `_review_trace_session_events`'s logic — rejected under CLAUDE.md's single-source-of-truth rule since a production accessor already exists and does exactly this.

**Per-test classification (anchors: row1, this session's subagent audit):** [verified: subagent read all 61 `TestReviewTrace` methods and the accessors' signatures this session; class-boundary corrected independently — the brief's cited range (4055–5493) includes ~236 lines of shared helper functions for the *next* class (`TestAuditRouting`, starting 5494); `TestReviewTrace`'s own body is 4055–5254]. Full per-test list is in "Critical files" below — 58 LOGIC-PROXY (rewrite), 2 FORMAT-CONTRACT (leave — genuine CLI mode/UX-branch behavior with no structured-data equivalent), 1 AMBIGUOUS (leave — a no-crash smoke test with no content assertion to rewrite).

**Alternative considered and set aside:** blanket-converting every `capsys` use in `TestReviewTrace` regardless of classification. Rejected per the brief's explicit instruction (§5, §7) — it would delete the 2 genuine format-contract tests, which the repo depends on since `cmd_review_trace`'s printed output is read by humans and shelled-out tooling.
