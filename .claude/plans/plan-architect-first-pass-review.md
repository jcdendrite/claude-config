# Plan: round-2 `plan-architect` consult trigger pilot

## Context

This repo's round-3-triggered `plan-architect MODE=consult` gate (`docs/design-decisions/round3-plan-architect-consult-gate.md`) has been live since ~2026-08-30/09-02 and, by every measurement gathered this session, remains well-calibrated: its post-launch fire rate (14.3% ground-truth on this machine, 13.6% and 11.4% independently from a second machine's broader window) tracks the original case study's cited "14% tail" closely. The engineer's opening ask — require `plan-architect` on `/code-review`'s first pass — turned out to be architecturally identical to a round-1 trigger the case study had already evaluated and rejected (catches ~50% of PRs to address a 14% problem). After that was surfaced, the engineer redirected: design a **time-boxed round-2 pilot** instead — retarget the trigger to fire on entry to round 2 (not round 1, not round 3), for a bounded, pre-registered sample, to directly test the specific, currently-untested hypothesis that an *earlier* `plan-architect` consult reduces total rounds-to-merge for the tail.

## Approach

Ship the round-2 trigger as an **opt-in machine sentinel** that lowers the shared round-state cap to 1 on the pilot machine only, leaving every other stow consumer on today's round-3 default, and pre-register the decision rule in this plan file before the sentinel is created. The pilot's decision-driving outcome is the **share of fired branches that still reach a 3rd review round** (a binary with a known historical base rate of 50% and an adequately-powered exact-binomial bar), not commits-to-merge — commits-to-merge stays pre-registered and reported, but the arithmetic below shows it cannot discriminate at any sample size this repo can accrue in a month.

**Root problem.** The round-3 gate interrupts a non-converging review loop only after two rounds have already been paid for; whether firing one round earlier converts tail branches into converging ones is untested, and the only evidence bearing on it (`docs/case-studies/opus-frontload-review-rounds.md`'s G0–G3 arms) cannot speak to `plan-architect` specifically. Nothing in the pipeline produces that evidence as a side effect, so it has to be produced deliberately, cheaply, and with a decision rule fixed in advance.

**Givens** (conditions this design treats as fixed, each with its qualifying reason):

- **Local session transcripts age out on a rolling 30 days** (`opus-frontload-review-rounds.md` § "Limits of this result"). The harness owns retention; the pilot's calendar bound and analysis timing are shaped around it rather than against it.
- **`review-trace`'s round count is an upper bound, not an exact count** (same file, "G1's round-count proxy can overcount"). Fixing the proxy is a `transcript-analysis.py` change with its own scope; this plan consumes the instrument as-is and uses it symmetrically on both sides of every comparison.
- **The pre-gate baseline window (2026-08-01 → 09-01) predates two live co-interventions** — the round-3 gate itself and `/code-review`'s Fix-route `plan-architect` dispatch (`docs/design-decisions/code-review-fix-route-plan-architect.md`, 2026-09-02). The window is history; it cannot be re-run under current conditions.
- **`commit_count` is the only durable per-PR rework outcome this repo captures** (`pr-cost-ledger.tsv`, `gh` PR data). Adding a better outcome variable is a separate instrument change.
- **The pilot machine is a single-machine, single-repo corpus.** Widening it needs another machine's operator to opt in — a decision outside this plan.

**Mechanism 1 — an opt-in presence-only sentinel resolving the cap, not a global constant flip.** `[anchors: root; rows 13, 15, 22, 23]` Add `_lib_reviewer_round_state_cap` to `_lib.sh`, returning `1` when `<config-dir>/.round-consult-round2-pilot` exists and `$_LIB_REVIEWER_ROUND_STATE_CAP` (unchanged at 2) otherwise — zero-arity, resolving its own `_lib_config_dir`, failing toward the default on an unresolvable config dir, exactly the shape `_lib_round_consult_gate_disabled` (`_lib.sh:2557`) already uses. Both call sites already hold `CONFIG_DIR` before they consume the cap (`require-architect-consult.sh:83` before `:97`; `log-reviewer-round.sh:81` before `:105`), so this adds no new resolution to either hot path. Lighter primitives considered and rejected:

- **Flip `_LIB_REVIEWER_ROUND_STATE_CAP` to `1` for a pilot window** — one line, but it ships a *deny* gate at roughly double frequency to every stow consumer for an experiment none of them opted into, and rollback needs a second PR rather than an `rm`. This repo's own CLAUDE.md requires framing a `claude/` change as "every stow consumer," and blast radius, not line count, is what the over-powered-primitive test measures. `[anchors: row 23]`
- **An environment-variable override** (`nudge-long-turn-subagent.sh`'s `LONG_TURN_NUDGE_THRESHOLD` precedent) — rejected because exposure attribution is the pilot's whole product: an env var can differ silently between terminals and appears in no `install.sh` inventory, so "was this branch under pilot conditions?" stops being answerable from machine state. `[anchors: row 19]`
- **No code at all — dispatch the consult by hand at round 2** — rejected because self-selected exposure is precisely the confound that would void the result (the engineer will remember on branches that already feel troubled), and this repo's own convention holds that an automatic-trigger request needs a hook, not prose. `[anchors: root]`

**Mechanism 2 — derive the deny message and both hook headers from the resolved cap.** `[anchors: row 13]` The gate's message currently hardcodes "entering its third distinct reviewed state," which is false under the pilot. State the recorded-state count and the fact that the current state is new, without an ordinal word. `test_require_architect_consult.py:314-325` pins only `plan-architect MODE=consult`, `report this block to the engineer`, `subagent`, and the absence of the disable-sentinel name, so the rewording is free. This wording change lives in the shared code path, so it reaches every stow consumer on their next `git pull` — only the deny *frequency* (cap value) stays pilot-scoped; the deny *text* does not.

**Mechanism 3 — measure with `review-trace` and `gh`; add no logging mechanism.** `[anchors: rows 14, 19]` Firings are recoverable as denial events with branch attribution (`review-trace --this-repo --deny-only --since <start>`), consults as `consult` rows, and rounds as `/code-review` skill invocations; commits-to-merge come from `gh` and are durable indefinitely. Two heavier alternatives rejected: appending a pilot log to `log-reviewer-round.sh` (a new durable per-branch write path shipped to every consumer for one machine's experiment), and suspending the recorder's latch short-circuit during the pilot so the state file keeps counting (a second pilot-conditional behavior in the write path, to replace a proxy that is already conservative in the right direction — see row 14). The binding consequence is operational, not architectural: **the analysis pass must run within 7 days of the stop point**, or the earliest firings are gone.

**Mechanism 4 — pre-registration lives in this committed plan file, with gates fixed before the sentinel is created.** `[anchors: root; rows 2, 3, 4, 10, 11, 12]` This mirrors the precedent the engineer named: `opus-frontload-review-rounds.md` opens by citing the plan "whose gates G0–G3 were fixed before any scan ran."

- **G0 — exposure recoverability (week 1, abort gate).** After the first firing, confirm `review-trace --this-repo --deny-only` returns it with branch attribution. If firings are not recoverable, abort: the pilot would otherwise run a month blind.
- **G1 — accrual.** Stop at **20 firings or 4 calendar weeks, whichever comes first**. Fewer than 12 firings at week 4 → report as under-accrued; do not extend by default.
- **G2 — primary outcome (binary).** Share of fired branches that still reach a 3rd round, against the historical conditional rate of 29/58 = 50%. Adopt-candidate bar: the largest count *k* with `P(X ≤ k | p=0.5, n)` ≤ 0.05 at the realized *n* — at n=20 that is **≤5/20 (25%)**. Computed two ways (proxy-on-proxy for like-for-like comparability with the 50% figure, and gate-truth denominator with proxy numerator); the bar must clear on **both**, so neither computation can be selected after the fact.
- **G3 — supporting, not decisive (qualitative).** Per firing: did a consult return, did it name a specific foundation problem, and did the branch act on it? Rubric fixed now, classification from artifacts (the consult's return in-transcript, the branch's later `agent-reviews/` findings and commits). Reported with its bias direction stated — a consult asked "is the foundation wrong?" usually finds something and sessions usually comply, so this over-credits the treatment and cannot drive adoption alone.
- **G4 — secondary, descriptive (commits-to-merge).** Mean plus bootstrap CI against the population-matched 4.59 as the primary comparator (rows 2, 4), with 6.31 and the n=3 ≈ 5.0 live figure reported as context. Pre-committed as unable to drive adoption or rejection alone (row 12).
- **Decision.** Adopt (make cap=1 the default for all consumers, in a follow-up PR that supersedes the round-3 decision file) only if G2 clears with G3 not contradicting it. Otherwise **revert** — remove the sentinel; the code path's fate is decided in the same follow-up. Extension past the stopping point requires an explicit new engineer decision recorded before the data is unblinded, never a default continuation.

**No concurrent randomized control arm.** `[anchors: rows 9, 12, 18]` Considered seriously and rejected on proportionality: the free coin flip is already sitting in `_lib_reviewer_round_state_key`'s branch hash, and randomizing would remove the period confound row 18 names. But it halves treatment accrual (20 firings moves from ~2-3 weeks to ~5-6), and the only comparison it improves is G4 — which stays underpowered by an order of magnitude either way (row 12). Buying a cleaner version of a metric that cannot decide anything, at double the calendar cost and double the Opus spend per decision-relevant firing, is the wrong trade. G2 needs no control arm; it compares against a historical base rate computed from the same instrument.

**No `claude/.claude/CLAUDE.md` edit.** `[anchors: row 17]` The Step 4 starting point proposed a new Opus carve-out clause. Reading line 109, the hook-deny path is already covered generically — "a skill or hook prescribing the dispatch (e.g. `/code-review`'s Fix-route step, or a round-3-consult hook deny) is already outside it" — where the round-3 deny is one of two `e.g.` examples, not the scope. Only the *self-recognition* exception ("your own recognition that this branch is entering a third `/code-review` round") is ordinal-anchored, and widening that to round 2 would actively harm the pilot: a session self-dispatching at round 2 writes the same latch and manufactures exposure outside the mechanism being measured. Leaving it alone is both correct and a scope win — that file is always-loaded context with a trim already claimed by another session.

**New decision file; the round-3 file is untouched.** `[anchors: root]` `docs/design-decisions/round3-plan-architect-consult-gate.md` is a preserved record and is not superseded by a scoped experiment. Supersession is edited in only if the pilot adopts, per `.claude/rules/design-decisions.md`.

### Assumption ledger

2. The population-matched baseline for branches that *reach* round 2 is (2.862 + 6.310) / 2 = **4.586**, not 6.310 — equal bucket sizes make it a simple average. 6.31 is the tail subset alone; comparing a pilot arm drawn from all round-2 entrants against it would show "improvement" from population composition even under zero treatment effect. `[verified: same table; arithmetic derived here]`
3. Among historical round-2 entrants, 29/58 = **50%** went on to 3+ rounds. This is G2's base rate. `[verified: same table]`
4. The engineer initially fixed commits-to-merge as the comparison metric, against 6.31 and the n=3 ≈ 5.0 live figure, then accepted this plan's revision as proposed: **4.59 (row 2) is G4's primary comparator, G4 is descriptive/supporting rather than decisive (row 12), and G2's binary round-3-recurrence rate is the decisive metric.** 6.31 and the ≈ 5.0 live figure remain reported as context. Settled before the sentinel is created, which is the point — changing a pre-registered comparator afterward is the exact post-hoc gap the pilot exists to avoid. `[engineer-verified]`
5. Of 5 gate-tripped branches, 3 merged at 4, 4, and 7 commits (mean ≈ 5.0); two others had not merged. Not re-verified here; the session that measured it did not preserve the output. `[unverified]`

7. Applying row 6's proxy-to-truth ratio (14.3/34.3 = 0.417) to the ≥2 proxy gives ~20% as a *lower* bound on the pilot's firing rate; 48.6% is the upper bound; overcount inflation is smaller at the lower threshold, so ~30% is the planning midpoint. `[unverified — derived from row 6]`
8. 120 distinct branches carried ≥1 `/code-review` invocation in a ~1-month window ≈ 28 branches/week. `[verified: opus-frontload-review-rounds.md line 35]`
9. Rows 7-8 give 6-14 firings/week, so **20 firings accrues in ~2-3 weeks**; the 4-week cap is the slack. 10. At n=20, p₀=0.5, the exact binomial gives P(X≤5) = 21700/1048576 = 0.021 and P(X≤6) = 0.058, so **≤5/20 is the α=0.05 one-sided bar**. `[verified: arithmetic]`
11. Power at that bar: ~62% against a true 25% rate, ~80% against 20%. A 50%→40% drop is invisible at this n. `[verified: arithmetic]`
12. G4 cannot discriminate. If the treatment converts a third of would-be-tail branches, the arm mean moves ~0.6 commits (rows 1-3); at n=20 with a plausible SD of 2.5-3.5 the SE is 0.56-0.78, so the CI swamps the effect. Detecting 1.5 commits at 80% power needs n ≈ 43. `[verified: arithmetic from rows 1-3]`

A read/write disagreement on the cap wedges the gate, so the resolver must be the single source for both. Mid-branch sentinel changes degrade gracefully in both directions: appearing early denies at the next new state (intended), disappearing allows one more append. `[verified: _lib.sh:2478-2487, both hooks]`
