# Handoff-nudge rationalization gap

## Context

Close the reasoning gap that let a `ready-for-review` session dismiss an over-threshold context-budget warning by conflating "few remaining named steps" with "low remaining token cost," and audit past sessions for how often the same substitution recurred unnoticed.

A user caught this live: a session running `ready-for-review` saw `--check` report `over_threshold=true` (210,116 vs 150,000 tokens) at Step 1 and planned to just note it in the completion summary. When the user asked why it wasn't calling `/handoff`, the agent defended continuing by citing the nudge hook's own "warn only, never halts" framing and its "if the task is nearly complete, ignore this and finish" clause, reasoning that the remaining tail (verification, cumulative code-review, skill-fidelity check, PR description, hygiene recheck) was "well-defined and bounded" and therefore cheap. The user pointed out this conflated step *count* with token *cost* — several of those steps are themselves full agent-dispatch passes that can cost hundreds of thousands of tokens — and the agent conceded and called `/handoff`.

Root cause: `ready-for-review/SKILL.md` Step 1 (line 43) deliberately overrides `handoff/SKILL.md`'s own "write when over_threshold" criterion with "warn and continue silently," giving the agent no information about what the remaining gate steps actually cost. The only later re-check is in the Completion section (line 171), by which point the expensive tail has already run — too late to save anything. Left without real cost information at the one point where a handoff decision would still matter, the agent borrowed the ambient nudge hook's generic "if nearly complete, ignore this" phrasing and used remaining-step-count as an unsound proxy for remaining cost.

Intended outcome: (1) `ready-for-review` Step 1 defers to a fresh session (calling `/handoff`) instead of freelancing a completion judgment, matching `plan-it` Step 7's already-correct pattern; (2) the hook's own shared advisory clause is qualified so "nearly complete" must be judged by cost-to-finish, not step count; (3) a new mechanical `transcript-analysis.py` subcommand plus a manual classification pass over this repo's own session corpus measures how often the same rationalization recurred, written up as a `docs/case-studies/` page.

## Approach

**Concluded design.** `ready-for-review`'s Step 1 stops warning-and-continuing past an over-threshold context measurement and instead defers the whole gate to a fresh session — the same criterion `handoff/SKILL.md` already states, with the override deleted rather than reworded. The prose that replaces it names why the tail is expensive (steps 3 and 4 each dispatch a full reviewer pass sized by the cumulative diff) and why deferring here is unusually cheap (every later step re-derives its inputs from the repository), so the agent never has to convert "few steps left" into a cost estimate. Separately, a new `transcript-analysis.py handoff-signal-response` subcommand measures how often a context-budget signal was visible in this repo's own corpus and the session kept going anyway, and a sampled manual classification over its curation cards answers whether the step-count-for-cost substitution recurred; both land as a `docs/case-studies/` page.

Two alternatives were weighed for Step 1 and set aside. Keeping warn-and-continue while adding cost prose leaves the same judgment call in the agent's hands, which is the defect itself, not its expression. Moving the existing Completion re-check earlier as a second warning duplicates a bullet and still ends in a discretionary call. The chosen rule is mechanical: a field in `--check`'s JSON decides, exactly as `plan-it` Step 7 already does.

**Engineer decision (confirmed during plan-review):** Phase 3 keeps short verbatim quotes of an agent's own rationalization sentences as evidence, but drops session ids from the published page entirely and restricts excerpt eligibility, at the instrument level, to plain assistant-authored text turns — never a tool call, tool result, file content, or user message. That source-restriction closes the cross-turn vector: a pasted path, diff, stack trace, or credential that reached the agent via tool output or a user message can never become an excerpt. It does not close the within-assistant-turn vector — an agent's own sentence that paraphrases or quotes such content in its own words still passes the filter — which is exactly what Phase 3's mandated manual redaction read (Critical files, Verification) exists to catch; that read is a required second layer, not optional scaffolding the filter makes unnecessary. See rows 12 and 17.

The hook's own generic injected clause is treated as a sibling arm of the same bug shape and gets a one-clause qualification, not a removal — `test_advisory_context_still_carries_the_nearly_complete_escape_hatch` pins the "nearly complete" affordance as a deliberate design element whose only home is the advisory path, so the fix qualifies how completion is judged rather than deleting the affordance.

**Engineer decision (confirmed during planning):** the Step 1 deferral keys on `--check`'s `over_threshold` field as-is (window-relative 40%, capped at 150k) rather than on the absolute cap alone. `[engineer-verified]` A 200k-window consumer who finds this too eager already has the documented `HANDOFF_NUDGE_ABS_CAP` override lever; no skill edit needed for that case.

### Assumption ledger

**Root.** `ready-for-review/SKILL.md` Step 1 measures context, then substitutes its own warn-and-continue action for `handoff/SKILL.md`'s write decision while supplying no information about what steps 2–7 cost — so the agent fills the gap with its own estimate, and remaining-step *count* is the nearest available proxy for remaining *cost*. That proxy is unsound precisely where it matters: steps 3, 4 and 5 are agent-dispatch-heavy and their cost tracks the cumulative diff, not the step counter.

**Givens** (conditions the design treats as fixed, each beyond this plan's reach):

- **G1.** `--check` writes no log line and no marker (`docs/handoff-nudge.md` § "Querying the current estimate (`--check`)"), so a `--check`-observed signal — the exact arm in the incident — is invisible in `.handoff-nudge.log` and detectable only transcript-side. The hook owns that contract; changing it is a different plan. `[verified: docs/handoff-nudge.md line 66]`
- **G2.** The transcript corpus is the only record of what an agent did after seeing a signal, and it is read-only historical data. No re-run is possible; the audit is observational.
- **G3.** `claude-skills/` and `claude/` are stow packages, so every edit here changes behavior for every contributor who ran `./install.sh` — not personal tooling. This repo's own `CLAUDE.md` fixes the framing. `[verified: CLAUDE.md § "Working in this repo"]`
- **G4.** Published measurement in this repo may draw only on this repo's own corpus; a figure computed over a union including private-engagement roots inherits that engagement's provenance and cannot ship publicly. `CLAUDE.md` § "Also redact structural fingerprints and provenance" owns this.

**Mechanisms and assumptions.**

1. **Rewrite Step 1's context-budget bullet as a deferral, not a warning.** `anchors: root`. On `"status":"ok"` with `over_threshold` or `already_fired` true, the gate does not run steps 2–7 in this session: report `estimate`/`threshold` (naming `nudge_disabled` inline when true), invoke `/handoff`, and — only once `/handoff`'s own "Verify the handoff file with Bash" step confirms the write succeeded — run `~/.claude/scripts/marker.sh deactivate ready-for-review`, then let the fresh session restart the gate from step 0. Deactivating before the write is confirmed would leave a session that fails mid-`/handoff` with no active marker, no completion marker, no `--check` log line (`--check` writes nothing, per G1), and no handoff file — silent loss of the deferral's own record, the opposite of the leaked-marker problem `marker.sh clear-stale` addresses. Delete the sentence "This bullet substitutes its own warn-and-continue action for that section's write decision" — the bullet now follows `handoff/SKILL.md` § "Before writing: is a handoff warranted?" rather than overriding it, restoring the single source of truth. Every other case continues silently, unchanged. One engineer-override clause stays: if the engineer has already said to finish in this session, finish — that is a human decision, not the agent's judgment. Detecting *whether* that human decision was actually made is itself an agent inference over ambiguous prior text — the same discretion shape as the bug being fixed, just moved one clause over — so the skill-review fixture pair (Verification) must include an allow/deny pair pinning that boundary: an explicit, unambiguous engineer instruction to finish triggers the override; a vague "let's wrap up soon" does not.
2. **The replacement prose names cost shape, never a token figure.** `anchors: row1`. Two sentences carry the whole fix: steps 3 and 4 each dispatch a full reviewer pass over the cumulative diff and step 5 runs `pr-description`'s own checks, so what remains costs what the diff costs, not what the step counter says; and deferring is unusually cheap here because steps 2–7 take their inputs from the repository (the cumulative diff, `gh pr view`, `skill-fidelity-report.sh`), so a fresh session rebuilds almost nothing this one holds. `[verified: ready-for-review/SKILL.md steps 2–7 name each of those inputs]` A measured token figure is deliberately excluded — `.claude/rules/skill-and-agent-self-review.md` requires global skill bodies to stay platform-agnostic, and a gate's cost is set by the consumer's own diff and test suite. The measured number belongs in the case study.
3. **Move the bullet ahead of the CI-watch launch.** `anchors: row1`. Step 1's current bullet order puts the context check last, after `gh pr view` has already launched `ci-watch.sh` in the background. A deferral fires a background watch whose result lands in a session that is about to end. Reposition the bullet to run immediately after "Working tree is clean" and before the PR-capture/CI-watch bullet — the tree is already known clean by then, which is what `/handoff` §5 wants, and nothing expensive has started. `[verified: ready-for-review/SKILL.md lines 36–43]`
4. **Apply the identical rule to the halt path.** `anchors: root`. Line 19 currently says a halt on step 2, 3, 4 or 7 re-runs the check and restates it in the halt report. That is the same arm of the same structure: a halt is where the fix loop's next round — the most expensive thing the gate does — is about to start. Change it so a re-run reporting over threshold routes to Step 1's deferral rather than restating a number and continuing. This sentence, and Step 1's own bullet, are exactly what `claude-skills/skills/tests/test_skills.py`'s `TestReadyForReviewContextBudgetNeverHalts` (`test_step1_context_budget_bullet_states_warn_only_never_halts`) and `TestReadyForReviewHaltRestatesContextBudget` (`test_overview_names_halt_steps_and_restatement_cross_reference`) pin verbatim as the *current* behavior, with docstrings that frame "warn only, never halts" and the halt-restatement cross-reference as deliberate design (`_assert_pinned_clause_right_bounded`). Rows 1 and 4 rewrite precisely those pinned sentences, so both test classes fail the moment the SKILL.md edit lands — not silently, `select-tests.py` catches the break, but the fix is not "swap the pinned constant." Both classes' docstrings and names state the invariant as "never halts" / "restates it"; they must be rewritten to state the new deferral invariant, mirroring the treatment row 6 already gives its own pinned hook test, or they become regression tests that defend a claim the code no longer makes — the same rationalization-preserving-fix failure mode this plan exists to close, recurring inside its own test suite. `[verified: claude-skills/skills/tests/test_skills.py lines 3925–3941, 3944–3970]`
5. **Close the completion-marker hole the deferral opens.** `anchors: row1`. Step 8's "Do NOT write the completion marker if" list keys on "produced findings that weren't fixed"; a deferral produces no findings, so add an explicit bullet for it. The deactivate call in row 1 is the paired half — without it the next session's gate sees a stale active-bypass marker from a session that may still be alive, which `marker.sh clear-stale` cannot evict. `[verified: docs/handoff-nudge.md § "Known limitations", final bullet, for the still-alive-PID case]`
6. **Qualify the hook's generic injected clause; do not remove it.** `anchors: root`. `nudge-handoff-near-context-cap.sh`'s advisory `additionalContext` ends "If the task is nearly complete, ignore this and finish" — the sentence the incident agent borrowed, and a sibling arm of the same shape (an invitation to judge completion with no statement of how to cost it). Append a cost qualifier to that same clause, e.g. "— judge that by what the remaining work costs, not by how many steps are left." The existing assertion `"nearly complete" in ctx` keeps passing unchanged, which is the point: `test_advisory_context_still_carries_the_nearly_complete_escape_hatch`'s docstring records that the hard-block path's own copy was deleted on the assumption this is the affordance's only home, so removing it here would silently retire a documented design element. `[verified: claude/.claude/hooks/tests/test_nudge_handoff_near_context_cap.py lines 2068–2077]` Add a new assertion for the qualifier so the clause is pinned in both directions — but not as an independent `in ctx` membership check: two disjoint `in` checks pass even if the qualifier lands unattached to the sentence it's meant to qualify (e.g. appended to the opening threshold sentence instead), silently failing the "qualify, not remove" goal while both assertions stay green. Assert the joined substring as one contiguous string (or `ctx.index("nearly complete") < ctx.index(<qualifier text>)` with a bounded distance) instead. Also add a negative-exclusion assertion, matching the suite's own established pattern for this exact shape (`"genuinely almost done" not in third.stderr` at ~line 1381), that the qualifier text is `not in` the hard-block stderr message — the suite has no test today that would catch a copy-paste of the qualifier into the untouched hard-block `printf`, which fires unconditionally on every hard-block in every repo. This is the widest-blast-radius edit in the change — it fires in every session in every repo — which is why it is one clause and why it adds tokens measured in the tens per fire.
7. **Repair the `handoff` checklist ambiguity the deferral creates.** `anchors: row1`. `handoff/SKILL.md`'s pre-write checklist reads "If this session pushed commits to a branch with an open PR and `/ready-for-review` did not run this session, run the `pr-description` skill before writing this file." Under the new deferral the gate *was invoked* and did not reach step 5, so a strict reading of "did not run" skips `pr-description` wrongly. Change it to "did not complete." One clause, in a file already inside this change's skill-review surface. `[verified: handoff/SKILL.md line 173]`
8. **Update the two docs that now misstate behavior.** `anchors: row1, row6`. `docs/hooks.md`'s `nudge-handoff-near-context-cap.sh` entry names `plan-it` Step 7 and the `handoff` skill as what acts on `--check` — `ready-for-review` Step 1 is a third consumer and was already missing before this change. `docs/handoff-nudge.md` line 17 paraphrases the injected reminder and must track row 6's new clause. `[verified: docs/hooks.md line 61; docs/handoff-nudge.md line 17]`
9. **`plan-it` Step 7 is audited and deliberately unchanged.** `anchors: root`. Its own context-budget step states a cost (the rebuild) and then hands the decision to a mechanical rule — "hand off when it says the session is past its threshold" — with no completion judgment in between. It is the correct arm of the structure, not a second instance of the bug. `[verified: plan-it/SKILL.md line 137]` The sibling set is bounded: only `handoff`, `plan-it`, `ready-for-review`, `docs/handoff-nudge.md`, `docs/hooks.md` and preserved-content plan files reference `over_threshold`/`already_fired` in prose. `[verified: repo-wide grep reported in dispatch; not re-run here]`
10. **New `transcript-analysis.py` subcommand `handoff-signal-response` for the audit's mechanical stage.** `anchors: root`. Per session in scope, it locates each *observed* context-budget signal record — a `--check` result carrying `over_threshold` or `already_fired` true, an injected advisory nudge, or a hard-block stderr — and for each one reports: position, `context_at_turn`, whether a handoff followed, turns-after-signal, and priced dollars-after-signal. "Whether a handoff followed" is scoped to **this same session's own transcript**: did a `/handoff` skill invocation (or a write under `~/.claude/handoffs/`) occur at any point after the signal, before this session's transcript ends. This is deliberately not a cross-session join. Row 1's own fixed behavior invokes `/handoff` in the same session that saw the signal, before that session ends — the fresh session that resumes afterward is a separate transcript the metric never needs to look at, since the positive signal (the invocation) already happened same-session. Aggregates: signal count, conversion rate, and the post-signal spend distribution, split by signal kind (`--check` query vs. hook injection) and by whether a live `ready-for-review` active marker context applies. **Over-powered-primitive check** — three lighter options in this system were weighed and each fails: (a) reusing `spend-over-threshold` plus `handoff-ratio` as-is fails because neither keys on an *observed* signal, so neither separates "the session was deep" from "the agent was told and continued," which is the entire question; (b) an uncommitted `rg`/`jq` pipeline fails the case-study genre's own convention that "How this was measured" name a re-runnable instrument, and would hand-roll the resolved-scope banner and root-narrowing contract on every run; (c) a flag on `spend-over-threshold` fails because that subcommand's documented output is a per-ISO-week aggregate table, and per-signal rows plus curation cards replace its shape rather than extend it. A new subcommand is this repo's own idiom for a published corpus measurement, not a heavier choice than the task warrants.
11. **Reuse, not reimplementation, inside that subcommand.** `anchors: row10`. `_hook_effective_fire_threshold`, `_read_bounded_log_lines`, `_parse_nudge_log_entries` and `_operator_response_lag_from_log` already exist and already do the threshold resolution, bounded log reads and post-signal-growth join; `audit-routing-samples` already implements the `--sample`/`--seed`/`--format json|md` curation-card shape this needs. `[verified: transcript-analysis.py lines 8736, 8821, 10384, 10527; docs/transcript-analysis.md § "audit-routing-samples"]`
12. **Redaction contract: banner plus multi-root `--no-redact` refusal, matching `context-distribution`, not `audit-routing-samples` — plus a second, instrument-level content restriction this new subcommand needs that neither existing model carries.** `anchors: row10, G4`. `audit-routing-samples` is documented as having no redaction of any kind and printing raw prior-user text; copying it wholesale would be wrong here because this output is destined for a public page. The curation run narrows to one root with a single top-level `--config-dir ~/.claude --this-repo`, which is what unlocks `--no-redact` — the same instrument limitation that blocked an arm of `case-studies/opus-frontload-review-rounds.md`, avoided here by narrowing up front rather than discovering it mid-audit. `[verified: docs/transcript-analysis.md § "Corpus scope: the declared-roots file", lines 53 and 56]` `context-distribution`'s contract is sufficient for it only because it "never builds the redact map and emits no project label at all, so there is nothing in its output to actually redact" (`docs/transcript-analysis.md` line 56) — pure aggregate numbers. This subcommand's core output is the opposite: quoted reasoning. Root-scoping alone stops cross-account leakage; it does nothing about a pasted path, diff, or stack trace ending up inside a quoted excerpt. Per the engineer decision above, the subcommand closes the cross-turn vector at the source: it refuses to emit an excerpt whose source record is not a plain assistant-authored text turn — a `tool_use`, `tool_result`, or user turn is never excerpt-eligible, full stop, regardless of what content it contains. That restriction is enforced at extraction time (a filter on the record's turn role/type before it ever becomes an excerpt candidate), not as a downstream check on text already selected. It does not reach an assistant turn that itself paraphrases or quotes such content in its own words — Phase 3's manual redaction read (Approach; Critical files; Verification) is the layer that covers that residual case.
13. **Narrowing to the personal root loses nothing for this audit.** `anchors: row12`. No `*claude-config*` project directory exists under any of the five non-personal declared roots, so this repo's entire corpus is under `~/.claude`. `[verified: glob of ~/.local/state/claude-accounts/*/projects/*claude-config* — zero matches]`
14. **The mechanical universe is large enough to need sampling and small enough to be tractable.** `anchors: row10`. Within `~/.claude/projects/*claude-config*`, an over-threshold `--check` result appears 2,670 times across 587 session files, and the advisory nudge's literal text 2,135 times across 578 files. `[verified: ripgrep counts run this session against those paths]` The classification stage therefore reads a seeded top-N sample of curation cards — ranked by post-signal spend, since that is where a wrong continue-decision actually cost something — not the whole population. Ranking by spend is unaffected by row 12's excerpt-source restriction for the cross-turn vector: the highest-spend sessions are exactly the ones most likely to carry large pasted diffs/logs/tool output, but that content is never excerpt-eligible in the first place, so concentrating the sample there doesn't concentrate that risk the way it would if excerpts could still be sourced from a session's pasted content. It may concentrate the within-assistant-turn vector instead — a high-spend session involves more tool activity for the agent to narrate in its own text turns — which is again why the manual redaction read (Approach) is a required pass over the actual sampled set, not a formality.
15. **The rationalization itself is not phrase-matchable; only the situation is.** `anchors: row10`. Every existing `transcript-analysis.py` subcommand is a deterministic classifier with no model call, and `cmd_struggle`'s literal-phrase list is the closest analogue — but "the agent substituted step count for cost" is a judgment about reasoning in context, not a phrase. Hence the two-stage funnel: the subcommand measures the situation mechanically, and a dispatched reader classifies the reasoning on a rubric over the shortlist. `[verified: dispatch-reported audit of transcript-analysis.py; not re-run here]` `review-vs-babysitting.md` establishes exactly this shape — mechanical counts plus manually pulled verbatim excerpts.
16. **The case study ships regardless of what the classification finds.** `anchors: row10`. The census output — conversion rate and post-signal spend distribution — is itself a result, and this repo routinely publishes negative and inconclusive findings (`delegate-instrument-authoring.md`, `targeted-read-discipline.md`, `opus-frontload-review-rounds.md`). If the sampled windows contain zero instances of the step-count substitution, that is reported as "0 of N sampled," not omitted, and the page carries a numeric revisit trigger like its siblings.
17. **The published page carries no session id, truncated or otherwise; internal curation cards may.** `anchors: row16, G4, engineer decision`. `docs/precompact-hook-behavior.md` and `review-vs-babysitting.md` both cite eight-character session ids in published prose, but confirmed with the engineer during plan-review: this page does not follow that precedent. A session id is a pointer back to the full private transcript, and nothing about this audit's evidentiary value requires it — the excerpt itself (an agent's own rationalization sentence, per row 12's source restriction) is what illustrates the pattern. `docs/case-studies/handoff-signal-response.md` numbers excerpts sequentially within the page itself (e.g. "excerpt 1," "excerpt 2"), never by session id or record number. The internal curation-card working material (`--no-redact` run, never committed — row 12) may still carry a truncated session id for the redaction-read's own traceability back to source. `[engineer-verified]`
18. **The 150,000-token cap's own grounding is what makes deferral defensible at 150k of a 1M window.** `anchors: row1`. The rule is not "you will run out of window" — at 150k there is 850k left. It is that `$/PR` and `$/1k output` rise monotonically past the 100–150k bucket, which is why the cap sits there; running the gate's most expensive steps above that line is precisely the spend the cap exists to prevent. `[verified: docs/handoff-nudge.md § "What the hook does", "Why this cap"]` A consumer whose session shape differs has the documented `HANDOFF_NUDGE_ABS_CAP` override, so a 200k-window consumer who finds the deferral too eager has a supported lever without editing the skill. Confirmed with the engineer during planning: ship keyed on `over_threshold` as-is. `[engineer-verified]`
19. **`pr-description` is the one step whose session-context independence is asserted rather than audited.** `anchors: row2`. Steps 2, 3, 4, 6 and 7 name their repo-derived inputs explicitly in the skill body; `pr-description`'s own body was not read end-to-end this session. The Step 1 prose therefore names the cumulative diff, `gh pr view` and `skill-fidelity-report.sh` as the re-derivable inputs and does not claim step 5 needs nothing from the session. `[unverified]`
