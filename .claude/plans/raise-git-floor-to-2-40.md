# Raise the supported git floor to 2.43

## Context

Goal: make git 2.43 the one supported git version, test it in CI at an exact pinned build, and delete the code, tests and prose that support anything older.

Ask: "I want to raise the floor for git version. I'm not going to support multiple [git] versions and make them backward compatible. I did a similar change for bash recently and it simplified things greatly." Enforcement chosen via label "install.sh check + README (Recommended)". Fix for the false `CLEAN` chosen via label "Include it (Recommended)". The floor was first chosen via label "2.40 (Recommended)", then changed by the engineer: "Then we should pin to 2.43. Thoughts?" and "Usually it's best pracitce (and this should be in your guardrails already) to pin an external library in case there are vulnerabilities introduced or incompatibilities." The session answered with a recommendation, and the engineer chose label "2.43 floor + exact archive-package CI pin (Recommended)". The text of every option above was drafted by the session, not the engineer.

Why now: `README.md` states a floor of git 2.31, while the divergence scripts need 2.38 (`git merge-tree --write-tree`) and `_lib_gate_diff_base` carries fallbacks for git that lacks `--write-tree` and for the 2.38–2.39 band that lacks `--merge-base=` (added in 2.40). Nothing in shipped code probes the git version, so the floor exists only as prose, comments, error messages and fallback code. One consequence is a false verdict: `branch-divergence-status.sh` and `check-branch-divergence.sh` print `Trial merge: CLEAN` whenever `merge-tree` prints no conflict lines, including when `merge-tree` was rejected or failed. This surfaced as a deferred review finding on the `ready-for-review` step-6 change.

Precedent: the bash 5.2 floor change touched `README.md` Requirements, `.claude/rules/shell-floor.md`, `docs/hooks.md` § "Bash version", a runtime check in `claude/.claude/hooks/_config.sh` with copies in the four hook-bearing plugins, `install.sh`, CI, parity tests, a CHANGELOG `### Removed` entry with a migration block, and major version bumps on the hook-bearing plugins.

Evidence gathered this session, all from read-only exploration and a temp-repo probe (verify before relying on it):

- No shipped code parses `git --version` or compares versions at runtime. The only parser is the test helper `_git_version_at_least` in `claude/.claude/scripts/tests/test_transcript_gh_cli.py`.
- `git merge-tree --write-tree` exit status: 0 is a clean merge, 1 is conflicts, any other status means the merge could not complete, per `git help merge-tree`. In a temp repo an unknown ref also exited 1 with empty stdout, so exit 1 alone does not mean conflicts. A conflict printed a tree OID on its first line.
- `--write-tree` mode arrived in git 2.38.0, `--merge-base=` in 2.40.0, and `rev-parse --path-format` in 2.31.0 (git RelNotes).
- Stock distro git: Debian 12 ships 2.39.5, Ubuntu 22.04 ships 2.34.1, Ubuntu 24.04 ships 2.43.0 (session explorer, Launchpad and Debian package pages). The first two fall below 2.43, and equally below 2.40.
- Why 2.43 and a pin, not a higher floor: git's `RelNotes/2.43.4` lists five CVEs fixed there (CVE-2024-32002, -32004, -32020, -32021, -32465), and the same batch patched the 2.39 through 2.45 lines. A minor-version floor cannot enforce a patch level, because distros backport fixes without changing the version string. So the floor states the minimum minor version, and CI runs one exact pinned build. A floor above 2.43 would drop stock Ubuntu 24.04 and delete no further code, since no use of a 2.41–2.43 feature was found.
- The git on the GitHub `ubuntu-24.04` runner image is unverified. If it is newer than 2.43, CI at the floor means installing one exact Ubuntu 24.04 archive package version, which the engineer confirms by exact version before any fetch.
- Fallback code: `claude/.claude/hooks/_lib.sh` (`_lib_gate_diff_base`, three `merge-tree` call sites near lines 1477–1485) and a byte-identical copy in `plugins/skill-management/hooks/_lib.sh`. Comment-only `merge-tree` mentions sit in `require-plan-review.sh` and `require-code-review.sh`.
- Documented floor statements: `README.md` line 97 (2.31), `claude-skills/skills/git-feature-branch-sync/SKILL.md` lines 36 and 68, `claude/.claude/scripts/branch-divergence-status.sh` line 7, `claude/.claude/hooks/check-branch-divergence.sh` line 20 and its known-gap comment.
- Pre-2.31 error messages in `marker.sh`, `review-pr-checkout.sh`, `review-pr-finish.sh` (two) and `review-pr-post.sh`; comments in `_lib.sh` and `cleanup-merged-branches.sh`.
- Old-git tests: ten `_make_git_rejecting_*` shim definitions across `test_lib.py`, `test_check_skill_length.py`, `test_require_code_review.py`, `test_require_plan_review.py` and `test_lib_reviewer_round_state.py`, with the tests that call them; two pre-2.31 tests in `test_lib.py` and `test_marker_lib.py`; one version-gated skip in `test_transcript_gh_cli.py`. Tests that guard other malformed `rev-parse` output stay.
- Bash precedent mechanics: `install.sh` sources `_config.sh` before any mutation and exits 1 below the floor; CI runs the floor version and `test_ci_bash_equals_the_floor` pins it; `test_no_other_shipped_file_defines_the_floor` forbids a second definition.

Out of scope, by the engineer's framing of the task: the stacked-PR base measurement in `branch-divergence-status.sh`.

## Approach

Git 2.43 becomes the one supported git. `install.sh` refuses to install below it, `README.md` and the `skill-management` plugin state it, and the prose, error-message clauses and simulated-old-git tests that serve an older git are deleted. 2.43 is Ubuntu 24.04's stock git and the version the engineer chose to pin, not a feature need: the code needs 2.40, and no use of a 2.41–2.43 feature was found (row 33). CI installs one exact Ubuntu 24.04 git build from two digest-pinned `.deb` files, and tests tie that build to the floor (Phase 3). The divergence check stops reporting a trial merge git could not complete as `CLEAN` (Phase 2). The single-absolute-path validation beside the old error messages stays, because it also rejects empty `rev-parse` output on a supported git.

Paths are relative to the repository root.

**Alternatives weighed and set aside:**
- **A runtime git check in `_config.sh` or in each hook.** Every hook sources `_config.sh`, so the check would run `git --version` on every hook call. The selected enforcement names only `install.sh` and `README.md` (rows 7-8). Below git 2.40, the commit gates already fall back to a HEAD-relative diff, which over-gates rather than lets content through (row 12).
- **Deleting the single-absolute-path checks along with the old-git tests.** Both checks also turn an empty `rev-parse` output into a failure on a supported git, and tests pin that (rows 14-15).
- **Fixing each divergence caller inline.** Both callers carry the same awk pipeline and the same blindness to `merge-tree`'s exit status (row 24). `CLAUDE.md` § "Engineering Judgment" asks for one shared helper once two arms share a fix.
- **Reporting a failed trial merge as exit 0 with a third verdict word.** `/respond-pr` parses only `CLEAN` and `CONFLICT`. A non-zero exit reuses the failure arm `/ready-for-review` step 6 already has (row 27).
- **Leaving the `skill-management` plugin untouched.** Its `_lib_gate_diff_base` comment would drift from the stowed copy with no test to notice (row 22). Its consumers never read `README.md`, so they would not learn the floor (G4). The engineer kept M4 in this PR (row 40).
- **A `uname`-branched `install.sh` message, as the bash floor has.** The fix is the same everywhere (put a newer git first on PATH), so one message covers it, as the python floor's does at `install.sh:83-88`.
- **Floor 2.40, the oldest git the code runs on.** The engineer moved the floor to 2.43 (rows 3-4), and no maintained Ubuntu release ships a 2.40 that CI could pin (row 32).
- **A floor above 2.43.** Context gives the reasons: it drops stock Ubuntu 24.04 and deletes no further code (row 33).
- **Building git 2.43.x from source in CI.** The engineer selected an archive-package pin (row 3), and a build adds a toolchain and minutes to every run for a binary no Ubuntu 24.04 user runs.

### Assumption ledger

**Root:** The repo's git floor exists only as prose, and that prose has drifted: `README.md` says 2.31, while `_lib_gate_diff_base`'s full recipe needs 2.40 and the divergence check needs 2.38. Code comments, error messages and tests still carry handling for git older than that, and nothing tests the floor. This plan makes git 2.43, Ubuntu 24.04's stock git, the one supported git. `install.sh` refuses to install below it, `README.md` and the `skill-management` plugin state it, and the old-git prose and simulated-old-git tests go. Phase 2 makes the divergence check stop reporting a trial merge git could not complete as clean. Phase 3 makes CI run the suite on one pinned Ubuntu 24.04 build of git 2.43.

**Givens:**
- G1. git added `rev-parse --path-format` in 2.31.0, the `merge-tree` mode that writes a merge tree (`--write-tree`) in 2.38.0, and `merge-tree --merge-base` in 2.40.0. *Reason: the git project owns its release history (`RelNotes/2.31.0.adoc:38-39`, `RelNotes/2.38.0.adoc:16-18`, `RelNotes/2.40.0.adoc:6`, read from a local copy of git's release notes).*
- G2. `git merge-tree --write-tree` exits 0 for a clean merge, with one tree-OID line on stdout. It exits 1 for conflicts, with the tree OID on line 1, then stage lines, a blank line and messages. Any other status means the merge could not complete. On git 2.56 an unknown ref also exited 1 with empty stdout, so exit 1 alone is not proof of conflicts. *Reason: git defines this interface (`git help merge-tree` and a temp-repo probe on git 2.56, both by a session explorer).*
- G3. `git pull` puts hook and script changes live with no install step, and `install.sh` runs only when a user runs it. *Reason: stow symlinks the checkout into `$HOME` (`CLAUDE.md`: "Changes under `claude/.claude/**` go live on `git pull`"). Changing that is an install-architecture decision outside this plan.*
- G4. Plugins install and update separately, through `claude plugin update`. `require-plugin-version-bump.sh` blocks a commit that touches a plugin directory unless the plugin's version strictly rose. *Reason: Claude Code's plugin mechanism, plus an existing gate this plan does not change (`.claude/rules/review-pipeline-dispatch.md`).*
- G5. The git on CI's `ubuntu-24.04` runner is whatever GitHub's runner image ships. *Reason: GitHub owns the image.*
- G6. Which git builds Ubuntu 24.04 publishes, under which version strings, and which stay downloadable, is Canonical's call. *Reason: Canonical runs the Ubuntu archive and Launchpad.*
