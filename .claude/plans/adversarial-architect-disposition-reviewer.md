# Key-gated adversarial architect reviewer for /code-review dispositions

## Context

Goal: let an Opus `plan-architect` challenge every ADDRESS/DEFER/KEEP row the `/code-review` orchestrator writes, so a disposition no longer stands on the orchestrator's own judgment alone.

Ask: "Yep, start planning it for this." — accepted via the shape the engineer confirmed with "Otherwise this makes sense."; revised by "Shouldn't the orchestrator get a chance to re-evaluate and then if it doesn't agree then ask me?" and "I think we want to have the adversarial architect on every round and then refine based on data."

Why now: PR #1349 tightened the never-DEFER bar for enforcement-invariant breaks, and the orchestrator still both writes and judges its own dispositions. Nothing challenges a DEFER that should have been an ADDRESS, or an ADDRESS that over-fixes.

Intended outcome, as the engineer settled it:

- After the orchestrator writes its disposition table, `plan-architect` (a new `MODE=challenge`, Opus) challenges every row in both directions and returns *uphold* or *flip* per row.
- On a *flip*, the orchestrator re-evaluates that row once with the architect's argument in front of it. If it concedes, it applies the flip and logs it. If it still disagrees, it stops and asks the engineer, showing both positions. There is no further back-and-forth.
- Existing rules still bind a concession: it never moves an enforcement-invariant break to DEFER, and a flip toward DEFER still needs a criterion from the closed DEFER list.
- It runs on every round, staged and cumulative, so the data can show later whether to narrow it.
- An owner-set config key gates it, the same pattern as `architect_fix_plan_pilot`. No session sets that key on any account.
- Each row outcome is logged as upheld, flipped-and-conceded, or flipped-and-escalated with the engineer's decision. Any baseline stays in a private directory outside the repository. Published text carries verdicts only, because the private reader is not a command that refuses a wider corpus, so nothing it computes is published as a count or rate (`docs/private-project-redaction.md` § "Publishing a tooling measurement").

User surface: every stow consumer's `code-review` skill, because `claude-skills/` installs to everyone who runs `./install.sh`.

## Approach

With an owner-set config key on, each `/code-review` round outside a `/review-pr` pass sends every ADDRESS or DEFER the orchestrator decided itself to one Opus `plan-architect` dispatch in a new mode, `MODE=challenge`, which answers `uphold` or `flip` per row. The engineer kept the challenger as this mode, not a separate agent (row 85), and answered that a `/review-pr` pass, which has its own consult process, is not a round for this rule (row 118). Before dispatching, the orchestrator marks as barred each row whose finding the enforcement-invariant rule or a loaded project layer bars from DEFER, counting a finding as barred when unsure, and leaves it out of the dispatch. The engineer chose that exclusion over having the architect argue such rows (row 116). A marked ADDRESS stays ADDRESS, and a marked DEFER becomes ADDRESS or the stop the rule that bars it prescribes. The orchestrator re-evaluates every flip once, concedes only when that re-evaluation reaches the flip's result under the rules above, and otherwise stops for the human (rows 2, 117). Every payload row's and every marked row's ledger `--rationale` is tagged with its outcome and the round's scope. The round-3 recorder and `review-trace` do not count a challenge as a consult, so a key-on branch still gets its round-3 foundation consult. A new decision record fixes the unit, metric, strata, guardrails, sample, window, decision rule and the action for each outcome, a private reader that only selects and copies ledger files by an explicit path set, and a behavioral fixture set, which a session runs as one subagent per case and hands the engineer as a pass/fail table before the key may go on, and keeps every threshold value private. It also carries a short note on the ad-hoc comparison of round count and PR cost, key on against key off, which the engineer asked for beside the per-row metric (row 103). The engineer reads that comparison by judgment at evaluation, with no join specified, and it cannot move the decision rule (rows 104, 109).

How it differs from the not-adopted architect-authored pilot (row 22):

- The orchestrator still writes every disposition. The architect only argues, and a flip changes a row only through the orchestrator's concession or the human's decision.

**Assumption ledger**

**Root problem:** The `/code-review` orchestrator both writes and judges its own ADDRESS/DEFER dispositions, so a DEFER that should be ADDRESS, or an ADDRESS that over-fixes, stands on one judgment. The one earlier attempt, an architect-authored disposition table, was not adopted: no detectable benefit, gross consult cost, and a DEFER of an enforcement-invariant finding went through without a stop (row 22). So this pilot must:

- ship default-off behind an owner-set key, in the shortest region that stays precise, in a file near its cap;
- leave every disposition to the orchestrator or the human, and leave among the architect's numbered rows none the orchestrator marks, before dispatch, as barred from DEFER, so such a row ends ADDRESS or at the stop the rule that bars it prescribes;
- leave the round-3 foundation consult firing on key-on branches, so the challenge and that consult are measured apart (row 45);
- have its per-row log, metric, sample, decision rule with an action per outcome, reader contract and behavioral fixture set fixed before it can be enabled, publishing no measurement value.
