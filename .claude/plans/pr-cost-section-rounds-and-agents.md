# Add review-round and agent-spawn counts to the PR Cost section

## Context

Extend the PR "Cost" section that `pr-cost-section.sh` embeds in every PR
body to add two new data points: per-branch review-round counts
(code-review, plan-review, ready-for-review) and per-branch subagent-spawn
counts broken down by agent type. Today's Cost section reports only dollar
totals by token class, model ID, and thread (main vs. subagent) — it
explains how much a branch cost but not what drove that cost, so engineers
can't tell from the PR body alone how many review cycles or what mix of
agent dispatches produced the number. After this change, every PR's Cost
section additionally shows review-round counts and per-agent-type spawn
counts (bare counts, no dollar attribution, no historical persistence), so
engineers — the requester foremost — can internalize which review-round and
dispatch patterns are driving cost, directly from the PR body they already
read.

### Decisions locked in this session

- **PR-body only.** No changes to the separate `pr-cost-ledger.tsv`
  persistence file or its schema — this is a live, regenerated-on-each-
  render addition to `pr-cost-section.sh`'s output only. `[engineer-verified]`
- **Counts only, no dollar attribution.** E.g. "code-review: 3 rounds" and
  "code-writer: 4 spawns" — not a $-per-round or $-per-agent-type
  breakdown. Dollar figures already exist elsewhere in the same Cost
  section (the existing thread-breakdown table), and dated per-round
  dollar breakdowns are separately flagged in this repo's docs
  (`docs/transcript-analysis.md:1071`) as a stronger de-anonymization/
  correlation key than aggregate counts. `[engineer-verified]`
- **Include `ready-for-review` in the round breakdown**, alongside
  code-review and plan-review. The underlying call computes all three
  `REVIEW_SKILLS` at no extra cost, and ready-for-review is a real,
  CLAUDE.md-documented cost driver peer to the other two gates.
  `[engineer-verified]`

### staff-product-engineer review findings to carry into the design

All findings below were adopted:

1. Agent-type labels in the new "spawns by type" section **must reuse the
   existing disclosure gate** (`_repo_tracked_agent_type_names` /
   `cmd_subagent_mix`'s `disclose` logic,
   `claude/.claude/scripts/transcript-analysis.py:2717,2864-2889`), not a
   fresh "this-repo scope means it's all safe" assumption — an untracked
   or ad hoc `subagent_type` string must stay redacted even under
   `--this-repo`, exactly as `cmd_subagent_mix` already does it.
2. The spawn-count data **must come from a non-truncated aggregate**, not
   a scrape of `cmd_subagent_mix`'s rendered table — that table caps at
   the top 5 spawn types per branch
   (`claude/.claude/scripts/transcript-analysis.py`, `top[:5]` around
   line 2705-2712), and this repo's own agent roster already exceeds 5
   types.
3. **Failure/degradation is per-subsection, not coupled to the existing
   `cost --summary` call.** Keep `cost --summary`'s existing fail-closed
   contract (`pr-cost-section.sh` exit 3) untouched. If the new
   round-count or spawn-count call fails, print a one-line visible
   caveat in the markdown itself rather than silently omitting the
   subsection. Omission is textually indistinguishable from "zero
   occurred." Zero is itself a legitimate state and must render
   distinctly from failure — `cmd_review_round_cost` already renders the
   zero case as "No review rounds found in scope."; reuse that exact
   framing for zero, with a visibly different one for failure. One
   *combined* caveat covers both subsections, since the two never fail
   independently, worded calmly rather than as an alarm. See the
   Approach section's M8 for the resolved design, including why no
   retry precedes the caveat (row24).
4. **Formatting matches the block's existing GFM-table convention** —
   `### Review rounds` / `### Subagent spawns` subheadings with small
   2-column tables (skill|rounds, agent type|spawns), not inline
   `key=value` prose.
5. **"Rounds" needs a one-clause disambiguation** next to the label —
   it's an invocation count, not a findings count
   (`claude/.claude/scripts/transcript_analysis/review_rounds.py:404-407`:
   "Every invocation is its own round... whether or not the round
   produced findings"). This is a public repo, so a skimming outside
   reader is also a plausible audience for misreading "code-review=3" as
   "3 rounds of findings."
6. **Verification must extend the existing GFM-table-boundary test
   coverage** to the two new sections' boundaries
   (`test_pr_cost_section.py`'s `TestCostBodyEndsWithTableRow` pattern) —
   this exact block has broken GFM rendering twice before via blank-line
   placement around table boundaries
   (`.claude/plans/pr-cost-block-render-and-caveat-alert.md`,
   `.claude/plans/pr-cost-section-deterministic-heading.md` — read these
   two prior plans for the specific landmine shape).

## Approach

Add one new, purpose-built subcommand — `transcript-analysis.py cost-counts` — that emits exactly two GFM subsections (`### Review rounds`, `### Subagent spawns`) for a branch, and have `pr-cost-section.sh` call it as a **second, independently-degrading** call whose output is spliced between `cost --summary`'s tables and the reproducibility trailer. The counts are computed by two new count-only aggregators that reuse the existing round-detection and spawn-scan semantics but skip all dollar pricing; agent-type labels are gated on the existing `_repo_tracked_agent_type_names()` allowlist, applied unconditionally rather than only under multi-root. `cost --summary` itself is not modified — its fail-closed exit-3 contract stays exactly as it is.

**The structural choice, stated plainly: neither of the two options handed to me.** Both were weighed and rejected.

*Rejected — extend `cost --summary` (Option A).* It is the heavier primitive on three counts. It couples the new content to a fail-closed contract (a crash in count code kills the whole Cost section, which finding 3 bars), so it would need a `try/except` wrapped inside a deliberately fail-closed path — the compounding-defensive-layers tell. `_cost_report` consumes its `session_iter` in one pass (`cost.py:515`), so round detection would need a second, separately-resolved pass inside the same function. And it would put two different branch-attribution models in one function: cost filters on `_attributed_branch` (`cost.py:64-91`) while round windows deliberately never use it (`review_rounds.py:14-18` records this as an explicit non-dependency).

*Rejected — `--summary` modes on `review-round-cost` and `subagent-mix` (Option B).* This looks like it mirrors the `cost --summary` precedent, but it doesn't. `cost --summary` is a genuine render switch over data the same pass already computed (`markdown=summary_mode` threaded into `_print_token_class_table`/`_print_model_id_table`/`_print_thread_table`, `cost.py:1000-1019`). A `--summary` on `review-round-cost` would have to bypass `compute_review_round_costs` entirely — the pricing walk is that command's whole reason to exist — and a `--summary` on `subagent-mix` would have to skip the model-mix join, the `_dispatch_usage_summary` pricing, the STALE PRICING banner, the top-5 truncation, *and* tighten the redaction rule. Each is an almost-disjoint code path wearing a render flag's name. Each also needs its own refusal matrix against its host's existing flags (`--config-dir`, `--per-session`, `--reprice-as`, `--since`, `--skill`), and `pr-cost-section.sh` would grow to three full corpus scans with two degradation paths for a failure surface that is empirically shared.

*Chosen — one new subcommand with a single output shape.* It is strictly **less** powerful than either rejected option: it has no non-summary mode, no `--config-dir`, no `--no-redact`, no dollar figures, no per-branch rows, and it resolves to the active config dir alone by construction rather than by flag. One extra corpus scan instead of two, and that scan is cheaper than `cost`'s (main-thread transcripts only, no pricing, no subagent-transcript descent).

**How finding 3 is satisfied.** `cost --summary` keeps its exit-3 contract untouched; `cost-counts` runs only after it succeeds, and its own failure never changes the wrapper's exit code. A failed `cost-counts` call substitutes a caveat paragraph into the same `printf` slot, so the markdown always carries either counts or a visible reason, never silence — no retry (row24): `corpus.py`'s own per-file error handling already degrades a transient read hiccup gracefully, so every failure this call can raise is deterministic and a retry would return the same result. **One caveat covering both subsections, not one per subsection** `[engineer-verified]`. The realistic independent-failure surface between them is empty — both walk the same records, and the only external call in the spawn path (`_repo_tracked_agent_type_names`'s `git ls-files`) already fails closed to the built-ins frozenset rather than raising (`transcript-analysis.py:2898-2899`). Finding 3's substance — a failure is visible in the body and textually distinct from zero — is satisfied by one caveat as fully as by two, and two would buy independence against a failure mode that does not exist at the cost of a third corpus scan.

### Assumption ledger

**Root problem.** The PR body's Cost block reports what a branch cost but nothing about what produced it, and the two facts that would explain it — review-round counts and per-agent-type dispatch counts — are already computed by tested code that no PR-body-facing path calls.

**Mechanisms:**

- **M1 — a new `cost-counts` subcommand with exactly one output shape.** `anchors: root, row4, row5, row11`. Over-powered-primitive check, two lighter primitives enumerated and each failing:
  (a) **Shell-scrape the two existing commands' rendered output** (`grep` the `rounds=N (code-review=X …)` line at `review_rounds.py:504` and the top-subagent-types column at `transcript-analysis.py:2731`). Zero Python change, genuinely lighter. Fails on three counts: the spawn column truncates at five (row4), the single-root label path publishes untracked types raw (row5), and `review-round-cost`'s stdout is a dated per-round dollar table whose presence would itself have to be suppressed — the exact artifact `docs/transcript-analysis.md:1071` flags as the stronger de-anonymization key.
  (b) **`--summary` flags on the two existing commands.** Lighter in surface-area terms. Fails because each flag selects an almost-disjoint code path inside its host rather than a render switch (see Approach), multiplies the refusal matrix across two commands' existing flags, and yields three corpus scans.
  The chosen mechanism is narrower than both rejected *and* than the heavier Option A: no flag matrix, no redaction-mode branching, no multi-root path to guard, no dollars.

- **M2 — `review_rounds.compute_review_round_counts(session_iter, *, branch_filter)`, reusing detection and skipping pricing.** `anchors: row7, row8`. Returns `{skill: count}` for every `REVIEW_SKILLS` member, zeros included. It calls `pricing.dedup_turns_by_request_id`, `_detect_round_windows`, and `_session_record_branches` — the same three, in the same order, as `compute_review_round_costs` (`review_rounds.py:317-320`) — then counts instead of pricing. What counts as a round therefore has exactly one definition. Over-powered alternative rejected: calling `compute_review_round_costs` and tallying its `rounds` list. That walks `_index_subagent_dispatches`, opens every dispatched subagent transcript, and recurses through nested dispatches (`review_rounds.py:183-256`) to produce dollars this plan discards — the heavy primitive for a count.

- **M3 — `_spawn_counts_by_agent_type(session_iter, branch_filter)` in the shim, beside `cmd_subagent_mix`.** `anchors: row4, row9, row5`. Walks main-thread assistant records, matches literal `gitBranch`, counts `subagent_type` per `_SPAWN_TOOL_NAMES` block. It lives in the shim, not the package, because the disclosure allowlist it must respect lives in the shim (`transcript-analysis.py:2864`) and the package may not import back from the shim. The shared datum with `cmd_subagent_mix` is three constants, not logic: `_SPAWN_TOOL_NAMES`, the allowlist, and the `"unknown"` fallback literal at `transcript-analysis.py:2653` — promote that last one to a module constant used by both sites. Deliberately **not** refactoring `cmd_subagent_mix`'s loop to share code: that loop interleaves spawn counting with model-mix accumulation, `meta.json` joins, per-session keying, and `--since` filtering, and the honest overlap is about six lines.

- **M4 — the allowlist is applied unconditionally; untracked types fold into one `(withheld — untracked agent type)` row.** `anchors: row5, row6, G3`.

  - **Stricter than `cmd_subagent_mix`'s single-root behavior, deliberately.** The correct justification is G3, not "public body" alone: the allowlist can only ever resolve *claude-config's own* tracked `agents/` tree (G3), regardless of whose branch is being scored, so any consumer's own real, project-tracked agent types are as unresolvable to this function as a genuinely ad hoc dispatch and must fold into the same withheld row.
  - **The tradeoff, named rather than silently accepted.** For claude-config's own PRs this is exactly the public-disclosure floor intended. For another stow consumer running `pr-cost-section.sh` in their own (possibly private) repo with their own custom agents, the same fold withholds real, locally-known agent names for no privacy benefit in that context — a real tradeoff, inherited from G3 and not fixable within this plan's reach (fixing it means teaching the shared, tested allowlist function to resolve a consumer's own tracked agents, which `cmd_subagent_mix` also depends on). Named in the CHANGELOG entry (Critical file #13).
  - **A single folded row, not `agent-type-<N>` ordinals.** Ordinals need a root ordinal that doesn't exist here (row6), and per-type ordinals would disclose the *number* of distinct non-toolkit agent types for no reader benefit. Sort real rows by `(-count, name)` matching `transcript-analysis.py:2730`; append the withheld row last regardless of count, so it can never be mistaken for an agent name.
  - **Render-time backstop.** Immediately before the per-row print, check that every non-withheld label is a member of `_repo_tracked_agent_type_names()` — independent of whichever step computed the partition — and fail with an explicit `if not (...): raise AssertionError(...)`, not a bare `assert` statement, since `assert` is compiled out under `python -O`/`PYTHONOPTIMIZE=1` and this control's entire purpose is to fail loudly rather than silently disclose. A future edit that regresses to calling `_stype_label` directly (the exact gate-free path row5 identifies) then fails loudly, as a test failure or exception, instead of silently disclosing an untracked name.
  - **No pipe-escaping.** An arbitrary `subagent_type` string is never printed raw regardless of its content: it either matches a stem in `_repo_tracked_agent_type_names()` — this repo's own committed `agents/*.md` filenames — or it folds into the withheld row before this table ever sees it. Today, all 13 tracked filenames happen to follow a kebab-case/PascalCase convention containing no `|` (verified by listing `claude/.claude/agents/*.md`), but that is a fact about the current file set, not an enforced invariant: `_AGENT_TYPE_NAME_RE` (`transcript-analysis.py:2821`) gates a different code path — `_declared_pin`'s transcript-sourced `agent_type`, as a path-traversal guard before building a file path — and enforces nothing about what filenames may be committed under `agents/`. A new test (Critical file 7) asserts every tracked `agents/*.md` stem matches `_AGENT_TYPE_NAME_RE`'s charset, so a future filename outside it fails a test rather than silently reaching a GFM table cell raw once that agent is dispatched. Escaping would also be self-defeating in the order this mechanism runs ahead of it: escaping a label before checking it against the allowlist means an escaped label could never match the unescaped allowlist entry it corresponds to.

- **M5 — single-root by construction: `roots = [config_dir() / "projects"]`, with `cost --summary`'s own scope gate replicated.** `anchors: row11, row12, G4`.

  - **Root construction.** `roots = [config_dir() / "projects"]`, resolved directly rather than via `_resolve_cost_roots` (row11).
  - **`--this-repo`/`--projects` refusal.** `--this-repo` required and any non-default `--projects` refused with exit 2 on stderr, mirroring `cost.py:534-544` verbatim in shape and message.
  - **Tuple membership.** No `--config-dir` flag is registered on the subcommand's own parser, but `cost-counts` **is** added to `_SUBCOMMANDS_REFUSING_TOP_LEVEL_CONFIG_DIR` (`scope.py:480-485` — renamed from `_SUBCOMMANDS_WITH_OWN_CONFIG_DIR`, see Critical file 3), same as every other member of that tuple. Per Critical file 3's rename, the tuple's members share only the one property it actually guarantees: the top-level flag is refused outright, regardless of how each member resolves its own scan roots. A top-level `--config-dir PATH` flag is therefore refused with the existing loud exit-2 message rather than silently falling through `main()`'s reassignment branch and being ignored — the exact silent-divergence trap the tuple exists to close.
  - **Why `--branches` is runtime-checked, not parser-required.** `--branches` is declared optional on the parser but refused at runtime inside `cmd_cost_counts` when absent, exit 2 on stderr, in the same style as the `--this-repo`/`--projects` checks above. An argparse-level `required=True` would raise its own error during `parser.parse_args()`, before `main()`'s top-level `--config-dir` refusal check ever runs — that check (`test_transcript_analysis.py:245`'s existing parametrized bare-invocation test) depends on firing first for every `_SUBCOMMANDS_REFUSING_TOP_LEVEL_CONFIG_DIR` member, `cost-counts` included. ## Out of scope

- **Any dollar attribution per round or per agent type.** `[engineer-verified]` — and independently, `docs/transcript-analysis.md:1071` flags a dated per-round dollar series as a materially stronger de-anonymization key than aggregate counts.
- **Any change to `pr-cost-ledger.tsv`, its schema, or historical persistence of these counts.** `[engineer-verified]`
- **Any change to `cost --summary`'s output, refusals, scope guarantee, or fail-closed exit-3 contract.** The wrapper gains a second call around it; `cost.py` is untouched.
- **Retrying the `cost --summary` call, or retrying `cost-counts` at all.** The cost call's failure is fail-closed by contract — exit 3, no stdout, a documented signal `pr-description/SKILL.md:76-89` tells its caller how to read — so a silent retry there would change a published contract for no reader benefit. `cost-counts` gets no retry either: `corpus.py`'s own per-file error handling already degrades a transient read hiccup gracefully (`corpus.py:78-80`), so every failure that reaches `cost-counts`'s own exit code is deterministic, and a retry would return the same result while adding a second corpus scan for nothing.
- **Removing `cmd_subagent_mix`'s top-5 truncation, or changing its single-root raw-label behavior.** Both are correct for a terminal-facing maintainer command. The new path avoids them by not routing through that command at all (row4, row5). A change to either would churn a large tested command for no benefit to this feature.
- **Reconciling `cmd_subagent_mix`'s `CR`/`PR`/`RR` columns with `review_rounds`' round detection.** They disagree today: `transcript-analysis.py:2682-2685` matches a raw `input.skill` against `REVIEW_SKILLS` on the `Skill` tool_use path only, while `review_rounds._round_open_skill` (lines 82-116) also detects the `/slash` path and normalizes `plugin:`/directory qualifiers first. So `subagent-mix`'s CR column can read lower than this plan's round count for the same branch. Real, pre-existing, and not this diff's to fix — correcting it changes `subagent-mix`'s published numbers and needs its own evidence about which shapes are being missed in practice. Filed as [GH-981](https://github.com/jcdendrite/claude-config/issues/981).
- **Designating a single canonical home for the disclosed-fields inventory.** It lives in four places today (row17); this plan updates all four rather than leaving one stale. Collapsing them to one home with cross-references elsewhere is a separate change, out of proportion to this feature: it would touch `README.md`, `docs/transcript-analysis.md`, `docs/hooks.md`, and `pr-description/SKILL.md` — four doc surfaces with four different readerships and altitudes (Prose and Output Format's "place prose where its reader and altitude match") — for a documentation restructure unrelated to what this feature adds.
- **Counting nested dispatches (an agent spawned from inside another agent) in the spawn totals.** Excluded deliberately, matching `cmd_subagent_mix` and `pricing._count_subagent_spawns` (`pricing.py:445-456`). Including them would require the `meta.json` dispatch index and a recursive descent — the pricing-weight machinery this design exists to avoid — and the exclusion is stated in the section's own caption (M7).
- **Unifying the two subsections' branch-attribution models** (rounds carry forward, spawns use the literal `gitBranch` — row10). Each preserves its own source's documented contract; changing either would fork a semantic that a dollar-bearing command also depends on.
- **A `--summary`-style flag on `review-round-cost` or `subagent-mix`.** Rejected in the Approach; if a future consumer genuinely needs a markdown render of either command's *full* output, that is a different feature with a different consumer.
- **Making the failure caveat two independent per-subsection caveats.** Resolved: one combined caveat, `[engineer-verified]` (row24) after being raised as an open question. Both subsections walk the same records and the spawn path's only external call already fails closed rather than raising, so a second caveat would buy independence against a failure mode that does not exist, at the cost of a third corpus scan.
- **Back-filling counts into already-merged or already-drafted PR bodies.** Any live PR's block regenerates on its next `/pr-description` sync; editing a merged PR's body rewrites a historical record for no functional gain.
