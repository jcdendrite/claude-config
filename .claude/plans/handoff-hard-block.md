# Tighten the handoff-nudge hard block and reference agent output on handoff

## Context

**Goal: make the existing handoff-nudge hard block actually engage soon after it's ignored, fix a bug that currently makes it dangerous to tighten, and point a written handoff at subagent output the session hasn't yet synthesized.**

The engineer reported sessions repeatedly blowing past the handoff-nudge hook's context threshold before ever handing off, showing a transcript where a session hit 485k tokens after dismissing two advisory nudges ("I'm almost done" — reasonable each time in isolation, but the pattern recurs). He asked for the nudge to become a hard block soon after being ignored, for background subagents to never be stopped by that block, and for unprocessed subagent output to be captured into a secondary file as part of handoff.

Discovery found the hard block already exists (PR #636, `HANDOFF_NUDGE_BLOCK_AFTER`, default 3) but almost never engages in practice, and — independent of anything this plan changes — its exit path has a live inversion bug on one of its two hook registrations that lowering the block-after count would turn from latent to routinely triggered. Discovery also found the harness already durably persists every subagent dispatch's full transcript to disk, independent of the parent session, which changes "capture output" from a new-mechanism problem into a reference problem.

## Approach

**Concluded design, in two parts:** (1) tighten `HANDOFF_NUDGE_BLOCK_AFTER`'s default from 3 to 1 and fix a pre-existing exit-code inversion bug in the same hard-block path that the tightening would otherwise turn from dormant to live; (2) have the `handoff` skill name any not-yet-synthesized subagent dispatch by its harness-assigned `agent-<agentId>`, inside its existing "mid-flight" clause, rather than building a new file-capture mechanism — the content is already persisted by the harness.

Both parts stay inside files this plan already owns. Neither touches `HANDOFF_NUDGE_ABS_CAP`, `PCT_THRESHOLD`, or `HANDOFF_NUDGE_REARM_SPACING` — a peer session (coordinated live, this session, via cross-session message) is independently regrounding the absolute-cap value; the engineer separately confirmed this plan must not hardcode or relitigate that constant.

**Alternatives considered**, inline per mechanism, are in the ledger below (each mechanism row carries its own rejected-lighter-primitive pair, per the over-powered-primitive gate).

## Amendment: subagent-safe handoff + PR #708 review fixes

## Context

**Goal: stop a handoff from stranding this session's own in-flight background subagent dispatches, and clear the three PR #708 review comments that trace to that same root cause.**

Three review comments landed on PR #708. (1a) The hard-block stderr message (`nudge-handoff-near-context-cap.sh:616`) ends with a sentence telling the engineer to raise `HANDOFF_NUDGE_BLOCK_AFTER` — guidance `docs/handoff-nudge.md:22,24` already documents in full. (1b) The same message's "if the current task is genuinely almost done, finish it in this reply" clause is the exact rationalization the `BLOCK_AFTER` 3→1 change exists to defeat (`docs/handoff-nudge.md:24`: "two dismissed advisory nudges, each dismissal reasonable in isolation"). (2) A handoff written while a dispatch is still running wastes that dispatch. (3) The shipped §2.5 text (`SKILL.md:61`) tells a resuming session to "address it by this session's name rather than re-dispatching" — unsound, because a handoff normally precedes the spawning session ending.

Independent research this session (`claude-code-guide` dispatch) concluded no session can recover a subagent it did not itself spawn once the spawning process ends — matching this plan's own **Other assumptions #5**, already tagged `[unverified — flagged for plan-review]`. The engineer chose **wait-before-handoff** over after-the-fact capture: waiting sidesteps cross-session recovery instead of attempting it.

## Approach

**Collect before handing off, using a non-blocking status check; leave the hard block alone.**

`ListAgents` reports, per row under "Subagents", whether a dispatch this session spawned is still `running` — a fact the harness reports about a real dispatch, not the blocked agent's self-assessment, satisfying the constraint that a wait must never become a self-granted "I'm almost done" excuse. The `handoff` skill gains a collect-then-write step; §2.5 then names *collected* or *stranded* dispatches rather than instructing a resuming session to chase a dead session.

A synchronous blocking-retrieval tool (`TaskOutput`, `block: true`) was considered and rejected: its own tool schema opens with "DEPRECATED: Background tasks return their output file path in the tool result, and you receive a `<task-notification>` with the same path when the task completes" — the harness is steering callers toward the passive notification path, which this session used successfully twice already (both background dispatches this session ran delivered their result via an automatically-injected `<task-notification>`, with no explicit retrieval call). `[verified: TaskOutput tool schema, loaded and read directly this session, superseding an earlier draft of this amendment that proposed `TaskOutput(block: true)` based on corpus evidence of past usage — that evidence predates this deprecation and doesn't establish current-recommended status]`. Building a new load-bearing mechanism on a tool the harness marks deprecated would be its own defect, and `TaskOutput`'s undocumented internal timeout (surfaced by the same corpus evidence) would otherwise have forced an ungrounded retry-budget literal under CLAUDE.md's "Ground every choice" — `ListAgents` needs neither.

**The hook's block path is not modified.** This plan's own Out-of-scope entry ("An in-session escape from a hard block… a block the blocked agent can undo from inside its own blocked turn isn't a block") is respected, not amended: the hard block still fires at the same estimate, on the same event, with the same exit 2. The wait happens *after* the block, inside `/handoff`, which is already the block's documented exit route (`docs/handoff-nudge.md:26`).
