# Block more types of "no-op" agents

## Context

`claude/.claude/hooks/deny-no-op-dispatch.sh` denies an `Agent`/`Task`
dispatch only when its prompt is under 600 characters AND matches one of
two closed, corpus-grounded idiom lists (`NOOP_STUB_TOKEN_RE`,
`NOOP_PHRASE_RE`). GitHub issue jcdendrite/claude-config#1022 reports a
no-op dispatch that clears both regexes: `"This is a no-op check.
Immediately return 'ack' with no further action."` The hook's own design
doc (`docs/design-decisions/no-op-dispatch-hook-gate.md`, Known gaps)
already names this exact failure mode — "a differently-worded future
no-op prompt using none of the listed idioms is not caught" — as an
accepted, revisitable gap rather than a surprise. This plan extends the
idiom lists to close the specific shape the issue reports, and — per the
engineer's request — surveys this machine's own transcript corpus for
any other no-op shapes that evaded the gate before it shipped further
idioms.

## Approach

Extend `NOOP_PHRASE_RE` by exactly two edits — add `no work to do` as a new alternative, and widen the existing `no action` alternative to `no (further )?action` — then update the hook header and `docs/design-decisions/no-op-dispatch-hook-gate.md` to record a third grounding source for the idiom list: a prompt quoted verbatim in a public issue on this repository and confirmed by the maintainer as a real occurrence. Those two edits close both confirmed evading prompts: the repo-transcript-sourced one ("…there is no work to do. Return immediately with no tool calls.") via `no work to do`, and GH-1022's reported one ("…Immediately return 'ack' with no further action.") via the widened alternative. `NOOP_STUB_TOKEN_RE` and `NOOP_MAX_PROMPT_LEN` are untouched.

**Why two edits and not four.** The transcript sweep proposed `immediately return`, `no work to do`, `no tool calls`, and the `no (further )?action` widening. Each additional alternative buys coverage only by spending false-positive surface, and two of the four buy nothing that the other two do not already cover:

- `no tool calls` is excluded by the decision doc's own rule, not by a judgment call. That doc states a grounded source is necessary but not sufficient: "a read-scoping instruction ('do not read any files') restricts tool access rather than stating 'do no work,' a materially different instruction shape from every idiom actually in the list, so it stays excluded regardless of its own corpus provenance." "Return immediately with **no tool calls**" is that same shape — a restriction on which tools may be called, not a statement that there is no work. The repo-sourced occurrence is already caught by `no work to do`, which sits in the sentence before it and *is* a do-no-work statement, so excluding `no tool calls` costs no coverage. Adding it would also sit in tension with the pinned allow case `test_read_scoping_instruction_allowed`, which encodes exactly this distinction (it would not fail that test — its fixture text differs — but it would contradict the principle the test exists to hold).
- `immediately return` carries a materially different false-positive profile from every alternative currently in the list, and closes nothing the widening does not already close. "Immediately return" has no do-no-work semantics of its own: "return" is the ordinary verb for delivering a result and "immediately" is an ordinary urgency modifier. The shape it collides with is this repo's most common short-prompt dispatch — a locate-and-report discovery prompt well under the 600-character ceiling ("Grep for the `_lib_capped` call sites and immediately return the line numbers"). A denial there is worse than the usual false positive, because the deny message's compliance path ("state that work in the prompt and retry") is already satisfied — the prompt *does* state real work, so the dispatching session has nothing useful to change and will pad or loop. Contrast the accepted residuals already in the list, where the matched phrase genuinely is a do-no-work statement and the ambiguity is only about *whose* inaction it describes.

**False-positive judgment, per new alternative.** Both additions are judged to carry the *same* accepted risk class as the existing `do(ing|es)? nothing` / `no action` residual, not a materially different one:

- `no (further )?action` adds one optional word between two tokens already in the list, so the only new matching string is "no further action" — a phrase whose ordinary meaning is an instruction to the addressee to stop acting, which is the no-op shape itself. Its residual is the identical referent ambiguity the doc already records for `no action` ("no further action is required from the retry handler"), at lower density than bare `no action` because the longer phrase is more specific.
- `no work to do` is a four-token phrase whose referent ambiguity is the same class as `does nothing` ("Check whether the scheduler decides there is no work to do at midnight"), and is narrower than either existing residual because all four tokens must be adjacent.

**Why the grounding rule needs amending rather than stretching.** The hook header and the decision doc both state that every idiom traces to one of exactly two sources: a verbatim appearance in a confirmed no-op dispatch from *this repo's own transcript history*, or a phrase `claude/.claude/CLAUDE.md`'s Agent Briefing bullet names as prohibited. `no work to do` satisfies source 1 cleanly. The widening's grounding is GH-1022's reported prompt, which is neither — it is a real occurrence the maintainer confirmed, reported through a public issue rather than read out of this repo's transcripts. Stretching source 1 to cover it would either make a false claim about where the occurrence was observed, or require the doc to characterize a corpus this repo may not describe (see the fourth given). The honest fix is a third source, stated with its own bar: **a prompt quoted verbatim in a public issue filed against this repository and confirmed by the maintainer as a real occurrence, not a hypothetical the issue author invented.** That keeps the list closed in the sense that matters — source 3 is still a confirmed-occurrence rule, differing from source 1 only in where the occurrence was observed, never in whether it was observed. A speculative phrase written into an issue still fails all three sources.

**Alternatives set aside.** (a) Leave the gap — the doc's Known gaps bullet already licenses it ("a differently-worded future no-op prompt using none of the listed idioms is not caught"). Set aside because that bullet is about *unknown* future wordings; these are two confirmed occurrences, one of them filed as a bug, so the accepted-gap framing no longer covers them. (b) Doc-only note with no regex change — set aside on the same evidence the original decision rests on: an advisory surface does not reach this impulse. (c) Add an unanchored `no-op` or `ack` alternative to catch GH-1022's prompt by its most distinctive token — set aside as clearly worse than the widening: `test_no_op_substring_in_non_anchored_position_allowed` already pins that "Find every no-op dispatch fixture" must allow, and a repo that discusses no-op dispatches in its own prose is the worst place to match that substring freely. (d) A new decision file for the third grounding source — set aside because this is the same decision's rule being restated, not a decision overturning it; `.claude/rules/design-decisions.md` reserves supersession for the overturned case, and the doc's maintenance model is editing in place.

### Assumption ledger

**Root:** The gate's closed idiom list does not reach two confirmed no-op prompt shapes — the one reported in GH-1022 and one from this repo's own transcript history — and the list's stated grounding rule admits only two sources, neither of which covers a prompt confirmed through a public issue rather than a transcript read.

**Givens:**

- The `PreToolUse` `Agent`/`Task` payload carries no non-content signal for "this dispatch does no work." The harness owns that schema, so content matching remains forced rather than chosen, exactly as in the original decision.
- No idiom list can be proven complete: transcript retention rotates and any sweep is keyword-based, so every occurrence set is a floor. No repo-side instrument changes this.
- `claude/` is stowed, so this hook fires for every consumer who runs `./install.sh`, on every `Agent`/`Task` dispatch they make. The user surface is every stow consumer, not this session's owner.
- Occurrences observed outside this repo's own transcript history may not be quoted, counted, or characterized in any committed artifact. Repo-root `CLAUDE.md`'s redaction rules bind this public repo absolutely; relaxing them is not this plan's to do.
- The gate remains a cooperative guardrail, not an adversarial-resistant boundary — padding a no-op prompt past the ceiling always clears it. Fixed by the prior decision; reopening it is a separate decision with its own evidence bar.
