# Give every /code-review reviewer agent a precomputed diff artifact

## Context

Give every reviewer agent `/code-review` dispatches — `comment-discipline-reviewer` and the eight `ciso-reviewer`/`staff-*` specialists — an actual, parent-computed diff artifact to read, instead of leaving them to self-compute one (only some have Bash, and none are instructed to run `git diff` even when they do) or to work from a prose-only "file paths with added/modified line ranges" description that can drift across review rounds. This surfaced from a report that the second and third `comment-discipline-reviewer` rounds in one `/code-review` fix-loop — lacking Bash and lacking an actual diff — guessed review scope by content correlation and flagged four issues in pre-existing, untouched content: a false-positive churn mode. `skill-fidelity-reviewer` already solves this correctly for its one call site (`/ready-for-review`'s skill-fidelity pass, via `pr-diff-against-base.sh --diff-file`). This plan adopts the same pattern for `comment-discipline-reviewer` specifically — the one specialist `/code-review` dispatches with no `Bash` of its own — computing the artifact once in the orchestrating session and handing it to that spawn as a file path or literal text, immediately before that spawn. The other eight specialists already self-fetch their own diffs via `Bash`, commonly scoped to the files in their own lane, and keep doing so unchanged — see row18 for why widening this to all nine would regress rather than improve their behavior.

## Approach

Give `comment-discipline-reviewer` — the one reviewer `/code-review` dispatches that carries no `Bash` — a real diff artifact to read, resolved by the orchestrating session immediately before that one spawn. The eight Bash-having reviewers (`ciso-reviewer` and the seven `staff-*`) are not touched: they already fetch their own diffs, commonly scoped to the files in their own lane, and handing them a shared unscoped artifact would widen what each reads rather than sharpen it.

`claude/.claude/scripts/pr-diff-against-base.sh` gains a `--staged` mode: a branch taken before the existing `gh pr view`/merge-base resolution that sets `DIFF_TEXT=$(git diff --cached)` and falls through into the same `--record`/`--diff-file` writer blocks the cumulative mode already uses. The two diff kinds differ only in how `DIFF_TEXT` is computed; they share the entire artifact-writing mechanism (mktemp-then-`mv`, the single composed EXIT trap, the `DIFF_FILE:` announcement convention), so a second script would be a third inline copy of that mechanism, not a new capability. `/code-review` resolves that artifact inside the Change-type table row that spawns `comment-discipline-reviewer` — not in Step 0 — mirroring `findings-path-suffix.sh`'s compute-once-right-before-the-first-spawn idiom. `comment-discipline-reviewer` gains an `## Input contract` section telling it to read the artifact and never to infer scope from content. `/ready-for-review` computes its cumulative artifact once in step 3 and hands the path down to both step 4 and `/code-review`, so when the comment spawn happens under the cumulative pass it reads the same diff the `cumulative-review` marker attests.

Four design points are settled, not open:

- **The fix is one agent wide, not nine.** Only `comment-discipline-reviewer` lacks `Bash` and therefore cannot self-fetch. Making the artifact a session-wide Step 0 input would have replaced eight reviewers' existing per-lane self-fetching with one unscoped shared file — a regression dressed as a generalization.
- **`--staged --record` is rejected at argument-parse time, exit 2, before any git call.** `marker.sh`'s `write cumulative-review` arm reads the `--record` subject file and hashes whatever text it finds, with no provenance check on the contents (`marker.sh:539-551`). A staged diff recorded there would make the `cumulative-review` marker attest a cumulative review that never happened. The combination has no valid use, so it fails loudly rather than being silently ignored.
- **`--staged` writes to `code-review-diff-markers/`, not the cumulative mode's `cumulative-review-diff-markers/`.** Both paths are fixed per repo-hash-and-session. A single session that runs `/ready-for-review` and then a fix-commit `/code-review` would, on a shared path, have the staged write clobber the cumulative artifact that step 4's `skill-fidelity-reviewer` dispatch is about to read. Separate directories make that collision unrepresentable.
- **On any diff-artifact-resolution failure, halt and ask for help** — never fall back to a prose-described scope. This covers an unresolvable config dir and a failed `mkdir`/`mktemp`/`mv`; it does not cover "nothing staged," which is a normal outcome with its own announcement. Concretely: the resolution runs before this round's single batched spawn message (the same "before the first spawn this round" point `findings-path-suffix.sh` already occupies), so a failure here means *no* reviewer is spawned this round, not only `comment-discipline-reviewer` — there is no partial batch to send. `/code-review` reports the failure in prose, quoting the script's own stderr line, and stops, exactly like any other halt-on-fail step in these skills (e.g. `ready-for-review/SKILL.md`'s halt-on-fail steps 1–4 and 7). Nothing is "killed," because nothing has been dispatched yet at that point. The engineer's own framing: "this is an error case, same as if you couldn't make any more Bash calls."

**Assumption ledger**

Root: `comment-discipline-reviewer` is dispatched with no `Bash` and no machine-readable statement of what changed, so it infers review scope by correlating file content against a prose description of changed line ranges and flags untouched, pre-existing prose as findings. The other eight reviewers `/code-review` dispatches carry `Bash` and already fetch their own diffs, so this is one agent's defect, not the roster's.

Givens:

- **G1.** A subagent sees none of its dispatcher's tool results; everything it knows arrives in its prompt or through its own tools. Harness-imposed, outside this repository's reach.
- **G2.** A single `Read` returns at most 2,000 lines, so a long diff truncates silently unless the reader paginates with `offset`. Harness tool contract; the design works around it in prose rather than dissolving it.
- **G3.** The worktree-isolation Bash guard refuses a Bash call that captures a temp path and reuses it in the same call. Harness-side guard (`docs/worktree-bash-guard.md`); it is why a script, not an inline recipe, is the only available shape.

Mechanisms:

- **M1 — a `--staged` mode on `pr-diff-against-base.sh`.** `anchors: root`. The staged-diff case is the high-frequency `/code-review` invocation and has no script today. Over-powered-primitive check, three lighter primitives weighed: (a) an inline multi-statement Bash recipe in the skill body — fails on G3, since capture-then-reuse is exactly the shape the guard blocks; (b) the orchestrator running `git diff --cached` and transcribing its output into the dispatch prompt — fails because transcription by the model *is* the drift vector this change exists to remove, and above the Bash tool's truncation threshold the parent never holds the full text to transcribe; (c) a separate `staged-diff-file.sh` — rejected because it would reimplement the mktemp/trap/announce mechanism a third time for a four-line difference in how `DIFF_TEXT` is derived, leaving two files to keep in sync on every future change to the artifact convention. The `--staged` branch sits entirely upstream of the `gh pr view` block, so the cumulative path's fixed ordering — the original reason this option looked closed — never applies to it.
- **M2 — marker directory `code-review-diff-markers/`.** `anchors: row8`. Slots into the existing `<kind>-markers` / `<kind>-subject-markers` / `<kind>-diff-markers` family, and the `-markers/` suffix puts it inside `enforce-marker-script-shape.sh`'s shape glob, so a reviewer agent can `Read` the artifact but cannot write it. Distinct from `cumulative-review-diff-markers/` so the two diff kinds never share a fixed path within one session.
- **M3 — one `## Input contract` block in `comment-discipline-reviewer.md`, plus a single-file test.** `anchors: root, row1, row11, row14, row18`. Over-powered-primitive check: the heavier form — two byte-identical blocks across nine files, a `DIFF_INPUT_BASH_AGENTS`/`DIFF_INPUT_NO_BASH_AGENTS` roster, a cross-file byte-equivalence test, and a completeness assertion against `CANARY_AGENTS` — was designed and rejected. It exists to stop drift between duplicated copies, and with one file in the roster there are no copies to drift. The lighter form is a presence-and-literals check on one file, mirroring `test_all_reviewer_agents_have_write_tool`'s per-agent frontmatter-plus-content shape (row14). No conditional for plan dispatches is needed either, because that agent is not on `/plan-review`'s roster (row11).
- **M4 — the cumulative diff is computed once per gate pass and its path is handed onward.** `anchors: row10, row17`. Step 3 writes the artifact with `--record --diff-file` and hands its `DIFF_FILE:` path to both step 4 and `/code-review`. Step 4 invokes the script itself only in the cache-hit branch, where step 3 was skipped and nothing was computed this turn. Recomputation is not merely wasteful: a second invocation resolves a *fresh* diff that can differ from the one `--record` stamped as the marker subject, making the marker attest a review of a diff nobody read.
- **M5 — resolve the artifact inside the Change-type row that spawns `comment-discipline-reviewer`, not in Step 0.** `anchors: row7, row18, row19, row20`. Over-powered-primitive check: a Step 0 resolution is the heavier primitive — it runs on every `/code-review` invocation, including the many that never spawn this row, and it frames the artifact as every spawn's input, which row18 shows is wrong for eight of nine. Row-local resolution is the lighter one and already has an idiom in this same section (`findings-path-suffix.sh`, `code-review/SKILL.md:297`). It also costs no lines against a 19-line cap headroom (row19) and covers 100% of the agent's dispatches, because that row is its only dispatch site (row20).

**Prescribed text — the `--staged` mode's contract**

`--staged` is accepted in the same parse loop as `--record` and `--diff-file`. `--staged --record` in either order is rejected after the loop and before any git call: `pr-diff-against-base.sh: --staged cannot be combined with --record (the cumulative-review subject must be the cumulative diff)`, exit 2.

When `--staged` is set, the `gh pr view`/merge-base block (`:41-53`) is skipped entirely and `DIFF_TEXT` comes from `git diff --cached`. Three outcomes:

- **Staged changes exist:** `DIFF_TEXT` reaches stdout through the existing shared `printf '%s\n'` at `:58`, then the unchanged `--diff-file` writer block runs. On success it announces `DIFF_FILE: <path>` on stderr after the `mv`, so the line's presence is proof the file exists.
- **Nothing staged:** `DIFF_EMPTY: no staged changes` on stderr, exit 0, nothing on stdout, no file written. This returns early, before the shared `printf` and before the writer blocks — otherwise `--staged --diff-file` on an empty index would write a one-byte artifact and announce `DIFF_FILE:`, forcing every caller to re-derive emptiness by reading the file. The early return is safe at that point because both temp-file variables are still empty and the EXIT trap has nothing to clean up.
- **`git diff --cached` fails:** `pr-diff-against-base.sh: --staged could not compute the staged diff`, exit 1. This is a new safeguard, not parity with the cumulative branch: that branch's own `git diff` at `:57` runs unguarded (row22), so a wrapped check exists nowhere to match. `--staged` adds one because a locked or corrupt index is a reachable failure and a bare `set -e` abort would leave the caller holding git's stderr with no script-named cause.

One line inside the `--diff-file` writer block changes: its `DIFF_DIR` assignment reads a `DIFF_MARKER_DIR_NAME` variable set once in the mode branch above — `cumulative-review-diff-markers` in the default arm, `code-review-diff-markers` in the `--staged` arm. Assign it unconditionally in both arms, ahead of the `if [ "$WRITE_DIFF_FILE" -eq 1 ]` block rather than inside it, so `set -u` never dereferences it unset when `--diff-file` is passed. Every other byte of both writer blocks, including the trap composition and the trailing-newline conventions, is unchanged. The diff command is `git diff --cached`, the same invocation `marker.sh`'s `write code-review` arm hashes (row21), so the artifact the reviewer reads is byte-identical to the subject that completion marker attests.

Update the script's header comment: the usage line becomes `pr-diff-against-base.sh [--staged] [--record] [--diff-file]`, and `--staged` gets its own paragraph naming the mutual exclusion with `--record` and its distinct marker directory. Leave the `--diff-file` paragraph's caller sentence for phase 2, which is what makes its replacement true.
