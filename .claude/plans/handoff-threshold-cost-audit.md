# Did raising the handoff hard-block floor to 470,000 tokens (PR #769, inherited unchanged by PR #782) cut cost?

## Context

The original goal was to determine whether replacing the count-based handoff hard-block (`HANDOFF_NUDGE_BLOCK_AFTER`, tightened in PR #708 to fire after 1 ignored re-arm) with an absolute-token hard block (`HANDOFF_NUDGE_BLOCK_AT`, default 470000) — merged in PR #782 on 2026-08-31 12:06:15 -0700 — reduced overall handoff-related cost. This is a follow-up to `docs/case-studies/handoff-threshold-impact.md`, which evaluated an earlier, different mechanism change (the advisory-nudge absolute cap drop from 360,000 to 150,000 in PR #727, plus the BLOCK_AFTER count tightening in PR #708) captured 2026-08-28/29, before PR #782 merged.

**This plan's premise was wrong and was corrected mid-session before any data was pulled.** The plan's own mandatory row-6 mechanism-verification step (`git show <pre-boundary-sha>:...`, required to pass before any downstream tier is written) found that PR #769 ("Restore handoff-nudge hard-block point after the 150k cap retune," merged 2026-08-30 17:55:36 -0700 — **inside** the originally-stated before era, about 18 hours before it ends) already raised the default block floor from 230,000 to 470,000 by changing `BLOCK_AFTER`'s default from 1 to 4. PR #782, merged the next day, swapped the *encoding* (a re-arm count times a spacing, versus an explicit absolute token value) but landed on the identical floor value its predecessor had already set. Row 16 below proves this is not a coincidence of default values but a structural equivalence across every context-window size. **For the dominant population of sessions, PR #782 changed nothing measurable about when the hard block fires.** The engineer confirmed (mid-session, 2026-09-06) reframing the study around the real floor-raising event (#769) rather than either silently absorbing the confound or abandoning the study — see row 16/17.

Scope decisions confirmed by the engineer: full case-study rigor (mirroring the precedent's four-tier methodology, confounds section, statistical framing, and publication-scope discipline); proceed now rather than wait for more after-era data; fold in the second machine's corpus via cross-session coordination; and, on discovering the premise error, reframe around the actual boundary of PR #769 rather than keep the PR #782 boundary as a documented limitation or halt the study.

## Approach

Design the study as a **matched counterpart to the precedent**, not a copy of it. `handoff-threshold-impact.md` measured a *tightening* (advisory cap 360,000 → 150,000) and found "gate tighter, overhead grew." The corrected question here is the mirror image but attached to the correct commit: **did loosening the hard-block floor (230,000 → 470,000, PR #769) give back the overhead the precedent measured, and did the deep-context tail eat the savings** — with PR #782 characterized honestly as a mechanism-only refactor riding on the same floor, not a second cost-relevant event. Three consequences follow the corrected mechanism model: **Tier 0 is rebuilt on hard-block position/rate around the #769 boundary** (`spend-over-threshold` has no `BLOCK_AFTER`/`BLOCK_AT` term and cannot be a mechanism-engagement gate for this change — it demotes to a Tier 3 mediator arm with a *reversed* expected direction); **era attribution for `.handoff-nudge.log` lines uses block-time, not session-start**, because the blocking population is by construction long sessions and the two eras are roughly a week apart; and **the study reports row 16's structural equivalence as a falsifiable prediction**, not an assumption — if Tier 0's empirical block-position distribution shows a detectable shift specifically at the 2026-08-31 #782 boundary rather than the 2026-08-30 #769 boundary, that contradicts the arithmetic below and must be surfaced as a surprise, not smoothed over.

### Pre-registered decision rule (fixed before any number is pulled)

Tier 0 confirming the block point moved **at the boundary of #769, and did not move again at the boundary of #782,** is expected by construction and carries no cost verdict on its own — the second half (no shift at #782) is row 16's falsifiable prediction, and a positive finding there (a detectable shift at the #782 boundary) must be reported as a contradiction of the arithmetic, not folded into the cost verdict. Given Tier 0 confirms the shift at the #769 boundary only:

- **Reversal candidate (deep-tail dominance).** Trigger if *either*: the after-era Tier 1 median exceeds the before-era interquartile range's upper bound (the precedent's own rule, reused verbatim at `handoff-threshold-impact.md:79` so the two studies stay comparable); **or** both Tier 2 instruments decline in the same direction — reviewer-spawn intensity per branch falls *and* user-facing-friction events per branch rise. Either fires, and the report names the 470,000 floor (as landed by #769, inherited by #782) a candidate for lowering.
- **Clean win.** Tier 1's after-era median is at or below the before-era median, Tier 3 arm A (sessions-per-branch, startup-burn share) falls, and Tier 2 shows no decline.
- **Real trade** (the predicted outcome). Arm A falls, arm B (`spend-over-threshold` share) rises, Tier 1's median stays inside the before-era IQR. Reported as a trade, not a win.
- **Falsification test, pre-registered.** If Tier 0 confirms hard blocks collapsed but Tier 3 arm A does *not* fall, then hard blocks were never a material driver of handoff volume. That is a publishable negative finding on its own terms: it would mean the 470,000 floor is neither helping nor hurting at this corpus's session shapes, and `docs/handoff-nudge.md:32`'s revisit trigger should be relaxed rather than tightened.
- **Small-n ladder for Tier 1** (row 14 makes this likely to bind). After-era captured n ≥ 10 → mean/median/IQR as the precedent reports. 3 ≤ n < 10 → raw per-PR values plus a point delta on the median, labelled directional-not-decisive, **no percentage headline** (this repo's existing floor, `handoff-threshold-impact.md:137`). n < 3 → report the count, decline a Tier 1 verdict entirely, and rest the study's verdict on Tiers 0 and 3 with "primary outcome not measurable at this elapsed time" stated in the short answer, not buried.
- **Peer-data fallback.** If the peer reply (including the row-18 follow-up) does not arrive, is unusable (stale checkout per row 12), shows a late deploy (row 7), **or contributes a negligible share of a pooled bucket's n** (e.g. Machine A n=9, peer n=1, both clearing the small-n ladder's n≥10 total only in combination), the study ships single-installation with that stated as a scope limit. Pre-registered here so it is not a post-hoc convenience. Whenever a figure is presented as "pooled," the doc states each side's share of *n* (count only, never values) alongside it, so a lopsided split reads as what it is rather than as genuinely joint data.
