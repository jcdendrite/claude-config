# Changelog

All notable changes to `claude-config` are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed

- **`require-respond-pr.sh` gates comment-write shapes it previously let through.** Newly denied: `gh issue comment` and its `--edit-last` / `--delete-last` forms, which post and rewrite through the same `issues/{n}/comments` endpoint `gh pr comment` uses and formerly missed the gate entirely; lowercase and mixed-case `-X delete` / `--method patch`, which `gh` normalizes before sending, so they executed as real writes while reading to the gate as a GET; `gh api graphql` comment mutations, including multi-line and file-sourced bodies; a REST URL wrapped across lines with a backslash continuation, now matched the way the shell would join it; and `gh pr`/`gh issue` writes with `-R`/`--repo` anywhere ahead of the verb rather than after it — `gh pr --repo o/r comment N`, `gh --repo o/r pr comment N`, and the glued `gh pr -Ro/r comment N` all dispatch the same write and all previously fell through every arm, including for the current repo. The `pr`/`issue` arms now tolerate that flag and its value in either position and in all three spellings, and nothing wider: `gh pr list --search comment` and `gh pr -R review view 5` both stay allowed. Cross-repo *writes* now deny for every repo — reads are unaffected — and the write denial no longer directs you to `/respond-pr` for a PR that skill cannot service. **If you drive any of these shapes from a script or a session hook, expect a deny where you previously got through**: route the write through `/respond-pr`, or run it outside a hooked session. Match arms moved to POSIX `[[:space:]]` and bash `[[ =~ ]]`, so the gate no longer depends on GNU-only regex classes that a BSD/macOS `grep` could silently fail to honour.
- **Code-review marker directory renamed to `~/.claude/code-review-markers/`** — it was the only one of the four review gates whose directory did not derive from its skill name (`plan-review` → `plan-review-markers/`, `skill-review` → `skill-review-markers/`, `ready-for-review` → `ready-for-review-markers/`, but `code-review` → `review-markers/`). Sessions debugging a blocked commit inferred `code-review-markers/`, found nothing, and read the absent directory as a failed marker write. `TestMarkerDirectoryNamingConvention` now runs each of the four `write` skills and asserts the marker lands in `<skill>-markers/` and nowhere else, pinning the convention on the write side; `TestMarkerWriteSatisfiesTheGate` adds the first end-to-end round trip (`marker.sh write code-review` → real `require-code-review.sh` → allow), so write and read side are proven consistent by execution rather than by matching literals in two files. The four read-side hooks still hard-code their marker paths independently, so the same asymmetry could still be introduced there. `/code-review`'s body also names the marker path outright and states that the command chains only to `git commit`. **Migration:** none required — markers are per-session and ephemeral, so the gate simply re-arms once and the next `/code-review` writes to the new path. Delete a leftover `~/.claude/review-markers/` at leisure.
- **Citation placement normalized across skills** — `SKILL.md` bodies carry the rule and the rationale that lets it generalize; canonical URLs and verbatim source quotes live in a co-located `REFERENCES.md`, which is never loaded at skill runtime. Four skills moved their citations (`ai-instruction-and-memory-files`, `branch-creation`, `claude-hook-review`, `npm-semver`), and `test_skill_bodies_carry_no_citation_urls` now asserts the split so it cannot silently regress. Plugin bumps: `claude-hook-review` 2.0.1, `npm-semver` 1.0.2 — both patch, provenance storage only, no rule change, so pinning consumers need not re-pin.
- **Four macOS-only bugs closed across `require-memory-skill.sh`, `require-plan-review.sh`, `enforce-marker-script-shape.sh`, `require-ready-for-review.sh`, `require-plugin-version-bump.sh`, and `cleanup-merged-branches.sh`/`cleanup-idle-open-pr-worktrees.sh`'s shared `_worktree-lib.sh`.** All four silently degraded a security-relevant check into an unconditional allow, or a live worktree into a false "idle," rather than erroring loudly — confirmed absent from CI (which runs `ubuntu-24.04`) and reproduced only under stock macOS tooling. (1) `realpath -m`, used for lexical path-boundary checks, is GNU-only; BSD/macOS `realpath` rejects `-m` outright, and none of the three call sites checked its exit status, so `REAL_REPO`/`REAL_PATH` silently went empty and every boundary check became a no-op. New `_lib_realpath_m` in `_lib.sh` prefers native `-m` support, falls back to `grealpath` (Homebrew coreutils), and finally to resolving the nearest existing ancestor via plain `realpath` and reattaching the not-yet-existing suffix — no external dependency required. (2) `sed -E`'s `\s` is a GNU extension that BSD/macOS `sed` doesn't support in `-E` mode and fails to match rather than erroring; `require-ready-for-review.sh`'s `--tags`-push branch-detection always saw an empty capture on macOS, silently bypassing the gate for every `git push --tags` that also pushed a branch ref. Switched to POSIX `[[:space:]]`. (3) `require-plugin-version-bump.sh` iterated `"${PLUGIN_ROOTS[@]}"` while the array could still be empty — bash <4.4 (including macOS's frozen system bash 3.2) treats that as an unbound-variable error under `set -u` rather than zero iterations, crashing the hook outright (silent-allow, since a crashed `PreToolUse` hook emits no deny). Guarded with the same `${#ARR[@]} -gt 0` pattern `npm-semver`'s sibling hook already established. (4) `collect_process_cwds` excluded only its own PID (`$$`) from the `lsof`-based live-process scan, but `lsof` itself is a running process at scan time and inherits the caller's cwd — its self-report, under a different PID, made every worktree the scanning shell was itself sitting in read as "in use." Runs `lsof` in the background now specifically so its PID (`$!`) can be excluded alongside `$$`. On Linux, `lsof` additionally forks a short-lived helper that inherits and reports the same cwd before exiting — invisible to CI (`ubuntu-24.04` always has `/proc`, so this branch never runs there in production) but caught by a synthetic test that forces the branch; a `kill -0` check scoped to entries matching the scanning shell's own cwd drops the exited helper without risking a false negative against another user's live process elsewhere. Also fixed: `require-skill-review.sh`'s structural-validator Python fallback assumed system `python3` has `pyyaml` installed; it doesn't on a properly venv-isolated contributor machine. Added a second-choice fallback to this repo's own contributor `.venv` (located via `git rev-parse --git-common-dir` from the hook's own on-disk path, not the target repo's — the two differ in the plugin's own cross-repo test fixtures). Plugin bumps: `plugin-semver` 1.1.4, `skill-management` 3.0.3 — both patch, bug fixes only, no behavior change for anyone the bug didn't already affect.

### Removed

- **Retired `check-runner` agent.** Transcript-corpus measurement (649 sessions, 784 dispatches) showed neither the context-cost nor verdict-ergonomics justification holds. Parent runs checks inline. Removes the agent, `check-runner-bash-guard.sh` hook, and dispatch-id contract. See `docs/case-studies/check-runner.md#retirement`.

### Added

- **`cleanup-idle-open-pr-worktrees.sh`** — new sibling script to `cleanup-merged-branches.sh` that reclaims disk space from git worktrees for open PRs that are ready for review but not currently being worked on, without touching the branch, the remote, or the PR itself. One bulk `gh pr list --state open` call per repo drives classification (no open PR / draft / still active per `--idle-hours`, default 4 / worktree in use); survivors are removed via `git worktree remove` with no `--force`. The live-process detection and branch-to-worktree-path lookup shared with `cleanup-merged-branches.sh` are extracted into `_worktree-lib.sh`, sourced by both scripts. See [`docs/scripts.md`](docs/scripts.md).
- **`skill-management` self-provisions `pyyaml`** — plugin bumped to 2.1.0; a `SessionStart` hook installs `pyyaml` into a persistent venv at `${CLAUDE_PLUGIN_DATA}/venv` on first session and after manifest changes, and the commit-time hook prefers that venv's `python` (falling back to system `python3`). Consumers no longer need to run `python3 -m pip install pyyaml` after installing the plugin.
- **Structural SKILL.md validator** — `description + when_to_use ≤ 1536` chars and strict-YAML frontmatter checks shipped with the `skill-management` plugin; the existing commit-time hook now runs the validator on every staged SKILL.md (#290)
- **check-runner subagent** — Haiku agent for suite-level command dispatch; returns structured pass/fail verdicts and writes full output to a temp file so the parent context doesn't inhale raw output (#189)
- **Foundation-critique gates** — plan-review, plan-it, reviewer agents, and CLAUDE.md now include compounding-defensive-layers and wrong-foundation prompts to catch design tells early (#190)
- **Backtick escaping block** — `deny-escaped-backticks-in-pr-body.sh` blocks `gh pr create`/`gh pr edit` bodies that contain `\`` sequences, preventing shell-expansion surprises in heredoc-constructed PR bodies (#192)
- **`~/.local/bin` script wrappers** — `analyze-context`, `token-analyzer`, `cleanup-merged-branches`, and `marker` are now accessible as short-form commands without the full path (#184)
- **Proactive handoff + marker re-injection** — `session-marker-dashboard.sh` now fires on `compact` events (not only session start), restoring gate-marker state automatically after auto-compaction; CLAUDE.md prompts Claude to suggest `/handoff` at ~60% context (#172)
- **Ready-for-review active-marker ceiling** — 90-minute hard expiry on the bypass marker prevents stale bypasses from carrying across sessions unnoticed (#173)
- **Verify-class subagent routing** — `/ready-for-review` now dispatches `pytest`/`ruff`/`tsc`-class commands through the `check-runner` subagent so suite output doesn't expand the parent context window (#171)
- **Auto-discovery in cleanup-merged-branches** — script now discovers merged branches itself via `gh pr list`; no manual branch-name input required (#165)
- **`.env.example` reads allowed** — `deny-env-reads.sh` now permits `.env.example`, `.env.template`, and `.env.sample` reads while continuing to block all other `.env.*` variants (#175)
- **PATH-resolved check in review-permissions** — `/review-permissions` now verifies that referenced scripts resolve on PATH, not just that the allow-rule string looks correct (#186)

### Changed

- **Skill renamed `sync-pr-description` → `pr-description`** (breaking, and the first stow-level skill *directory* rename). **Re-run `stow` (or `./install.sh`) after pulling.** A `git pull` alone is only sufficient when `~/.claude/skills` is a single tree-folded symlink; if it exists as a real directory — which it does for anyone who has ever put a personal skill under `~/.claude/skills/` — stow linked each skill individually, so pulling leaves `sync-pr-description` behind as a dangling symlink and never creates `pr-description`. Neither name resolves until you restow. Also update local references by hand: `settings.local.json` entries, project-layer skills, and typed `/sync-pr-description` invocations, none of which have an alias or soft-fall-back. The skill now owns the PR body in both directions: on a branch with no PR it authors one to a stated standard and writes it to a file for `/ready-for-review` step 6 to create the PR from, instead of stopping at "no PR to sync". Step 6's `git log`-derived body template is removed — the first PR body is now written to the same standard, and checked by the same passes, as every later revision (#477)
- **`cleanup-merged-branches.sh` trusts reachability as a confident merge signal** — a branch whose commits are all already ancestors of `origin/<default>` (a direct merge with no PR) is now auto-deleted with no prompt, matching the confidence already given to gh-confirmed merges. The `--yes` flag is removed since it no longer confirms anything.
- **`install.sh` no longer modifies host Python** — pyyaml `pip install --user` block removed. `pyyaml` is contributor-only (needed by `pytest claude/.claude/`); contributors set up a repo-local `.venv` per `CONTRIBUTING.md` "Tests and lint". Pins moved into `requirements-dev.txt` so CI and contributors share one source. Fixes install-time failures on macOS systems where PEP 668 / Homebrew Python rejects `--user` writes.
- **Plugin renamed `skill-review` → `skill-management`** — bumped to 2.0.0 (breaking — downstream installers must `claude plugin uninstall skill-review && claude plugin install skill-management@claude-config --scope project`); between uninstall and install there is a brief window with no SKILL.md gate active, do not commit SKILL.md changes during that window (#290)
- **CI workflow renamed** — workflow display name changed from "Hook tests" to "Tests"; job id `tests` (the branch-protection check context) unchanged (#169)
- **Handoff format inlined** — `/handoff` format moved inline into the command file; dependency on `/compact` docs removed (#176)
- `_marker_lib_repo_hash` extracted as a shared helper across `require-*` hooks and `marker.sh`, eliminating duplicated hash-computation logic (#168)

### Fixed

- **`cleanup-merged-branches.sh` restores per-branch Tier B prompting** — a branch reachable from `origin/<default>` with no merged PR now prompts `[y/N]` on a TTY and skips with a warning on non-TTY stdin, rather than auto-deleting; the open-PR guard only protects branches that already have a PR, so a branch with active, uncommitted-to-a-PR work could otherwise be auto-deleted along with its worktree. `--yes` stays removed.
- **Chained `marker.sh write && git commit` no longer denied** — three coordinated changes: `enforce-marker-script-shape.sh` accepts a chain of one or more `marker.sh write <skill>` invocations followed by `git commit`; `require-code-review.sh` and `require-skill-review.sh` (plugin bumped to 2.2.0) honor an in-chain marker write that precedes the commit. PreToolUse fires once per Bash tool call before the chain runs, so an on-disk marker check would otherwise deny these naturally-typed forms even though the chain would create the marker. Chains to non-commit tails (curl, rm, semicolon-arbitrary) stay denied, and the structural validator still fires when chained, so malformed SKILL.md files can't slip through.
- Two false-positives in `enforce-marker-script-shape.sh` that blocked legitimate `marker.sh` invocations with certain argument orderings (#187)
- `cleanup-merged-branches.sh` now skips locked worktrees rather than erroring; a follow-up fix adds unlock-and-remove for worktrees that can be released (#174, #177)
- Memory-write hook debounce replaced with active-marker bypass pattern, eliminating per-turn UUID thrash (#170)
